# 本机候选环境冒烟检查

在独立工作目录使用 Node 24.19.0，先完成 `pnpm install --frozen-lockfile`。脚本复用 `apps/web` 的 Playwright 依赖；首次使用时安装 Chromium：

```sh
pnpm --dir apps/web exec playwright install chromium
```

默认入口是 `http://127.0.0.1:32802`，也可用 `--url` 指定本机候选入口。不要连接试用服务器。

使用现有私密 JSON，选择普通账号 C：

```sh
node deploy/smoke/check.mjs --credentials '<私密JSON>' --account ordinaryUserC
```

文件必须是权限为 0600 的普通文件。支持顶层 `email`、`password`，或账号字段下的同名字段；`--account` 默认是 `ordinaryUserC`。文件若有 `publicOrigin`，其来源必须与本次入口一致。

也可在运行环境中提供 `PE_CLOUD_SMOKE_EMAIL`、`PE_CLOUD_SMOKE_PASSWORD`，然后运行：

```sh
node deploy/smoke/check.mjs
```

口令不放在命令行参数中。`--help` 无需凭据，可查看参数。

## 九项检查

1. 首页返回 200，未登录的 `/cloud/bootstrap` 返回 401。
2. 测试账号登录成功，登录后 `/cloud/bootstrap` 返回 200。
3. 新建对话并收到模型回复。
4. 在沙箱执行一条命令，核对工具成功和回复中的随机输出。
5. 同一对话连续执行五次独立命令，覆盖沙箱更换路径。
6. 创建文件，用文件名搜索和内容搜索工具找到它。
7. 上传文本文件，由模型读取其中的随机内容。
8. 生成文件，在界面预览并下载，核对内容。
9. 退出后重新登录，找到原对话并继续执行命令。

结果逐项打印到终端。每项从五分钟总预算中按操作数分配独立时限，并为重新登录和最终退出保留时间。单项超时记本项失败，结束本项操作后继续其余检查；无法确认对话轮次已停止时，依赖该对话的项明确记为未验证，有本轮对话时仍尝试重新登录检查。必选项全部通过且总用时不超过五分钟，退出码为 0；存在失败、未验证或超时，退出码为 1。结束时通过网页正常退出测试账号，再关闭浏览器；退出未确认时同样返回非 0，总用时包含清理。

## 更新前对话的继续使用

更新、回滚或再次更新后，用同一对话行标识及原模型回复中的随机标记运行：

```sh
node deploy/smoke/check.mjs --credentials '<私密JSON>' --account ordinaryUserC \
  --continue-session '<完整session:...行key>' --continue-marker '<原回复中的随机串>'
```

这两个参数必须成对提供。脚本在登录后、新建本轮对话之前执行第 12 项：从侧栏打开指定旧对话，核对原模型回复的标记，再实际执行一条新的命令。原九项继续运行，此时必须十项全部通过；不提供这两个参数时仍为原九项。脚本不会重命名或删除旧对话。

旧标记不在首次加载的历史中时，第 12 项会在该对话内容区点击“加载更早”（英文为“Load earlier”），逐页查找，沿用本项原有时限；历史已全部加载仍没有标记时明确报告没有找到。超时会注明停在“打开对话”“等原回复”或“等新一轮结束”。每次成功续用会给这个旧对话增加一轮。

错误口令负例会在内存中生成随机错误口令；预期登录失败，退出码非 0：

```sh
node deploy/smoke/check.mjs --credentials '<私密JSON>' --account ordinaryUserC --wrong-password
```

MCP 和科研模式检查尚未实现。显式指定 `--mcp` 或 `--research` 时报告未做，并以非 0 退出。

检查会留下一个对话及三个随机命名的小文件供复核，不自动删除。失败时保留终端结果交给评审者，不通过手工改数据库、删除产品状态文件或重启应用来制造通过。

## 可选的 MCP 停服与恢复检查

`--mcp-offline` 在原九项（带旧对话参数时为十项）之后追加第 13 项；`--mcp-recover` 必须与它同轮提供，继续追加第 14 项。原检查顺序、通过标准和五分钟总时限不变；新增检查只使用原检查之后的剩余时间，并保留最终退出的时间。默认不启动 MCP 服务，不加载 MCP SDK。旧 `--mcp` 参数仍是未实现的第 10 项占位，不代替这两个参数。

```sh
node deploy/smoke/check.mjs --credentials '<私密JSON>' --account ordinaryUserC \
  --mcp-offline --mcp-recover
```

第 13 项启动本轮独有、无需密钥的 `ping` 服务，在设置页先测试可达，再保存随机命名的新连接。账号已注册工具数大于 0 后实际调用一次，正常关闭本轮服务并等到关闭完成，然后正常退出、重新登录，新建对话执行命令并核对模型回复和真实命令输出。

第 14 项让服务保持停止，通过设置页“刷新”只读观察该连接的已注册工具数，直到为 0；在原地址正常启动本轮服务，对原来已启用的连接只点一次“测试连接”。随后必须观察到连接卡片工具数大于 0，新建对话并实际调用工具。测试结果的工具数不代替连接卡片的已注册工具数；不点“停用”“启用”，不重启应用或账号插件树。

工具检查同时要求成功的工具卡片、模型回复包含服务随机返回值，以及本轮服务端调用计数恰好增加一次。随机返回值不放在提示词中。任何失败不重试整项，不自动记作已知失败；原第 10、11 项占位报告继续保留。结束前在已确认登录的账号里刷新连接列表，只移除本轮添加且名称、地址仍精确相同的唯一连接，确认列表不再有它；未尝试保存时不读账号列表。随后正常退出账号并正常关闭本轮服务。身份变化、登录不明、移除或关闭未确认均返回非 0，不自动新增登录、重发删除或修改其他连接。新增对话保留供复核。

最小服务默认仅监听 `127.0.0.1`，端口由系统分配，恢复使用同一地址和端口。只有显式执行 MCP 检查时才读取公开环境变量 `PE_CLOUD_SMOKE_MCP_HOST`；它允许默认回环或本机当前网卡上一个精确的私网 IPv4，绑定和广告使用同一个 IP。拒绝通配地址、DNS 名称、IPv6、公网或未分配给本机的地址，不提供独立的广告 URL。SDK 的 Host 校验只允许这个精确 IP。测试服务只提供本轮随机标记及 `ping` 计数，不接收密钥或业务数据。

正常更新工具精确透传 `--mcp-offline` 和 `--mcp-recover` 两个无值开关，其他参数范围和原停止流程保持。这样一次正常更新即可运行原十项及新增第 13、14 项，无须另跑完整冒烟：

```sh
PE_CLOUD_SMOKE_MCP_HOST='<本机当前自有LAN IPv4>' node deploy/local/update.mjs update '<产品更新包>' \
  --line 接口线 --credentials '<私密JSON>' --account ordinaryUserC \
  --continue-session '<最新成功对话>' --continue-marker '<对应标记>' \
  --mcp-offline --mcp-recover
```

地址在参数预检时及实际监听前核对，不自动换地址。候选应用容器能否访问它仍须正常设置页探测成功才能确认；失败时不保存连接，不改防火墙、容器网络、根配置或创建新容器。MCP SDK 复用 `packages/mcp/mcp-client` 已有依赖，未增加安装项。开启 LAN 监听和候选验证仍需该版本独立 A 审查及运行时段；源码和自测不代表已完成真实可达性或候选验证。
