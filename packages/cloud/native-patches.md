# Native integration maintenance

English | [中文](native-patches.zh.md)

This reference separates the seven Cloud packages from the native code they consume. It adds no runtime component. The comparison base is `master`, the local native baseline used for this fork's audit; it is not a claim that this is the latest upstream release. Choose the intended upstream revision separately before upgrading.


Upload adaptation retains the target file/image engine and staged-receipt discriminant. The original finite Native intake/receipt owner and protected file/workspace hook are restored through target Schemastery configuration; actual body return waits for source cancellation, terminal state, pending reads and lock release, without claiming Connection wire closure. Cloud consumes only the exact file arm through its original collector/storage/publication owner and refuses ungranted prompt-image intake before source work. Its prepared Client supplies the original context carrier and an explicit file-only draft projection, so image MIME selections retain the ordinary-file path; Native default image behavior remains. The optional attachment unknown marker creates no settled default, and all unknown cleanup/handoff responsibility remains retained.
## Ownership

Cloud packages own account identity, owner routing, tenant policy, storage admission, execution binding and browser revocation. Native DSH owns Agent/Session state, dispatch, configuration application, filesystem primitives, Shell consumers and generic UI. A native callback performs its check at the actual commit or release point; an HTTP precheck cannot replace that check after an await.

The Fiber revision also detects an attempted update rejected before the waterfall. The existing `/account` entry exposes the two provision readers used by API and execution plugins. API and execution ownership checks use the target's original provisions, retain isolated duplicates and pending teardown records, and preserve current/identity checks and finite visit bounds. The original AgentRegistry entry retains an optional exact creator supplied by create/resume, and `isOwnedBy` observes that same object without inferring durable lineage or granting current-parent authority. The original Cloud reservation remains with its existing owner. The original SubagentRuntime consumes its existing admission types through effect-scoped checks at provider dispatch, cold reconstruction and actual factory/activation publication. ## Upgrade procedure

1. Record the current clean source revision, deployment revision, chosen upstream revision and trusted configuration before changing anything. Source tests and an old running release are different evidence.
2. Inspect `git diff --stat <base> HEAD` and the ownership table. Keep Cloud policy in its package. Remove a native patch only when an equivalent public native capability preserves its actual callers, default behavior, authorization, cancellation and settlement.
3. Export outside the worktree with `git diff --binary --full-index <base> HEAD > /absolute/output/cloud-native.patch`. An optional split into Cloud, native API, native client, native runtime and support patches must cover every changed path once. On the exact base, replay in an isolated Git index and compare the resulting tree with `HEAD^{tree}`; this proves reconstruction, not compatibility with a newer upstream.
4. Review conflicts in an isolated checkout of the chosen upstream. Do not force an old patch over a changed commit point, weaken a guard, duplicate a native engine or enlarge tenant quotas to resolve a conflict.
5. Build the changed artifacts and run their native default and Cloud composition regressions. Configuration work includes `packages/boot/config-editor/tests` and the Cloud approved-control tests; browser changes also need the owning GUI/browser cases. Inspect skipped tests and retain failed results.
6. Stage a versioned product, preserve the previous release, then normally stop and join the original application and verify owner/allocation release before starting its successor. Check real login, model/Shell execution, history, file preview/download and logout. Do not declare closed optional capabilities accepted or turn quarantined state into readiness.

Native patch removal is conditional on equivalent behavior, not on reducing a file count. Optional plugin management, preview, arbitrary SSH, host failover and large-file acceptance require their own runtime evidence; passing this maintenance workflow does not enable them.

Native PTC and terminal spawn requests carry their resolved per-call sandbox policy into the remote provider. Local argv wrapping remains native; the Cloud provider consumes the original confinement handoff and signs the approved policy on the same operation.

The optional Native `ProfileContext.entryAliases` keeps trusted launch-time entry renames consistent across detached boot/HMR reads and the original ConfigEditor. Cloud uses one bounded, explicitly selected historical `presets` to `agent-preset-registry` alias with the original guarded provider; existing profile bytes remain unchanged until an explicit Native save. Ordinary Native profiles have no alias.

The native attachment staging provider exposes a phase-scoped storage-capacity error for its own prepublication I/O only after its descriptor and temporary name are released. Cloud preserves that exact failure across its original mutation settlement and the original Native receipt mapping; it does not infer capacity from a source error, a queue reservation or a filesystem precheck.

Independent account plugins reuse `CloudAccountApi.sessionProject(actualSession)` through Runtime's original `projectForSession` callback; missing callback or current business admission rejects access. This Host-only method creates no Session, Agent or execution authority.

The native SubprocessHandle has optional `releaseCollected()`; Cloud collected handles delegate it to their original ManagedCommandOperation.release(). The consumer copies output first. Original range/I/O settlement retains reservations and unknown cleanup, so a single native research tool can run sequential workflow/Git commands without retaining every completed output until final projection.

The original Session Controller connects embedding preparation, model checks, and finite control buffering during service initialization, using its existing Agent, Command, and Control owners. Its [preparation and settlement rules](../api/session-controller/README.md) retain Native defaults, the guarded factory and SessionPreparation, original receipts, and unknown outcomes. Cloud supplies its existing account policy and exposes only reviewed methods; this adds no Session store, migration, or runtime owner.

The original Host Schedule runtime accepts one optional pre-initialization dispatch admission over stored tasks and their explicit targets and receipts. It rechecks after preparation awaits, before reservation, Session creation, recovery wakeup, and enqueue. Accepted messages keep their original flush and receipt owner. Readiness rescan and idle observation use the same runtime, mutation FIFO, notices, and execution slots; Native defaults, retention, intervals, and unknown writes are unchanged. Cloud target authorization is supplied separately by its adapter.

The same Schedule management FIFO offers `prepareMutation(before, after, actorSessionId)` for embedding admission over actual stored and proposed rows. Its synchronous recheck runs after asynchronous preparation and before each original put/delete or batch removal. A refused check starts no write or change notification; accepted writes keep their original settlement and unknown outcomes.

Plugin Manager retains one optional save-submission hook and one selection guard around its original profile writers. Entry and bundle selection prepare the actual profile composition, check the native plan and publication disposition, and retain native application, restart, diagnostic and unknown-result ownership. Guarded preview does not persist or activate entries; Native callers without a hook retain their existing behavior.

Agent preset selection rechecks optional embedding admission inside its original Agent queue and maintenance operation before appending the committed selection. Account policy reads the owning registry’s typed `presetForSession()` rather than a string-keyed projection. The native ZIP export registration keeps its original Fetch response, ZIP stream and cleanup; an embedding may authorize the actual parsed Session before any read and supply the signal retained through settlement. Native mounting retains its separate Markdown route.

Public fallback owners reuse the native static Request/Response responder through its resource module. WebServer renders explicit public injection rows separately from Peer-bound index sources and raw taps; native authenticated rendering is unchanged. Client Modules can supply explicitly declared browser packages without activating their Host entries, retaining current artifact revision checks and original graph withdrawal; module-only declarations remain inactive on the browser as well.

Read-only export and table conversion retain Native defaults. Log downloads keep the original authenticated HEAD and optional navigation binding, while generic manual-link and temporary-DOM enhancements are withdrawn; browser handoff proves no completed save. Generic double-BOM and synthetic-tail CSV fixes are withdrawn without changing source bytes, Cloud file providers, limits or the original download binding owner.

Cloud owns the additional `skills/change` subscription, shared API event selection, existing admitted account sender and original dependency lifetime. Native event forwarding files retain their defaults. Native ui-skill only exposes explicit `uiSkillCatalog.invalidate()` over the existing cache. Without an embedding call, Native preset/plugin-manager/reset behavior is unchanged; cache reads, aborts, Session retention and actual RPC settlement remain in the original Native engine.
