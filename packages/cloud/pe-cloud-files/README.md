# @deepseek-ai/dsh-pe-cloud-files

English | [中文](README.zh.md)

## Summary

You can inspect bounded file-work admission, cancellation, and drain outcomes for account generations. Caller cancellation does not erase actual work, and a held result keeps its byte reservation. A trusted runtime can prepare one graph-owned files owner; the account entry installs its real native Workspace Registry and selected FileSystem, defaulting to restricted S2 metadata. Production readiness still requires deployment storage authority and the complete account recipe.

## Use this package

The `/root` and `/account` entries are Loader plugins. On Linux, `/root` requires the runtime registration service, a reviewed helper binary (ABI6 for existing S2, independently built ABI7 for text writes), and explicit pool limits. It starts all configured workers before registering the unique files participant. `/account` requires a runtime-prepared `CloudAccountFiles` owner and empty configuration. It preserves the native Registry dependencies, installs that Registry and its selected FileSystem in its own native child fibers, and awaits the actual default project. Root-pool startup and successful files installation do not establish account readiness.

Trusted `AccountFilesPreparation.createFileSystem`, when supplied, selects a native constructor only after the original Registry and actual default Workspace exist, before installing the sole filesystem. Omission keeps the metadata-only S2 constructor; preparation failure neither falls back nor reports readiness. The real `StaticStorageLease` explicitly supplies its bound `port.createTextFileSystem` closure for the new text candidate, whose writes require the separate ABI7 helper. The account entry remains empty-configured, and existing running R8 artifacts are not replaced by this source change.

All [FilesLimits](src/types.ts) fields are required finite positive safe integers. Per-lane concurrency, queue capacity, and resident bytes must fit their global limits; wait time must fit a Node timer. The [root schema](src/root.ts) also requires worker count, minimum healthy count, worker and reply reservations, handshake and drain deadlines, helper location, and read/path/chunk/retry limits. The global resident limit includes the fixed worker reservation and any static-storage root reservation; the remaining capacity bounds account work. Configured reservations must conservatively cover buffers, cloning, decoding, and retained results.

During native account boot preparation, trusted runtime constructs [CloudAccountFiles](src/account-service.ts) with the exact installed binding, an existing bounded lane’s Registry construction port, its fixed default grant, and separate mount/current and unpublished-window checks. This input accepts no shared root pool, caller-selected path, Workspace receipt or plugin. After Loader settlement, `project()` returns the actual native Workspace and its files-owned `projectDirectory` for API/runtime assembly. Missing or foreign owners, nonempty configuration, competing providers and stale generations reject. The package supplies no host-filesystem fallback.


`project()` keeps its bootstrap-default meaning. `projectFor(actualWorkspace, signal)` derives a directory capability for the exact object still held by the original Registry, without replacing the filesystem or selecting a project from a path. `createProject(use, title, signal)` requires the original ready borrow. The storage lease fixes one server UUID under its original projects parent; the display title is bounded by `maxPathBytes` and retained in the same directory reservation through the actual native registration result. Cancellation after admission does not abandon that mutation. Native IDs, canonical uniqueness, membership and durable ordering remain Registry-owned. Unknown registration retains its responsibility and blocks a clean drain. The original unpublished preparation and default initialization checks remain separate.

`AccountFileSelection.directoryPreparation` is an internal typed same-process preparation identity. Runtime supplies one stable object whose `assertCaller(actualContext)` checks the original binding, exact child scope and current preparation record; Files calls it with the real contextualized caller. Files keeps its own weakly held sequence: one `resolve(root, { cwd: root })` with both strings exactly equal to the approved Workspace root, one native `stat` of that issued target, then one `processPath` after a directory result. Aliases, extra or concurrent attempts, cancellation and failure cannot restart that identity. File and missing stat results retain their native meaning and grant no process path. Preparation grants no content, streaming, listing, writing, editing, file URL or containment capability. Original selection, target, backend and lifetime checks surround asynchronous work on the existing lane and reader. Host-path mapping still forwards the real caller to the original independently guarded attachment projection. Component checks of this protocol do not establish complete Runtime/factory integration or deployment readiness.

`CloudAccountFiles.assertContentAvailable()` requires successful settlement of the original installation, its unique Registry/FS providers, and the trusted preparation callback. The storage lease delegates that callback to the same bound pool, which checks current generation, pool health, explicit content limits and actual ABI8 worker handshakes. Omission for S2, mixed ABIs, unavailable workers or a partial installation reject. Runtime must call this assertion after installation settles before admitting content-dependent recipes; method presence alone grants no readiness.

Production factories first obtain the actual storage owner through the original pool’s `requireStorageOwner()`. The optional root `staticStorage` configuration is described by [StaticStorageConfig](src/storage-types.ts); omission supports component callers and grants no owner. Preparation checks one of exactly two preplaced account assignments. The factory retains the actual lease before native Profile reads, checks its Profile/base selectors, then binds the canonical installed runtime generation once to the original projects lane. Another live epoch rejects. Lease shutdown joins that lane’s actual work and held results after runtime joins native/save/execution writers; it never returns persistent capacity or remounts storage. Local indexes receive no grant.

Static storage plan v1 retains closed-execution compatibility. Plan v2 additionally requires a finite `environmentBank` per account: a protected `bankId` and unique `slotId` entries, each with an independent ext4 `StaticStorageDomain` under that account's environments root. The owner checks every slot's actual identity, byte/inode geometry, fully allocated backing, arena total and reserve through the original pool/probe. Project and environment trees reject undeclared submounts, including read-only and pseudo filesystems. A v1 plan cannot satisfy `assertExecutionStorageAvailable()`.

Trusted deployment initialization places one regular, single-link record at `private/.pe-env-<bankId>-<slotId>.json` for each slot. Its initial fields are `schema: 1`, the exact `bankId`/`slotId`, a positive safe-integer `slotGeneration` and `state: "free"`. A bound record adds `sessionId`, `workspaceId` and `environmentVersion` and changes state to `"bound"`; no sandbox or command state is stored. The runtime never initializes a missing record or infers freedom from an empty environment directory.

Root must approve the exact native Agent/Session and Workspace relationship before calling `prepareExecutionMounts(originalProject, sessionId, environmentVersion, signal)`. The original issued project object is required. The method prepares the fixed project `.pe` directory, reads the bank's fixed private records and atomically binds one explicitly initialized free slot before returning `ResidentResult<ExecutionMountGrant>`. Missing, invalid or duplicate records close bank admission; unknown publication retains the original operation and reservation. A confirmed read/probe cancellation leaves the bank reusable. A confirmed late write remains bound after observer cancellation. Private bank metadata and original attachments stay private; the grant describes only the selected project and environment, measured hard limits, current binding and a read-only `.pe` policy. Execution must independently verify the actual mounts and process stopping.

Execution storage requires the helper's actual independent `projectMetadataVersion: 1` capability; an older ABI8 helper rejects preparation before SDK creation. Its fixed native operation verifies the original project device, inode and mount, opens only `.pe` without following links or crossing mounts, and creates a missing directory with mode `0700`. An existing directory must have the expected UID/GID, mode and hard storage domain. Success follows directory and parent synchronization, repeated identity checks and actual descriptor closure; the fixed 96-byte frame supplies `.pe` identity to the opaque grant. The original mutation, worker and positive reservation cover this operation and the private bank binding. Successful `.pe` directories remain after cancellation. Unknown creation, synchronization or closure retains that operation and budget without issuing a grant. Actual ARM64 helper compilation and Linux syscall verification remain deployment prerequisites.

The separate actual `environmentLayoutVersion: 1` capability prepares only `home`, `venv` and `tmp` beneath the selected verified environment anchor before private slot binding. Each entry must be a directory with the expected application UID/GID, mode `0700` and the same device/mount; links, special entries and mismatches reject without replacement. Missing directories are created without clearing existing Session content. The fixed 256-byte frame records each identity, creation and synchronization facts after directory/parent fsync, repeated identity checks and all descriptor closure. This preparation shares the original mutation and its complete reservation; unknown effects retain both and issue no grant. A successful late receipt leaves directories intact after cancellation and does not bind the free slot. The grant sets `environment.rootReadOnly: true`, fixes `writablePaths` to `home`, `venv`, `tmp` and carries their separate `layout` identities. Execution must mount the environment root read-only and bind only those three entries read-write from the same hard domain, preventing user replacement of their source entries. This package prepares identities; actual mount enforcement and startup checks remain execution-owned. Older helpers still serve their existing ABI8 content methods and closed v1 plans, while execution-storage preparation requires both fixed capabilities.

`assertExecutionMountGrant()` accepts only this owner's original unreleased object and rechecks the graph, providers and native project membership. Release or graph lifetime end revokes the grant and returns its retained memory; it does not stop compute, delete data or free the persistent slot. Ordinary compute reclamation retains Session ownership. Changed projects, incompatible environment versions and deletion require explicit stop/cleanup evidence; this package supplies no environment erasure or automatic slot reuse.

Optional root `skillVersions` requires the verified static private domain, explicit version/content-byte/inode/resident limits, and an ABI8 asset compiled with `DSH_FD_SKILL_ABI`. `CloudAccountFiles.skillVersions()` returns the original bound [port](src/skill-versions.ts), never a private filesystem path. It prepares exactly `SKILL.md` and `resource.bin`, with sealed `0500` version directories and `0400` files. The original pool reserves 2 KiB per possible version handle globally and deducts it from each lane capacity; preparation releases its mutation turn before the caller releases the retained result. The native inventory charges every retained version; logical totals also reserve 1,024 pointer bytes and three control inodes. The independent private filesystem continues to enforce all-writer physical limits. Incomplete or unrecognized entries block new preparation rather than disappearing from accounting.

Without `skillBundles`, preparation does not choose the active version. `commit` uses original native text CAS for `skills/current.json` inside the caller's existing API save turn; confirmed late outcomes remain observable, and unknown mutation or cleanup retains the original operation, reservation and lease. Source methods expire when consumption ends; repeated copies share a finite emission allowance. The worker running slot ends before consumption, while the original resident result remains charged until release. All originals remain charged throughout the live graph. Only the original storage lease's post-drain path cleans noncurrent versions after runtime confirms native/source/save/execution shutdown and files settlement; current data persists across restart. When projection is configured or protected project-copy metadata still exists, post-drain retirement conservatively retains every original under the existing finite source limits, preserving persistent copy references. This storage port does not publish native catalogs, project resources or expose model/UI management.

Optional `skillProjection` uses the original verified private/projects domains and mutation lane, with an independent `skillProjectionVersion: 1` helper. `prepareSkillProject` fixes `.pe/skills` without creating a sandbox; its result belongs to allocation/export lifetime. `materializeSkillVersion` publishes exactly `SKILL.md` and `resource.bin` as a writable `0700` directory with `0600` files, then confirms a protected private `skill-working-copies/` association using native FsVersion CAS. Record bodies obey `maxRecordBytes`; their CAS requests use the original worker-wide `maxReadBytes` transport capacity. Confirmed copies retain user edits and replacement file inodes; immutable original hashes remain checked.

The closed [limits and budget model](src/skill-projection.ts) separately charges bounded projects, retained copies, parent/operation borrows, scans and old/new record buffers. Private metadata charges actual allocated blocks, one block-rounded atomic-record temporary and bounded directory growth; copies/staging stay under the original project hard quota. `borrowAllSkillWorkingCopies` derives the complete associated project set from protected records, rejects the whole set if its operation cap or any original issued source qualification fails, and verifies every actual directory before Root signs execution facts. The explicit-copy method retains the same checks for its selected set. Its resident result survives observer/lifetime abort until the original operation's actual remote/local/physical settlement. Releasing materialize ends its I/O reservation while the files-owned bounded copy handle remains; it does not delete data or stop scripts. Partial/unknown publication remains original-mutation owned without automatic rollback, replay or GC.

The [association format](src/skill-project-work.ts) is separate from immutable inventory and native Session/PG formats. Records bind measured source boot/namespace and directory identities. Ordinary cold reads refuse changed scope or mounts. Optional Root-only `staticStorage.skillRevalidation` supplies a fixed protected `proofPath` and `proofSha256`, bounded by `maxPlanBytes`, for one exact complete/pending-null record SHA/native revision and account/Workspace. Root must bind actual prior process/writer termination and owner recovery receipts plus continuous original volume/backing identities. The worker validates and retains this optional proof selector across workerData decoding; omission supplies no proof, and malformed fields or a hash mismatch refuse. The original owner captures its actually verified plan/process, then the installed lease captures the authentic factory instance/epoch/lifetime; the proof never preselects future identities or limits later ordinary mounts. The original mutation lane verifies the current registered Workspace, every directory/copy inode and immutable source before association CAS and fresh capability issuance, preserving edited copies. Only a confirmed successful revalidation CAS consumes the exception in the original Root qualification, shared across its leases; identical JSON bytes with a new native revision cannot force it again. Unknown or rejected CAS does not consume it. Missing proof, pending/unknown work, changed backing or a failed native check refuses. In two-file-only mode, full-set cold borrowing still refuses if any historical version lacks an exact object from the current source issuer. Native provider integration, signed operations, SDK nested mounts and the writable execution world remain separate prerequisites; these methods alone open no model/UI capability.

Optional `skillBundles` extends the same account files port, original mutation lane and private/projects hard domains. All [bundle limits](src/skill-bundles.ts) are explicit; Config validates complete archive/input/manifest/catalog/request/reply/staging/resident bounds and charges retained manifest handles. It requires the independent helper capabilities `skillBundleVersion: 1`, `skillBundleProjectionVersion: 1` and `skillBundleReclaimVersion: 1`; ABI8 and the original fixed frames are unchanged. Complete files or ZIP/`.skill` bytes are decoded by the locked yauzl library with canonical relative paths, duplicate/type/link checks, actual expanded sizes and CRC. Scripts remain data. Full ZIP export includes nested resources and empty directories; no URL intake or resource execution is provided.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The [work queue](src/work-queue.ts) reserves global and per-lane bytes before admission, bounds concurrent and queued work, cancels queued work without starting it, and keeps running work after its caller aborts or times out. Every operation requires a positive safe-integer reservation that includes its overhead. Zero is refused before backend invocation, so retained records cannot bypass the resident budget. A settled successful result retains its reservation until its consumer releases it. Closing a lane stops new work while preserving unresolved records; closing the queue stops all lanes.

Configuration idleness reads the same lane records. Only completed execution-mount and skill-parent grants use passive lease retention; their future I/O reenters this lane. Their positive resident reservation and terminal-drain operation id remain until original release. Ordinary retained results, streams, queued/running I/O, directory responsibility and unknown mutation settlement remain busy. No deadline, observer cancellation or local configuration check releases these resources.

Settlement observers run independently: a failed observer is reported without preventing budget release, later observers, or queued work. A failed reporter falls back to a default-enabled diagnostic without exposing the original exception text. A final abort check immediately before the deferred backend invocation prevents cancelled work from starting.

The [file work owner](src/work-owner.ts) consumes runtime-owned account binding, operation-id, participant, and receipt types. It binds an internal object-capability lane to an exact generation and a trusted current-owner callback, refuses another generation while the first owns work, and reports unknown until actual work and held results settle. Lifetime abort stops admission, and expired drain waits remove their settlement observer while the owner continues tracking work.

The private [directory responsibility](src/directory-responsibility.ts) registers retained ownership and preparation I/O atomically on that same lane. Its [budget calculation](src/directory-budget.ts) reserves bounded intent and identity copies, records, one observer, result frames, and one complete cleanup scratch area before dispatch. Actual preparation settlement returns running capacity and its I/O bytes; created or unknown responsibility keeps a positive reservation and operation id. Observer abort or deadline does not cancel this ownership. Only the original private responsibility may schedule cleanup through the shared running/queued limits, using its retained scratch even after business closure. Exposure is irreversible; exposed or unknown responsibility cannot be declared clean, and unresolved responsibility prevents lane retirement or a new epoch. The base scheduler accepts audited component callbacks, which provide no filesystem authority or kernel evidence. A privileged root-owned isolated tmpfs fixture grant, or a deployment-owned exact independent ext4 mount grant, can derive a fixed single-leaf port; this is not a production grant issuer or an account provider. Server-selected intents admit the fixed default leaf `default-workspace` and a new project’s once-generated UUID; valid spelling and an AccountLayout object do not grant write access. Root shutdown closes ordinary admission first and retains idle slots for explicit cleanup of original responsibilities. Cleanup may use one healthy idle slot below the business health minimum; zero healthy slots remains unavailable. Queue overflow never triggers automatic retry or a hidden waiting queue. Slots close only after actual work, held results and responsibilities settle, and the root effect then waits for actual exits.

This internal work port cannot choose another account or close the shared queue; it is not a native filesystem or an issued storage capability. The queue measures reservations rather than enforcing allocation sizes inside arbitrary callbacks, so only an audited bounded backend may submit production work.

The private [Linux worker](src/file-worker.ts) probes the required kernel operation during startup without retaining an account directory. The [ABI 6 N-API helper](native/fd.c) verifies a fixed root identity and uses `openat2` beneath that anchor, with no magic-link, cross-mount or portable fallback. Metadata uses an `O_PATH` FD and returns native version fields for directories or single-link regular files; absent paths return undefined, while special files and hard links are rejected. Nonstream reads close their FD and anchor before replying; streams retain one FD until actual EOF, cancellation, or worker exit.

The same bound lane also exposes a read-only [directory port](src/directory.ts) with `canonicalPath` and `isDirectory`. Its helper observes bounded physical FD spellings, reopens beneath the same anchor to compare identities, rechecks the anchor, and closes descriptors before success. Target ENOENT/ENOTDIR can be definite missing/non-directory failures; anchor loss, verification failure, capacity, stale generation, cancellation, and transport faults remain unavailable with their causes. The private `DirectoryMetadataFailure` records the reason and failed stage. This port has no `ensureDirectory` and cannot be installed as the complete native Workspace directory dependency. Read-only Linux coverage does not certify creation or cleanup; ABI 6 requires separate published-worker verification.

ABI 6 adds self-contained single-leaf preparation and exact empty-directory removal at mode `0700`, with a real tmpfs backend check. A fixed 64-byte frame records mutation phase, parent/leaf identity, original mkdir errno and actual descriptor closure. ABI 6 separates the tmpfs branch from the ext4 branch, which requires the exact mount id, ext4 type, filesystem-root inode, and same-mount lookup. Persistent prepare synchronizes the leaf and its parent; persistent cleanup synchronizes the parent after removal. Success requires explicit mount and sync facts. A sync failure after mutation keeps unknown responsibility. These kernel observations do not establish deployment ownership, physical capacity reserve or production authority. Confirmed not-created failures reject the business operation and settle its temporary responsibility; cancellation after a fully verified created frame retains identity and responsibility. Failed post-create parent verification permanently disables cleanup even if the path or window assertion later recovers; lost replies, worker faults and ambiguous outcomes remain unknown. Cleanup requires the original private identity and a still-valid complete namespace exclusion window; empty or missing paths alone never prove safe removal. Close errors retire the FD number before fatal worker failure, preventing a finalizer from retrying a possibly reused number. General recursive preparation remains unavailable; actual published ABI 6 syscall validation remains coordinator-owned.

The [Workspace adapter](src/workspace-adapter.ts) fixes all three native directory methods before native initialization, while the registration window is valid. Its constructor and metadata selection require both the Context and its independent root to hold the exact bound `peAccount` generation. Read methods share the existing pool and lane and check the current graph before and after I/O. They remain available after the registration window closes. Unpublished preparation, exposure and transfer still require that separate window. `ensureDirectory` admits only the pregranted `default-workspace` leaf; the public native default initializer still decides eligibility, history rechecks and durable identity. The thin override supplies the account project address instead of the desktop Documents resolver. After the window closes, native default initialization can still return an existing default or its deleted/ineligible state; an actual request for a new directory rejects before a ticket or mkdir. New projects receive a once-selected server UUID grant, independently of the display title, then use the original native `create` operation.

Public `Registry.create(path, title)` only resolves an already registered native object, including its canonical aliases, and checks that the same object remains registered after the lookup. An unknown existing directory rejects without invoking native creation. Only the private fixed-grant and admitted-ready preparation paths may register new objects through native `create`; default initialization retains its original private native path.

Temporary directory responsibility transfers only after the actual native registration Promise fulfills with a Workspace. The private adapter verifies the original ticket, its unpublished window or operation-local ready borrow, each candidate’s complete namespace window, matching physical path, and internal FD identity before and after registration. Native cache membership is only a cross-check. Transfer releases the retained reservation without removing the directory or retaining a project-to-ticket map. Undefined results, rejection, late graph closure, identity mismatch and lost preparation waits retain unknown responsibility and prohibit cleanup; a later successful preparation reply cannot reverse that uncertainty. Ordinary prepared-leaf controls remain exposure and cleanup only.

The native Registry’s internal `createS2Project()` obtains the actual default Workspace result and derives a separate project root from private worker metadata on the same lane. The [S2 provider](src/s2-project.ts) implements the complete native FileSystem method table while granting only `resolve`, `stat` and `processPath`. Content reads, listing, preview, watching and mutations reject with native filesystem errors before dispatch. Its fixed graph-owned `projectDirectory.prepare(cwd)` validates that registered directory through the same project reader after registration closes; it never creates a directory from the supplied address. Constructor installation checks the original account root and refuses a duplicate provider. Deleted Workspaces, stale generations, replaced anchors and forged targets reject. The [account owner](src/account-service.ts) installs these native providers through `/account`; this component does not issue a production storage capability.

An owning graph requests `createTextFileSystem(actualDefaultWorkspace, assertInstalled, resolveProject)` from its existing bound port before installing its sole filesystem. The exported asynchronous `ResolveAccountFileProject` callback obtains an `AccountFileSelection` from the actual native caller before a model path is interpreted. Files independently checks the original providers, account binding and exact Registry object. Each target privately captures that selection, a same-lane project backend and its original FD anchor; no permanent project backend map is kept. Synchronous process paths, URLs and containment check the captured selection without querying headers. Asynchronous target operations recheck both that captured selection and the fresh caller selection before and after I/O, rejecting another project or an expired scope. Absolute paths grant no authority to select another project. Canonical keys are stable within their selected project across atomic replacement and aliases. The [text provider](src/text-project.ts) supplies resolution, metadata, process paths, file URLs, containment, bounded text reads/streams and `writeText`; its additional raw-content methods require the ABI8 capability below. The original S2 provider remains available.

With explicit ABI8 `content` configuration and verified worker handshakes, the same router grants path-level nofollow `lstat`, `listDir`, complete `readBytes` and positional `readByteRange`. Selection precedes lstat path interpretation. Directory entries receive valid targets from the same provider and captured project backend; links and special entries map to `other` and their targets permanently grant metadata observation only. They cannot be read, written or listed through those targets. Complete bytes use the existing worker read with a cap-plus-one probe and return exact buffers; their effective cap is the minimum of the caller cap, `maxReadBytes` and `maxReplyBytes` minus 128 framing bytes. Range length must fit both configured byte limits, while the full file may be larger. Before dispatch, one positive same-lane reservation covers native/path scratch, reply and name/metadata copies, expanded entry targets and byte results through handoff. Overflow or insufficient per-lane capacity rejects. Cancellation retains that actual operation until its worker reply or exit; no extra pool or backend cache is created. `editText` remains unavailable and `watch` explicitly rejects as unsupported.

The default helper build remains ABI6. A separately named asset built with `-DDSH_FD_TEXT_ABI` reports ABI7 and adds bounded text publication; it must not replace a running ABI6 asset. The worker accepts both, but ABI6 text writes reject before dispatch. Existing `maxReadBytes` bounds complete raw text reads, UTF-8 write input and optional prior context; context at the cap or containing binary/invalid UTF-8 returns `before: null`. Result context normalizes newlines while stored and read text retain the supplied bytes. No additional text-limit setting is introduced.

A separately named ABI8 asset requires both `-DDSH_FD_TEXT_ABI` and `-DDSH_FD_CONTENT_ABI`; default ABI6 and ABI7 exports remain unchanged. ABI8 workers require explicit `content` limits: `maxEntries`, `maxNameBytes`, `maxReplyBytes` and `operationTimeoutMs`. The transport adds `lstat(root, path, signal)`, `list(root, path, maxEntries, maxBytes, signal)` and `readRange(root, path, offset, length, maxBytes, signal)`; ABI6/7 reject these commands before dispatch. These private methods do not install or grant native FileSystem capabilities.

ABI8 `lstat` strips trailing separators and opens the final entry with `O_PATH | O_NOFOLLOW`, reports file/directory/symlink/other metadata and definite target absence, and retains the existing single-link rule for regular files. `list` iterates direct children beneath the verified project anchor, observes each final entry without following it, and returns UTF-8 byte-sorted names and metadata after descriptors close. Its configured name/entry limits and caller's complete metadata-reply limit reject excess; it never silently truncates. Native admission charges 128 bytes for framing plus 512 metadata bytes and six times each raw name's bytes before retaining an entry, and the worker/client also check the complete reply's UTF-8 JSON size. Invalid UTF-8 names and names ambiguous as path components reject. Listed symlinks grant metadata-only entry targets, never followed-target or content authority. `readRange` reads only the requested safe positional window, including empty EOF/zero-length results, without requiring the complete file to fit that window's cap. The window length plus 128 framing bytes must fit `maxReplyBytes`; full reads retain their existing cap-plus-one behavior.

Content operations check cancellation and a monotonic deadline, recheck the original anchor, and close file/directory descriptors before replying. Directory enumeration also reopens the selected directory to compare its identity. A blocked syscall remains owned until it returns or the worker actually exits; the deadline is not a claim of kernel interruption. Unconfirmed closure or a malformed native reply is fatal, while the client retains pending work until actual exit. No content method creates directories, publishes attachments or starts a watch. The opt-in [Linux content check](tests/linux-content-interop.mjs) exercises the separately compiled ABI8 helper through a freshly built worker; production deployment and pool/provider wiring require their own evidence.

Text mutations enter the original bounded queue before waiting their turn, then serialize all writes on that bound lane, including aliases. The ABI7 transaction requires an existing canonical parent, creates its own exclusive same-directory temporary file at mode `0600`, writes and synchronizes it, rechecks root/parent/target identities and version, publishes by rename and synchronizes the parent. Create-if-absent and replace-if-version use the native intent and error taxonomy. It rechecks publication and closes descriptors before success. Confirmed prepublication failure removes only its exact temporary identity and synchronizes cleanup. Native write cancellation and queue deadlines signal actual I/O without ending the native wait ahead of its reply: cancellation after publication returns the confirmed outcome once received. A queued write can cancel before backend invocation. The original task retains the result reservation until its native consumer releases it. A lost reply, uncertain publication, failed cleanup or ambiguous closure retains the original operation id and full positive reservation, rejects later writes and prevents a clean account drain. No automatic retry or recovery declares such work clean. This text API grants no recursive parent creation, external-writer compare-and-swap or `editText`; binary staging uses the separate companion below.

Optional `staging` selects a separate ABI1 companion on the same bounded workers; it does not replace ABI6/7/8. Every helper path, file/batch byte and ref count, native source chunk, deadline and complete `reservationBytes` is explicit. One admitted mutation batch lazily collects authorized native refs, copies each original stream sequentially through exact single-credit frames, and independently verifies size/hash/EOF before durable no-replace publication at `.pe/attachments/<digest>/<name>`. Existing copies require complete verification; corrupt or linked copies reject without replacement. Both source and sink must actually close before known settlement. A successful retained result releases its running slot while the original queue keeps its byte reservation until release; unknown publication or cleanup keeps the original task and blocks later account mutations. Root retains responsibility for source collection, current Agent/Session authorization, native receipt retirement, hard disk/inode limits and its finite metadata budget.

The optional account attachment provider inherits the native local store, original persistence, streams and image handling. Its synchronous file path lookup exposes only an active request's already verified project copy; the filesystem maps that exact same host file to its process path. Neither a private-root prefix nor a matching digest grants access. Ordinary filesystem text writes to `.pe/attachments` are denied. Intake uses the same mutation lane before native storage starts, and unconfirmed native cleanup cannot release its original work reservation.

The graph-owned account owner retains one installation Promise through actual settlement. It rechecks the exact binding, original native providers and unpublished window after awaited installation work. Repeated installation from the same entry joins that Promise; another entry rejects. A partial or failed installation never returns a project or certifies cleanup. Native fibers retain provider teardown, the existing lane retains uncertain directory responsibility, and runtime retains graph drain and shared-pool ownership. The returned directory capability rechecks both original providers before and after its real same-lane directory validation, including after registration closes.

The bound port exposes an internal [reader](src/read-only.ts) with the native `resolve`, `stat`, `streamText`, and `processPath` signatures needed by account-instructions. Resolution stays within its previously authorized root and issues opaque targets; every later operation checks the exact issuing reader and current epoch. Absolute paths never select another project. This adapter supplies no complete filesystem service or trusted-root issuer.

`withInstructionReaders` requires the account owner's exact registered Workspace and a storage-owner-issued private parent. The parent grants metadata observation only: an existing `instructions` directory must resolve to its own verified root before any account content reader is issued; only confirmed absence omits that source. Project and account readers share one positive snapshot reservation and one borrowed worker, without nested queue admission. Actual source reads and closure settle before a successful result is returned; its complete reservation remains held until release. The caller still owns exact active Agent/Session admission, and the account owner rechecks its original providers and Workspace around the operation.

The [shared root pool](src/worker-pool.ts) prebuilds a fixed number of workers and reuses them across bound accounts. Binding and reading create no workers; failed workers are not automatically replaced. Each operation obtains one queue reservation for request/result buffers. A text stream holds its slot between pulls, grants one chunk credit, and uses `readChunkBytes` per chunk and `maxReadBytes` for the complete raw content. It reads at most the total cap plus one byte, decodes UTF-8 across chunks, and uses the native fatal-decoding and first-8192-byte NUL-sample rules. Early consumer return cancels the operation without declaring its FD closed. After I/O closes, a paused iterator retains the same reservation for its decoded chunk until it finishes or returns. Consumers must finish or return their iterator. The [transport](src/worker-client.ts) waits for a real reply or actual exit after cancellation; malformed replies and worker errors stop admission, and late replies cannot reverse a transport failure. Account drain closes that generation and signals active I/O while preserving the shared pool.

The [root effect](src/root-lifecycle.ts) retains root reservations and the files participant until root probes actually finish, all workers exit, and all account work and held results settle. A bounded shutdown may report unknown; the effect continues owning cleanup and keeps registration and the root service until actual closure. Pool lifecycle alone grants no project root.


The [static storage owner](src/storage-owner.ts) reads a root-owned, hash-pinned deployment record through the separate read-only [probe ABI1](native/storage-probe.c). Root writes it after allocating and synchronizing the actual retained backing resources. Existing slots measure ext4 identities, finite byte/inode geometry, backing metadata, arena free reserve, protected ancestors and application permissions. Root initialization requires a read-only application root, the recorded nonroot UID/GID, zero capability sets, NoNewPrivs and seccomp. These observations do not identify the seccomp filter or device policy: trusted Root composition must retain that confinement and verify real denied mount/device/loop/execute attempts. Host or whole-VM storage failure is an infrastructure fault; account-approved writes causing another account or control failure remain a deployment failure. Hashes and requirement numbers cannot replace live observations or Root’s resource ownership.

The `/root` entry also exposes the same `parseStaticStoragePlan` and `accountEnvironmentBank` selectors to trusted deployment composition. They decode the protected record without issuing a files grant or certifying live storage; execution consumers still require the original current account grant and actual source measurements.

Root probe configuration reserves bounded record/proc/asset copies, native scratch and retained facts globally before account admission. One account verification runs at a time. The two fixed assignments retain at most two preparation/lease records and join verification serially; duplicate generation inputs share the same Promise. A failed verification closes admission, while root closure or an aborted queued lifetime rejects before further I/O. Pending verification remains owned until it actually settles. Observation expiry retains the busy slot, root operation id and reservation until an actual reply or exit. Neither component transports nor macOS can issue a real storage owner. ABI6 and its S2 behavior remain separate; Linux helper compilation, actual confinement, byte/inode exhaustion and continued control/account writes require deployment verification.

The files idle query observes the original exact epoch lane, pending work and root-probe ownership. Resident results still count as work. It releases no result, retires no lane and supplies no drain receipt.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

Production activation of the complete S3 file capability still requires the following integrations.

- The shared root pool provides a complete Workspace metadata adapter inside a trusted isolated graph. Registration transfer requires its original unpublished window or actual ready borrow; metadata reads can continue while the published graph remains current. This lifecycle distinction supplies no production storage authority. Static admission covers exactly two Root-preplaced independent private/projects domains and bounded auxiliary mounts. Dynamic allocation, general recursive preparation and live concurrent registration/deletion remain unavailable. The explicit text and instruction-reader paths do not establish complete S3 acceptance, complete target/write coverage, link-race acceptance or complete allocation accounting. A backend string or statfs result cannot supply actual deployment ownership, privilege exclusion or all-writer byte/inode reserve.
- Runtime binding and receipt types are consumed from the runtime package. Root registers the files participant after worker startup, but the trusted factory must retain the actual storage owner/lease before Profile I/O and connect the complete approved recipe before production use.
- The default S2 FileSystem grants metadata methods only; trusted preparation can select the bounded text provider and fixed-source `withInstructionReaders` described above. ABI8 content preparation also grants the bounded read-only methods described above. Attachment intake/staging, native skill-provider/writable-world integration, editText and watches remain unavailable; complete link-race and allocation acceptance still requires separate evidence. These explicit additions do not certify a complete S3 or real Web flow. Each selected helper binary must be built and pinned by the reviewed Linux deployment recipe; the package does not ship a preverified binary.
- Workspace source tests use real native Loader, JSONL and JSON StorageDomain with a test-only Node-backed worker transport; they establish no kernel or quota facts. Separate published ABI 6 Linux checks verify exact ext4 mount identity, reject a wrong mount id and a same-device nested bind, and restore the same native Workspace and Session JSONL event hash after clean unmount and a new container/Node process. These component checks do not validate the account entry’s complete product recipe. Directory-sync fault injection, native WorkingDirectory/SessionController composition, production all-writer isolation and hard quota, total physical reserve, crash/power-loss recovery and a Web flow remain separate requirements.
- Text source tests also use that test-only Node transport. The opt-in [ABI7 Linux check](tests/linux-text-interop.mjs) requires the separately built helper, published worker entry and an approved test parent. It checks native create/update/version outcomes, bounded context, link rejection, prepublication cancellation, temporary cleanup and descriptor closure. It does not establish deployment isolation, running-cancellation fault coverage, sync-failure recovery or crash/power-loss durability. Published ABI7 verification remains required before using the new candidate; no verified binary is supplied here.
