# 实验参考方案生成规则

## 1. 适用目的

当用户没有提供完整实验数据、实验设置、数据集说明、对比方法、消融方案或评价结果时，不再把这些缺口全部视为阻塞项。模型允许在不冒充真实项目事实的前提下，生成一份独立的“实验参考包”，用于帮助用户设计、补做或补充实验。

实验参考包是给用户的参考设计，不是已完成实验的事实证据。它应作为章节计划和实验正文草案的结构化来源；当当前章需要实验验证且真实数据不足时，默认生成并可直接写入报告草稿，结构化包中必须保留来源状态；正式正文不需要逐项显式写“参考实验/模拟实验/示例数据/参考结果”，统一按 `experiment-evidence-layering.md` 在章末说明一次。它不会因为进入正文而自动晋升为最终报告中的已验证结果。

## 2. 可以自主生成的内容

模型可以结合当前章研究目标、电力对象、算法/模型、工程约束和预期指标，自主提出：

- 实验目标、验证问题和假设；
- 实验场景、工况、变量、控制变量和随机种子策略；
- 数据集使用方案，包括用户已有数据字段设计、公开数据集候选、合成/模拟数据构造方法、训练/验证/测试划分方式；
- 评价指标及其选择理由；
- 对比方法、经典基线、强基线和与本章方法相近的候选方法；
- 对比实验、消融实验、参数敏感性实验、鲁棒性实验、泛化实验、不同电网工况实验；
- 建议的软件环境、硬件类别、主要超参数和重复实验次数；
- 用于说明预期表格结构、数量级和结果趋势的模拟/示例实验数据；
- 结果表、消融表、敏感性曲线数据、误差分布数据及对应绘图说明等参考图表结构；实际插图仍按白框占位规则处理；
- 用户后续需要补充、替换或实测确认的项目清单。

允许提出比用户现有材料更完整的实验设计，只要不改变已确认研究问题和技术边界。

## 3. 参考数据与真实数据必须分层

所有由模型自主生成的实验数值必须标记为以下状态之一：

- `simulated_reference`：模型生成的模拟参考值；
- `illustrative_example`：仅用于说明表格或趋势的示例值；
- `expected_range`：基于技术常识给出的建议范围或目标区间。

不得把以上状态写成：

- 已测得；
- 实验结果表明；
- 相比基线提升了；
- 项目达到某准确率/响应时间/鲁棒性；
- 已在某真实数据集或现场系统完成验证。

只有用户提供、文件中存在或后续明确核验的实验数据，才可以标记为 `verified_real_result` 并进入正式成果结论、摘要第三段和本章小结中的已实现结果。

## 4. 实验参考包的默认结构

推荐输出：

```yaml
experiment_reference_package:
  reference_only: true
  evidence_status: "model_generated_reference"
  draft_report_inclusion: "allowed_with_chapter_end_notice"
  chapter_id: ""
  research_question: ""
  experiment_objectives: []
  dataset_plan:
    - dataset_or_source: ""
      source_status: "user_data_template | public_candidate | synthetic"
      intended_use: ""
      fields_or_features: []
      split_strategy: ""
  experiment_settings:
    scenarios: []
    variables: []
    software_assumptions: []
    hardware_assumptions: []
    random_seed_strategy: ""
    repeated_runs: ""
  evaluation_metrics: []
  baseline_methods:
    - method: ""
      baseline_role: "classical | mainstream | strong | related"
      selection_reason: ""
  experiment_items:
    comparison: []
    ablation: []
    sensitivity: []
    robustness: []
    generalization: []
  simulated_reference_data:
    - table_id: ""
      data_status: "simulated_reference"
      purpose: ""
      columns: []
      rows: []
  reference_result_analysis:
    - "说明模拟参考数据的比较关系、预期趋势、模块贡献和后续真实实验需要核验的结论"
  user_supplementation_checklist: []
```

`reference_only: true` 只表示该包在**证据语义上属于参考材料**，不能作为已验证项目证据；它不表示“只能放在报告外”。当 `draft_report_inclusion: allowed_with_chapter_end_notice` 时，可以按第7节规则写入报告草稿，并在使用模拟数据的章节末尾统一说明一次。

## 5. 数据集候选规则

数据集方案可以分三类：

1. **用户项目数据模板**：根据当前研究对象设计建议字段、时间粒度、样本单位、标签和数据划分方式，等待用户替换为真实数据；
2. **公开数据集候选**：可以提出适合的公开数据集类别或名称。若具体数据集的来源、版本或可获取性未核验，只能写成候选，不得声称已实际下载或使用；
3. **合成/模拟数据**：可以给出仿真系统、规则生成、扰动注入、故障注入、采样策略和规模建议，生成参考表格或示例值时必须在结构化数据中标记为模拟；正式报告正文按章末统一说明规则处理，不在每个表格中重复提示。

## 6. 对比方法规则

对比方法应形成层次，而不是只挑最弱基线：

- 传统或物理/统计基线，用于说明基本增益；
- 与当前任务匹配的主流计算机方法；
- 至少一个较强或较新的同类技术路线候选；
- 本章方法的关键变体，用于消融。

如果具体方法并非用户已有实现，只能表述为“建议对比方法/候选基线”，不得在正式结果中写成已经完成对比。

## 7. 与正式报告正文的关系

实验参考包既可以作为结构化用户参考材料，也可以直接支撑报告草稿中的实验部分。正式正文继续遵守真实性边界：

- 实验设置、数据集使用方式、对比方法等设计性内容，经用户确认后可以作为“实验方案”进入正式正文；
- 模型生成的模拟数值不得因为用户确认实验方案而自动变成真实结果；
- 用户提供真实结果后，应使用相同表格、指标和实验结构替换参考数值；
- 当真实数据不足且当前章节需要实验验证时，默认允许在报告草稿中保留模型生成的实验内容，不必等待用户额外授权。正式正文不在标题、表注和每个结果句中反复增加“参考/模拟”提示；只要实际使用了模型生成数据，按 `experiment-evidence-layering.md` 在整章末尾统一增加一次说明。用户明确要求不生成模拟数据时除外。

## 8. 与摘要、本章小结和审核的关系

`simulated_reference`、`illustrative_example` 和 `expected_range` 的实验结果、趋势与分析如需进入技术章“本章小结”，统一按 `references/chapter-summary.md` 的成果与实验结果使用方式进行归纳。摘要仍执行其自身的事实与篇幅规则。

这些参考内容可以用于：

- 说明后续应补哪些实验；
- 形成实验章节/三级标题的结构；
- 帮助用户补充真实数据；
- 给出预期趋势和分析框架。

审核时，清楚标记为参考方案的模型生成实验内容不视为“编造项目事实”；只有当参考内容被改写为已完成事实时，才按证据不足或虚构结果处理。

# 结果分析生成规则

结果段按“验证问题—测试条件—关键结果—技术原因—电网意义—能力边界”组织。先指出图表中最能支撑主张的结果，再解释产生差异的机制。

不得连续罗列多组数值，也不得用逗号和顿号堆叠多个指标。一个实验可以在图表中展示多个指标，但结果分析正文最多重点分析2个指标：优先选择1个最能证明当前技术主张的主指标，必要时再选择1个能说明代价、约束、稳定性或工程边界的辅助指标。其余指标保留在表格/图中用于完整展示，不逐项展开原因分析，避免结果段演变成指标流水账。

电网意义应具体到安全裕度、潮流可行性、设备热状态、调度时限、故障恢复、资源调节能力等真实对象。不得把算法准确率直接等同于工程价值。

正式报告中的“已验证项目结果”缺少真实数据时使用明确占位或保守定性表述，不得把模型生成值冒充 REAL_PROJECT_EVIDENCE。与此同时，应按 `experiment-reference-generation.md` 和 `experiment-evidence-layering.md` 生成模拟/示例结果表、预期趋势和实验分析框架供用户参考；参考数值必须在结构化数据中标记 `simulated_reference`、`illustrative_example` 或 `expected_range`。模型生成实验可以进入报告草稿；正式正文按章末统一说明规则处理，不在每个结果句中重复“参考/模拟”提示。

结果进入技术章“本章小结”时统一执行 `references/chapter-summary.md` 的成果归纳与实验结果使用方式；进入最终总结时继续执行最终总结规则。

# 实验数据与项目证据分层规则

## 1. 两类内容必须严格区分

本 Skill 中所有“数据、实验结果、验证结果、性能提升、应用成效”必须先归入以下两类之一，禁止使用含糊的“有没有数据就不生成实验”处理方式。

### 1.1 REAL_PROJECT_EVIDENCE：真实项目证据

用于描述项目已经取得、已经测试、已经达到或已经应用的事实。包括：

- 用户或任务材料提供的真实项目数据；
- 用户提供的真实实验、测试、第三方验证结果；
- 已核验的真实数据集使用记录和真实对比结果；
- 已确认的项目应用成效、性能提升、准确率、时延、规模和工程结论。

真实项目证据不得由模型臆造。没有真实证据时，不得写成“已测得”“实验结果表明”“相比基线提升了”“项目达到”“现场验证证明”等已完成事实。正式成果结论需要真实结果而当前缺失时，可使用待补数据位、已确认设计阈值、验证目标或保守定性表述。

### 1.2 REFERENCE_EXPERIMENT：模型生成的参考实验

用于帮助用户设计、补做或补充实验，不属于真实项目证据。只要当前研究内容需要实验验证，而用户没有提供完整实验材料，默认允许并应主动生成完整参考实验，不得因为“没有真实实验数据”而只停留在方案论证、案例化场景、预期效果或空白占位。

模型可以生成：

- 实验目标、研究假设和验证问题；
- 实验环境、软件环境、硬件类别、随机种子、重复次数和主要超参数；
- 数据集使用方案、公开数据集候选、项目数据字段模板、合成/仿真数据构造方案和训练/验证/测试划分；
- 评价指标及选择理由；
- 传统基线、主流基线、强基线、同类技术候选和本方法变体；
- 对比实验、消融实验、参数敏感性、鲁棒性、泛化和不同电网工况实验；
- 模拟参考数据、示例结果表、预期区间、参考曲线数据/预期趋势/绘图说明及对应结果分析；
- 用户后续需要替换、补测、核验的清单。

模型生成数值必须使用以下状态之一：

- `simulated_reference`：模拟参考值；
- `illustrative_example`：用于说明结果结构和趋势的示例值；
- `expected_range`：建议目标区间或预期范围。

这些内容不是“虚构项目结果”。结构化数据层必须始终保留 `simulated_reference`、`illustrative_example` 或 `expected_range` 等状态，以便系统和审核器知道其来源；**正式报告正文不要求在每个标题、表题、数值或分析句中反复写“参考实验”“模拟结果”“示例数据”**。只要本章实际使用了模型生成的模拟实验数据，统一在章末增加一次模拟数据说明即可，正文按正常实验叙述方式展开。

## 2. 无真实实验数据时的默认动作

若用户回答“没有实验数据”“暂不提供实验数据”或材料中缺少完整结果，而当前章节需要验证，默认流程为：

`缺少真实数据 → 生成完整 REFERENCE_EXPERIMENT → 给出模拟结果和分析 → 内部保留来源状态 → 章末统一说明一次 → 用户后续替换或补做实验`

不得默认改成：

`缺少真实数据 → 不生成数据 → 只写验证方案/预期效果/待补占位`

除非用户明确要求“不要生成模拟参考数据”或当前章节本身不需要实验验证。

对用户说明时优先使用：

> 当前没有实测数据不影响实验部分起草。我会生成实验设置、数据集方案、对比方法、消融实验和模拟结果供你后续补做或替换，并在本章末尾统一说明其中模型生成数据的性质，避免正文反复出现“参考/模拟”提示。

避免把“没有实验数据”描述成报告内容生成的限制。

## 3. 模拟实验进入报告草稿时的统一说明方式

`experiment_reference_package` 是结构化来源，但不要求实验参考内容只能存在于报告外。包内 `reference_only: true` 表示“只具有参考证据地位”，不是“只能作为报告外附件”。

当当前章节包含模型生成的实验设置、对比/消融实验、模拟结果或结果分析时，可以直接按普通科技报告的实验叙述方式写入正文：

- 实验标题直接写“对比实验”“消融实验”“参数敏感性分析”等，不额外加“参考”或“模拟”；
- 表题、图题、结果段和每个数值附近不需要反复标注“模拟结果”“参考数据”；
- 结构化 `experiment_reference_package` 中仍必须保留每个数值的来源状态，供工作流、审核和后续替换使用；
- 同一章中如果同时存在真实数据和模型生成数据，应在内部数据结构中分清来源，正文组织时不得故意把来源关系写反；
- **只要本章正文实际使用了模型生成的模拟实验数据，必须在整章最末尾统一增加一次说明，且只提示一次。**

推荐章末说明：

> 说明：本章未由实际材料提供的实验数据为模拟生成数据，用于实验设计与结果展示，后续可根据实际实验结果替换。

该说明放在“本章小结”正文之后，不计入本章小结500—600字。若本章没有使用模型生成的模拟实验数据，则不添加该说明。

## 4. 参考数据的使用边界

REFERENCE_EXPERIMENT 可以用于：

- 完整起草实验设置、数据集、评价指标和对比方法；
- 给出对比、消融、敏感性、鲁棒性、泛化等实验表格；
- 给出合理的模拟结果、趋势和结果分析示例；
- 帮助用户判断后续应补哪些真实数据；
- 在报告草稿中形成可替换的完整实验段落。

REFERENCE_EXPERIMENT 不得自动升级为：

- 项目已经取得的量化成果；
- 已完成第三方测试；
- 已在真实现场或真实数据集完成验证；
- 摘要中的“已取得”量化结论；
- 最终总结中的已验证性能。

只有用户提供、文件中存在或后续明确核验的数据，才能转为 `verified_real_result`。

## 5. 全局统一约束

所有活动规则都必须直接使用本文件的两层证据语义，不再使用未区分证据类型的绝对禁令：

- REAL_PROJECT_EVIDENCE：严格禁止模型补造；缺失时只能使用已确认设计阈值、待补位置、验证目标或保守定性表述；
- REFERENCE_EXPERIMENT：允许模型生成模拟/示例/预期数值，并应在需要实验验证且真实数据不足时主动生成完整参考实验。

论文、标准、政策、真实第三方结论和真实应用案例始终属于真实性约束范围，不因参考实验能力而放宽。
