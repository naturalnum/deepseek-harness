# 一级标题与首个二级标题之间的无标题过渡正文规则

本文件统一约束报告正文中一级标题与其后首个二级标题之间的正文过渡。目标是避免出现“一级标题下一行立即接二级标题”的空壳章节结构。该规则作用于正文生成与最终审核，不改变已确认目录中的标题层级。

## 1. 通用硬规则

只要某一级章节下存在二级标题，一级标题之后就必须先出现一段或若干段**无标题正文**，再进入该章第一个二级标题。不得出现以下结构：

```text
# 第1章 项目概述
## 1.1 项目背景与研究意义
```

应改为：

```text
# 第1章 项目概述

[无标题过渡正文]

## 1.1 项目背景与研究意义
```

无标题过渡正文必须承担实际内容作用，不能只写“本章主要介绍以下内容”“本章分为三节”等目录复述。

## 2. 第一章及一般非技术章节

第一章“项目概述”以及其他没有更长章首导入专项规则、但确实存在二级标题的非技术章节，一级标题与首个二级标题之间的无标题过渡正文控制在 **50—100字**。

这50—100字应优先完成以下任务：

- 概括本章要回答的总体问题；
- 说明本章各部分为什么需要放在同一章中；
- 自然引出后续二级内容，但不逐条复述二级标题名称；
- 与全文目标建立必要联系。

不得用空泛套话、章节编号清单或“首先/其次/最后”机械复述目录来凑满50—100字。

## 3. 技术章节的更具体规则优先

第2章起的技术章节已经执行“章首无标题导入正文”专项规则。以5万字报告为基准，该部分约800—1200字，因此天然满足“一级标题与首个二级标题不得相邻”的要求。

技术章节**不得为了满足本文件再额外插入一段50—100字短引言**，也不得把原有800—1200字章首导入压缩成50—100字。技术章继续执行 `references/report-architecture.md`、`references/technical-chapter-generation.md` 中更具体的章首导入规则。

## 4. 最终总结章例外

最终“总结 / 总结与展望 / 结论”章不设置二级标题，因此本规则不适用。该章继续执行 `references/conclusion-and-outlook.md` 的单一级标题规则。

## 5. 生成与验收

正文生成前应在章节计划中明确 `heading_bridge_requirement`：

- `short_50_100`：第一章或一般非技术章节；
- `technical_chapter_intro`：技术章，使用既有长章首导入；
- `not_applicable`：没有二级标题的章节。

正文展示给用户前必须检查：

1. 一级标题后是否先有正文而不是直接出现二级标题；
2. `short_50_100` 模式下正文是否为50—100字；
3. `technical_chapter_intro` 模式下是否保留原长篇章首导入规则；
4. 过渡正文是否有真实内容，而不是目录复述。
