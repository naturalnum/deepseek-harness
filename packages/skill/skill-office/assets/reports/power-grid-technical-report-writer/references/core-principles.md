# 核心原则

1. 全文围绕一个总体问题，研究内容、技术章节、验证证据和结论保持对应。
2. 技术章映射先读取报告范围：总报告中每个课题按来源顺序形成一个技术章，具体课题报告中每个研究内容小点按来源顺序形成一个技术章；章名仅作必要名词化，技术章数量、顺序和边界与对应映射单位严格一致，其他课题内容逐章排除。
3. 每个技术章默认设置X.1、X.2、X.3章内核心研究小点；只有预期目标/进度技术点确实过多且无法合理归并时才最小扩展到4—5个，并记录来源与理由。全部核心标题从研究内容、预期目标、进度计划和内部技术要求中拆解，并逐项完整体现电力对象/运行约束、具有区分度的具体人工智能/数据/知识/算法/系统技术和作用，禁止纯计算机标题。目录生成前先区分前序技术研究课题与最后工程实现课题；技术研究标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点。二级标题若含“的”，以“的”之后完整部分为主语，该主语本身必须带有强电力相关词。
4. 技术章一级标题后直接写无标题章首导入正文，随后设置X.1—X.N核心研究小点。先自动判定 `report_theme_type`：非评估主题的二、三级标题不得出现验证、评估、评价、测评、验收、测试、试验、实验类章节词，本章小结紧随最后一个核心研究点；仅评估相关主题且确有大量成体系数据或用户明确要求时，才可在核心研究点后设置独立评估/验证节并将本章小结顺延。
5. 内部技术要求在X.1—X.3正文中隐性覆盖，直接写成技术目标、性能约束、工况条件、结果和边界，不出现任务书、考核指标、考核要求、考核细则、规定指标或内部编号。预期目标、进度计划及考核要求中的关键技术词还要通过 `heading_source_term_plan` 分散进入二、三级标题：概括性词落二级，窄技术点落三级；非评估主题下不字面搬运“验证/测试/验收”。
6. 正文直接陈述技术对象、技术关系、证据和边界，不暴露任务材料来源。
7. 每段围绕一个主要判断，减少过渡词和长串并列；存在因果、先后、约束、包含或反馈关系时按逻辑链组织。
8. 技术解释在确有联系时落到电网设备、状态量、物理机理和运行约束。
9. 公式只用于真实问题定义、机理、算法、约束或验证计算，不写装饰性公式。
10. 证据强度决定结论强度。REAL_PROJECT_EVIDENCE 不得由模型补造；缺少真实实验材料时允许并应按 `experiment-evidence-layering.md` 生成带内部来源状态的 REFERENCE_EXPERIMENT、模拟数据和结果分析；正式正文采用章末统一说明，不逐项重复“参考/模拟”标签。文献、标准、真实第三方结论和真实应用成效不得虚构。
11. 分阶段确认，未确认当前阶段不得进入下一阶段。
12. 项目档案确认前一次性确定内容生成依据模式。基于已有内容生成时逐章先准备材料；交由模型自行生成时不重复询问材料。用户可随时主动切换，但模式选择本身不得每章重复询问。
13. 既有公式分级、有效性和符号解释规则保持不变；描述性公式从简，技术公式从充分。
14. 每章小结和最终总结必须把可追溯定量表述、定性判断与电力应用意义结合起来；没有真实数据时不得把模型数值写成已实现成果，但正文实验部分仍可生成并展示 REFERENCE_EXPERIMENT 模拟数值；如实际写入正文，章末统一说明一次其模拟性质。
15. 第一章1.2.1“国外研究现状”与1.2.2“国内研究现状”采用一致的研究主题组织口径，并保持作者指代方式统一；默认使用“XXX等人”，选择“XXX团队”后则两节统一。

6. 技术研究章二、三级技术标题的最终落脚词只使用“技术”或“方法”，按每章约40%“技术”、60%“方法”分配，全文“技术”结尾比例控制在35%—45%；该分布与40%—60%“基于……的……”句式比例分别计算。
