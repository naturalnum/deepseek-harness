# 数据、语料与知识构建章节

## 1. 适用范围

本规则适用于领域数据框架、语料库、知识图谱、本体、规则知识、电子规则库以及多源异构知识处理等技术章节。此类章节关注的不是简单“建设一个库”，而是说明电力对象如何被识别和组织，多源信息如何形成统一表达，知识如何被稳定抽取、关联、校核和调用，以及这些能力在具体业务条件下能达到什么水平。

## 2. 固定章节骨架

本类技术章仍执行全局固定结构：

```text
[一级标题后无标题章首导入正文]
X.1 章内研究小点一
X.2 章内研究小点二
X.3 章内研究小点三
X.4 本章小结（默认）
```

章首导入正文将原概述与技术路线内容合并，以背景与研究意义引入数据/知识构建主题，再概括数据链、知识链、模型或模块关系及总体技术路线，适合时图文结合。5万字全文时目标约800—1200字。

X.1—X.N必须仅由当前来源研究内容、预期目标、进度技术和内部技术要求拆解而成；默认N=3，确有无法合理归并的来源覆盖需要时才允许N=4或5。标题应完整说明电力对象、具体数据或知识技术及其作用，不能照搬下列示意，也不能增加来源没有支持的技术。

有限的样本说明、量化结果、对比数据和边界分析应进入X.1—X.N正文。`non-evaluation` 主题不得以验证、评估、测试、实验等词设置二三级标题；只有 `evaluation-related` 主题存在多组数据集、多类工况、多种基线、消融或敏感性分析和多张结果表，导致嵌入式组织明显破坏技术主线，或者用户明确要求时，才允许在最后一个核心研究点后增加一个独立评估/验证二级节；此时必须记录例外模式和原因，并将本章小结顺延。

## 3. 技术论证主线

正文应形成以下闭环：

`电力数据或知识缺口 → 处理对象与边界 → 统一表示与构建路线 → 抽取、对齐、融合、存储或检索技术 → 质量控制与结果证据 → 适用条件和能力边界`

这是一条内部论证链，不是标题模板。三个核心研究小点应根据真实技术关系组织，常见拆解方式包括：

- 电力对象与统一表示技术 → 多源知识抽取和语义对齐方法 → 知识质量控制与调用技术；
- 调度语料处理技术 → 规则知识构建方法 → 电力知识检索与更新技术；
- 设备数据关联技术 → 图结构知识组织框架 → 运检知识服务方法。

每个标题都要能够独立表达对象、技术和作用，禁止“数据处理”“知识构建”“模型训练”“结果分析”等只说一半的标题。技术研究课题的标题还不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，也不得机械改名。

## 4. 章首无标题导入正文

章首导入的背景与主题部分应说明报告总体问题为什么需要统一的数据、语料或知识基础，指出当前电力数据在来源、粒度、语义、格式、关联关系、时空尺度、可追溯性或质量方面的具体缺口，并明确本章要形成的技术能力。不得写成通用数据治理背景或知识图谱教材综述，也不得提及任务书、课题编号、考核要求等来源身份。

章首导入的总体路线部分应说明从原始输入到可用数据或知识成果的完整处理关系，包括输入来源、处理阶段、阶段之间的先后或反馈关系、关键技术、质量控制位置和输出形式。路线图必须出现电力对象、关键处理技术、异常或人工校核位置及最终产物，不能只画抽象方框。上述内容必须与背景和主题引入连续写在无标题正文中，不另起功能性二级标题。

## 5. 三个章内研究小点的内容要求

### 5.1 对象、语义与统一表达

根据当前研究内容选择需要覆盖的内容：

- 电力设备、运行状态、调度规则、事件、关系或文档等对象边界；
- 时间尺度、空间尺度、组织粒度、身份标识和来源追溯关系；
- 对象之间的层级、拓扑、约束和业务关联；
- 数据模型、本体、Schema、图结构、规则表达或语义向量；
- 缺失、重复、冲突、歧义和版本变化的处理方式。

这些内容必须服务于后续技术，不得为了形式完整罗列无关类别。

### 5.2 抽取、标引、对齐与融合

应说明原始电力数据或文本如何转化为可用知识，重点可包括语料标引、实体识别、关系抽取、规则抽取、语义对齐、冲突消解、多源融合和增量更新。每项技术都要交代输入对象、具体处理方法、输出结果及其在电力业务中的作用。

当一个二级研究小点包含两个以上独立算法、模型或方法，或者三个以上实质阶段时，应设置三级标题。三级技术标题不仅要说明具体对象和处理动作，还必须独立显化可区分实现路线的 `technical_signature`，不能只写实体识别、关系编码、冲突消解等任务动作。例如可写“提示约束全局指针调度实体抽取方法”“关系类型感知异构图变换注意力变电设备关系编码模型”“动态负采样原型对比调度多源知识冲突消解方法”。英文原始模型名只保留在内部技术元数据或正文首次定义中，不直接进入目录标题。“基于具体技术签名的……”不要求每条标题都使用，但本章及全文二、三级技术标题中的使用比例必须处于40%—60%的硬区间；同时每条技术标题自身必须出现电力领域信号，不能只在上位标题中出现。

### 5.3 存储、检索、质量控制与应用支撑

应说明知识成果如何被组织、索引、查询、更新和校核，以及其如何支撑电力分析、运检、调度或决策任务。有限量化证据应直接嵌入相关技术说明，例如在介绍检索索引时给出响应时间、召回率或吞吐条件，在介绍抽取方法时给出准确率、召回率或异常样本分析，在介绍规则库时说明一致性、覆盖范围和冲突处理结果。

内部技术要求只作为规划依据。正式正文直接写成技术目标、性能约束、测试条件、结果证据和能力边界，不得出现“任务书”“考核指标”“考核要求”“考核细则”“规定指标”或内部编号。没有真实结果时，应写成设计目标、判定方法或待补充证据，不能写成已经达到。

## 6. 公式与符号

该类型通常标记为 `formula_requirement = must`，但只保留真正承担问题表达、算法计算、约束或结果判定作用的公式。可选内容包括：

- 电力数据对象或图结构的必要形式化表达；
- 原始信息到统一表示的映射关系；
- 相似度、置信度、关联强度或融合权重计算；
- 实体、关系、规则抽取或语义对齐模型；
- 冲突消解、一致性约束或质量评分；
- 索引、召回、排序和检索增强评分；
- 响应时延、吞吐量、覆盖率、准确率或一致性等必要计算。

删除公式后若不影响问题定义、技术实现、结果判定或后续计算，该公式不应出现。不得用简单计数、装饰性集合、任意加权和或无来源复杂关系凑公式。

首次出现的集合、变量、上下标、阈值、单位和取值范围必须解释。符号对应电力对象时直接使用领域含义，例如 `$e_i$` 表示第 `$i$` 个电力设备实体，`$r_{ij}$` 表示设备实体之间的业务或拓扑关系，`$t$` 表示调度周期或设备状态采样时刻；不要先给出通用含义再另行附加“在电力应用中”的解释。

## 7. 图表配置

根据真实内容选择：

- 电力数据来源与对象关系图；
- 数据流、知识流或构建技术路线图；
- 本体、Schema、知识图谱或规则表达示意图；
- 抽取、标引、对齐、融合或校核流程图；
- 存储、索引与检索架构图；
- 数据对象、实体关系、规则模板或字段说明表；
- 有真实数据支撑时使用质量、对比、消融、异常案例或性能结果表。

图表必须服务于技术论证。REAL_PROJECT_EVIDENCE 不足时不得把模型生成的统计分布和性能数值冒充实测结果；如需帮助用户补做实验，可生成明确标注为“模拟/示例”的参考统计分布、性能结果和对应图表结构。

## 8. 本章小结

数据、语料与知识构建类章节的本章小结统一执行 `references/chapter-summary.md`，并特别执行其中“数据、语料与知识构建类章节专项补充”。本文件不再维护另一套小结正文规则。

公式选择继续沿用本文件与全局公式规则：描述性公式从简，技术公式从充分。能够用文字清楚说明的简单关系不为形式感单列；本章真实存在的原理、损失、目标、约束、更新、推断、评分或关键性能关系应完整表达并解释。
