# 最小工作流示例

用户提出：

> 撰写一份面向新能源场站设备异常检测的科技项目结题技术报告。研究内容包括：研究多源运行数据融合技术；研究面向设备异常识别的时序模型；开展边缘部署与应用验证。约2万字。

## 1. 项目档案和生成模式

项目档案默认将报告类型设为“科技项目结题技术报告”，并固定确认四项：是否有任务书及对应具体课题/总报告、后续采用“基于已有内容生成”还是“交由大模型自行生成”、是否指定报告字数/模板/章节数量、是否可提供实验数据。

## 2. 报告范围、课题角色与技术章映射

本示例按`task_book_scope=specific_topic`演示，因此从当前报告范围内提取三个研究内容小点，并登记所属课题角色：

1. `研究多源运行数据融合技术`，所属前序技术研究课题；
2. `研究面向设备异常识别的时序模型`，所属前序技术研究课题；
3. `开展边缘部署与应用验证`，所属最后工程实现课题。

只做必要名词化：

1. `多源运行数据融合技术`；
2. `面向设备异常识别的时序模型`；
3. `边缘部署与应用验证`。

不得额外改写为“基于多模态学习的新能源场站可信数据融合技术”等来源没有支持的标题。

> 若用户确认`task_book_scope=total_report`，则不使用上述三个小点分别成章。应先按任务书列出全部课题，每个课题形成且只形成一个技术章；同一课题下的多个研究内容小点默认进入该章X.1—X.3，必要时最小扩展至X.1—X.N，并通过其三级标题展开。

## 3. 基于已有内容生成时的目录前概述

若用户选择“基于已有内容生成”，在下面目录生成前先按预计章节询问每章大概内容。该信息只用于确定章节重点、三级标题和篇幅，不改变固定目录规则。

## 4. 固定目录

第一章同时承担项目背景与意义、国内外研究现状、主要研究内容和研究思路。`1.3.1 主要研究内容`必须与技术规划书、任务书或等效技术文件中的研究内容逐项对应，并在不改变边界的前提下稍作展开。

技术章从第2章起。一级章标题后先直接写一段或若干段无标题导入正文，把原“概述”和“技术路线/技术架构”合并：先说明本章背景与研究意义并引入研究主题，再概括总体技术路线、输入输出和关键关系，适合时配置技术路线图或架构图。随后默认直接进入X.1—X.3三个核心研究小点，必要时最小扩展至X.1—X.N。

以5万字全文为基准，每个技术章的无标题章首导入正文目标约800—1200字；本章小结统一执行 `references/chapter-summary.md`。

三个核心二级标题均需逐项显式体现电力对象/约束、具体计算技术和技术作用。先判定 `report_theme_type`。`non-evaluation` 主题二三级目录不得出现验证、评估、测试、试验、实验类章节词，有限结果与证据写入对应研究小点正文，X.4为本章小结；只有 `evaluation-related` 主题且存在大量成体系数据或用户明确要求时才可例外，此时X.4为评估/验证节，本章小结顺延为X.5。

## 5. 逐章材料交接

采用“基于已有内容生成”时，第一章计划前先询问第一章已有材料。完成一章后，结束语同时请求用户确认当前章并提供下一章材料，或回复“下一章交给模型生成”。模式不在每章重复询问。

## 6. 内部检查

目录提交前检查：

- 第一章是否固定为“项目概述”，且二级、三级标题与当前架构完全一致；
- `1.3.1 主要研究内容`是否与技术规划书/任务书研究内容逐项对应并适度展开；
- 1.2.1国外与1.2.2国内研究现状是否采用一致研究主题和作者指代口径；
- 技术章映射是否符合报告范围：总报告是否一个课题一个技术章，具体课题报告是否一个研究内容小点一个技术章；
- 技术章是否从第2章起，且一级标题下直接规划无标题章首导入正文，没有“概述”“技术路线/技术架构”二级标题；
- 章首导入是否包含背景与意义、研究主题和总体技术路线/架构，适合时是否图文结合；
- 技术章标题是否只进行了名词化，没有添加额外技术信息；
- 是否正确区分前序技术研究课题与最后工程实现课题；
- 技术研究标题是否避免把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，并避免机械改名；
- 每个技术章是否默认设置三个章内研究小点；若扩展到4—5个，是否具有无法合理归并的来源依据；
- 三个核心二级标题是否完整说明电力对象、具体技术和作用，是否不存在纯计算机标题；
- 每个X.1—X.N核心二级标题是否均完整体现电力对象/约束、具体计算技术和技术作用；每个技术章X.1—X.N是否默认分别具有2—4个、必要时最多5个进一步具体的三级标题；
- 目录中已确认的三级标题是否已加入标题锁定清单，正文生成后是否按原编号、原名称、原层级和原顺序全部保留；
- 是否排除了其他课题内容；
- 进度技术是否分配到核心研究小点，内部技术要求是否在所属技术章X.1—X.N正文中隐性覆盖，且正文没有出现“任务书”“考核指标”“考核要求”等来源性表述；
- 本章小结是否已按 `references/chapter-summary.md` 完成统一检查。

## v3.3附加检查

- 章节计划将公式标记为`technical`或`descriptive`，优先展开真实技术公式，删除可由文字说明的表面关系；
- 本章小结确认前执行 `references/chapter-summary.md` 的统一检查；
- 第一章1.2生成前锁定`author_et_al`或`author_team`，国外与国内两节保持一致。

## v3.5附加检查

- 每章目录确认计划字数和80%最低验收字数；
- 每节或整章展示前运行字数校验，不足时补充实质内容；
- 标题原则上不超过25个可见字符；技术研究章二、三级标题优先保证技术签名和40%—60%“基于……的……”比例，必要时允许长度例外；实验类功能标题可简洁；
- 技术章正文展示前运行 `validate_heading_coverage.py`，防止三级标题在生成时被合并或省略；
- 最终Markdown末尾运行 `normalize_markdown.py`，统一长划线并删除数字与汉字间空格。
