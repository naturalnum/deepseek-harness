# 分报告补充审查与盲审意见最终版规则

仅在首轮总报告审查完成、用户选择继续并提供课题分报告后读取本规则。

## 证据层级

1. 任务书或合同仍是要求基线。
2. 总技术报告是项目级结论和成果总索引。
3. 课题、专题、测试或应用分报告是补充证据，可证明方法、试验、应用和成果细节，但不能单独变更任务要求、承担主体或成果归属。
4. 用户说明可帮助定位版本；涉及任务变更、单位更名、成果状态或验收结论时，仍需正式依据。

## 续审步骤

1. 清点全部分报告，记录文件名、题名、版本、日期、承担单位及其对应课题；重复、缺失或无法打开的文件列为待核事项。
2. 把初审“任务要求—报告位置—证据—判定”矩阵扩展为“任务要求—总报告证据—分报告证据—交叉一致性—最终判定”。每条新增证据必须定位到分报告页码、章节、图表或可搜索原句。
3. 对初审意见逐条标记：
   - 已解决：分报告提供了直接、可复核证据；
   - 部分解决：新增证据缩小了问题，但仍缺条件、口径或附件；
   - 未解决：分报告没有对应证据；
   - 新增问题：分报告暴露了新的矛盾、计算错误或真实性风险。
4. 重新执行百分比、单位、图表、摘要、结论、参考文献、成果数量、承担单位和版本日期交叉校验。总报告与分报告数值不一致时不得取较优者，必须写明双方位置并要求确认权威版本。
5. 重新组织五名专家的编号意见，仍统一从 `1.` 开始且不新增“总体评价”标签。分报告若补足关键证据，应同步改写前部承担总体判断的编号意见；若出现新的关键冲突，也应相应降低总体判断。不要只修改后面的细节意见而保留已经失效的宏观判断。
6. 删除具体意见必须有“已解决”证据支撑；部分解决的意见应改写为剩余风险；新增意见仍须满足每名专家1至4条且避免重复。若材料变化引出多个相互独立的总体层面判断，可以用多个连续编号表达，不要求压缩成单独一条。
7. 重新判断每名专家的审查结论和汇总统计，并检查其与更新后的全部编号意见一致。没有真实专家表决时沿用主 Skill 的结论规则，不得把材料补充自动等同于真实专家同意。
8. 在 Markdown 的五个专家区块之前加入“补充审查变更记录”，列出初审文件、纳入的分报告、已解决/部分解决/未解决/新增问题数量及关键变化。不得新增独立总体评价区块、第六个专家或破坏五专家解析结构。
9. 输出新的 `*_盲审意见最终版.md` 和 `*_盲审意见最终版.docx`，先运行模板校验，再生成并逐页渲染验收。初审 Markdown 和 DOCX 保持不变。

## 最终版边界

- “最终版”表示已纳入用户本次提供的分报告，并不表示项目通过验收、专家已经签字或项目组已经整改。
- 分报告补足了证据但总报告仍未建立项目级索引时，可把相关编号意见中的“指标无法验证”调整为“证据已见于分报告，但总报告缺少引用或汇总”，并建议在总报告补入定位。
- 项目组回复继续保留“（待项目组填写）”，除非用户提供真实回复并明确要求原样纳入。
- 盲审文件不得写入虚构专家姓名、单位、职称或可识别身份；审稿人类型只保留在 Markdown，不写入Word模板。
- Word继续使用原有五个专家行；每名专家意见直接从“1.”开始，不增加“总体评价”行、栏、标题或标签。

## 结束提示

交付最终版时说明已纳入哪些分报告、哪些初审总体判断或具体问题发生变化、仍有哪些事项需要人工裁决；不要再次循环询问是否还有分报告，除非用户明确表示还有一批材料。
