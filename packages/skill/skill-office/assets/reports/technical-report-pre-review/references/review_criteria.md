# 评审准则与问题分类

## 判定顺序

1. 先核对材料身份：项目名称、课题名称、承担单位、项目编号、版本和日期。
2. 再核对任务完成：逐项映射研究内容、目标、指标和成果。
3. 再审技术正确性：方法描述、假设、公式、单位、对比和因果归因。
4. 再审证据质量：试验条件、样本、基线、重复性、统计量、图表和原始记录。
5. 最后审报告质量：结构、引用、图表、术语、成果清单、密级和知识产权。

## 总体层面意见

总体判断不是独立栏目，也不是写在编号意见之前的一段无编号评语，而是正式编号意见的一部分。每名专家的意见都应由总体到具体展开：前面的一个或多个编号先回答“从本专家视角看，任务书相关要求在报告中总体承接得怎样、现有证据能支撑到什么程度、最重要的风险是否影响当前判断”，随后再用编号意见定位具体问题。

总体层面意见依据“任务要求—报告位置—证据—判定”矩阵和本专家负责的技术维度形成，可以综合多个章节、多项指标或多类证据，不要求机械绑定某一页。它应至少覆盖以下逻辑中的关键部分：

- 总体对应：与本专家视角相关的研究内容、目标、指标、成果或应用要求，报告是否系统承接，技术主线是否与任务目标一致；
- 已有支撑：报告已经给出了哪些方法、数据、试验、成果或应用证据，哪些内容目前可以较有把握地确认；
- 主要不足：最影响整体判断的证据缺口、口径冲突、方法缺陷或呈现问题是什么；
- 判断影响：这些不足属于补充材料、统一口径即可闭环，还是已经影响关键指标验证、核心结论成立或需要人工裁决。

同一专家可以有多条总体层面意见。例如，R1可以分别从“任务与指标完成证据”和“成果与应用闭环”形成第1、2条综合性判断，然后再以第3、4条下钻到具体证据缺口。不要为了形式强行压缩成唯一一条，也不要给这些意见加“总体评价”“综合评价”等前缀。

总体层面意见应有实质判断，而不是空泛表态。例如，不应只写“报告内容较完整，建议进一步完善”；也不应把“图3标题不一致、表5单位缺失、参考文献未引用”直接拼成宏观意见。更合适的写法是先判断“报告总体覆盖任务书规定的研究内容，但关键性能结论的试验口径和证据链尚不完整，现有材料可支撑技术路线基本成立，尚不足以完整验证部分量化指标”，再由后续编号定位具体试验、图表和引用问题。

## 从示例归纳的问题类型

以下类型来自示例意见的抽象，不照搬示例结论：

- 图、表、正文或题注不一致；
- 报告提出性能、能效或准确率提升，但缺少测试条件或量化对比；
- 工程应用内容与研究任务关联不足；
- 任务书要求的工具、平台或应用落地描述过少；
- 模型定位、功能和性能缺少与现有方案或基线的比较；
- 通用、专用和业务能力测评覆盖不足；
- 专利、论文、软著等成果名称或数量前后不一致；
- 参考文献未引用、错引或著录不规范；
- 后续研究建议有价值，但不应伪装为本期强制考核缺陷。

## 意见结构

每名专家的全部意见共用一套连续编号。总体层面意见负责“报告整体做到什么程度、主要支撑和风险是什么”，具体问题意见负责“哪些证据导致这个判断、具体应如何修改”。两类意见不使用额外标题或标签，也不要求固定只有一条总体判断。

具体问题意见优先使用这一逻辑：

“报告第X章/第X页/表X给出了A；任务书第Y页要求B（或通用评审准则要求说明C）；现有材料缺少D，因此尚不能验证E或结论适用范围不清。建议补充F，并同步修订摘要、表格或结论中的相关表述。”

具体问题意见至少包含：

- 定位：页码、章节、图表编号或可搜索原句；
- 事实：材料实际写了什么或缺少什么；
- 依据：任务书条款、报告内部一致性或可靠公开准则；
- 影响：为何妨碍验证、复现、理解或验收；
- 动作：具体补什么、改什么、复算什么。

总体层面意见可以综合多处证据，因此不强制逐条写单一页码，但必须能够回溯到任务矩阵和材料事实；如果宏观判断只依赖某一项具体缺陷，则应直接写成具体问题，避免人为拔高。

## 内部优先级

以下等级用于审查者判断问题轻重，默认不作为每条正式意见的固定前缀。只有在需要明确整改先后顺序或提示人工裁决时，才可偶尔写出“重大”“主要”等级；其余意见直接说明事实、影响和建议，或以“建议”起笔，避免标签化和句式重复。

- 重大：关键考核指标无法验证，材料主体或成果真实性存在重大冲突，或结论可能影响验收判断。
- 主要：方法、基线、数据、测试条件或关键链路缺失，补充后方能支撑主要结论。
- 一般：局部图表、术语、引用、单位或表述错误，不改变核心结论但影响规范性。
- 建议：面向后续研究或扩展应用的改进，不作为当前任务未完成的证据。

## 技术复核清单

- 百分比、绝对差值和相对变化是否混用；
- 参数数量、模型文件大小、显存占用和位宽是否混称；
- FLOP、FLOPS、GOP/s、GFLOPS/W、时延和吞吐是否可相互复算；
- “同等网络规模”“同等算力”“相同模型层数”等约束是否真的保持；
- 训练速度是否包含数据加载、编译、预热、同步和故障恢复；
- 是否报告重复次数、均值、离散性和异常值处理；
- 测试集是否与训练集隔离，样本量和评分规则是否明确；
- 多个改动同时发生时是否有消融，避免把全部增益归给单一方法；
- 个别场景结果是否被不当外推到所有硬件、模型或业务；
- 摘要、正文、表格和总结中的数字是否一致。

## 结论规则

每名专家的审查结论必须与其编号意见中的总体判断和具体问题一致：

- “同意通过”：该专家负责的关键任务已有可核查证据，剩余问题不影响主要结论。
- “同意通过（修改后）”：核心路线和结果基本成立，但仍需补充证据、澄清口径或修正规范问题。
- “不同意通过”：存在关键任务缺失、核心指标明显未达到、材料真实性存在实质风险，且不能通过文档补正解决。
- “需人工裁决”：输入材料冲突或证据不足，使模型无法负责任地代替真实专家表决。
