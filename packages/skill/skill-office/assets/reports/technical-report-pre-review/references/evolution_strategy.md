# 训练与迭代策略

## 第一阶段：不训练

先使用本 Skill 的规则、审稿人画像、模板和校验脚本。当前只有一个完整案例，无法覆盖不同项目类型，也无法可靠划分训练集和独立测试集；此时蒸馏或强化学习容易复制单一案例的措辞和偏差。

每次运行保存脱敏后的任务要求矩阵、报告证据索引、五名专家的连续编号意见、人工修改、最终采用或驳回结果、驳回原因、漏检问题和格式错误。标注时区分“总体层面判断”和“具体问题”，但不要把“总体评价”训练成一个必须单独输出的字段或固定标签。专家姓名、项目敏感信息及未公开成果不进入训练集。

## 第二阶段：建立评测集

优先积累至少30至50个跨主题案例，其中保留20%以上作为永不参与调参的测试集。评测维度包括：

- 任务指标覆盖率与漏检率；
- 引用定位正确率、数字复算正确率；
- 无依据指控率和虚构事实率；
- 每名专家是否形成了实质性的任务书—报告总体判断，而不是只堆积局部修改建议；
- 总体层面判断与审查结论、后续具体意见的一致性；
- 五类审稿人的互补度、重复意见率；
- 意见由总体到具体的层次是否自然，是否避免固定“总体评价”标签和模板化句式；
- 建议的可执行性；
- Word模板结构与渲染通过率；
- 人工采纳率及平均修改时间。

## 第三阶段：可选训练

当高质量案例达到约100至300份且标签一致时，可先做监督微调（SFT），训练“任务书+报告证据包到五专家连续编号审查意见的Markdown审查稿”。训练目标应让模型学会在同一编号序列中先形成总体判断、再下钻具体问题，而不是学习一个独立的“总体评价”槽位。不要把原始长文档直接无筛选地送入训练；先保留页码、表号、证据片段和要求映射。

如需降低推理成本，可由强模型产生候选、由真实专家校订后蒸馏到较小模型。蒸馏目标应是总体判断、证据对齐、问题分类和整改可执行性，不是模仿专家姓名、固定措辞或标签。

只有在积累成对偏好数据（同一材料的两个候选及明确优劣原因）后，才考虑DPO一类偏好优化。当前不建议在线强化学习：奖励难以客观定义，错误奖励容易鼓励“意见更多、语气更重”，反而降低事实准确性。

任何训练版本都必须与未训练基线在独立测试集上盲评；若事实准确率、漏检率、总体判断质量或无依据指控率没有显著改善，则保留规则型 Skill。
