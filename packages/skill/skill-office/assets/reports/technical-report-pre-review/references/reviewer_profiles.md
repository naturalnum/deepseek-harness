# 审稿人池与选择规则

## 选择算法

每次必须选择5个角色：

1. 固定选择 R1“任务符合性与验收证据审稿人”；
2. 固定选择 R7“试验设计、测评与可复现性审稿人”；
3. 根据报告标题、目录、关键词、任务指标和图表，从其余角色中选择匹配度最高的3个；
4. 若前三名集中在同一技术链路，用 R9“报告规范、成果与知识产权审稿人”替换最低匹配角色；
5. 平分时优先选择能覆盖尚未审查的任务指标者；仍平分则按角色编号选择，保证结果可复现。

不要虚构具体专家姓名、单位、职称。角色只是审查视角，不代表真实专家身份。

## 意见层级与角色分工

每名专家的正式意见都直接从 `1.` 开始连续编号，不单设“总体评价”。前面的一个或多个编号应从该角色视角形成任务书—报告的总体判断，再自然下钻到具体问题。总体层面意见数量不单独限定；只要有不同的宏观判断依据，可以连续使用多条，但全部意见仍遵守每名专家1至4条的总数约束。

五类视角的总体判断重点不同：

- R1：项目任务是否被报告整体覆盖，关键指标、成果和应用是否形成验收证据闭环；
- 技术角色（R2至R6、R8）：与本技术领域相关的任务要求是否形成完整方法链、试验或应用结果，结论是否被技术证据充分支撑；
- R7：试验设计、评价口径和复现证据是否足以支撑任务指标及报告结论；
- R9：报告结构、成果清单、引用和材料一致性是否足以形成清晰、可复核的验收材料。

前部综合性意见只保留本视角的整体状态、关键支撑和主要风险；后续具体意见再写页码、表号、数据冲突和整改动作。不要在正式意见中写“总体评价：”“总体意见：”“综合评价：”等标识。同一总体风险可以由一名专家主评，其他专家只有在自身技术维度确有不同影响时再补充，避免五名专家用不同措辞重复同一判断。

## 角色定义

### R1 任务符合性与验收证据审稿人（固定）

关注任务书与报告之间的逐项映射：承担主体、课题边界、研究内容、预期目标、量化指标、成果数量、应用对象和报告名称。重点发现指标口径替换、只给结论不给证据、材料主体冲突以及遗漏任务。编号靠前的综合性意见优先回答“报告整体能否证明任务书要求已被承接和完成到何种程度”，必要时可分别从任务指标闭环、成果与应用闭环等不同层面形成多条判断。

### R2 基础大模型架构、预训练与微调审稿人

触发词包括基础大模型、Transformer、MoE、预训练、SFT、奖励模型、PPO、指令微调。关注模型架构贡献、训练数据、训练目标、基线、消融、模型规模、准确率口径和业务适配证据。前部综合性意见应概括相关技术任务的方案完整性、有效性及对任务指标的支撑程度。

### R3 多模态、知识图谱与样本构建审稿人

触发词包括文本图像、多模态、实体抽取、实体对齐、知识补全、知识图谱、样本构建工具、思维链。关注模态覆盖、标注方案、数据质量、抽取指标、工具功能、样本管理和图文链路的一致性。前部综合性意见应判断该技术链路是否形成从任务要求到数据、方法、结果和工具/成果的闭环。

### R4 分布式训练、并行计算与系统性能审稿人

触发词包括数据并行、张量并行、流水线、异构算力、通信优化、AllReduce、训练加速、故障恢复。关注同尺度对比、公平基线、计时边界、重复试验、扩展效率、网络拓扑、吞吐单位和故障注入验证。前部综合性意见应判断系统性能任务是否有公平、完整、可复核的验证支撑。

### R5 云边协同、模型压缩与部署审稿人

触发词包括云边端、量化、剪枝、蒸馏、轻量化、边缘部署、调度、国产芯片。关注参数量与存储量口径、压缩前后模型同一性、精度损失定义、端到端时延、带宽条件、设备业务闭环和失败回退。前部综合性意见应判断部署与轻量化任务是否真正形成从指标到设备、场景和运行效果的闭环。

### R6 可重构计算、芯片与能效审稿人

触发词包括 FPGA、TVM、VTA、加速核、软硬协同、GOP/s、GFLOPS/W、功耗、资源利用率。关注功耗实测方法、吞吐与时延换算、资源占用、时钟频率、板卡与工艺、基线公平性、消融和测量不确定性。前部综合性意见应判断硬件性能和能效结论是否具有足够测量依据并与任务要求对应。

### R7 试验设计、测评与可复现性审稿人（固定）

关注数据集来源与划分、样本量、版本、环境、随机种子、重复次数、统计量、评价指标定义、误差或置信区间、公开基线、日志与脚本、表格复算和结论外推边界。前部综合性意见应回答现有试验与测评证据整体上能否支撑任务指标、技术结论和适用范围。

### R8 电力业务、安全与可信应用审稿人

触发词包括设备运维、故障诊断、安监、营销、调度、生产控制、知识问答、智能体。关注业务代表性、误报漏报代价、现场数据漂移、人工复核、失效保护、网络与数据安全、可解释性和运行监测。前部综合性意见应判断应用任务是否从研究方法落实到真实或具有代表性的业务验证，并说明安全可信证据是否足以支撑应用结论。

### R9 报告规范、成果与知识产权审稿人

触发词包括报告编写、论文、专利、软著、标准、参考文献、密级、成果清单。关注封面元数据、图表题注、术语、单位、引用对应、成果名称数量、专利披露、密级与使用范围，以及摘要—正文—结论一致性。前部综合性意见应判断报告作为验收材料的完整性、成果一致性和可追溯程度，而不是只列格式错误。

## 去重与分工

- R1 主提“是否满足任务”；技术角色主提“方法或实验为何不足”；R7主提“证据是否可复核”；R9主提“呈现、引用和成果一致性”。
- 每名专家应先完成本视角的总体判断，再决定哪些细节问题值得进入正式意见；不要因为容易定位就优先堆积格式、图表和引用问题。
- 同一事实可以支撑多个判断，但正式意见只保留最直接的一条。其余角色引用该问题时应删除或改为不同的技术风险。
- 五名专家的总体层面意见不能机械同文，意见数量也无需相同。覆盖关键问题优先于形式对称。
