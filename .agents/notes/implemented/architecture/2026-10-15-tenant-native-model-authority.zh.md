# Agent Note: 租户模型配置与原生准备调用

Status: implemented

[English](2026-10-15-tenant-native-model-authority.md) | 中文

## Problem

云端 Host 服务多个账户，而原生模型插件通常从进程读取配置和凭据。共享进程状态会使一个用户的模型修改影响另一个用户。经 Host 传递密钥还会把展示服务不需要的凭据交给它。将派发移到 Platform 时，必须保留原生适配器的准备调用行为：能力描述与执行属于同一配置代次。

## Decision

Platform 按账户存储带修订号的原生 DeepSeek 与 Pi-AI 设置，并按账户身份加密凭据引用和原生刷新记录。原有适配器继续负责协议选择、请求转换、重放处理和失败分类。其可选 fetch 注入使用现有 Platform 目标地址与套接字策略。Host 传输原生选项、公开元数据和原生流式块，不接收提供方密钥。

原生 Models 页面保留现有字段和本地 `credentials.set` 默认行为。可选浏览器直传适配器提供远端权威。产品要求该适配器存在，缺失时拒绝提交输入的密钥，包括模块重载期间，因为退回 Host RPC 会越过预期的凭据归属。浏览器取得仅含元数据的票据后，将密钥字节直接上传到 Platform；回执只显示原提交的结果。

按用户归属绑定且会过期的准备记录存储原生公开配置和凭据引用，不含密钥值。其标识让 Host 的原生准备闭包把能力描述、图片定价与后续派发绑定到同一配置代次。流式调用受理仅消费该记录一次，并清除已存配置。原操作、租约、所选模型和已提交工具声明仍负责执行授权；准备记录不授予其中任何权限。账户凭据轮换使未消费的准备记录失效。容量与有效期由运维配置。

本云端组合遵循[提供方路由决策](2026-07-14-provider-routed-llm-adapters.zh.md)和[原生凭据记录决策](2026-08-13-credential-records-and-authorization-flows.zh.md)。两者的适配器及授权语义仍独立适用。

## Alternatives considered

**共享原生进程设置。** 无需云端持久化适配器，但无法隔离同一 Host 服务的账户。

**Host 持有提供方密钥。** 可从 Host 直接进行原生派发，但会把凭据交给展示进程，并重复 Platform 的执行授权。

**分别读取元数据与派发配置。** 比准备记录更小，但并发设置写入可使能力描述对应另一个端点。拒绝每次期间发生的写入也会改变原生准备调用行为。

**冻结整个操作的配置。** 可避免准备记录，但会阻止同一操作中后续原生调用读取已受理的配置修改。

## Consequences

配置与凭据存储增加一个相邻数据库代次。已消费或过期的准备记录不能重放推理；原生重试会准备新调用，且仍需原始存活执行权限。既有共享运维路由为历史账户保留独立授权。原生 HTTP 提供方使用维护中的实现；本组合不提供显式 WebSocket 传输。云端模型配置不增加原生浏览器授权流程控件。
