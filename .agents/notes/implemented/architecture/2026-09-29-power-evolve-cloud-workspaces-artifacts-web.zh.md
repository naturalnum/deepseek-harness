# Agent Note：PowerEvolve 云工作区与产物接入原生 Web

状态：已实施

[English](2026-09-29-power-evolve-cloud-workspaces-artifacts-web.md) | 中文

## 问题

PowerEvolve 需要多个云工作区和不可变的已发布产物，同时保留原生 DSH Web 导航与文件浏览器。另做项目选择器或文件树，会让会话和文件状态分散到两套界面。

## 决策

产品云工作区插件占用现有的两个 `directoryFlow` 插槽。标题表单通过现有 `path` 字段向原生工作区属主交付编码后的不透明标题。Host 验证编码，调用平台创建工作区，再返回权威工作区记录。原生工作区控制器随后选择平台生成的 ID。每个工作区的执行路径都可以显示为 `/workspace`；该路径和标题都不是授权依据。

产品产物插件在原生文档预览工具栏中，为选中的文件提供显式发布操作。它通过已认证的产品接口发送会话 ID、经过校验的工作区相对路径和稳定请求 ID。原生右侧栏页面按当前会话或其工作区列举产物，获取有界预览数据，并链接到已认证的流式下载接口。平台负责文件授权、不可变副本和产物元数据；浏览器不从模型输出推断发布行为。

现有的输入框上传及文档预览编辑、下载操作在每次文件请求中传入当前会话 ID。编辑在读取时保留会话 ID，并拒绝以另一个会话保存；缺少会话上下文时，预览操作不可用。原生文件树已通过限定到会话的 Remote 读取。

## 考虑过的替代方案

**另做云工作区选择器和文件树。** 这会重复原生选择与文件状态，让同一个会话出现两条导航路径。现有插槽已经提供所需的用户操作。

**从模型回复推断要发布的文件。** 回复不等于经过授权的文件选择，也可能指向过期或不存在的路径。发布应从用户在原生预览中选中的文件开始。

## 结果

- 工作区创建和产物发布沿用现有 DSH Web 控件，无需另一套选择器或文件树。
- 即使执行路径相同，原生工作区记录仍按平台 ID 区分。
- 发布失败后可以用相同请求 ID 重试；源文件后来变化不影响已发布产物的获取。
