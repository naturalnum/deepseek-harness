# Isolated Connector Runner

English | [中文](README.zh.md)

This short-lived process runs one platform-authorized SSH or fixed read-only STDIO MCP call in a dedicated Kubernetes Pod. It has no workspace, Home, skill, database, Kubernetes credential, or generic command HTTP route. The platform keeps durable state and decides which exact command may run; this Runner keeps only bounded in-memory results. After a restart, a changed `instanceId` means an absent call has an uncertain outcome, never permission to replay it.

## Build and deployment

Run `pnpm --filter @power-evolve/connector-runner build`, then `pnpm --filter @power-evolve/connector-runner deploy --legacy --prod --ignore-scripts /private/runner-image-context`. Build the image with `docker build -f products/power-evolve/connector-runner/Dockerfile /private/runner-image-context`. The Dockerfile copies only the deployed package and starts as UID/GID 10001. The Pod must use gVisor, `runAsNonRoot`, a read-only root filesystem, dropped capabilities, no ServiceAccount mount, no user volumes, and a private memory-backed scratch volume if needed. Mount a one-Pod control token file readable by GID 10001; the token value never belongs in an environment variable or Pod description.

Configuration uses `CONNECTOR_RUNNER_TOKEN_FILE` (default `/run/power-evolve/runner-token`), `CONNECTOR_RUNNER_PORT` (default `8080`), `CONNECTOR_RUNNER_ALLOWED_DESTINATIONS` (exact comma-separated `host:port` values), and `CONNECTOR_RUNNER_FORBIDDEN_PROBE` (one exact forbidden `host:port`). Empty allowlist denies every SSH destination. Missing forbidden probe keeps `/health` unready. No user can set these deployment fields. The SSH Pod policy permits its approved target and platform ingress; the STDIO Pod policy permits platform ingress and no egress.

The Runner requires three consecutive denied TCP probes before readiness and withdraws readiness when a later probe connects or is inconclusive. It treats `ECONNREFUSED` as inconclusive by default. Set `CONNECTOR_RUNNER_REFUSED_PROVES_DENIAL=1` only when the platform has independently connected to that fixed probe listener from a control Pod and continues to establish its health. A refusal from an arbitrary closed port does not show egress isolation. If the cluster cannot establish this proof, do not dispatch credentials. The platform must additionally test an allowed connection and a forbidden connection in the deployed namespace.

## Wire API

Every request carries `x-power-evolve-runner-token`. `GET /health` returns `{ready,instanceId}` (503 until ready). `GET /calls/{callId}` returns the in-memory state or 404, including `instanceId`; it never returns credentials. SSH `POST /calls` accepts exactly `{callId,instanceId,digest,kind,destination,timeoutMs,maxOutputBytes,...}`. The `kind` is `ssh.inspect`, `ssh.authenticate`, or `ssh.execute`. `destination` contains `host`, `port`, and `username`; authenticated calls also require `hostKeySha256`. Authenticate and execute include a `credential` (`{kind:'password',password}` or `{kind:'private_key',privateKey,passphrase?}`); execute additionally includes `command`. Inspect refuses credentials and never authenticates. A wrong host fingerprint refuses authentication before any command.

The fixed STDIO request is exactly `{kind:'mcp.stdio.whoami',callId,instanceId,digest,accountId,timeoutMs,maxOutputBytes}`. The Runner starts its image-owned MCP server under the Pod's gVisor isolation, uses the SDK STDIO transport, and returns only bounded text from its read-only `whoami` tool. No request can supply an executable, arguments, environment, filesystem path, URL, credential, or other tool name. Each call starts a fresh process; the shared DSH Host never starts it.

The platform computes `digest` with the exported `requestDigest(unsignedCall, podToken)` helper. It is HMAC-SHA256 over recursively key-sorted JSON without the `digest` field, including credential bytes. The token keys the digest so the status response does not expose an offline password verifier. A repeated ID and digest returns the existing state; the same ID with another digest is a conflict. By default, the Runner accepts only one distinct call ID for its lifetime. The platform queries GET before POST, compares both Pod UID and `instanceId` on recovery, and never automatically retries an uncertain SSH write. One Pod serves one approved call, with a fresh token and a short lifetime.

SSH failures retain `state:'failed'` and `errorCode` and include `effectMayHaveOccurred`. It is `false` before the Runner attempts `exec`, including authentication and fingerprint failures, and becomes `true` when `exec` is invoked. Disconnects, timeouts, cancellation, and output limits after that point retain `true`; an unclassified execute exception is also conservatively `true`. Closing a command channel without an observed exit code or nonempty exit signal fails with `ssh_exit_missing`. GET and repeated POST return the same recorded flag. For execute calls, the platform must treat a `true` flag or a missing flag from an older Runner as an uncertain command outcome. STDIO responses retain their existing shape.

The entire HTTP JSON body is capped at 256 KiB (`MAX_CALL_BODY_BYTES`), including JSON escaping; larger bodies return 413 before reserving a call ID. Individual UTF-8 field limits remain unchanged: command 16 KiB, password 4096 bytes, private key 7168 bytes, and passphrase 1024 bytes. SSH combined stdout and stderr are capped at 128 KiB and its deadline at 60 seconds. STDIO MCP text is capped at 8 KiB and its deadline at 30 seconds. The Runner has no file transfer, PTY, port forwarding, local shell, or arbitrary process MCP command. These capabilities need separate review and implementation.


## Shared STDIO SDK provider

`@power-evolve/connector-runner/stdio-v2` exports `runStdioV2(input, options, signal)` for isolated Cloud and Device executors. This fixed connector Runner does not expose it; the separate [Sandbox Runner](../sandbox/README.md) can load its trusted cloud runtime library. The shared Host must not execute it. The executor owns approval, immutable runner/program pins, directory authorization, prepare/permit, durable request identity, result interpretation and container/UID cleanup.

The separate Node-only `@power-evolve/connector-runner/stdio-v2-digest` leaf starts no process. It hashes complete original JSON with distinct management/configuration/task/catalog/prepared/scope/spec/dispatch/result domains using the shared browser-safe codec. Ordered full-catalog fingerprints include every schema, metadata and extension field. Approval HMAC uses the existing Platform-owned 32-byte key and its own domain; executors never receive that key. Encoding budgets include the complete domain envelope. The browser-safe contracts package imports neither this leaf nor the SDK provider. Existing legacy request digests remain unchanged.

The input selects `discover` or `call` with a literal program, argument array and absolute cwd. A call also supplies the frozen entire raw catalog, raw tool name and JSON arguments. Options supply every input/message/protocol/JSON/page/tool/catalog/result/stderr/runtime/request/cleanup budget, the exact `HOME`/`PATH`/`LANG` environment, and a synchronous callback that validates the whole raw catalog and computes the shared frozen digest. The provider contains no second canonical digest implementation. Node on macOS may add its own `__CF_USER_TEXT_ENCODING` hint; no ambient environment is merged. HOME and PATH must point to the executor's approved isolated locations.

Options also require an explicit process identity: `current` retains the already isolated caller's UID/GID; `unix` supplies validated numeric UID/GID to actual spawn. The cloud runtime requires Unix 1000/1000. The `stdio-v2-dispatch` leaf validates complete original start packets and maps frozen invocations to the SDK; the `stdio-v2-runtime` leaf reserves a single writer, bounds the whole response and waits for independently supplied UID cleanup. Neither leaf authenticates HTTP callers or persists Platform state.

The public SDK2 Client performs one `initialize` handshake using its explicit `legacy` negotiation mode (the supported 2025-era handshake, unrelated to the product's fixed `whoami` route). A public Transport adapter starts one child with `shell:false`, uses the SDK's public framing and message schema helpers, checks strict UTF-8 JSONRPC lines and counts raw incoming/outgoing protocol bytes. Unsupported protocol versions fail without a sibling process, a second initialize, reconnect or retry. The provider reads every tool page with public SDK requests and compares the entire catalog before exactly one `tools/call`. Raw schemas, annotations, metadata, content, structured content, `isError`, extensions and escaped NUL remain JSON. `readOnlyHint` never grants approval, and an `isError:true` result is a completed RPC for the outer owner to classify.

Program startup itself may have effects. Lost replies, cancellation, directory changes and budget failures retain conservative effect/call facts, never a truncated successful directory or result. Cleanup waits independently for configured stdin, TERM and KILL deadlines and records actual direct-child `exit` and `close` events. An unobserved close fails with `cleanupConfirmed:false`; SDK close alone proves no exit. Even a confirmed direct-child close cannot prove descendants, a container, a writer or its directory lease are retired. The outer stop protocol must supply that evidence and must not replay an uncertain call.

Run the focused source tests with `node --import tsx/esm --test products/power-evolve/connector-runner/tests/stdio-v2.test.ts` from the repository root. They use the real SDK2 Client and owned synthetic Node peers, including pagination, literal special arguments, full JSON preservation, changed catalogs, lost replies, budgets, abort, KILL and a descendant-held pipe. Their fingerprint callback substitutes for the future shared catalog validator. These tests establish provider behavior; they do not verify approval, Cloud/Device integration or a deployed product workflow.
