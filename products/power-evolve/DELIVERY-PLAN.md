# PowerEvolve 纵切面交付计划

基线：官方 DSH `dsh-v0.1.7-rc.2`；产品分支 `power-evolve/native-cloud-client`，从已固定的 [S1 产品基线](TRIAL-S1-NATIVE.md)继续。目标是可发布、可在原生 DSH Web 中试用的共享 Host＋可信平台＋云端／桌面执行产品。旧 PowerEvolve `main` 是客户端功能迁移来源，不整体替换当前实现。本文计数是交付预算，不要求为了凑数拆包。

## 计数口径与现状

| 可装配产品插件入口 | 当前 | 目标 |
| --- | ---: | ---: |
| Host：运行时、Session 持久化、模型适配、应用入口 | 4 | 4 |
| 可信平台 Profile、桌面设备 Profile | 2 | 2 |
| Web：品牌／关于、工作区文件、执行位置 | 3 | 3 |
| Web：账号设置、产物、云工作区、扩展中心 | 4 | 4 |
| **合计** | **13** | **13** |

云工作区和扩展中心现已分别作为原生 Web 插件装配。S5–S6 扩展既有入口；只有原生 DSH 扩展点确实要求独立宿主适配器时才新增第 14 个。技能、内置插件和连接器的每个条目是数据／受控工具，不是每个都新增一个 DSH 插件。架构文档 P01–P10 是职责；可信后台 T01–T06 是一个进程内的 6 个所有权模块，不是 6 个新服务。

T01–T06 都已有最小实现；发布验收按以下 **24 项能力**检查，而不以模块文件存在视为完成：

| 可信模块 | 验收能力 |
| --- | --- |
| T01 身份与权限（4） | 登录与设备身份；逐资源授权；独立审批；撤销及令牌轮换 |
| T02 状态与任务（4） | 持久受理和幂等；原生事件日志；租约围栏与恢复；配额和公平调度 |
| T03 用户配置（3） | 用户设置快照；技能目录和版本；插件／连接器启用配置 |
| T04 文件（4） | 工作区归属；文件版本读写；产物发布／下载；路径及云桌面传输边界 |
| T05 模型与外部调用（4） | 模型代理；凭据保管；连接器调用与对账；出口和用量审计 |
| T06 执行与设备（5） | 云沙盒生命周期；桌面授权执行；命令状态／取消；挂载与资源隔离；回收和不确定结果对账 |

S1 的原生客户端组合验收及固定试用版本见 [TRIAL-S1-NATIVE.md](TRIAL-S1-NATIVE.md)。多节点共享存储、平台多副本、规模容量和完整旧版扩展中心尚未发布验收。

## 7 个纵切面及其验收范围

每片都从真实客户端操作出发，经 Host 插件、可信平台和所需基础设施，回到用户可见结果。表中的插件数是本片直接联测的可装配入口，包含基础 Host 插件，不表示每个都需改代码；`+` 表示计划新增。

| 片 | 插件 | 可信模块 | 用户可验证的完成出口 |
| --- | --- | --- | --- |
| S1 基线封口（已固定） | 9 个现有，新增 0 | T01/T02/T04/T05/T06（5） | 两用户全新登录，`hi`、追问、文件上传编辑下载、云 Git 与本地 Git 各走通；`hi` 无沙盒；刷新、取消和一次重启恢复可核对。先修发现的回归，不叠加新页面。 |
| S2 工作区与产物 | 现有 Host 4＋平台 1＋文件 1；新增 Web 1–2（共 7–8） | T02/T04/T06（3） | 选择两个云工作区，运行任务后得到可列举、可预览、可下载的产物；两个用户互不可见，沙盒回收后 Git 和文件保留。旧 `dsh-client-artifacts`、`dsh-client-cloud-workspaces` 定向迁移。 |
| S3 账号与设置 | 现有 Host 4＋平台 1＋品牌 1；新增 Web 1（共 7） | T01/T03/T05（3） | 原生设置页能显示本人、修改可编辑配置、选择获授权模型；刷新与另一个用户的设置隔离，凭据只在平台。迁移旧 `dsh-client-account` 适用部分。 |

S2–S6 的已记录云端场景通过，独立试用版见 [S2](TRIAL-S2-NATIVE.md)、[S3](TRIAL-S3-NATIVE.md)、[S4](TRIAL-S4-NATIVE.md)、[S5](TRIAL-S5-NATIVE.md) 和 [S6](TRIAL-S6-FINAL-QA.md)。这些场景尚未覆盖旧产品全部功能；[完整性审计](PARITY-AUDIT.md)核对了旧 `main` 的真实入口及当前缺口，下节列出补齐顺序。S6 的确切 SSH 命令审批、真实 Runner 执行、原会话续接及 V17→V18 隔离迁移均有证据；旧 [S6 预览](TRIAL-S6-PREVIEW.md) 保留供对照。固定 `whoami`、`qa:ping` 仅验证相应受控目标，不作为通用 MCP／SSH 验收。S4–S6 共用一个扩展中心包，但分别交付。S7 的多节点 POSIX 一致性、文件路径隔离、网络出口和平台多副本需要真实部署证据；本机单节点通过不等于该片通过。

S7a 的[本机双 Host、双 Platform 故障演练](TRIAL-S7A-LOCAL.md)已验证一次受控写入在响应丢失及 Platform 切换后只执行一次，并在原会话续接。它使用确定性模型和同机 POSIX 根；S7 的跨节点部署、生产入口、容量与备份恢复仍未验收。

S7b 的[本机双 k3d 节点演练](TRIAL-S7B-LOCAL.md)已验证真实 Sandbox 在不同节点容器间的 Git／Home／技能文件可见性及旧 Pod 停止证明；两个节点仍在同一物理主机。简短对话的[容量探针](TRIAL-S7-CAPACITY.md)已记录 8、64、128 用户的本机实测值，不代替目标硬件和业务混合负载验收。

S7c 的[停写备份与恢复](TRIAL-S7C-BACKUP.md)已从 V18 恢复到 V19；[当前 c3 预览](TRIAL-S7-CURRENT-PREVIEW.md)在修复后通过两用户新对话、文件／产物隔离、恢复后的真实云 Git 和重启读回。[登录容量探针](TRIAL-S7-LOGIN-CAPACITY.md)记录了双 Platform 经负载均衡的吞吐与锁等待。S7d 的[镜像启动](deploy/QA-S7D-IMAGE-STARTUP.md)和[本机网络策略与 RBAC 演练](TRIAL-S7D-POLICY.md)分别已有实测；[集成验证](TRIAL-S7-INTEGRATED.md)记录各项提交、测试和适用范围。S7 仍须通过独立物理节点、真实共享卷和生产入口的端到端验收后才能封口。

## 产品完整性补齐顺序

S7 本机镜像启动和 c3 双用户试用已留存证据及独立快照，接下来按下表返回对应切片补齐。外部物理集群验收继续列为 S7 未完成项；等待访问期间推进已确认的产品缺口，不将本机证据升级为生产证据。下表复用既有插件和可信模块，暂不增加插件入口；每行须完成原生客户端端到端验收后再合入下一行。

| 顺序与归属 | 直接涉及插件／可信模块 | 完成出口 |
| --- | --- | --- |
| 1：S4–S5 内置技能（已固定） | Host 4＋平台 1＋扩展中心 1；T03/T04/T06 | 复用旧目录和 9 个技能包，支持全部／我的、安装和预置；说明按需读取且无需沙盒，代码在真实 Runner 执行。逐包检查格式、依赖与版本，配额容纳目录规模；双用户安装、禁用、撤销及重启后状态可核对。 |
| 2：S6 连接器完整功能 | Host 4＋平台 1＋扩展中心 1；T01/T03/T05/T06 | 迁移多连接 MCP 配置、发现、调用及编辑删除，进程型工具只进执行环境；补 SSH 私钥、编辑删除和普通命令。凭据、出口授权、具体动作审批、撤销和不确定结果对账贯穿真实连接试用。 |
| 3：S3 账号生命周期 | Host 4＋平台 1＋账号 1；T01/T02/T03 | 管理员开通／停用／重置及个人改密码，从独立可信入口生效；普通用户不能管理他人，停用和改密码撤销适用会话，重启不由种子配置覆盖已修改状态。组织身份同步另按目标部署验收，不以种子文件代替。 |

每行内可以分别准备服务端适配、旧客户端迁移和验收脚本。接口、错误码和文件所有权先由集成者固定；共享的 Profile、schema、锁文件只由一个所有者修改。目录资产和只读兼容性检查可提前并行，未集成的准备成果不计作该行交付。

## 并行与串行规则

1. **串行的关口：** 为当前片锁定接口和验收例子 → 各自实现 → 合并集成 → 两用户真实端到端验收 → 固定提交与独立试用快照 → 下一片。未通过的片只修缺陷，不叠加新的产品页面。
2. **可并行的工作：** 一个执行者负责 Host／DSH 接口，一个负责平台／PG／执行边界，一个负责旧版客户端页面迁移；集成者维护共同契约与试用验收。各自使用隔离分支／工作树；同一迁移文件、Profile、锁文件和 schema 只给一个所有者。下一片可做只读审计和独立原型，不能在本片验收前合入。
3. **每片最小证据：** 原生浏览器真实操作；真实 PG；涉及模型、k3s、设备时用真实服务至少一次；两个用户的越权拒绝；重复请求；一个失败／恢复场景；构建、类型检查、相关回归；实际提交、试用地址、日志和未通过项。替身测试单独标记。
4. **时间边界：** 半个月优先确保 S1–S4 成为稳定可试用的产品路径，同时并行准备 S5–S6 的云端实现。S5–S7 的完成日期服从真实端到端证据，不能为了日程降低隔离或恢复验收标准。

不停止 PowerEvolve 总任务。既有固定试用版本保持可回退；当前以 S7 本机集成验证和上述产品完整性补齐为序，不分散新增页面。

当前只推进云端：桌面 S1 的已验收能力保留，不在 S2–S7 增加桌面功能，也不以桌面联测阻塞云端发布。S4 已完成技能说明；S5–S6 验收云端可执行技能、插件与连接器。桌面与云端打通仍属于最终目标，云端版本稳定后再安排桌面适配和组合验收。
