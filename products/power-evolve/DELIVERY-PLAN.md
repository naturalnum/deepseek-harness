# PowerEvolve 纵切面交付计划

基线：官方 DSH `dsh-v0.1.7-rc.2`；产品分支 `power-evolve/native-cloud-client`，从已固定的 [S1 产品基线](TRIAL-S1-NATIVE.md)继续。目标是可发布、可在原生 DSH Web 中试用的共享 Host＋可信平台＋云端／桌面执行产品。旧 PowerEvolve `main` 是客户端功能迁移来源，不整体替换当前实现。本文计数是交付预算，不要求为了凑数拆包。

## 计数口径与现状

| 可装配产品插件入口 | 当前 | 目标 |
| --- | ---: | ---: |
| Host：运行时、Session 持久化、模型适配、应用入口 | 4 | 4 |
| 可信平台 Profile、桌面设备 Profile | 2 | 2 |
| Web：品牌／关于、工作区文件、执行位置 | 3 | 3 |
| 待迁 Web：账号设置、产物、云工作区、扩展中心 | 4 | 4 |
| **合计** | **13** | **13** |

云工作区和扩展中心现已分别作为原生 Web 插件装配。S5–S6 扩展既有入口；只有原生 DSH 扩展点确实要求独立宿主适配器时才新增第 14 个。技能、内置插件和连接器的每个条目是数据／受控工具，不是每个都新增一个 DSH 插件。架构文档 P01–P10 是职责；可信后台 T01–T06 是一个进程内的 6 个所有权模块，不是 6 个新服务。

T01–T06 都已有最小实现；发布验收按以下 **24 项能力**检查，而不以模块文件存在视为完成：

| 可信模块 | 验收能力 |
| --- | --- |
| T01 身份与权限（4） | 登录与设备身份；逐资源授权；独立审批；撤销及令牌轮换 |
| T02 状态与任务（4） | 持久受理和幂等；原生事件日志；租约围栏与恢复；配额和公平调度 |
| T03 用户配置（3） | 用户设置快照；技能目录和版本；插件／连接器启用配置 |
| T04 文件（4） | 工作区归属；文件版本读写；产物发布／下载；路径及云桌面传输边界 |
| T05 模型与外部调用（4） | 模型代理；凭据保管；连接器调用与对账；出口和用量审计 |
| T06 执行与设备（5） | 云沙盒生命周期；桌面授权执行；命令状态／取消；挂载与资源隔离；回收和不确定结果对账 |

S1 的原生客户端组合验收及固定试用版本见 [TRIAL-S1-NATIVE.md](TRIAL-S1-NATIVE.md)。多节点共享存储、平台多副本、规模容量和完整旧版扩展中心尚未发布验收。

## 余下 7 个纵切面

每片都从真实客户端操作出发，经 Host 插件、可信平台和所需基础设施，回到用户可见结果。表中的插件数是本片直接联测的可装配入口，包含基础 Host 插件，不表示每个都需改代码；`+` 表示计划新增。

| 片 | 插件 | 可信模块 | 用户可验证的完成出口 |
| --- | --- | --- | --- |
| S1 基线封口（已固定） | 9 个现有，新增 0 | T01/T02/T04/T05/T06（5） | 两用户全新登录，`hi`、追问、文件上传编辑下载、云 Git 与本地 Git 各走通；`hi` 无沙盒；刷新、取消和一次重启恢复可核对。先修发现的回归，不叠加新页面。 |
| S2 工作区与产物 | 现有 Host 4＋平台 1＋文件 1；新增 Web 1–2（共 7–8） | T02/T04/T06（3） | 选择两个云工作区，运行任务后得到可列举、可预览、可下载的产物；两个用户互不可见，沙盒回收后 Git 和文件保留。旧 `dsh-client-artifacts`、`dsh-client-cloud-workspaces` 定向迁移。 |
| S3 账号与设置 | 现有 Host 4＋平台 1＋品牌 1；新增 Web 1（共 7） | T01/T03/T05（3） | 原生设置页能显示本人、修改可编辑配置、选择获授权模型；刷新与另一个用户的设置隔离，凭据只在平台。迁移旧 `dsh-client-account` 适用部分。 |
| S4 技能说明与管理 | 现有 Host 4＋平台 1；新增 Web 1（共 6） | T03/T04（2） | 原生“技能”页按用户显示、安装、启停、查看说明；会话读取说明不创建沙盒；版本固定、跨用户拒绝。迁移旧 `dsh-client-extension-center` 页面与测试。 |
| S5 可执行技能（已固定） | Host 4＋平台 1＋扩展中心 1（共 6），新增 0 | T03/T04/T06（3） | 一个真实带代码的技能在获授权云沙盒运行，记录输出与产物；禁用、撤销、失败和重试均可验收。桌面执行适配暂缓。 |
| S6 插件与连接器 | Host 4＋平台 1＋扩展中心 1（共 6），新增 0 | T01/T03/T05/T06（4） | 原生“插件”页展示内置和个人插件；受控 API 与审批走可信入口；进程型 MCP／SSH 只进云端执行环境。桌面执行适配随后补齐。 |
| S7 多副本与发布 | 最多 13 个联测，新增 0 | T01–T06（6） | 两个 Host、平台多副本、负载均衡和真实 k3s／共享文件系统反复故障演练；旧写者隔离、任务去重、资源回收、容量数据、备份恢复、发布产物和安全边界通过。 |

S2–S5 已完成云端验收，独立试用版见 [S2](TRIAL-S2-NATIVE.md)、[S3](TRIAL-S3-NATIVE.md)、[S4](TRIAL-S4-NATIVE.md) 和 [S5](TRIAL-S5-NATIVE.md)。S6 是当前切片。S4–S6 共用一个扩展中心包，但分别交付，不等到整包迁完才试用。S7 的多节点 POSIX 一致性、文件路径隔离、网络出口和平台多副本需要真实部署证据；本机单节点通过不等于该片通过。

## 并行与串行规则

1. **串行的关口：** 为当前片锁定接口和验收例子 → 各自实现 → 合并集成 → 两用户真实端到端验收 → 固定提交与独立试用快照 → 下一片。未通过的片只修缺陷，不叠加新的产品页面。
2. **可并行的工作：** 一个执行者负责 Host／DSH 接口，一个负责平台／PG／执行边界，一个负责旧版客户端页面迁移；集成者维护共同契约与试用验收。各自使用隔离分支／工作树；同一迁移文件、Profile、锁文件和 schema 只给一个所有者。下一片可做只读审计和独立原型，不能在本片验收前合入。
3. **每片最小证据：** 原生浏览器真实操作；真实 PG；涉及模型、k3s、设备时用真实服务至少一次；两个用户的越权拒绝；重复请求；一个失败／恢复场景；构建、类型检查、相关回归；实际提交、试用地址、日志和未通过项。替身测试单独标记。
4. **时间边界：** 半个月优先确保 S1–S4 成为稳定可试用的产品路径，同时并行准备 S5–S6 的云端实现。S5–S7 的完成日期服从真实端到端证据，不能为了日程降低隔离或恢复验收标准。

不停止 PowerEvolve 总任务。已提交的 S1 保持为可回退基线；停止零散加页面与先调技能／插件的做法，从 S2 逐片推进。

当前只推进云端：桌面 S1 的已验收能力保留，不在 S2–S7 增加桌面功能，也不以桌面联测阻塞云端发布。S4 已完成技能说明；S5–S6 验收云端可执行技能、插件与连接器。桌面与云端打通仍属于最终目标，云端版本稳定后再安排桌面适配和组合验收。
