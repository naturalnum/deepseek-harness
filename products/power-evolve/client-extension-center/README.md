# PowerEvolve Extension Center

English | [中文](README.zh.md)

The native DSH Web sidebar hosts per-user Skills and Plugins pages. Skills has My skills and All skills views, category search, and a Platform-backed catalog of nine pinned built-in Skills. Catalog installation uses a stable request ID across uncertain retries and updates My skills. The page also lists, reads, installs, enables, disables, and revokes personal text skills and ZIP packages. Installed instructions can be previewed without starting a Sandbox. The same-origin Host RPC issues a short-lived upload ticket; the browser sends package bytes directly to the Platform, and the Host never buffers the ZIP. Package versions, digests, and readiness come from the Platform. “Try skill” opens an editable native invocation draft in a new Conversation, using the Host's stable alias while displaying the original name; the user sends the task, and any code runs only in an authorized cloud Sandbox. Plugins displays the Platform-owned controlled notes status, changes its personal enablement with a stable request ID, and links to the separate trusted approval page. The personal MCP page installs one operator-fixed read-only whoami connection per user, toggles it, and displays a bounded test result. It accepts no endpoint, header, or credential input. The personal SSH page lists servers, creates password-based connections with an independently verified host-key fingerprint, and changes enablement. The browser sends at most 4096 UTF-8 password bytes directly to the trusted Platform's pinned upload endpoint using a short-lived ticket; the Host receives only metadata and the byte count. The SSH credential check performs authentication without running a remote command. A recent-check list restores owner-scoped call states after a browser refresh and polls nonterminal calls through one bounded list RPC. An Agent can propose one exact command for a pinned SSH connection; the trusted Platform shows the command and target for separate user approval. Only an approved command runs through the dedicated Runner, with a bounded result continuing the original Session; rejection creates no Runner call, and an execution request can be cancelled. Private-key authentication, connection edits, and deletion remain unavailable.
