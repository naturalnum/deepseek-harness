# PowerEvolve Extension Center

English | [中文](README.zh.md)

The native DSH Web sidebar hosts per-user Skills and Plugins pages. Skills has My skills and All skills views, category search, and a Platform-backed catalog of nine pinned built-in Skills. Catalog installation uses a stable request ID across uncertain retries and updates My skills. The page also lists, reads, installs, enables, disables, and revokes personal text skills and ZIP packages. Installed instructions can be previewed without starting a Sandbox. The same-origin Host RPC issues a short-lived upload ticket; the browser sends package bytes directly to the Platform, and the Host never buffers the ZIP. Package versions, digests, and readiness come from the Platform. “Try skill” opens an editable native invocation draft in a new Conversation, using the Host's stable alias while displaying the original name; the user sends the task, and any code runs only in an authorized cloud Sandbox. Plugins displays the Platform-owned controlled notes status, changes its personal enablement with a stable request ID, and links to the separate trusted approval page. The legacy fixed MCP page installs one operator-fixed read-only whoami connection per user, toggles it, and displays a bounded test result. It accepts no endpoint, header, or credential input. The personal SSH page lists servers, creates password-based connections with an independently verified host-key fingerprint, and changes enablement. The browser sends at most 4096 UTF-8 password bytes directly to the trusted Platform's pinned upload endpoint using a short-lived ticket; the Host receives only metadata and the byte count. The SSH credential check performs authentication without running a remote command. A recent-check list restores owner-scoped call states after a browser refresh and polls nonterminal calls through one bounded list RPC. An Agent can propose one exact command for a pinned SSH connection; the trusted Platform shows the command and target for separate user approval. Only an approved command runs through the dedicated Runner, with a bounded result continuing the original Session; rejection creates no Runner call, and an execution request can be cancelled. Private-key authentication, connection edits, and deletion remain unavailable.

The Remote MCP plugin opens the original multi-connection page with search, details, create/edit modal, enablement, deletion, write-only Bearer and custom-header fields, and saved/draft checks with cancellation and durable status. The browser adapter sends metadata through the same-origin MCP management RPC and sends replacement credentials directly to the trusted Platform's fixed upload endpoint using a short-lived ticket. The Host receives names, actions, and byte counts; it never receives credential values. Lost upload responses are reconciled through the original request receipt. Explicit retries keep the same request ID and immutable input.

Checks use an existing native Session, defaulting to the Session retained by the main view. The selected Session stays fixed while a check is pending; deleting it invalidates that draft, and late responses cannot replace a changed draft or canceled check. Configuration and credential revisions identify stale checks. Expiry and cancellation requests remain visible, and unavailable management blocks writes while allowing refresh. The legacy fixed MCP card keeps its own records and API.

Focused client tests use explicit network and Port substitutes and an owner-local list snapshot. They verify browser transport, credential masking, page behavior, and native Session selection; they do not establish real Platform integration or two-user isolation.
