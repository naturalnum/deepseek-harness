# S5 云端可执行技能接口

S5 沿用原生 DSH Web 的“技能”页、共享 Host 和独立可信平台。桌面执行不进入本片。文本技能保持 S4 的入口和语义；技能包的安装与说明读取不创建沙盒，只有会话提出实际执行请求时才按需创建云沙盒。

## 安装与版本

浏览器从同源 Host RPC 请求上传票据，提交稳定的 `requestId`、ZIP 字节长度及 SHA-256。Host 认证当前用户并向平台申请票据，不接收 ZIP 字节。平台返回已完成安装的技能项，或者返回短期票据及平台上传 URL。浏览器以票据把原始 ZIP 直接发给平台；票据绑定用户、请求 ID、字节长度和摘要，上传接口只允许配置的 Host Origin。结果未知时浏览器用相同请求 ID 和摘要重新查询／领票，平台必须返回既有结果或按同一安装意图继续，不能创建第二份安装。

平台在私有暂存目录限界验证 ZIP：压缩包最多 1 MiB、最多 256 项、解包最多 8 MiB、`SKILL.md` 最多 256 KiB；拒绝路径穿越、符号链接、特殊文件、重复项和不受支持的压缩格式。技能技术名及说明从包内 `SKILL.md` 读取。可选 `skill-package.json` 提供 `{schemaVersion:1,version}`；没有它时版本为 `sha256:<压缩包摘要>`。发布时记录逐文件摘要清单，把不可变目录按用户和包摘要原子落到 POSIX 存储，再提交 PG 安装元数据。失败不产生可见安装；孤立的未引用暂存文件可回收。

每个技能的 `revision` 是启停或撤销状态修订，`version` 是包版本，二者不能混用。已有 `digest` 始终表示 `SKILL.md` 内容摘要；`packageDigest` 表示压缩包摘要，`manifestDigest` 表示文件清单摘要。S4 历史文本技能及旧操作选择保持可读。包更新要保留旧不可变版本，使已受理操作继续引用受理时的确切摘要。禁用或撤销阻止后续任务选用；撤销后不能再次启用，已运行脚本的副作用无法撤回，旧操作引用的包字节暂不删除。

## 会话、运行与隔离

平台受理任务时，按可信用户身份冻结启用技能的技术名、说明摘要、包版本和包摘要。Host 在每个 Agent scope 中只收到所选技能的说明、版本及沙盒内虚拟路径；不得在共享 Host 加载用户脚本或扫描全用户技能目录。技能说明仍按用户内容处理，不提升系统权限。代码执行继续走现有 `cloud_exec` 的平台受理、调用 ID 去重、runner 查询和结果续接。

首次需要命令时，可信平台为该用户会话创建云沙盒，除了授权工作区和 Home，只读挂载该用户的包库到 `/opt/power-evolve/skills`。不得挂载共享根，也不得让受控文件 API 写入包库。已有 Pod 若缺少只读挂载，必须确认停止或隔离后重建，不应当视为可复用实例。禁用或撤销后的通用 `cloud_exec` 仍可能访问同一用户已挂载的旧字节，因此本片的撤销承诺限于后续自动选用；按脚本逐次强制撤销需要专用受控执行工具。

部署时 Host 不挂载技能包库，Host 与可信平台使用不同的操作系统身份和存储权限。单机开发环境若把两个进程都运行在同一 Unix UID 下，应用边界虽已分开，POSIX 权限不能抵御 Host 进程失守后直接读取平台目录；这种配置只用于本地试用，不能作为生产隔离证据。

## 本片验收

从两个账号的原生技能页分别导入不同真实代码包，在原生会话发送任务，由各自云沙盒运行脚本并产生可见输出和文件／产物。验证列表、详情、版本和摘要在刷新与重启后保持；另一用户不能读取、启停、撤销或在自己的沙盒看到该包。验证坏包和超限包拒绝、上传不确定结果的同 ID 对账、禁用与撤销后新任务不选用、执行中断不盲目重跑、只读挂载不可改写、`hi` 和技能说明读取没有 Pod。通过相关类型检查、构建、测试和真实 k3s 试用后固定提交与独立试用环境。
