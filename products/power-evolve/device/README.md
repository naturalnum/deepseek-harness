# Local device bundle

English | [中文](README.zh.md)

This standalone `dsh` bundle starts a local-only authorization page and a paired device worker. The current OS user grants project directories; absolute paths and the device token remain in its private local state. Commands run in disposable Docker containers with one granted directory mounted. Cloud file transfers require an explicit action on the device page.

On macOS/Linux, an upstream native `flock` excludes another worker using the same private root. The journal stores the accepted request digest, creation owner, immutable image/container IDs and an observed stopped state before cleanup. A cold recovery never creates or starts a replacement command; missing identities and old journals require review and block new commands. Absence alone is not a stop observation. The Platform freezes the original command and timeout, binds a distinct worker process to its dispatch, and registers the exact container before issuing one start permission. The original process and queued inputs are journaled before claiming. A lost claim acknowledgement may be retried by that same live process; a cold process retains the claim intent for review without creating or starting a command. A lost registration acknowledgement never authorizes a second start. Stop reports retain the original process/dispatch and a stable retry ID; matching durable terminal acknowledgements permit local cleanup. Revoked credentials can register or report only their original dispatch, not obtain new work. Unknown effects remain reserved in PostgreSQL without an automatic continuation.

Independent Platform approval may close a stopped unknown execution as `closed_unknown` only after rechecking its original request, enrollment, process, dispatch, exact container and stop-record digest. Closure retains the original output and stop facts and enqueues at most one continuation in the original Session. The Device may retry its unchanged stop report after closure or revocation; the ACK permits cleanup without new start authority. Missing stop facts, legacy identities and cold claim intents remain blocked. The native execution area shows read-only facts and links to the existing independent approval console.

All cooperating Device Profiles of one OS user use the same configured `coordinationRoot`, independently of their private journals. One persistent writer slot serializes commands and explicit transfers, including unrelated or overlapping project directories. Command intent precedes Platform claim and Docker creation; stopping or losing a process never clears unknown work. The slot clears only after exact-container removal and a matching known or independently closed stop ACK. A durable `waiting` entry can resume after restart because it never submitted a claim; a cold `claiming` entry still requires review. This conservative serialization does not isolate other OS applications or separate OS users. Changing the coordination root requires stopping existing writers and reconciling their recorded work.

Explicit local authorization records the physical root's decimal dev/ino identity. Legacy grants require local reauthorization; replacing the physical directory requires a new grant. Transfers retain a shared kernel-lock descriptor in their bounded Python helper, even after the parent dies. Descriptor-relative traversal rejects symbolic links and nonregular files; reads are bounded to 2 MiB and imports create without overwriting. An interrupted import may have committed its destination, so inspect before retrying. Cloud receives directory IDs and labels, never local paths; root, Home and overlapping private/coordination directories cannot be granted.

The [bundle configuration](cordis.patch.yml) sets the shared coordination root, Python executable, file deadline, polling, contact-loss, platform/Docker request and picker timeouts, plus the Docker stop grace period. Python 3.9 or later is required on macOS/Linux. Shutdown closes admission, waits for actual helper exit, local actions and the bounded command stop attempt, then attempts both writer and journal lock release; an unconfirmed Docker writer remains recorded. The Platform also prevents overlapping live commands under the same Device/directory grant across Sessions. Full desktop recovery and Electron delivery remain defined by [desktop completion](../DESKTOP-COMPLETION.md). Device readiness is distinct from WebServer availability when a plugin fails to activate.

Use the [slice 5 trial guide](../TRIAL-SLICE5.md) to pair a device and test cloud and desktop execution. The web server must bind loopback. This bundle does not include the cloud host's Agent loop or platform database credentials.
