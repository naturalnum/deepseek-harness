# 本机设备 Bundle

[English](README.md) | 中文

这个独立 `dsh` Bundle 启动仅在本机开放的授权页面和已配对设备执行器。当前 OS 用户授权项目目录；绝对路径和设备令牌留在本机私密状态中。命令在只挂载一个授权目录的临时 Docker 容器中运行。云端文件传输需要在设备页面明确操作。

macOS/Linux 使用上游原生 `flock`，阻止另一 Worker 同时使用同一私有根目录。Journal 在清理之前保存已受理请求的摘要、创建者身份、不可变镜像／容器 ID 和观察到的停止状态。冷恢复不会创建或启动替代命令；身份缺失及旧 Journal 需要核查，并阻止新命令准入。实例缺失不能单独作为停止观察。平台固定原命令与超时，将独立 Worker 进程绑定到派发，并在精确容器登记后只发放一次启动许可。领取前先将原进程与排队输入写入 Journal。领取回执丢失时，同一存活进程可以重试；冷进程保留领取意图等待核验，不创建或启动命令。登记回执丢失不会授权第二次启动。停止报告保留原进程／派发与稳定重试 ID；匹配的持久终态回执才允许本地清理。已撤销凭据只能登记或报告原派发，不能获取新任务。副作用结果不明时，PG 保留占用且不自动续接。

[Bundle 配置](cordis.patch.yml)明确轮询、失联、平台／Docker 请求及选择器超时，以及 Docker 停止宽限期。关闭时停止准入，等待本地操作及有界命令停止尝试，再释放 Journal 锁；未确认停止的 Docker 写者继续保留记录。这把锁不协调不同私有根、重叠目录或其他 OS 应用。平台也阻止不同会话在同一 Device／目录授权内并发运行命令。完整桌面恢复切片仍需跨 Device 或重叠物理目录协调、本地目录描述符相对访问及可信未知结果结案，见[桌面补齐约定](../DESKTOP-COMPLETION.md)。插件未激活时，Device readiness 与 WebServer 可访问是不同状态。

按照[切片 5 试用指南](../TRIAL-SLICE5.md)配对设备并测试云端和桌面执行。Web 服务必须绑定本机回环地址。此 Bundle 不包含云宿主的 Agent 循环或平台数据库凭据。
