迁移前快照 `4acb888058b3e5a95ec7d085ba75bcf2442d3636` 的链接用于查阅历史源码和 QA 附件；验收范围仍以本页记录的测试版本、结果和发布边界为准，不能据此认证当前云端版本。

审计日期：2026-09-30。旧产品基线为 `naturalnum/power-evolve` 的 `origin/main` **`a03460fe66a3f77114ff3bb906476105e1d470b7`**；本地该 ref 与当天 `git ls-remote origin refs/heads/main` 相同。旧工作区当前在别的分支，本次只从该 ref 读取源码，未改动旧工作区。新产品基线为共享 DSH 分支 **`5c87bcdaa7eee9cc00ad06e9dbb4a183147d23be`**，上游 DSH 为 `dsh-v0.1.7-rc.2`。本审计只读源码、已有测试/试用证据，没有重新运行完整 Web 验收或生产部署。

证据等级：**实现**表示调用链在构建入口和服务端均可追到；**本地实测**表示既有真实浏览器、模型、PG、Pod 或文件验收有记录及本机留存证据；**未验收**表示当前提交或目标生产环境没有对应实测。单元测试与文档文字本身不提升为生产验收。

后续补齐：下表保留上述基线的审计结果。内置 9 包目录及代表性执行已有[固定 S8 试用](TRIAL-S8-NATIVE.md)，逐包范围见[S8 当前矩阵](TRIAL-S8-SKILLS-QA.md)；多连接 MCP、真实 SSH 和账号生命周期分别有[远程 MCP](TRIAL-S6-REMOTE-MCP-QA.md)、[SSH](TRIAL-S6-SSH-P24-QA.md)、[账号 V25](TRIAL-S3-ACCOUNT-V25-QA.md)固定试用。原生 Files 多选及批量下载、每轮产出、内联文件动作、存储选择及绑定恢复已完成 S2 A–C 本机验收，并形成[独立恢复的 V27 固定试用](TRIAL-S2-STORAGE-BINDINGS-QA.md)。云端组合与目标部署验收继续按[交付计划](DELIVERY-PLAN.md)推进。

## 证据与发布边界

- 旧 `main` 的 Web 构建从 DSH 补丁中[发现上游客户端并排除少数不适用插件](https://github.com/naturalnum/power-evolve/blob/a03460fe66a3f77114ff3bb906476105e1d470b7/clients/cloud-web/scripts/build.mjs#L13-L66)；当前构建从[明确的根列表](../cloud-web/scripts/build.mjs#L15-L33)递归依赖。这能证明两个产品组装策略不同，不能单凭根列表推断所有上游功能缺失；上表的缺口都另有具体旧入口和当前接口证据。
- 本机 S2/S5 的 `.artifacts` 中实际存在脱敏 JSON、截图/文件快照；S6/S7c 结果保留在各自私有目录。本次没有再次读取含凭据的私有配置。既有本地试用分别固定在旧切片提交，**不是**对 `5c87bcdaa7` 全功能浏览器回归的替代。[S7 集成报告](TRIAL-S7-INTEGRATED.md)只证明本提交附近的构建/自动测试、部分故障演练；其发布边界明确指出独立物理机、真实 RWX 卷、外部 PG、Ingress、生产容量与回滚尚未验收。
- 桌面适配在 [S1 试用](TRIAL-S1-NATIVE.md)后暂缓；本报告的“缺失”指云端原生 Web 对旧云端能力的差异，不把桌面托盘、更新器等桌面专属功能算成 Web 回归。

## 修复顺序建议

1. 恢复内置技能目录与包的受控分发，并重新验证 9 包及其 Runner 依赖；同时设计与目录规模一致的个人安装配额。
2. 设计可自配的多连接 MCP 能力及工具发现/调用验收；固定 whoami 保留为试用探针即可。
3. 补账号生命周期和改密码，再补 SSH 私钥、编辑/删除及工作区绑定恢复。
4. 恢复产出文件行、内联提及和文件批量下载入口，使用双用户原生浏览器回归确认。
5. 在目标生产拓扑完成 S7 发布门槛后，才能称迁移与发布均已验收。
