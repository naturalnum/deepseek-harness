# S2 B 对话产物验收

本组在原生 DSH Web 中验收编程任务的文件产出、内联发布和不可变下载。代码基线为 `b38c437820`，数据库 V26；它完成 [S2 补齐约定](S2-COMPLETION.md)的 B 组，不代表尚未实现的 C 组或 S7 生产验收通过。

## 真实流程与结果

| 场景 | 实际结果 |
| --- | --- |
| Alice 对话后开始编程 | `hi` 时没有执行记录或 Sandbox；随后真实 DeepSeek 调用云执行，在 k3s Sandbox 创建 Python 模块、测试、README 和报告，并做本地 Git 提交。3 个 unittest 通过，提交 `0c3af75`。 |
| Bob 独立编程 | Chrome 与 Alice 的应用内浏览器使用独立登录；Bob 在自己的工作区创建同名文件，2 个 unittest 通过，提交 `4ae92f4`。 |
| 每轮产出与下载 | 原调用轮显示平台核验的 4 个文件；两用户从原生列表下载各自 `report.txt`，字节分别是 `ALICE-PRODUCED-FILES-20261001` 和 `BOB-PRODUCED-FILES-20261001`，SHA-256 与 PG 保存的不可变产物及执行事实一致。 |
| 内联操作 | 修复原生 `turn/start → step/start → user/message` 的续接关联后，两个浏览器的摘要路径均显示内联按钮。Alice 内联下载原报告，Bob 内联下载 `adder.py`，字节与各自已核验版本一致。 |
| 文件变化与重复发布 | 验收程序在执行事实持久化后改动 Alice 的 README，实际页面拒绝发布并显示“源文件已变化”。恢复原字节；同一页面连续点击报告下载，PG 仍只有该次发布的一条报告产物记录。 |
| 跨用户拒绝 | 使用产品真实 HTTP 协议、对浏览器创建的实际数据核验：Bob 查询本人执行返回 200，查询 Alice 会话／执行及下载 Alice 产物返回 404，额外伪造用户字段返回 400。该项为协议核验，不冒充浏览器点击。 |
| 重启与沙盒回收 | Host／Platform 重启后，两用户历史和产物恢复。Alice 在旧 Sandbox 回收后继续原会话，在新 Sandbox 重新跑通 3 个测试、读到原 Git 提交及报告，并生成、下载 `recovery.txt`。 |
| Linux 逃逸子进程清理 | 在真实 QA Pod 内直接调用 Runner，创建 `fork + setsid`、持有输出管道并持续写文件的子进程。611 ms 后原命令结束，后代只剩不可写的僵尸状态，文件字节不再增长；后续命令 274 ms 完成并返回文件事实。该项为 Linux 组件验收，不冒充模型任务。 |

扫描按配置排除 `.git` 等目录时，页面显示部分扫描及原因，只列出平台实际重新读取核验的文件。执行回执、模型摘要及 stdout 路径不作为产物事实。产出列表的发布动作必须与展示的文件版本一致。

平台文件事实、执行结算和真实 Host／Platform HTTP／PG 组合检查已通过；后者 7 项使用明确的执行记录 fixture，不使用模型或 Sandbox。原生 Chat 异步文件来源及装配检查 157 项通过；产物客户端 Loader 14 项覆盖实际事件顺序、快照、条件发布和下一普通轮不继承关联。Runner 专项 22 项在协作者工作树通过，macOS 中只清理测试自己创建的 PID；Linux UID 清理另由上表真实 Pod 核验。相关应用与客户端类型检查、产物插件打包及云 Web 构建通过。

## 当前试用与证据

开发验收入口为 `http://127.0.0.1:19711/login`，原生 Host 为 `http://127.0.0.1:19710/native/`。账号为 `alice`、`bob`，密码仅保存在本机 `~/.config/power-evolve/shared-host-s2-produced-files-qa/users.json`，不在文档或输出中发布。两个账号使用独立浏览器会话。

1. 登录后打开已有 `workspace` 会话，核对本人的编程任务和摘要。
2. 点击原调用轮的文件产出行，或摘要中带按钮的文件路径，下载已核验版本。
3. 以另一账号重复，确认同名报告字节不同、历史只属于本人。
4. 刷新后再下载。相同请求标识的重试复用原产物；刷新后再次点击可能发起新的显式发布请求。可在 Alice 的后续复核轮下载 `recovery.txt`。

从开发 checkout 运行 `/Users/jingchao/.nvm/versions/node/v22.22.1/bin/node .artifacts/power-evolve/s2-produced-files-qa/control.mjs up|stop|status`；每次选择一个动作。控制器仅管理 19710／19711／19712，复用已有 PG 和 k3s。日志与去除凭据的数据库、浏览器、下载摘要、越权和 Linux 清理证据位于该 `.artifacts` 目录。上一组 19700／19701／19702 已停止，原 V25 和 S8 固定试用保持独立。

V26 停写备份位于本机私有目录 `~/.config/power-evolve/backups/s2-produced-files-v26-20261001-a`，包含 PG、POSIX 数据和恢复所需配置，496 项清单、停写约 1.85 秒。首次备份因专用运行身份没有 Sandbox 列举权而被拒绝；实际备份只在本 QA namespace 临时授予只读列举权，完成后已移除，Host／Platform 已恢复。两个临时 PG 库分别验证 V25 备份升级到 V26、V26 备份恢复：前者保留 11 个会话、434 个事件和 30 个操作；后者保留 2 个会话、91 个事件、7 个操作及 5 个带版本条件的产物。检查后删除临时库，原固定试用库未修改；这不是另一套完整产品恢复试用。

该入口仍属于当前开发 checkout，不是独立冻结发布版。B 留存验收证据与数据检查点，C 通过后再冻结整个 S2 试用版本，避免为每个子组长期运行一套服务。Runner `pe-s2-produced-files-runner:qa2` 是已有固定 QA 镜像加当前三个 Runner 文件的覆盖构建；完整 Dockerfile 构建因依赖下载停滞而未完成，不计作 S7 可重复发布镜像验收。独立物理节点、生产存储／入口及目标负载仍待 S7。
