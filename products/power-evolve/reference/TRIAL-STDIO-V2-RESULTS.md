## 实际通过项

- 真实隔离 PG 管理／审批／许可／结果与迁移组合 32/32；最终迁移补充测试 11/11。V34 原始任务、准备记录、执行记录的完整文本在 V35 和重复启动后不变；未来 schema 36 被拒绝。观察记录以 `json` 追加且不能修改或删除，完整 NUL、schema、页和元数据保留。
- 原动作的 worker 租约由数据库时钟认领和续期。并发同 owner 保留一个 epoch；有效 owner 不被替换，到期后接管增加 epoch，旧写入者被拒绝。保存结果时，每次变更都核验原 owner、epoch 与有效期。账户到执行记录保持同一锁序，取得租约不发放启动许可。
- 缺少独立停止证明时，即使直接子进程已关闭，也只追加观察并保留执行占用；`unknown` 保持不确定写者。完整原 Pod／Runner／任务／派发／挂载停止证明与终态匹配后，原子保存完整结果及唯一目录。配置变更、取消或账号禁用仍能保存实际终态，不能据此发布新目录。结果提交成功但回复丢失后读取原结果，目录只生成一次。
- Root 集成的私有调用通道定向回归 63/63。完整 Prepared 在私有请求前后重新核验，首次 true 在第一个等待前消费，丢回复后只 GET；GET 404 不构成停止证明。明确的 `maxTrackedActions` 限制活跃追踪数，过期后同步回收双索引，时钟回退不能恢复旧启动。容量满仍允许查询和取消，通过一个截止时间保守阻止新启动，不保存无限历史或增加常驻定时器。
- 新私有 `observe` 模式要求原事务 client。撤销后仍核验原 Workspace、完整 binding、mount slot、Pod、Runner、spec 和镜像，不重新授予执行权限。受影响捕获、结果替身及旧 TLS 回归 52/52；新增完整响应字节边界后，实际 TLS 回归 9/9。511 字节接收、512 字节拒绝并正常关闭连接，后续健康查询正常。
- 实际私有 Docker／SDK 与 PG 组合 2/2。两个新 PG 用户分别通过真实身份、独立审批、唯一许可、动作租约、私有调用和结果／目录入库完成一次 discovery。重建授权服务和调用通道后，原许可返回 false，实际 trace 确认各只有一次程序启动；UID/GID1000 无法读取 Linux root 令牌。完整 SDK 输出与 PG 结果逐项一致。

组合夹具在同一 QA 容器顺序执行两个用户，Pod、PVC 和注册表 manifest 为明确替身；它验证 PG 原始许可进入真实 SDK 执行及结果读回，不证明不同用户物理文件系统隔离、真实 k3s 调度、原生客户端、通用 call 或唯一续接。已有单独的云／桌面隔离验收范围不因本测试扩大。
