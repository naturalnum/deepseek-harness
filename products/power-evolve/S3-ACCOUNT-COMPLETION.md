# S3 账号生命周期实施约定

## 范围与完成出口

本片承接[连接器固定试用](TRIAL-S6-SSH-P24-QA.md)，补齐[完整性审计](PARITY-AUDIT.md)中的账号管理。复用原生账号插件、共享 Host 和可信平台，不新增 DSH 插件入口。管理组件与文案从旧 PowerEvolve 账号实现迁移；可信账号资产由账号包拥有，在平台 origin 提供。`application/web` 不增加产品管理页。

完成出口为管理员从原生入口开通、更新、停用、删除空账号和重置密码，个人可修改密码；新用户完成首次改密后能实际对话、使用自己的工作区。权限拒绝、旧凭据撤销、任务停用与不确定结果对账、重启不覆盖持久状态随本片验收。

## 身份与数据规则

- V25 保留已有用户 ID、密码哈希、设置、模型授权和历史；增加显示名、角色、启停状态、账号版本、凭据版本、强制改密及删除状态。已有账号迁移为普通启用账号，不自动授予管理员。
- 新账号用户名采用旧版小写 3–64 字符规则，拒绝与已有用户名大小写折叠后冲突；存量用户名和登录匹配规则不重写。用户名创建后不变，显示名可编辑。新密码沿用旧版不少于 12 UTF-8 字节，设置有界最大长度；存量密码仍可登录。
- 管理员开通、重置生成随机临时密码，只有可信响应可以显示一次，强制首次改密。个人改密验证当前密码并拒绝相同新密码。密码与管理凭据不经过 Host，不进入日志、审计摘要或普通幂等摘要。
- 所有变更携带稳定 `requestId`，更新、停用、删除与重置还携带 `expectedRevision`。重复同请求只返回原 receipt，不再次旋转密码；不同内容返回冲突。临时密码响应丢失后可查询 receipt，再明确发起新的重置，不能重放开通操作。密码参与去重时使用适合密码的验证或有密钥摘要，禁止保存可快速离线猜测的裸摘要。
- 删除仅允许没有持久业务内容、没有活跃或不确定执行的账号；有内容的账号先停用。保留内部身份墓碑与审计，不能删除历史或让种子重新创建同名身份。保护最后一个有效管理员，不能通过并发更新或删除绕过。
- 初始管理员使用独立私有配置、数据库锁和一次性初始化记录。已有库必须显式指定现有身份；配置再次读取不能覆盖密码、角色、启停或授权。种子仍仅插入新用户，不能覆盖管理员操作。

## 可信入口与协议

新增独立 `account` audience；`agent`、`approval` 凭据不能管理账号。账号页面与接口要求可信平台 origin，管理员资格在每次操作事务内检查。强制改密期间只发放可用于本人改密、状态查询和退出的受限 account 凭据，不发放 Agent 或审批权限。

| 接口职责 | 调用方与字段 |
| --- | --- |
| 本人账号能力 | Host 使用 Agent 身份查询只读能力；返回是否可管理及可信入口地址，不返回管理凭据 |
| 账号登录／本人状态／退出 | 浏览器直达平台；复用现有密码验证、登录限流和有界请求 |
| 管理列表 | account 管理员；有界分页，隐藏密码、token、连接器凭据 |
| 创建 | account 管理员；`requestId`、用户名、显示名、角色、初始设置及获授权模型 |
| 更新 | account 管理员；`requestId`、目标 ID、`expectedRevision`、显示名、角色、启停状态 |
| 删除与重置 | account 管理员；`requestId`、目标 ID、`expectedRevision`；返回可查询 receipt |
| 本人改密 | account 本人；`requestId`、当前密码、新密码；成功撤销所有旧登录凭据，当前浏览器重新登录 |

具体路由、Zod DTO、响应和错误码由身份负责人在首个基础提交中定义，作为另两组实现依据。原生账号插件提供“修改密码”“管理账号”入口；界面显示的角色只是展示，不能替代平台授权。可信页面复用旧组件和原生视觉，不另做产品外壳。

## 撤销、任务与执行

| 动作 | 登录与任务语义 |
| --- | --- |
| 修改／重置密码 | 原子更新密码与凭据版本，撤销所有旧 agent／approval／account 凭据。已受理任务保留原 grant；不把浏览器登出等同于停止远端任务。重置后须先完成改密才能新登录产品。 |
| 停用 | 拒绝登录、新输入、新任务领取、新审批与新派发；围栏旧 grant、终结排队输入，请求取消运行中的执行。 |
| 停用后对账 | 平台继续观察原执行、保存终态并清理资源。缺少确定结果时保留 uncertain；不得重发外部效果或在停用期间自动启动 Agent 续接。 |
| 再启用 | 要求新登录；旧 token、grant 和停用前排队输入不能自动恢复。历史及对账结果仍可读取。 |

登录签发、exchange、持久受理与新派发必须在适用事务内重查当前账号状态和版本。统一用户锁与资源锁的顺序；不能让停用与登录、claim 或 dispatch 之间留下已检查后再授权的窗口。执行负责人提供事务内停用与持久取消入口；清理、结果观察和停止证明不依赖已撤销的用户登录权限。

云沙盒继续使用原 Pod UID 和挂载停止证明；SSH、MCP、STDIO 复用各自派发、取消和对账状态机。不能以账号已停用代替旧进程已停止。现有桌面路径保持撤销语义，桌面功能扩展仍暂缓。

## 文件所有权与集成次序

| 负责人 | 独占范围 |
| --- | --- |
| 身份负责人 | 新账号 DTO、V25/schema/database 接线、identity、account-settings、账号服务/bootstrap/路由、身份与迁移回归。先提交共享基础再实现完整服务。 |
| 执行负责人 | TaskStore、执行／Sandbox／SSH／MCP／Device 的账号派发检查、停用围栏和取消／对账；新增账号撤销协调模块与定向回归。不得另改 schema。 |
| 客户端负责人 | client-account 的旧组件迁移、原生菜单、可信账号资产、文案与组件回归；不修改平台接线或共用 DTO。 |
| 集成者 | 平台与 Host composition、Profile／配置／备份／部署接线、根构建门禁、文档及真实验收；负责解决共享接口争议。 |

各组保留原分支，从本片基线创建独立开发分支；固定 MCP、SSH、S8 试用 checkout 禁止用作开发。首个基础提交固定接口和锁顺序后再并行集成；不同时启动多套测试服务、不运行全仓构建或安装依赖。测试复用现有 PG 的独立临时库，真实试用使用独立 V25 库，不能迁移固定试用库。

## 六组验收

1. V24→V25 保留历史和授权；两个平台并发 bootstrap 后管理员唯一；变更后重启与旧种子不恢复旧密码、角色或启停状态。
2. 管理员从原生入口创建新用户，新用户只能先改密，随后真实模型对话和私有工作区文件操作成功；两账号互不可读。
3. 普通账号、管理员 Agent 凭据、approval 凭据、错误 origin、伪造目标身份均不能越权管理；最后管理员保护及并发更新成立。
4. 本人改密后两个 Host 的旧登录、原生 follow 与审批凭据失效；旧密码失败、新密码成功，其他用户不受影响，已受理任务按约定继续。
5. 重置、更新、删除空账号的重复请求及响应丢失可查询，不重复变更；有内容账号删除拒绝；连接器密钥、设置和历史不受密码变更影响。
6. 停用覆盖排队输入、待审批／待派发动作和真实运行中的云／SSH 执行；无新派发，清理有实际证据，不确定效果不重放；重启和再启用不复活旧输入或旧 grant。

代码回归中的模型／Runner 替身单独标明；真实浏览器、PG、模型及涉及的集群路径另行验收。通过后固定独立试用，再进入文件与产物补齐。
