# S6 controlled MCP transport

`src/platform/mcp-transport.ts` is a Platform-only leaf implementation. `discoverMcp(target, options)` returns the SDK's raw tools, first-page metadata, and a complete bounded directory without `nextCursor`; zero tools is valid. `callMcp(target, { name, arguments }, options)` freezes JSON arguments before discovery and returns the SDK's original `CallToolResult`, including `isError`. Identity, stored configuration versions, catalog comparison, input-schema validation, approvals, PostgreSQL, and durable continuation remain with the caller.

`options.onBeforeDispatch({ toolName, catalog }, signal)` receives the full current directory after handshake and immediately before the unique `tools/call` HTTP request. The caller commits its one-use dispatch intent in this callback. Throw `McpDispatchRejected` only after confirming no intent was issued; it produces `code=dispatch_rejected` and `dispatched=false`. Other callback errors produce `code=callback_uncertain` and `dispatched=true`. Cancellation while a callback is pending is also conservative: the database may already have committed. Neither late callback completion nor any retry can send a request after cancellation. `dispatched` records possible intent issuance, not confirmed remote execution; the outer layer queries its durable action record before deciding the terminal state. Error messages contain only their fixed code and no endpoint, credential, argument, response text, or nested cause.

Each operation creates a fresh official MCP SDK 2.0 Client. Public `Client.request` uses Standard Schema adapters after the SDK's protocol decoding. Official SDK schemas validate known fields while the adapters retain original descriptor and result extensions, including nested content metadata; missing legacy call content keeps the SDK's empty-array default. Modern wire requirements remain enforced by the SDK. `request` avoids `callTool`'s automatic `HEADER_MISMATCH` retry; the HTTP adapter independently blocks a second `tools/call` attempt. SSE reconnect, authorization refresh, scope escalation, redirects, schema fetching, and resource fetching are disabled. Session deletion is best effort within the remaining deadline; local streams, requests, and sockets are always closed and awaited. A deletion failure cannot replace a known result.

Network policy belongs to the operator. The default permits HTTPS and public unicast addresses; mapped IPv6 is classified as IPv4, IPv6 must be in global unicast space, and every DNS answer is checked before opening sockets. An `internalExceptions` entry names an exact origin, exact approved IP addresses, optional CA, and optional `allowHttp`. Every answer must belong to that entry. Resolution happens once per operation; native Node sockets use the selected approved IP while TLS retains the original hostname and SNI verification. Native `http`/`https` with a separate Agent ignores ambient proxy settings. User headers cannot override routing, framing, proxy, cookie, MCP session, or connection headers; duplicate casing, control characters, excessive count, and excessive bytes reject before network access.

The caller supplies all `McpTransportBudgets` fields: total `timeoutMs`, socket `idleTimeoutMs`, `maxRequestBytes`, per-response `maxResponseBytes`, operation-wide `maxTotalResponseBytes`, `maxResponseHeaderBytes`, `maxRequests`, `maxHeaderBytes`, `maxHeaders`, `maxPages`, `maxTools`, and `maxCatalogBytes`. Limits are finite positive integers; idle timeout cannot exceed the total timeout, and per-response bytes cannot exceed total response bytes. Handshake, pagination, background stream, call, and cleanup share the same deadline and byte counters. No partial or truncated directory is returned.

## Focused validation

Compile the two leaves using the repository TypeScript compiler, then run the dedicated Node test:

```sh
pnpm exec tsc --ignoreConfig --strict --noUncheckedIndexedAccess --exactOptionalPropertyTypes --noUnusedLocals --noUnusedParameters --types node --target es2024 --module nodenext --moduleResolution nodenext --rewriteRelativeImportExtensions --esModuleInterop --skipLibCheck --outDir products/power-evolve/application/lib/platform products/power-evolve/application/src/platform/mcp-network.ts products/power-evolve/application/src/platform/mcp-transport.ts
node --test products/power-evolve/application/tests/s6-mcp-controlled-transport.test.mjs
```

The fixture creates a temporary certificate and a real loopback TLS listener on an allocated port. It covers legacy and modern protocol negotiation, parameterized tools, raw pagination, zero tools, Bearer/custom/no authentication isolation, NUL/Unicode and unknown nested extensions, invalid known-field rejection, modern cache metadata requirements, legacy content defaults, exact response-byte limits, stream overflow, deadlines, malformed and truncated responses, certificate rejection, all-answer DNS policy, mapped addresses, socket pinning and SNI, explicit HTTP exceptions, redirect denial, proxy environment isolation in a child process, callback rejection, lost commit acknowledgement, pending cancellation with late callback completion, and one-use dispatch under attempted SDK replay. Every listener, child, temporary file, request, and socket has owned cleanup. The tests use deterministic protocol fixtures; they do not establish a real external service, native-client workflow, PostgreSQL approval recovery, or live-model acceptance.
