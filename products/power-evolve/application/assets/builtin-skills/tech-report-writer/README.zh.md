# 技术报告 Word 准备

[English](README.md) | 中文

本 Skill 将已审核报告转换为 Word 并校验版式。[SKILL.md](SKILL.md) 定义完整生成流程与视觉检查要求。

## 已审核 Markdown 输入

提供 `source_report` 时，已审核 Markdown 是摘要、章节、参考文献与附录的唯一来源；来源不可读或不完整时不得选取旧产物。前置中英文双语题名须分别匹配本版 `word_metadata.title_cn` 和 `title_en`。两个题名均位于报告各节之前；其他额外一级标题仍不受支持。

Markdown 可在正文与后置部分之前包含一个非空的 `# 目录` 或 `## 目录` 节。其条目不会成为摘要文本或额外 Word 章节。Word 模板根据已审核标题生成带实际页码的目录。

参考文献来源说明放入连续编号的附录，例如在附录 A 之后使用 `# 附录 B 参考文献来源与获取链接`。其文字与从 `[n]` 连续编号的正式参考文献条目分开保留。

## 图题与表题

目录标记、段落排版与校验使用同一题注规则：带编号的标题须具有 Caption 样式、直接居中属性或相邻的图/表对象。普通正文中的图表引用保留原文和正文排版。真正题注必须带有对应目录的 TC 域；普通正文段落中的 TC 域会被拒绝。续表标题保留题注排版，不重复加入目录。

## 段落行距

中英文摘要正文和关键词使用 12 pt 字体、1.5 倍行距，并关闭段落网格对齐。正文和参考文献也关闭段落网格对齐。分节网格继续供其他内容使用；这些段落属性可防止继承网格的取整行为扩大指定行距。

## 原生公式渲染

源 DOCX 保留原生 OMML 公式。在 LibreOffice 分页和 PDF 导出之前，临时排版副本将分隔符字符属性按起始符、分隔符和结束符排序，以适配顺序读取的 Math 导入器。分隔符取值、显式空结束符、公式内容及其他属性保持不变。

## 命令失败

校验、生成或排版命令失败时返回 `blocked`，不返回 Word 产物。`error` 对象记录失败命令阶段、`returncode`、实际 `data_dir`，以及捕获的 `stdout` 和 `stderr` 各自最后 4096 个 UTF-8 字节，并附总字节数和截断标记。失败前保存的 DOCX 仍是不完整输出，须待生成和校验通过。

## 验证

[适配器回归](tests/test_orchestration_adapter.py) 覆盖确定性准备、严格拒绝和 Word 段落/表格读回。它们不能证明 LibreOffice 分页或逐页视觉验收通过；这些检查仍属于实际 Word 流程。

[题注回归](tests/test_captions.py) 使用合成 DOCX 验证标记、排版和结构校验，包括题注缺少 TC 域及正文错误附带 TC 域。

[行距回归](tests/test_format_layout.py) 读回合成 DOCX，检查中英文摘要及关键词，保留文本、字体、指定行距和分节网格。实际渲染行距仍须逐页视觉检查。

[分隔符回归](tests/test_layout_math_delimiters.py) 使用合成 OMML 检查绝对值竖线、开放分段式、嵌套分隔符和分页副本隔离。测试替代 UNO 子进程；实际 Math 导入与 PDF 符号仍须在 Word 渲染流程中检查。
