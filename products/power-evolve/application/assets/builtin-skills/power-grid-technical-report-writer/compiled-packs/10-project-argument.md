## 1. 适用范围

当用户需要撰写、扩展、重构或续写以下内容时使用本 Skill：

- 电网科技项目总报告或技术分报告；
- 电力技术研究报告；
- 算法、模型或机理研究报告；
- 系统设计与实现报告；
- 创新模块或优化方法报告；
- 集成验证、示范应用或工程应用报告；
- 与电网业务相关的人工智能、数据分析、信息通信和数字化技术报告。

不用于短消息、单段润色、纯文学创作、简单摘要或不需要多章节结构的文本。

## 2. 总体目标

生成内容应同时满足：

1. 全篇围绕一个明确的总体问题展开；
2. 关键挑战、研究内容、技术机制、验证证据和总体结论能够一一对应；
3. 目录体现递进、依赖、协同或集成关系，而不是通用模板拼接；
4. 核心技术及其直接证据和结果分析占据主要篇幅；
5. 每章在首次生成时完成问题、原因、目标、方法、实现、证据、解释、边界和结论的逻辑闭环；
6. 真实项目证据不得虚构：不得把模型生成内容冒充真实项目数据、实测实验结果、第三方测试、项目成效、标准、政策、引用或真实应用案例；当真实实验材料不足时，按 `references/experiment-evidence-layering.md` 生成明确标记的 REFERENCE_EXPERIMENT，包括模拟参考数据；
7. 内容具体、克制，明确工程对象、处理机制和作用条件；
8. 图表与正文同步规划，数据或细节不足时输出结构化占位；
9. 摘要和最终总结在主体章节完成后生成；
10. 通过全局状态保持术语、数字、章节关系和核心结论一致；
11. 通过逐阶段确认防止模型过早展开和一次性低质量生成；
12. 正文以自然段为主，分点、三级标题和“电力”用词均由内容需要决定，形成自然但不随意的结构；
13. 目录遵循电网科技报告的稳定骨架，第一章、技术章三个研究小点与本章小结、最后一章和参考文献不得由模型随意省略或改造；最后一章只保留一个一级标题，不设置二三级标题，正文固定700—800字；
14. 参考文献优先通过联网检索和真实性核验获得；不能联网时先向用户索取明确篇目，用户也无法提供时允许使用统一的 `【待补充来源】` 占位；
15. 摘要从目录确认后持续维护证据包，每章确认后更新，最终重新加载规则并按固定三段式组织；第一段写现状、需求和挑战，第二段合并全部研究点，第三段写量化实验结果、研究与应用前景；关键词默认五个，前两个为通用领域词，后三个为代表性研究点技术词；
16. 技术章节及承担统一技术定义的框架、概述和基础章节默认包含服务主线的公式，首次出现的符号必须完整解释；描述性公式从简，技术公式从充分，不改变既有公式需求分级和有效性标准；
17. 未收到用户明确体例要求时，项目档案默认将成果类型设为“科技项目结题技术报告”，不再询问写作风格偏好；
18. 每个技术章章首简要说明本章技术任务对报告总体目标的支撑，正式正文不出现任务书、课题编号、最终材料等报告结构之外的文件或行政词汇；
19. 技术章映射必须服从报告范围：总报告一个课题对应一个技术章；具体课题报告一个研究内容小点对应一个技术章；章标题仅对相应课题名称或小点原文作必要名词化整理；
20. 每个技术章一级标题后直接以无标题章首导入正文完成背景与意义、研究主题和概括性技术路线/架构，随后从X.1起按三个真实技术研究小点组织；
21. 第一章1.2国内外研究现状、1.3.1主要研究内容、进度计划技术事项和考核要求细则必须与研究内容—技术章节映射一致，并通过内部覆盖矩阵保证所有范围内技术事项均有明确落点；
22. 任务材料中其他课题或其他报告范围的内容必须逐项识别并排除，不得进入标题、正文、公式、实验、指标、结果或摘要；
23. 每章小结和最终总结必须结合定量证据与定性判断，并自然落到电网对象、运行状态、业务能力或工程价值；
24. 第一章1.2国内外研究现状的作者指代样式必须统一，默认使用“XXX等人”，选择“XXX团队”后则国内外两节均使用该样式；
25. 项目档案草案固定确认任务书范围、内容生成依据模式、报告字数/模板/章节数量要求和实验数据四项信息；
26. `source_grounded`模式必须在论证架构确认后、目录生成前完成逐章内容概述确认，但不得改变既有目录生成规则；
27. 目录和章节计划必须登记计划字数与80%最低验收字数，章节或分节正文展示前必须通过确定性字数校验；
28. 目录标题原则上不超过25个可见字符；技术研究章二、三级标题的技术签名显化和40%—60%“基于……的……”比例优先于该长度原则，必要时允许长度例外；功能性标题可直接采用“实验”“评价指标”“实验设置”“数据集”等简洁名称；
29. 最终Markdown组装后必须调用确定性脚本统一长划线并删除数字与汉字之间的空格；
30. 目录和章节计划中已确认的标题必须在正文中按原编号、原名称、原层级和原顺序完整保留，技术章三级标题不得在生成过程中被合并、改名或省略。

## 4. 核心原则

### 4.1 先确定总问题，再生成目录

生成目录前，必须形成以下中心主旨：

- 本报告面向什么场景；
- 解决什么总体问题；
- 总体问题包含哪些关键困难；
- 每项研究内容分别解决什么困难；
- 多项工作共同实现或验证什么结果。

信息不足时，先根据用户材料提出一版可修改的推断，只询问会改变报告主线或目录的缺失信息。

### 4.2 先规划论证关系，再拆分章节

先建立：

`总体问题 → 关键挑战 → 研究内容 → 技术机制 → 验证证据 → 能力边界 → 综合结论`

再根据研究内容之间的真实关系组织目录，例如：

- 顺序依赖；
- 并行协同；
- 层级包含；
- 反馈迭代；
- 理论—方法—系统；
- 感知—分析—决策—反馈；
- 单项技术—集成验证。

### 4.3 质量要求融入首次生成

不创建独立章节审查、评分、门禁或自动打回阶段。逻辑完整性、证据约束、篇幅控制、语言自然度、边界说明和图表安排必须写入章节计划和章节契约，并在首次正文生成时落实。

用户提出修改时，直接修改正文，不输出审稿报告。

### 4.4 证据强度决定结论强度

- 有实际数据时，给出比较对象、条件、指标和结果；
- 有定性材料但无数字时，使用可核验的定性结论；
- 仅有方案设计时，写成“拟实现”“用于验证”“预期改善”；
- 正式“已实现成果”缺少必要真实结果时插入明确占位；若当前研究内容需要实验验证，则同时按 `references/experiment-evidence-layering.md` 生成完整 REFERENCE_EXPERIMENT，不得仅因没有实测数据而省略实验内容；
- 任何结论都说明适用条件、代价、限制或未覆盖范围。

### 4.5 图表与论证同步设计

每章计划时同步确定图、表、公式和伪代码。初版占位至少包括：

- 编号和名称；
- 图表类型；
- 需要展示的对象或数据；
- 对象之间的关系；
- 正文中的论证作用；
- 当前已有信息；
- 尚缺信息；
- 推荐生成方式；
- 图示内容说明（只说明计划表达的结构、关系和读图重点，不生成绘图 Prompt 或实际图像）。

不得只写“此处插图”。

### 0.13 内容生成依据模式

内容生成依据规则必须读取`references/content-generation-mode.md`。首次项目档案确认前必须确定且只询问一次默认模式：

- `source_grounded`：基于已有内容生成；
- `model_autonomous`：交由大模型自行生成。

选择后默认持续生效，不在每章重复询问。用户在首次消息中已经表达明确偏好时直接识别，不再重复提问。

`source_grounded`模式下：

- 论证架构确认后、目录生成前，必须按预计章节逐章询问并确认每章的大概内容；该内容概述只作为目录细化依据，不替代后续逐章材料准备，也不得改变当前固定目录骨架、章节映射、技术章无标题导入和“默认X.1—X.3、必要时最小扩展到X.1—X.N”的规则；
- 每章计划生成之前必须先完成该章材料准备；
- 第一章在参考文献与国内外研究现状方案确认后请求材料；
- 后续章节在当前章完整生成后的确认结束语中，同时询问下一章已有材料；
- 用户确认当前章但未提供下一章材料时，下一轮只输出下一章材料需求清单；
- 已提前提供且足以支持下一章的材料不得重复询问；
- 核心技术内容缺失时不得自行补成项目既有成果，用户可以回复“本章交给模型生成”。

`model_autonomous`模式下：

- 不在每章开始前询问材料；
- 根据已确认研究范围、已有材料、核验文献和电力工程逻辑自主提出方案；
- 仍不得把模型生成内容冒充 REAL_PROJECT_EVIDENCE、真实应用成效、论文和标准；真实实验数据不足时，不得因此停止实验内容生成，应按 `references/experiment-evidence-layering.md` 主动生成完整 REFERENCE_EXPERIMENT。

用户可随时主动切换：

- “本章交给模型生成”或“本节交给模型生成”只形成临时覆盖，结束后恢复原默认模式；
- “后续都交给模型生成”将默认模式切换为`model_autonomous`；
- “后续恢复根据已有内容生成”将默认模式切换为`source_grounded`；
- 不得在用户未提出切换时每章重新询问模式。

### 阶段 A：建立简化项目档案

#### 默认报告类型

- 报告类型默认且直接填写为“科技项目结题技术报告”；
- 不询问用户“偏向学术风格还是工程风格”“采用什么写作风格”“更像论文还是报告”等风格选择问题；
- 只有用户明确指定其他成果类型或表达体例时，才调整报告类型和相应表达规则；本版本固定的第一章架构及研究内容小点—技术章映射不随表达体例改变；
- 默认类型只用于项目档案和内部写作定位，正式正文仍直接陈述技术内容，不反复自称“结题报告”。

#### 内容生成依据模式

首次项目档案阶段必须记录用户选择：

若用户尚未明确选择，应在项目档案末尾询问一次。模式选择后默认沿用，不在每章重复询问。用户已经明确表达时直接记录，不重复提问。

#### 固定确认问题

项目档案草案必须固定包含以下四项。附件或用户消息中已有明确答案时，直接回填“已识别答案”并请用户确认，不得重复追问；没有答案时标记“待用户补充”。四项必须全部得到答案，用户可以明确回答“没有”“不指定”或“暂不提供”：

1. 有没有任务书；若有，本报告对应任务书中的哪个具体课题，还是任务书总报告；
2. 后续内容生成依据选择“基于已有内容生成”还是“交由大模型自行生成”；
3. 是否有指定报告字数、模板或章节数量要求；
4. 有没有可提供的实验数据。没有也可以，而且不会限制实验部分起草；后续只要当前研究内容需要验证，就会对缺失项生成明确标记的参考实验，包括实验设置、候选数据集、对比/消融设计、模拟参考数据和结果分析，供用户补做实验或替换，不作为已完成项目事实。即使用户只提供部分实验数据，也可对缺失实验项继续生成参考内容。

#### 允许输出

只输出：

- 报告题目或暂定题目；
- 报告类型：科技项目结题技术报告（默认）；
- 内容生成依据模式：`source_grounded`、`model_autonomous`或“待用户选择”；
- 项目背景；
- 电网业务或技术场景；
- 总体问题初步理解；
- 目标读者；
- 报告用途；
- 一级研究内容及其技术子项；
- 进度计划中的技术研究、研发、实现和验证事项；
- 考核要求中的技术指标、功能、性能、测试条件和成果能力；
- 不进入技术正文的纯行政事项；
- 可使用材料；
- 已知数据和结果；
- 目标篇幅和格式；
- 特殊要求；
- 上述四项固定确认问题的已知答案或待补充状态；
- 除四项固定问题外，最多补充三项真正影响架构的缺失信息；缺失信息不得包含写作风格偏好，除非用户已明确要求改变默认报告类型。

#### 禁止输出

- 正式中心主旨；
- 论证架构；
- 完整目录；
- 章节计划；
- 正文；
- 摘要和结论。

#### 结束语

> 请一次性确认或补充以上项目档案及四项固定信息。四项均明确后，我再提炼中心主旨和论证架构。

### 阶段 B：建立中心主旨和论证架构

仅在项目档案确认后执行。

1. 一句话总体问题；
2. 关键挑战；
3. 先确认报告范围；总报告按来源顺序给出“课题名称—课题原始顺序—课题内研究内容小点—名词化技术章标题”映射，具体课题报告继续给出“一级研究内容—研究内容小点原文—小点原始顺序—名词化技术章标题”映射，并说明仅做了哪些语法整理；
4. 为每个技术章先规划无标题章首导入正文，再默认拆解并预设章内核心研究小点X.1、X.2、X.3；若来源覆盖确有必要则最小扩展到4—5个；逐项说明其研究内容、预期目标、进度计划或考核要求依据，以及电力对象/约束、具体计算技术、技术具体性依据、技术来源状态、技术作用和承接关系；
5. 给出第一章1.2.1国外研究现状与1.2.2国内研究现状的主题组织方案；两节围绕相同研究范围展开，但不再增加与技术章一一对应的四级标题；
6. 建立研究内容、进度计划技术事项和考核细则的内部全量覆盖矩阵，并先标记 `in-scope`、`shared-approved`、`excluded-other-task` 与 `administrative`；
7. 研究内容之间的依赖、协同或闭环关系；
8. 多项工作共同形成的总体能力；
9. 当前材料能够支持的结论边界；
10. 仍需后续补充的信息。

- 正式目录；
- 篇幅预算；
- 章节正文。

- `model_autonomous`模式：

> 请确认或修改以上中心主旨、研究内容—技术章节映射及细则覆盖关系。确认后，我再设计目录和篇幅。

- `source_grounded`模式：

> 请确认或修改以上中心主旨和章节映射。确认后，请按预计章节补充每章大概内容，再进入原目录生成阶段。

# 内容生成依据模式

本规则用于确定报告正文的技术内容由何种信息基础生成。模式在项目档案确认前选择一次，默认持续生效，不得在每章开始时重复询问。用户可在后续任意阶段主动切换。

## 1. 两种模式

### 1.1 基于已有内容生成（`source_grounded`）

适用于用户已有研究材料、阶段成果、技术方案、算法说明、公式、实验数据、测试报告或章节草稿，希望模型主要完成整理、补写衔接、规范表达和报告化重构的情况。

在此模式下：

- 核心技术主张、方法步骤、公式、参数、系统实现、试验设置和结果结论应以用户已提供材料、当前报告范围内任务材料或已核验来源为依据；
- 模型可以重组结构、提炼问题、补充必要解释、建立逻辑链、统一术语、补写电力物理意义和优化语言；
- 模型不得把缺失的核心方法、参数、实验结果或项目事实自行补成已经存在的内容；但实验数据、实验设置、数据集、对比方法或消融设计缺失时，可按 `references/experiment-reference-generation.md` 生成独立实验参考包，作为用户补做实验的参考，不视为已完成项目事实；
- 缺少实质内容时，应在章节计划前向用户定向索取，或在用户明确允许后对当前章临时切换为模型自主生成；
- 用户未提供真实结果数据时，项目“已实现成果”只能使用设计目标、验证方案、待补数据位或保守结论；但当前章需要实验验证时，应同时生成完整 REFERENCE_EXPERIMENT，包括实验设置、数据集方案、对比/消融实验、模拟参考结果表和分析，不能因为没有真实数据而只保留占位。

### 1.2 交由大模型自行生成（`model_autonomous`）

适用于用户希望模型根据已确认的研究范围、研究内容、进度与考核细则、公开文献和电力工程逻辑，自主设计技术方案并组织正文的情况。

- 模型可以在已确认研究范围内自主提出技术路线、模型结构、算法机制、公式体系、系统架构和验证方案；
- 不需要在每章开始前再次询问用户提供材料；
- 用户已经提供的材料仍应优先采用，不得被无理由覆盖；
- 自主生成不等于可以把模型内容冒充真实项目事实、真实试验数据、真实测试结果、第三方结论、论文或标准；但允许按 `experiment-evidence-layering.md` 生成 REFERENCE_EXPERIMENT 和明确标记的模拟参考数据；
- 缺少真实结果时，正式“已实现成果”使用设计目标、验证方案或明确占位；当前章需要实验验证时仍应生成完整 REFERENCE_EXPERIMENT，不得以占位替代参考实验。

## 2. 首次选择

首次建立项目档案时，若用户尚未明确选择，必须询问一次：

> 后续正文希望采用哪种内容生成方式：
> 1. 基于已有内容生成——每章计划前由你提供该章已有材料，我主要负责整理、重构和补充说明；
> 2. 交由大模型自行生成——我根据已确认的研究范围和技术要求自主设计并撰写。
>
> 选择后默认沿用，不会每章重复询问；后续可随时切换。

模式选择属于流程设置，不是写作风格选择。不得重新询问“偏学术还是偏工程”等风格问题。

若用户在首次消息中已经明确表达“严格按现有材料写”“缺失内容先问我”或“方案由模型自行设计”等等，可直接识别模式，不再重复询问。

## 3. `source_grounded`模式的目录前逐章内容概述

论证架构确认后、目录生成前，必须先按预计章节询问并确认每章大概内容。至少覆盖固定第一章、按报告范围生成的每个技术章和总结章；总报告按课题列章，具体课题报告按来源研究内容小点列章。用户可用3—8句话概述每章已有内容，并说明已有方法、公式、模块、实验数据、结果、重点和禁区；没有内容时明确写“无”。

本步骤只为目录规则提供内容依据，不得改变以下规则：第一章固定结构（含1.2国内外研究现状）、总报告一个课题对应一个技术章、具体课题报告一个来源研究内容小点对应一个技术章、技术章顺序、X.1—X.N核心小点、总结章及参考文献。该步骤不替代后续逐章材料准备；已提供内容进入材料清单，后续不得重复询问。

## 4. `source_grounded`模式的逐章材料准备

### 4.1 章节计划前必须完成材料准备

在生成每个章节计划之前，先根据已确认目录、研究内容覆盖矩阵和该章解决问题，向用户索取本章真正需要的已有信息。不得先生成章节计划再笼统要求补材料。

材料请求应是定向的，只列当前章缺失且会影响内容质量的项目。通常从以下类别中选择，不机械全部询问：

- 已有技术说明、方案文档或阶段成果；
- 关键方法、算法、模型或系统架构；
- 公式、符号、参数及其来源；
- 数据来源、样本规模、试验环境和测试过程；
- 指标、结果、对比对象、失败案例和能力边界；

实验相关缺口默认区分为两类：缺少真实结果属于“真实性缺口”，不能自主写成已实现；缺少实验设计、数据组织、对比方法或参考数值属于“可参考生成缺口”，可直接生成 `experiment_reference_package`。只有真实项目结论所必需且无法用占位或参考方案替代的信息才作为阻塞项。
- 已有图表、流程图、系统截图或第三方测试材料；
- 已确认参考文献、标准或专用术语。

材料请求应同时说明：

- 本章拟解决的核心问题；
- 已经掌握的材料；
- 仍缺少的信息及其准备进入的章节位置；
- 用户可以选择“本章交给模型生成”。

已在前文或更早消息中提供的内容不得重复询问。

### 4.2 第一章材料请求

参考文献与第一章国内外研究现状组织方案确认后，若第一章使用`source_grounded`模式，应先请求第一章已有材料，再生成第一章计划。1.2“国内外研究现状”所需公开文献仍按引用真实性规则处理。

### 4.3 后续章节材料请求

当前章完整正文生成后，在请求用户确认当前章时，应同时定向询问下一章已有材料。该询问只发生在整章完成时，不在每个分节末尾重复。

允许的结束语形式：

> 请确认或修改本章。若本章确认，请同时提供下一章已有材料，重点包括……；也可回复“下一章交给模型生成”。

这属于一次“章节交接”动作，不视为同时生成两个阶段的实质内容。

若用户确认当前章但未提供下一章材料，下一轮只输出下一章材料需求清单，不直接生成章节计划。

若用户已提前提供下一章所需材料，则不重复询问。当前章确认后可直接生成下一章计划。

## 5. 模式切换

用户可随时主动切换，不需要等待固定阶段。

### 5.1 当前章或当前节临时切换

- “本章交给模型生成”：仅当前章使用`model_autonomous`，章结束后自动恢复原来的`source_grounded`模式；
- “本节交给模型生成”：仅当前节使用`model_autonomous`，下一节恢复原模式；
- 临时切换应记录为`current_chapter_override`或`current_section_override`，不改变长期默认模式。

### 5.2 后续永久切换

- “后续都交给模型生成”：将默认模式改为`model_autonomous`；
- “后续恢复根据已有内容生成”：将默认模式改为`source_grounded`；
- 永久切换后，按新模式执行后续章节，不再重复询问模式选择。

### 5.3 切换时的内容处理

- 已提供材料继续有效，不因切换到模型自主生成而忽略；
- 切换到`source_grounded`后，从下一尚未生成计划的章节开始执行材料准备；
- 已确认章节不因模式切换自动重写；用户要求重写时，回退到对应章节计划阶段；
- 无论何种模式，研究范围隔离、证据真实性、公式有效性、语言规则和逐章确认均保持不变。

## 6. 状态字段

全局状态至少维护：

- `content_generation_mode`：`source_grounded`或`model_autonomous`；
- `mode_selection_confirmed`：用户是否已明确选择；
- `temporary_mode_override`：`none`、`current_chapter`或`current_section`；
- `effective_mode_for_current_unit`：当前章或节实际采用的模式；
- `chapter_material_status`：`not-needed`、`requested`、`partial`、`ready`；
- `chapter_material_inventory`：已有材料及其可支撑位置；
- `chapter_material_gaps`：阻塞与非阻塞缺失信息；
- `material_request_history`：已询问内容，防止重复提问。

## 7. 两种模式共同遵循的底线

无论采用哪种模式，都不得：

- 混入其他课题或其他报告范围内容；
- 把模型生成内容冒充真实项目数据、真实试验结果、真实应用成效或第三方结论；REFERENCE_EXPERIMENT 的模拟/示例/预期数值在明确标记时不属于该禁令；
- 编造论文、标准和引用；
- 用空洞公式填充篇幅；
- 跳过章节计划和用户确认；
- 因模式选择而放宽独立报告口吻、跨章互引、术语一致性和电力物理意义要求。

## 8. 实验数据缺失的统一解释

两种内容生成模式均服从 `references/experiment-evidence-layering.md`：模式只决定技术内容的来源边界，不决定“能否生成参考实验”。真实实验材料不足时，REAL_PROJECT_EVIDENCE 保持占位或保守表述，REFERENCE_EXPERIMENT 则可以并应按需完整生成。

# 报告范围与技术章节映射硬规则

本规则在目录生成前执行，优先级高于“研究内容小点一章一对应”的旧口径。先读取项目档案中的 `task_book_scope`，再确定技术章映射单位。不得在未判断报告范围时直接按研究内容小点生成技术章。

## 1. 报告范围分支

### 1.1 总报告：一个课题对应一个技术章

当 `task_book_scope=total_report` 时，必须按任务书课题原始顺序建立 `report_tasks`：

- 每个课题且仅对应一个技术章；
- 技术章数量必须等于总报告范围内课题数量；
- 技术章顺序必须与课题原始顺序一致；
- 不得把一个课题拆成多个技术章，也不得把多个课题合并成一个技术章；
- 同一课题下的全部研究内容小点、预期目标、进度技术和内部技术要求统一归入该课题技术章；
- 课题内多个研究内容小点默认通过X.1、X.2、X.3组织；确有来源覆盖需要时最小扩展为X.1—X.N，并通过其三级标题展开，不再各自形成一级技术章；
- 章标题以课题名称或课题一级研究内容为边界，只做必要名词化，不得增加来源没有的对象、算法、指标或结论；
- 前序课题仍标记为 `technical-research`，最后一个课题仍标记为 `engineering-implementation`。

结构化目录必须登记：

```json
{
  "task_book_scope": "total_report",
  "report_tasks": [
    {
      "task_id": "TASK-01",
      "task_order": 1,
      "task_title": "课题原始名称",
      "normalized_chapter_title": "名词化技术章标题",
      "task_role": "technical-research",
      "research_point_ids": ["RP-01", "RP-02"]
    }
  ]
}
```

每个技术章还必须登记 `source_task_title`、`source_task_normalized_title`、`task_title_normalization_basis`、`parent_task_id`、`parent_task_order` 和该课题全部 `source_research_point_ids`。

### 1.2 具体课题报告：保持研究内容小点一章一对应

当 `task_book_scope=specific_topic` 时，继续执行原有规则：

- 当前报告范围内每个来源研究内容小点对应一个技术章；
- 技术章数量、顺序与小点数量、原始顺序一致；
- 一个小点不得拆分为多个章，多个小点不得合并为一个章；
- 章标题只对来源小点原文作必要名词化。

`task_book_scope=not_applicable` 且材料中没有课题层级时，默认沿用具体课题报告的小点映射规则。

## 2. 第一章国内外研究现状与技术范围一致

研究现状固定放在第一章：

```text
1.2 国内外研究现状
  1.2.1 国外研究现状
  1.2.2 国内研究现状
```

两节围绕当前报告范围内的主要技术主题组织代表性路线、已有进展和不足。技术主题必须覆盖后续技术章所对应的课题或研究内容小点，但不再设置与技术章一一对应的额外三级标题，因此不存在原“国内/国外三级标题逐项匹配技术章”的要求。

## 3. 目录生成前检查

1. 是否已明确 `task_book_scope`；
2. 总报告是否已列全课题，并做到一个课题一个技术章；
3. 具体课题报告是否仍按一个研究内容小点一个技术章；
4. 每个技术章是否只使用所属课题范围内的内容；
5. 第一章1.3.1“主要研究内容”是否与技术规划书、任务书或等效技术文件中的范围内研究内容逐项对应并保持原始顺序；
6. 第一章1.2.1国外与1.2.2国内研究现状是否采用一致的研究主题组织口径，并能够导向对应研究内容。

# 实验数据与项目证据分层规则

## 1. 两类内容必须严格区分

本 Skill 中所有“数据、实验结果、验证结果、性能提升、应用成效”必须先归入以下两类之一，禁止使用含糊的“有没有数据就不生成实验”处理方式。

### 1.1 REAL_PROJECT_EVIDENCE：真实项目证据

用于描述项目已经取得、已经测试、已经达到或已经应用的事实。包括：

- 用户或任务材料提供的真实项目数据；
- 用户提供的真实实验、测试、第三方验证结果；
- 已核验的真实数据集使用记录和真实对比结果；
- 已确认的项目应用成效、性能提升、准确率、时延、规模和工程结论。

真实项目证据不得由模型臆造。没有真实证据时，不得写成“已测得”“实验结果表明”“相比基线提升了”“项目达到”“现场验证证明”等已完成事实。正式成果结论需要真实结果而当前缺失时，可使用待补数据位、已确认设计阈值、验证目标或保守定性表述。

### 1.2 REFERENCE_EXPERIMENT：模型生成的参考实验

用于帮助用户设计、补做或补充实验，不属于真实项目证据。只要当前研究内容需要实验验证，而用户没有提供完整实验材料，默认允许并应主动生成完整参考实验，不得因为“没有真实实验数据”而只停留在方案论证、案例化场景、预期效果或空白占位。

模型可以生成：

- 实验目标、研究假设和验证问题；
- 实验环境、软件环境、硬件类别、随机种子、重复次数和主要超参数；
- 数据集使用方案、公开数据集候选、项目数据字段模板、合成/仿真数据构造方案和训练/验证/测试划分；
- 评价指标及选择理由；
- 传统基线、主流基线、强基线、同类技术候选和本方法变体；
- 对比实验、消融实验、参数敏感性、鲁棒性、泛化和不同电网工况实验；
- 模拟参考数据、示例结果表、预期区间、参考曲线数据/预期趋势/绘图说明及对应结果分析；
- 用户后续需要替换、补测、核验的清单。

模型生成数值必须使用以下状态之一：

- `simulated_reference`：模拟参考值；
- `illustrative_example`：用于说明结果结构和趋势的示例值；
- `expected_range`：建议目标区间或预期范围。

这些内容不是“虚构项目结果”。结构化数据层必须始终保留 `simulated_reference`、`illustrative_example` 或 `expected_range` 等状态，以便系统和审核器知道其来源；**正式报告正文不要求在每个标题、表题、数值或分析句中反复写“参考实验”“模拟结果”“示例数据”**。只要本章实际使用了模型生成的模拟实验数据，统一在章末增加一次模拟数据说明即可，正文按正常实验叙述方式展开。

## 2. 无真实实验数据时的默认动作

若用户回答“没有实验数据”“暂不提供实验数据”或材料中缺少完整结果，而当前章节需要验证，默认流程为：

`缺少真实数据 → 生成完整 REFERENCE_EXPERIMENT → 给出模拟结果和分析 → 内部保留来源状态 → 章末统一说明一次 → 用户后续替换或补做实验`

不得默认改成：

`缺少真实数据 → 不生成数据 → 只写验证方案/预期效果/待补占位`

除非用户明确要求“不要生成模拟参考数据”或当前章节本身不需要实验验证。

对用户说明时优先使用：

> 当前没有实测数据不影响实验部分起草。我会生成实验设置、数据集方案、对比方法、消融实验和模拟结果供你后续补做或替换，并在本章末尾统一说明其中模型生成数据的性质，避免正文反复出现“参考/模拟”提示。

避免把“没有实验数据”描述成报告内容生成的限制。

## 3. 模拟实验进入报告草稿时的统一说明方式

`experiment_reference_package` 是结构化来源，但不要求实验参考内容只能存在于报告外。包内 `reference_only: true` 表示“只具有参考证据地位”，不是“只能作为报告外附件”。

当当前章节包含模型生成的实验设置、对比/消融实验、模拟结果或结果分析时，可以直接按普通科技报告的实验叙述方式写入正文：

- 实验标题直接写“对比实验”“消融实验”“参数敏感性分析”等，不额外加“参考”或“模拟”；
- 表题、图题、结果段和每个数值附近不需要反复标注“模拟结果”“参考数据”；
- 结构化 `experiment_reference_package` 中仍必须保留每个数值的来源状态，供工作流、审核和后续替换使用；
- 同一章中如果同时存在真实数据和模型生成数据，应在内部数据结构中分清来源，正文组织时不得故意把来源关系写反；
- **只要本章正文实际使用了模型生成的模拟实验数据，必须在整章最末尾统一增加一次说明，且只提示一次。**

推荐章末说明：

> 说明：本章未由实际材料提供的实验数据为模拟生成数据，用于实验设计与结果展示，后续可根据实际实验结果替换。

该说明放在“本章小结”正文之后，不计入本章小结500—600字。若本章没有使用模型生成的模拟实验数据，则不添加该说明。

## 4. 参考数据的使用边界

REFERENCE_EXPERIMENT 可以用于：

- 完整起草实验设置、数据集、评价指标和对比方法；
- 给出对比、消融、敏感性、鲁棒性、泛化等实验表格；
- 给出合理的模拟结果、趋势和结果分析示例；
- 帮助用户判断后续应补哪些真实数据；
- 在报告草稿中形成可替换的完整实验段落。

REFERENCE_EXPERIMENT 不得自动升级为：

- 项目已经取得的量化成果；
- 已完成第三方测试；
- 已在真实现场或真实数据集完成验证；
- 摘要中的“已取得”量化结论；
- 最终总结中的已验证性能。

只有用户提供、文件中存在或后续明确核验的数据，才能转为 `verified_real_result`。

## 5. 全局统一约束

所有活动规则都必须直接使用本文件的两层证据语义，不再使用未区分证据类型的绝对禁令：

- REAL_PROJECT_EVIDENCE：严格禁止模型补造；缺失时只能使用已确认设计阈值、待补位置、验证目标或保守定性表述；
- REFERENCE_EXPERIMENT：允许模型生成模拟/示例/预期数值，并应在需要实验验证且真实数据不足时主动生成完整参考实验。

论文、标准、政策、真实第三方结论和真实应用案例始终属于真实性约束范围，不因参考实验能力而放宽。
