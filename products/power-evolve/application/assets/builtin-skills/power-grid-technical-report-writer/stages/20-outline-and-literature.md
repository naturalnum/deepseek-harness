### 0.7 目录结构不是自由创作

目录阶段必须执行 `references/outline-hard-rules.md`。当前固定架构为：第一章整合项目背景与研究意义、国内外研究现状、主要研究内容及思路；技术章从第2章起；技术章章首采用无标题导入正文；随后固定X.1—X.N核心研究小点并以本章小结收束。

以下要求属于硬规则：

- 第一章必须且只能命名为“项目概述”，二级标题依次为“项目背景与研究意义”“国内外研究现状”“主要研究内容及思路”；
- 第一章三级标题固定为1.1.1“项目研究背景”、1.1.2“项目研究意义”、1.2.1“国外研究现状”、1.2.2“国内研究现状”、1.3.1“主要研究内容”、1.3.2“研究思路”；
- `1.3.1 主要研究内容`必须与技术规划书、任务书或等效技术文件中的当前报告范围研究内容逐项对应，并在不改变边界的前提下稍作展开；
- 不再单设“国内外发展现状”一级章，技术章从第2章起按报告范围分支：总报告一个课题对应一个技术章，具体课题报告一个来源研究内容小点对应一个技术章；
- 技术章一级标题后直接规划无标题章首导入正文，不设置“概述”“技术路线”“技术架构”等二级功能标题；
- 章首导入正文必须包含本章背景与意义、研究主题引入、概括性技术路线/架构和适合的图示；以5万字全文为基准目标约800—1200字，其他总字数按1.6%—2.4%同比例规划；
- 每个技术章默认设置X.1、X.2、X.3三个核心技术二级标题，分别对应章内核心研究小点；只有预期目标、进度技术点或关键研究事项确实过多且无法在不失真的情况下合理归并时，才允许最小扩展到4—5个核心二级标题；每个核心二级标题默认继续生成2—4个三级标题，窄技术点确需标题级覆盖时最多5个；
- X.1—X.N必须先定义共同 `shared_chapter_question`，再按明确的先后承接关系拆解；每个核心二级标题先确定原始具体技术，再形成用于目录显示的中文语义 `technical_signature` 后组装标题；英文模型名和英文缩写不得直接裸露在二、三级目录标题中，中文表达应能让读者大致判断技术路线而不是机械展开长译名。RAG、图神经网络、Transformer、强化学习等技术族以及Span抽取、双塔匹配、置信校准、参数更新等任务动作都不能单独体现创新；“基于具体技术签名的……”作为优先显化句式，目录阶段必须先按标题总数规划数量，使每个技术研究章以及全文二、三级技术标题的使用比例都处于40%—60%；同时技术研究章二、三级标题只以“技术/方法”收束，按每章约40%技术、60%方法以及全文技术结尾35%—45%独立规划；所有二、三级技术标题仍须独立保留电力领域语义；
- X.1—X.N每个核心二级标题都必须显式识别电力对象、业务场景或运行约束，并同时体现具体计算技术与技术作用；二级标题出现“的”时，“的”后完整主语必须独立带有强电力相关词；
- 目录生成时还必须为技术路线未被来源唯一锁定的核心研究点建立 `technology_option_sets`：每个核心二级研究点给出2—3个同问题、同作用、同章节边界下的可选技术，分别写明中文技术签名、关键机制、适配理由和推荐项；正式目录只采用推荐/确认的一项。来源已经唯一指定技术路线时 `source_locked=true`，可只列1个来源技术，不得虚构替代方案；
- 预期目标、进度计划及对应课题区域考核要求中的关键技术词必须通过 `heading_source_term_plan` 按“概括性→二级、窄技术点→三级”分散进入目录；内部技术性考核事项同时在所属技术章X.1—X.N正文中隐性覆盖；
- 先自动判定 `report_theme_type`；`non-evaluation` 主题的二、三级标题不得出现验证、评估、评价、测评、验收、测试、试验、实验类章节词，全部核心研究点后直接为本章小结；只有 `evaluation-related` 主题且存在大量成体系数据或用户明确要求，才可在全部核心研究点后增加一个评估/验证节并将本章小结再顺延1位；
- 本章小结统一执行 `references/chapter-summary.md`；目录阶段只登记其结构位置、编号与计划篇幅字段，不维护另一套正文规则；
- 最后一章必须为“总结”“总结与展望”或“结论”，只设置一个一级标题，不设置任何二级、三级或更低级标题；该章正文计划固定700—800字，建议 target_words=750、minimum_words=700；其后设置参考文献；
- 目录中一级、二级、三级标题原则上不超过25个可见字符；技术研究章二、三级标题必须优先保留具体技术签名并满足40%—60%“基于……的……”比例，必要时允许长度例外；评估类功能标题仅在 `evaluation-related` 主题中允许简洁命名，非评估主题不得以功能标题绕过禁用规则。

若目录草案不满足这些要求，不得提交给用户确认。能够运行脚本时，使用 `scripts/validate_outline.py` 校验后再输出。

### 0.8 技术章章首无标题导入、三个研究小点与小结是硬规则

每个技术章采用：

```text
# X 技术章标题
[无标题章首导入正文：背景与意义 + 研究主题 + 概括性技术路线/架构 + 图示]
## X.1 章内研究小点一
### X.1.1 ...
### X.1.2 ...
## X.2 章内研究小点二
### X.2.1 ...
### X.2.2 ...
## X.3 章内研究小点三
### X.3.1 ...
### X.3.2 ...
## X.N 必要时扩展的研究小点（N≤5）
### X.N.1 ...
### X.N.2 ...
## X.(N+1) 本章小结
```

章首导入正文不是编号小节，不得显示“概述”“技术路线”“技术架构”等标题。技术研究课题与工程实现课题的路线差异通过正文内容和图示体现，不再通过固定X.2功能标题区分。

核心研究小点必须从当前章来源研究内容、预期目标、进度计划和内部技术要求中拆解，共同形成完整技术链。默认用3个核心二级标题完成归并；只有确实存在无法在不失真的情况下归并的独立预期目标/进度技术点时，才最小增加第4或第5个核心二级标题，并逐项登记扩展来源与必要性。能下沉到三级标题或并入既有二级研究点的内容不得触发扩展。

以下要求必须执行：

- X.1—X.N分别按连续顺序登记 `research_subpoint_index`、`derivation_basis` 和来源事项编号；
- 核心二级标题及其技术类三级标题都必须独立表达“电力对象或业务约束 + 具体技术签名 + 技术作用”，不得出现纯计算机标题；二级标题“的”后完整主语必须有强电力词；“基于……的……”句式只显化技术路线，不能覆盖或替代电力领域语义；
- 每个核心二级节必须展开2—4个三级标题，目录确认后进入标题锁定清单；同一技术章内所有技术类三级标题的任务主语必须互不重复，“基于……的……”标题重点比较“的”之后的完整任务主语，直接复合标题则比较去除 `technical_signature` 后的电力对象/业务与技术作用；不得只替换前置算法而重复相同后半段职责；
- 全文所有技术章X.1—X.N逐项满足“电力对象/约束 + 具体计算技术 + 技术作用”，不再使用全局比例替代逐项检查；
- `non-evaluation` 主题在全部核心研究点后直接设置本章小结；仅 `evaluation-related` 主题启用独立评估/验证例外时，在核心研究点后增加一个评估/验证节，小结再顺延1位；
- 本章小结正文规则统一引用 `references/chapter-summary.md`；
- 章首导入继续按本阶段既有篇幅规则规划；本章小结篇幅统一由 `references/chapter-summary.md` 规定。

具体规则必须读取 `references/report-architecture.md`、`references/outline-hard-rules.md`、`references/technical-title-naming.md`、`references/three-subpoint-and-indicator-coverage.md` 与 `references/research-content-traceability.md`。

### 0.14 研究内容驱动的章节映射与全量覆盖

研究内容映射规则必须优先读取 `references/report-scope-chapter-mapping.md`，再读取 `references/research-content-traceability.md`，并贯穿项目档案、论证架构、目录、第一章研究现状、章节计划、正文、摘要和最终组装。

`当前报告范围 → task_book_scope → 课题与课题角色 → 一级研究内容与研究内容小点 → 映射单位 → 名词化章名 → 一个技术章节 → X.1—X.N核心研究小点 → 范围内进度技术与内部技术要求落点`

必须遵守：

- 总报告范围内有几个课题，就设置几个技术章节，顺序与课题原始顺序一致；具体课题报告按研究内容小点数量和原始顺序设置技术章；
- 第一章1.3.1必须把当前范围研究内容逐项写出并适度展开，内部映射与后续技术章保持一致；
- 总报告中一个课题只对应一个技术章，课题内多个小点下沉到该章X.1—X.N及三级标题；具体课题报告一个小点只对应一个技术章；
- 第一章1.2国外、国内研究现状的检索主题与技术章范围一致，但不再设置与技术章一一对应的四级标题；
- 每项内部技术性考核事项必须在所属技术章X.1—X.N正文或其三级标题中隐性覆盖；
- 其他课题或其他报告范围事项标记为 `excluded-other-task`，不得映射到任何章节；只有经用户确认的共用基础可标记为 `shared-approved`；
- 纯管理事项可不进入技术正文，但必须登记处理方式；不得为追求覆盖而虚构技术内容或完成结果。

内部必须维护 `research_content_coverage`。来源性名称和编号只保存在内部映射中，正式正文按独立报告口吻表达。

### 阶段 C：生成目录和篇幅预算

仅在论证架构确认后执行；`source_grounded`模式还必须完成逐章内容概述确认。

目录必须先套用 `references/outline-hard-rules.md` 与 `references/report-architecture.md`，再执行报告范围映射、技术标题命名、研究内容追溯和三个研究小点覆盖规则。不得从空白开始自由设计。

目录草案必须明确包含：

- 中文摘要和必要时的英文摘要；
- 第一章“项目概述”；
- `1.1 项目背景与研究意义`，固定下设`1.1.1 项目研究背景`和`1.1.2 项目研究意义`；
- `1.2 国内外研究现状`，固定下设`1.2.1 国外研究现状`和`1.2.2 国内研究现状`；
- `1.3 主要研究内容及思路`，固定下设`1.3.1 主要研究内容`和`1.3.2 研究思路`；
- `1.3.1`的内容规划必须与技术规划书/任务书研究内容逐项对应并适度展开；
- 第2章起按报告范围生成技术章节：总报告一个课题对应一个技术章，具体课题报告一个研究内容小点对应一个技术章；
- 每个技术章登记“章首无标题导入正文计划”，包括背景与意义、研究主题、概括性技术路线/架构和图示计划，5万字全文时目标约800—1200字；
- 每个技术章默认设置X.1、X.2、X.3三个核心技术二级标题；只有来源化覆盖确有必要时最小扩展到4—5个，并分别继续生成2—4个三级标题，窄技术点确有必要时最多5个；
- 每章生成目录前，先从预期目标、进度计划及考核要求提取关键技术词，形成 `heading_source_term_plan` 并按粒度分配到现有二、三级标题，不新增第四个核心分支；
- 每个技术章登记本章小结计划；默认3个核心研究点时编号X.4，核心研究点扩展或启用评估例外时按实际顺延；具体组织、篇幅和证据字段按 `references/chapter-summary.md` 登记；
- 最后一章“总结/总结与展望/结论”（仅一级标题，正文700—800字）和参考文献。

技术章正式目录从三个核心研究小点开始显示，不显示章首无标题导入。例如：

```text
第X章 技术章标题
  X.1 核心技术二级标题
    X.1.1 具体三级标题一
    X.1.2 具体三级标题二
  X.2 核心技术二级标题
    X.2.1 具体三级标题一
    X.2.2 具体三级标题二
  X.3 核心技术二级标题
    X.3.1 具体三级标题一
    X.3.2 具体三级标题二
  X.N 必要时扩展的核心技术二级标题（N≤5）
    X.N.1 具体三级标题一
    X.N.2 具体三级标题二
  X.(N+1) 本章小结
```

目录至少登记每章标题、范围映射、章首导入规划、三个研究小点及其三级标题、证据与图表安排、计划字数、80%最低验收字数、篇幅比例、内部技术要求覆盖位置和范围排除项。

第一章结构、技术章核心研究点与本章小结、最后一章和参考文献属于固定项。技术章核心研究点数量默认3个，仅来源化覆盖确有必要时扩展到4—5个。最后一章的固定形态是“单一一级标题 + 700—800字连续正文”，不得再拆二三级标题。`non-evaluation` 主题不得出现独立实验、测试、应用验证或评估类二级/三级节；`evaluation-related` 主题的此类节也只是条件例外，不是固定项。

#### 禁止输出

- 任一章节正文；
- 大段项目概述或技术章章首导入样稿；
- 摘要或总结成稿。

#### 结束语

> 请确认或修改目录、研究内容映射、各章计划字数及80%最低验收字数。确认后，我再检索并整理参考文献与第一章国内外研究现状材料。

### 阶段 C2：参考文献检索与第一章国内外研究现状组织

仅在目录确认后执行，且必须在第一章章节计划之前完成。

目录确认后，应先在内部初始化 `abstract_evidence`，不得提前生成摘要正文。

#### 网络可用时

1. 根据已确认的技术章映射单位制定第一章1.2国内外研究现状的检索主题、技术缺口和文献检索式；
2. 搜索原始论文、标准、官方文档和数据集说明；
3. 打开论文或权威落地页，核验题名、作者、出版物、年份、DOI或稳定标识；
4. 判断论文原文是否真正支持拟写入正文的结论；
5. 将文献分为奠基工作、近期进展、最接近工作和比较基线；
6. 国外研究现状和国内研究现状均围绕当前报告范围内主要技术主题说明代表性路线、已有进展和不足，不再设置与技术章一一对应的额外四级标题；
7. 在生成第一章1.2正文前锁定作者指代样式：`author_et_al`对应“XXX等人”，`author_team`对应“XXX团队”；默认使用 `author_et_al`，两节必须一致；
8. 输出已核验文献集合、每篇文献支持的判断、研究现状主题—研究内容—技术章节内部映射、作者指代样式和未覆盖方向；
9. 等待用户确认，不同时生成第一章研究现状正文。

#### 网络不可用时

1. 明确说明当前无法完成真实性检索，并请求用户提供论文题目、DOI、官方链接、全文或已确认参考文献表；
2. 用户能够提供来源时，在可用信息范围内核验后继续；
3. 用户无法提供来源时，相关引用位置只能使用统一占位 `【待补充来源】`；
4. 不得把占位扩写为虚构题名、作者、年份、DOI或参考文献条目；
5. 同步登记“待补充来源清单”。

#### 结束语

- `model_autonomous`模式：

> 请确认或修改以上文献集合及国内外研究现状组织方案。确认后，我再生成第一章写作计划。

- `source_grounded`模式：

> 请确认或修改以上文献集合及国内外研究现状组织方案，并提供或补充第一章已有材料。确认后，我再生成第一章写作计划。

## 目录确认时的可选技术输出

生成目录给用户确认时，必须把正式目录与技术候选分开展示：先输出可直接进入报告的正式目录，再附一个不编号的“可选技术方案”块。该块按技术章/核心二级研究点列出2—3个候选（来源锁定时1个）、推荐项及一句适配理由；候选块不进入Word目录、不计入标题数量。用户未另选而直接确认目录，默认确认推荐项；用户选择其他候选时，只更新对应标题与必要的比例/结尾分布。
