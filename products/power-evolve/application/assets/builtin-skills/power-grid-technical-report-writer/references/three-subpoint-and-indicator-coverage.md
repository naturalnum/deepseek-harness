# 技术章研究小点、电力标题与技术指标覆盖硬规则

本文件约束目录、章节计划、正文生成和最终组装。其要求适用于第2章起的全部技术章节，优先级高于“按内容自由决定核心二级标题数量”和“默认单设实验验证二级节”的旧规则。

## 1. 每个技术章默认拆解为章内核心研究小点，目标过多时才最小扩展

一级技术章的映射单位服从报告范围：总报告一个课题对应一个一级技术章，具体课题报告一个来源研究内容小点对应一个一级技术章。章内核心二级标题数量默认固定为3个，优先形成X.1、X.2、X.3三个连续研究小点。只有当预期目标、进度技术点或当前研究内容中的关键技术事项数量确实较多，且强行归并会导致技术含义丢失、标题过宽或多个无直接关系的目标被塞入同一研究点时，才允许最小幅度扩展为4—5个核心二级标题。不得因为“内容看起来多”“目录更完整”或方便安排实验而扩展。

默认结构为：

```text
[一级标题后无标题章首导入正文]
X.1 章内研究小点一
X.2 章内研究小点二
X.3 章内研究小点三
X.4 本章小结（默认）
```

扩展后结构按实际核心研究小点数N顺延：核心技术二级标题为X.1—X.N，`N=4或5`时必须登记 `core_section_count` 与 `core_section_expansion_reason`，并逐项说明新增标题覆盖了哪些不能合理归并的预期目标/进度技术点；本章小结编号为X.(N+1)。如果为 `evaluation-related` 且确需独立评估/验证节，则该节位于核心技术二级标题之后，本章小结再顺延1位。章首导入和本章小结不计入核心研究小点。

三级标题默认每个核心二级节设置2—4个。若同一二级节对应的窄技术点或预期目标仍无法在2—4个三级标题内准确覆盖，可最小扩展到5个，并登记 `level3_expansion_reason`；没有明确来源覆盖需要时不得增加。

任何扩展都必须遵守“最少必要标题”原则：能通过重写标题边界、合并同类技术点或在正文中自然承接解决的，不新增二、三级标题。新增标题必须有明确 `source_item_ids`，不能生成可放到任意技术章的通用章节。

## 2. 独立实验、测试或应用验证二级节默认不设置

不得为了目录完整、指标覆盖或报告形式感，默认增加“实验与结果分析”“系统测试”“应用验证”等独立二级标题。技术说明、参数边界、测试条件、量化结果和适用范围应优先穿插到X.1—X.N中与其技术主张直接对应的位置。

只有 `report_theme_type=evaluation-related`，并且满足下列任一条件时，才允许在X.3之后单设一个评估/验证类二级节X.4，并将本章小结顺延为X.5；`non-evaluation` 主题不进入本例外：

1. 用户明确要求设置独立实验、测试或应用验证章节；
2. 当前章拥有大量、成体系的数据，包含多组数据集、多类工况、多种基线、消融试验、参数敏感性分析或多张结果表，嵌入核心研究小点会明显破坏论证结构。

启用例外时，章节计划和结构化目录必须记录：

- `standalone_validation_mode`：`large-data`或`user-requested`；
- `standalone_validation_reason`：说明数据规模或用户要求；
- 验证内容与X.1—X.N技术主张的对应关系。

没有上述记录时，独立验证二级节视为目录违规。即使启用例外，也不得把技术原理、关键方法或性能约束全部推迟到验证节。

## 3. 核心研究小点的拆解依据与本章边界

核心研究小点不得由模型凭空凑数。拆解时依次读取：

1. 当前一级技术章的来源范围：总报告为所属课题及其全部研究内容小点，具体课题报告为当前研究内容小点原文；
2. 该小点对应的预期目标；
3. 课题进度计划中的技术研发、构建、实现和验证事项；
4. 内部考核要求中的功能、性能、阈值、测试条件和判定标准；
5. 用户已确认的补充技术材料。

全部核心研究小点应共同覆盖本章完整技术链，优先按照“基础对象与输入处理—核心技术处理—输出应用与质量保障”或其他真实逻辑拆解。不得把其他课题事项拿来补足研究小点，也不得把一个数字阈值直接升格为独立研究小点。

进一步要求各核心研究点之间存在可追溯承接：前一节形成后一节所需的表示、特征、知识、状态、候选空间或中间结果，后续研究点基于前序产出完成推断、预测、识别、求解、优化、决策、控制、集成、风险约束或工程适配。全部核心二级标题必须共享一个一级章核心问题，不允许仅靠“协同/融合”字样把独立技术并列在一起。每个核心二级标题还必须显式使用细化到技术变体/关键机制层级的计算机技术名称，并记录技术来源状态；RAG、图神经网络、Transformer、强化学习等技术族名称本身不满足这一要求。

每个章内研究小点必须在结构化目录中登记：

- `research_subpoint_index`：按X.1—X.N连续登记，默认1—3，扩展时最多到5；
- `derivation_basis`：说明来自研究内容、预期目标、进度计划或内部要求的哪些条目；
- `source_item_ids`：对应内部来源事项编号；
- `technical_object`、`technical_method`、`technical_role`；
- `power_element`、`specific_computing_technology`、`technology_specificity_basis`、`technology_origin`；
- `shared_chapter_question`、`chain_order`、`chain_role`、`depends_on_previous`、`handoff_from_previous`、`output_to_next`；
- 对应三级标题和技术约束融入位置。

## 4. 二级标题必须服从一级标题并把电力对象与技术方法结合起来

全部核心二级标题均不得是纯计算机或纯人工智能标题。每个标题必须同时表达：

```text
电力设备、业务对象、运行状态或安全约束
+
具体人工智能、数据、知识、算法或系统技术
+
该技术在当前处理链中的作用
```

例如：

- 不合格：`多模态语义表示方法`；
- 合格：`电力设备多模态语义统一表示方法`。

- 不合格：`关系抽取与置信度校准方法`；
- 合格：`调度规程实体关系抽取与置信度校准方法`。

- 不合格：`智能服务接口编排技术`；
- 合格：`电网调度知识服务接口编排技术`。

标题不要求机械重复“电力”二字。“电网、调度、潮流、配电、输电、变电、运检、设备、线路、机组、负荷、新能源、储能、电压、功率、故障、保护、运行方式、安全边界”等均可承担电力语义。

## 5. 核心二级标题逐项电力语义与章节专属性

X.1—X.N每个核心二级标题必须直接写明当前电力对象、业务场景或运行约束，并与具体计算技术及技术作用形成完整表达；不得依靠其他标题替当前标题补足领域语义。更重要的是，每个二级标题必须是当前一级标题研究主线下的直接子问题、关键步骤或核心输出。判断不采用“数据预处理、模型优化、系统实现、性能分析、应用分析”等词语黑名单；这些词能否使用取决于其具体研究任务是否直接服务于本章一级标题。若标题只是与项目总体相关，却切换到另一研究对象、另一核心问题或另一独立输出，即使电力语义和技术签名都完整，也属于一级—二级逻辑偏离。

## 6. 三级标题保留并进一步具体化，禁止越界到后续章节

核心二级标题X.1—X.N必须分别按真实复杂度设置2—4个三级标题，编号从1开始连续；确因窄技术点/预期目标覆盖需要时可最小扩展到5个，并登记扩展理由。三级标题继续执行以下规则：

- 每个核心二级节不得缺少三级标题；默认每节2—4个，仅有明确来源覆盖需要时最多5个；
- 比二级标题更具体；
- 落到具体输入对象、处理动作、算法、模型、组件、接口或结果分析对象；
- 当需要区分多条技术路线、突出关键创新实现或避免标题过宽时，可采用“基于细粒度技术变体的对象处理方法”形式显式写入来源支持或已确认的技术名称，例如“基于关系感知异构图变换注意力的电网故障关联识别方法”或“基于混合检索重排序检索增强生成的电网故障处置建议生成方法”；“基于图神经网络/检索增强生成/自注意力变换的……”仍属于过宽写法；
- 具体技术名如果既未被材料支持、也未作为当前核心二级标题的 `model_suggested` 候选提出，则不得补造。三级标题可以沿用同一核心二级标题的候选技术来源状态，但**不得继承技术具体性**：每个三级技术标题都必须独立显化具体 `technical_signature`。如果仍属于同一技术体系，可写该体系下不同的具体模块、模型变体或关键机制；“基于具体技术签名的……”可用于突出技术点。只有用户确认后才进入标题锁定；
- 不使用“数据处理、模型训练、参数设置、模块设计”等空泛词；
- 不说半句话，不使用无关系的并列拼接；
- 技术研究课题标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点；
- 工程实现课题应落到系统、平台、模块、接口、部署、集成或应用对象；
- 目录或章节计划确认后，所有已设置的三级标题进入标题锁定清单，正文必须按原编号、原名称、原层级和原顺序逐项输出；
- 不得把已确认三级标题合并进自然段、改成列表或加粗短语、降级为四级标题或直接省略。确需修改时必须回到章节计划阶段重新确认。

需要呈现有限测试数据或结果时，优先在所属X.1—X.N下设置具体三级标题，例如“调度知识抽取准确率与错误样本分析”“电网策略生成时延及边界工况分析”，而不是单设泛化的“实验与结果分析”二级节。正文展示前应运行`validate_heading_coverage.py`确认三级标题保留率为100%。

## 7. 技术章节内容边界：当前章不得提前承接后续章职责

目录生成前必须建立 `chapter_scope_boundary`，至少登记当前一级标题的 `in_scope_objects`、`in_scope_outputs`、`reserved_for_later_chapters` 和 `forbidden_future_terms`。X.1—X.N及其三级标题只能描述当前章为完成一级标题核心问题所必需的研究对象、方法、输入输出和实验分析，不得把后续技术章的核心对象、核心输出、独立算法职责或工程应用提前写入当前章标题。

允许在正文中用一两句说明当前章输出将作为后续研究输入，但不得在当前章展开后续章的方法、实验或结论；目录标题尤其不得使用后续章专属技术词。若一个标题删除章节编号后仍可以原样放入后续章，或其主要技术作用由后续章负责，则视为越界，应回到目录阶段重写。

二级标题与本章一级标题必须存在直接的“对象—问题—输出”父子关系。审核时先抽取一级标题的核心研究对象、核心问题和预期输出，再逐项判断X.i是否为完成该主线不可或缺的子任务。不能只因为标题用了电力词、具体算法或与项目总体方向相关就判为合格；若X.i的核心任务换成了本章主线之外的另一类关联、识别、预测、决策或应用问题，则应判为章内逻辑偏离。

## 8. 技术指标与任务书硬指标的章节分配

每个技术章都应有与本章研究内容直接对应的 `chapter_technical_indicators`，用于说明本章技术效果；这些指标只服务本章技术主张，不需要把任务书全部硬指标平均分散到各章。

任务书中带有明确阈值、数量、精度、时延、可靠性、覆盖率、规模、成功率或其他验收边界的硬指标，统一建立 `task_hard_indicator_plan`，原则上集中放在**最后一个技术章节**承接。最后一个技术章先判断这些硬指标能否自然融合进已有X.1—X.N对应实验/结果分析：

1. 能与该节研究对象、数据、实验条件和技术主张直接对应的，融入原实验位置，不新增标题；
2. 无法与任何既有实验节自然融合，但必须完成总体性技术展示的，才在最后一个技术章最末核心研究点之后增加一个专门的总体实验三级标题；只有内容规模确实无法由三级标题承载时，才允许增加一个专门二级研究点，并计入4—5个核心二级标题的扩展上限；
3. 新增总体实验标题仍必须服从报告主题门禁：`non-evaluation` 不使用“实验/测试/验证/评估”等标题词，改写为“总体性能边界分析方法、综合运行性能分析方法”等技术语义标题；
4. 最后技术章本章小结必须覆盖这些硬指标对应的**实际结果与技术效果**，但不得复述“超过××、不低于××、小于××”这类任务书门槛句式，也不得写“达到考核指标”。应写成自然结果，例如“在典型工况下响应时间为8.2 s，支撑调度知识快速调用”，而不是“满足不超过10 s的指标要求”。
5. 任务书中的**定性指标同样属于必须形成结果的考核事项**。没有数值阈值不等于可以只写目标；应在最后技术章与摘要证据中写出对应能力、功能、成果状态、适用性或工程效果，例如“形成跨专业知识统一检索与可追溯调用能力”“完成多场景策略生成模块集成并具备受控回退能力”。

如果任务书硬指标与最后技术章研究对象完全无关，不得硬塞进标题；应在总体实验位置用跨模块输入输出或系统级工况把它们组织成整体性能展示，同时保持各指标的真实来源与证据状态。

## 9. 实验分析与小结指标数量控制

技术章正文的单个实验分析单元可以计算和展示多个指标，但**分析正文最多选择2个指标作为重点解释对象**。其余指标可以保留在表格、图或结果清单中，用于完整展示，不逐项展开原因分析。优先选择最能证明当前研究主张的主指标和1个必要的约束/代价指标。

本章小结按每个核心二级研究点最多总结1个代表性效果指标：每个X.i根据其研究内容只选择最能说明效果的1项指标，不在小结中堆叠多个指标；某一二级节没有实验或没有可靠量化结果时，不强行写指标，改用定性技术效果归纳。最后一个技术章除各X.i代表指标外，还必须在收束段自然覆盖任务书硬指标对应的结果与效果，但不得复述任务书阈值口吻。

## 10. 内部考核事项必须在正文中隐性覆盖

内部映射中的技术性考核事项不能只保存在覆盖矩阵、第一章、总结章或附录中。每项事项必须进入所属技术章正文，但正文不得暴露其外部来源身份，不得出现“任务书”“考核指标”“考核要求”“考核细则”“规定指标”或内部编号。

内部事项应转写为报告自身的技术内容：

- 阈值和目标值转写为技术目标、设计约束或性能边界；
- 测试条件转写为适用工况、数据范围或运行环境；
- 判定标准转写为方法有效性的判断规则；
- 已有结果转写为量化结果和能力结论；
- 缺失结果转写为设计目标、验证方案或明确待补充数据，不得写成已达到。

例如，内部记录为“知识检索响应时间不超过10 s”，正文直接写：

> 在典型调度知识查询负载下，知识检索响应时间目标设定为不超过10 s。

不得写：

> 根据任务书考核指标，知识检索响应时间应不超过10 s。

每项内部事项至少覆盖：

1. 所衡量的技术能力；
2. 适用的电力对象、业务场景或运行条件；
3. 计算方法或判定方法；仅在确有技术意义时使用公式；
4. 单位、阈值、目标值或允许范围；
5. 数据范围、环境或工况条件；
6. 有真实证据时给出结果和比较对象；没有结果时明确写成目标或验证安排；
7. 能力成立的边界、例外或代价。

内部覆盖计划必须登记：

- `assessment_item_id`；
- `planned_section`：默认落在X.1—X.N或其三级标题；
- `content_form`；
- `prose_realization`：技术目标、设计约束、性能描述、条件与阈值、结果证据或边界说明；
- `source_identity_hidden=true`；
- `evidence_status`；
- `confirmed_location`；
- `evidence_section`（可选，仅在确有独立数据分析位置时使用）。

默认不得要求单独的验证位置。不得只在本章小结中一句带过，也不得把目标值写成已经达到的结果。

## 11. 每章生成前后必经检查

生成每个技术章计划前：

- 确认默认形成3个章内研究小点；若扩展到4—5个，必须有不可合理归并的预期目标/进度技术点作为来源，并登记扩展理由；
- 确认默认结构为“无标题章首导入正文 + X.1—X.N核心研究小点 + X.4本章小结”；扩展时按X.1—X.N与X.(N+1)本章小结顺延；若为 `non-evaluation`，确认二三级标题完全不存在验证/评估/测试/实验类章节词；
- 需要独立评估/验证节时，确认 `report_theme_type=evaluation-related` 且存在大量数据或用户明确要求，并记录例外原因；
- 确认全部核心研究小点共同覆盖当前章研究内容、预期目标和主要进度技术，且没有跨入后续技术章的研究职责；
- 确认当前章自身技术指标已有X.1—X.N正文融入位置；若当前章是最后一个技术章，同时确认任务书硬指标已有集中承接位置；
- 确认全部核心二级标题均为“电力对象+具体技术+作用”的完整表达，并且都是本章一级标题主线下的直接子问题、关键步骤或核心输出，不存在一级—二级逻辑偏离；
- 确认未混入其他课题内容。

正文展示给用户前：

- 检查X.1—X.N是否均已实质展开；
- 检查技术目标、条件、单位、阈值、证据状态和边界是否完整；
- 检查没有把目标冒充为完成结果；
- 检查正文没有出现任务书、考核指标、考核要求、考核细则、规定指标或内部编号；
- 检查每个核心标题是否仍逐项显式体现电力对象/约束、具体计算技术和技术作用；
- 检查不存在纯计算机标题、一级—二级逻辑偏离、跨课题内容或提前涉及后续技术章研究职责的标题。


### 目录技术词分散覆盖与主题冲突消解

预期目标、进度计划以及考核要求中的关键技术词必须进入 `heading_source_term_plan`：概括性技术词分配到X.1—X.N二级标题，窄技术点分配到对应三级标题；不得为覆盖来源词破坏核心研究小点的技术链，也不得把全部词堆到同一分支。`non-evaluation` 主题下，验证/评估/评价/测试/试验/实验/验收等来源动作词不得作为二三级章节词，改为其背后的性能、约束、边界或工程技术语义。

技术研究章二、三级技术标题以“技术/方法”收束，按每章约40%“技术”、60%“方法”分配；“模型/算法”作为技术签名进入标题中部而非结尾。二级标题含“的”时，“的”后完整主语必须独立包含强电力相关词。
