# 叙述聚焦、电力语义与有效公式规则

本文件约束摘要和正式正文的句子组织、技术解释与公式使用。每次生成技术章或分节正文前后必须重新读取；摘要生成阶段也必须读取。目标是在不牺牲必要信息的前提下，减少表面完整、重点分散和脱离电力对象的表达。

## 1. 一段只承担一个主要论证任务

每个自然段应有一个可明确复述的中心判断。段内其他句子用于解释原因、技术机制、证据、条件或影响，不得同时平铺多个彼此关系不清的主题。

优先组织为以下逻辑链之一：

- `问题表现 → 技术原因 → 解决机制 → 形成能力`；
- `输入对象 → 处理关系 → 输出结果 → 验证方式`；
- `物理约束 → 数学表达 → 算法处理 → 电网作用`；
- `实验条件 → 关键结果 → 原因解释 → 适用边界`。

不能形成同一逻辑链的内容应拆分到不同句子、自然段或技术小节，不应依靠逗号和顿号强行并列。

## 2. 控制过渡词和过渡句

过渡词只在逻辑关系无法从内容本身自然辨认时使用。不得连续使用“首先、其次、再次、此外、同时、进一步、在此基础上、因此、综上”等词构造表面层次，也不得在每段首尾增加无信息的过渡句。摘要第一段和第二段属于明确例外：为建立“挑战排序—技术点排序”的一一对应关系，必须按摘要规则使用“第一、第二、第三”或“首先、其次、再次”等顺序词；该有限使用是信息结构标记，不属于表面层次。

优先直接写技术关系。例如：

- 不写：“在此基础上，进一步对模型进行优化，从而实现性能提升。”
- 改写：“约束感知更新抑制了不可行策略，使故障恢复方案在安全边界内收敛。”

段间确需承接时，可使用一次简短过渡，但过渡句本身必须携带新的技术信息。

## 3. 限制逗号和顿号堆叠的并列

“、”或“，”隔开的并列并非完全禁止。对象清单、离散模块、参数项、约束条件和评价指标确实需要逐项列明时可以使用，但应满足以下条件：

1. 各项属于同一上位概念；
2. 每项均与当前段落中心判断直接相关；
3. 项目数量不会遮蔽最重要的技术主线；
4. 不含当前报告范围之外的其他课题内容；
5. 后文会对这些项目进行解释、建模、实现或验证。

出现下列情况时应改写：

- 一个句子连续列出多组名词、动作和效果；
- 使用“构建……、提出……、实现……、提升……”连续罗列成果；
- 为显得完整而并列“数据、知识、模型、平台、应用”等宽泛词；
- 并列项来自不同研究范围，或其中部分属于其他课题；
- 并列项之间实际存在因果、先后、约束、包含或反馈关系。

改写时优先采取：删除次要项、突出主项、拆分句子、按因果或处理顺序重组、将真正离散的内容改成少量分点。

## 4. 摘要的聚焦表达

摘要固定为三个自然段，每段只突出一个主要任务：第一段聚焦领域现状、现实需求和关键挑战；第二段在同一自然段内合并说明全部主要研究点；第三段以当前报告范围内任务书考核指标的对应结果为主，定量指标写实际结果，定性指标写形成的能力、功能、成果状态、适用性或工程效果；非任务书指标仅在确有补充价值时再选1—2个，然后归纳总体结论、研究前景和应用前景。

第二段可以包含多个研究点，但应为每个研究点设置独立、完整的句组。每个句组只突出一个问题、一个主机制和一个代表性能力，再通过必要的因果、先后、约束、集成或反馈关系连接。不能把“合并为一段”理解为把全部技术压缩成一个超长句。

摘要中应尽量避免：

- 依靠多个过渡词串联段落或研究点句组；
- 一个长句并列多个技术名称、多个动作和多个效果；
- 连续使用“针对……，提出……，通过……，实现……”完全同构的句式；
- 将多个核心技术章压缩成一串顿号短语；
- 为涵盖所有细节而削弱每条研究线的主机制；
- 第三段只有空泛结论和展望，却没有量化结果、测试条件或适用边界。

核心技术章多于三章时，应先按共同问题或技术机制归并为主要研究线，再为每条研究线选择一个主机制和一个代表性能力。必要的次级技术只用于解释主机制，不与主机制并列争夺重点。第一段的挑战数量原则上与第二段的主要研究点数量一致，第三段的研究与应用前景不得超出已经验证的能力。

## 5. 技术解释必须落到电力对象和物理意义

介绍通用算法、数据方法、知识模型或系统机制时，应在与技术论证相关的位置穿插电力系统对象、运行机理和工程约束，使读者明确该技术处理的不是抽象数据，而是具体电网状态与业务关系。

可结合实际内容解释：

- 节点电压、支路电流、有功功率、无功功率、负荷、频率、相角和潮流约束；
- 变压器温度、设备健康状态、线路载流能力、保护动作和故障传播；
- 调度指令、运行方式、拓扑关系、资源可调节能力和安全边界；
- 量测误差、通信时延、计算时限、人工确认和异常回退。

物理意义应自然进入技术解释，不单独堆砌“电力应用意义”小节，也不机械在每个句子后补充工程价值。只有对象或关系确实具有电力含义时才说明。

## 6. 公式符号采用直接的领域定义

公式中的符号若对应明确电力对象，应直接定义为该对象，不先给通用含义再追加“在电力应用中表示……”。例如：

- `$T_i$ 表示第 $i$ 台变压器的绕组温度`；
- `$V_i$ 表示节点 $i$ 的电压幅值`；
- `$P_{ij}$ 表示支路 $i$—$j$ 上的有功功率`；
- `$u_g$ 表示发电机组 $g$ 的启停状态`；
- `$\Delta t$ 表示相邻调度周期的时间间隔`。

仅当符号确实是通用算法量时，才使用通用定义，如注意力权重、嵌入向量或损失项。此时仍应在公式后的技术解释中说明它如何影响电网对象、约束或决策结果。

符号定义必须依据当前报告真实对象。不得为了增加电力色彩，将一般变量错误解释为电压、温度或功率。

## 7. 只保留承担论证作用的公式

公式应至少承担以下一种作用：

- 定义真实研究对象或状态关系；
- 表达电力物理机理或运行约束；
- 定义模型、目标函数、损失、更新规则或推理关系；
- 给出实际使用的评价指标或性能关系；
- 支撑算法实现、实验计算或结论判断。

下列表面公式应删除：

- 仅把自然语言重新写成集合或映射符号，后文不再使用；
- 任意设置权重的加权和，但没有权重来源、求解方法或验证用途；
- 为满足公式数量而加入的简单计数、单位换算或显然比例；
- 与算法、系统、实验和结论均无对应关系的输入输出等式；
- 符号众多但无法说明物理含义、维度、来源或计算方式的复杂表达。

`formula_requirement = must`表示章节必须存在至少一个真正承担核心论证作用的公式，不代表需要凑数量。计划中的某个公式没有实质作用时应直接删除。若整章不存在可以真实、有效形式化的关系，应在章节计划阶段将需求调整为`should`或`exempt`，给出具体理由并由用户确认，不得用空洞公式维持`must`标记。

## 8. 与其他课题范围隔离联动

并列内容过多时，必须额外检查是否混入其他课题的技术、指标、数据、案例或成果。属于`excluded-other-task`的内容应直接删除，不能通过压缩成并列短语、改写名称或泛化为“多源技术”继续保留。

删去范围外内容后，应重新确认当前段落的中心判断。若剩余内容仍存在主次不清，应按当前研究点的主要问题和核心技术重组，而不是补入新的并列项维持篇幅。

## 9. 生成前后检查

生成前明确：

- 当前段落或小节的唯一主要判断；
- 该判断的逻辑链；
- 需要落到的电力对象、物理量或工程约束；
- 必须保留的必要公式及其用途；
- 可能造成重点分散的并列项；
- 必须排除的其他课题内容。

展示前检查：

- 是否存在无信息过渡句或连续过渡词；
- 是否存在逗号、顿号堆叠的长串并列；
- 并列项是否可以改造成因果、先后、约束或包含关系；
- 技术原理是否自然落到电网对象和物理意义；
- 符号是否直接定义为真实电力对象；
- 是否存在装饰性或空洞公式；
- 是否借并列写法混入其他课题内容。
