# 报告总体架构规则

本文件规定科技项目结题技术报告的一级、二级、三级固定结构。目录阶段必须先套用本架构，并优先读取 `report-scope-chapter-mapping.md` 判断总报告或具体课题报告，再补充技术章节。不得改变下列骨架。若用户明确要求其他整体结构，应在项目档案中记录结构例外，而不是由模型自行漂移。

## 1. 全文固定骨架

```text
图、表目录条目（排版阶段直接续接主目录，不显示独立“图目录”“表目录”标题）

第1章 项目概述
  1.1 项目背景与研究意义
    1.1.1 项目研究背景
    1.1.2 项目研究意义
  1.2 国内外研究现状
    1.2.1 国外研究现状
    1.2.2 国内研究现状
  1.3 主要研究内容及思路
    1.3.1 主要研究内容
    1.3.2 研究思路

第2章起 按报告范围映射的技术章节
  [章节标题后的无标题章首导入正文]
  X.1 章内研究小点一
  X.2 章内研究小点二
  X.3 章内研究小点三
  X.4 本章小结（默认）

最后一章 总结 / 总结与展望 / 结论
参考文献
```

第一章不得命名为“引言”“绪论”或单独的“概述”，必须使用“项目概述”。国内外研究现状不再单独设置为第二章；技术章节从第2章开始编号。

## 2. 第一章“项目概述”

第一章二级标题必须且仅采用以下三节，并按顺序排列：

1. `1.1 项目背景与研究意义`；
2. `1.2 国内外研究现状`；
3. `1.3 主要研究内容及思路`。

第一章三级标题固定为：

```text
1.1.1 项目研究背景
1.1.2 项目研究意义
1.2.1 国外研究现状
1.2.2 国内研究现状
1.3.1 主要研究内容
1.3.2 研究思路
```

不得在第一章增加与上述结构并列的其他二级标题；确需进一步细分时优先通过自然段、表格或图示完成，不默认扩展到四级标题。

第一章一级标题“第1章 项目概述”之后不得立即出现 `1.1`。必须先写50—100字无标题过渡正文，再进入 `1.1 项目背景与研究意义`。具体执行 `references/heading-transition.md`。

### 2.1 项目背景与研究意义

#### 2.1.1 项目研究背景

从电力业务场景、运行对象、现实约束、已有能力和待解决问题出发，说明项目开展的技术与工程背景。背景应服务于后续研究主题，不写成长篇政策罗列或通用技术发展史。

#### 2.1.2 项目研究意义

围绕项目解决上述问题后能够形成的技术能力、工程价值、业务作用和可验证改善说明研究意义。不得只写宏观口号，也不得提前把尚未验证的目标写成已完成成果。

### 2.2 国内外研究现状

固定采用：

```text
1.2.1 国外研究现状
1.2.2 国内研究现状
```

两节围绕当前报告范围内的主要技术主题，分别说明代表性路线、已有进展、可核验成果和仍存不足。作者指代样式必须统一：默认使用“XXX等人”，经计划确认后也可统一使用“XXX团队”。机构、标准组织使用正式名称。不得逐篇文献机械罗列，不得虚构无法核验的文献事实。

研究现状的技术主题必须与后续技术章节覆盖的研究内容一致，但不再要求设置与技术章一一对应的额外三级标题，也不得为了映射技术章而扩展到四级标题。每一节内部通过自然段按技术主题组织即可。

### 2.3 主要研究内容及思路

#### 2.3.1 主要研究内容

本节必须与技术规划书、任务书或等效技术文件中属于当前报告范围的“研究内容”保持对应。要求：

- 按来源研究内容的原始顺序组织，不合并、不遗漏、不跨课题借用；
- 不能只复制标题，应在每项研究内容后稍作展开，说明研究对象、拟解决问题、主要技术方向和预期形成的能力或产物；
- 展开只允许使用来源材料、用户确认信息或后续技术章已确认的技术边界，不得新增无依据算法、数据、指标或完成结果；
- 总报告应覆盖全部课题范围内研究内容，具体课题报告仅覆盖当前课题研究内容。

#### 2.3.2 研究思路

说明研究内容之间的总体逻辑、依赖关系、输入输出关系、关键处理链和研究推进思路。应回答“各研究内容为什么这样衔接、整体如何从问题走向技术实现与验证”。适合时应配置总体研究思路图或技术关系图。该节不承担逐章目录复述功能，正文原则上不使用“第二章、第三章”等章节编号说明全文结构。

## 3. 课题角色与技术章节映射

目录生成前必须先按任务材料区分课题角色。前序课题均按技术研究组织，最后一个课题固定按工程实现组织，通常承担系统研发、平台实现、集成部署、示范应用或工程验证。每个研究内容小点继承所属课题角色。

技术章节从第2章起编号，并先读取 `task_book_scope`，不得由模型自由设计章数。

总报告执行：

```text
课题原始顺序与课题角色
→ 课题名称及课题内全部研究内容小点
→ 必要的名词化与标题用词整理
→ 一个技术章节
```

- 有几个课题就设置几个技术章；
- 一个课题只承担一个技术章，不得拆分或合并课题；
- 课题内多个研究内容小点默认归并到该章X.1—X.3，并在确有来源覆盖需要时最小扩展为X.1—X.N，再通过其三级标题展开。

具体课题报告执行：

```text
所属课题与课题角色
→ 研究内容小点原文
→ 必要的名词化与标题用词整理
→ 一个技术章节
```

- 有几个研究内容小点就设置几个技术章；
- 技术章顺序与小点原始顺序一致；
- 一个技术章只承担一个研究内容小点；
- 不得把多个小点合并成一个章，也不得把一个小点拆成多个章。

以下规则对总报告和具体课题报告均适用：

- 不得把其他课题的小点、进度技术、指标、数据、案例或成果写入当前章；
- 章标题不得增加当前映射单位来源标题没有提及的对象、算法、能力、指标或结论；
- 技术研究课题标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，也不得机械改名；应直接描述实际采用的具体技术、方法、算法或模型；`report_theme_type=non-evaluation` 时，二、三级标题另外禁用验证、评估、评价、测评、评测、验收、测试、试验、实验类章节词；
- 工程实现课题标题应落到系统、平台、架构、模块、接口、部署、集成或应用能力。

## 4. 技术章标题的名词化整理

当前映射单位的来源标题已经是名词性技术短语时，直接作为章标题。若原文带有任务动作词，应仅做语法整理，不做内容扩写。

允许删除开头的“研究、开展、研发、构建、建立、提出、实现”等任务动作词，或调整少量语序使标题能够独立成立。禁止在原文之外增加新的电力对象、人工智能方法、评价性限定词、进度计划、考核指标或实验结果。

## 5. 技术章章首无标题导入正文

技术章不再设置“X.1 概述”和“X.2 技术路线/技术架构”等功能性二级标题。章节一级标题之后直接进入一段或若干自然段的章首导入正文，随后再进入核心二级标题。核心二级标题必须与当前一级标题的研究对象、核心问题和核心输出形成直接父子逻辑：每个二级标题都应是完成该一级标题研究主线所必需的直接子问题、关键步骤或核心输出。判断重点不是标题里是否出现“数据处理、模型优化、系统实现、性能分析”等词，而是该标题承担的研究任务是否属于本章主线；即使技术上相关，若只是项目外围内容、相邻章内容或后续章可独立成立的研究任务，也不得放入本章。

章首导入正文必须同时包含：

1. 简要背景介绍：说明本章研究对象、应用/工程场景、现实问题和研究价值，作用类似第一章的“背景与研究意义”，但聚焦本章主题，不重复第一章；
2. 研究主题引入：明确本章要解决的核心技术问题、目标能力、主要输入输出和适用边界；
3. 概括性技术路线：用连贯文字说明主要处理阶段、关键模型/算法/模块关系、输出与反馈；
4. 图文结合：技术关系适合可视化时，优先安排技术路线图、总体架构图、数据流/知识流/控制流图或研究思路图。

章首导入不设置任何“概述”“技术路线”“技术架构”二级标题，也不计入X.1—X.N核心研究小点。

篇幅按全文计划字数同比例规划：以5万字报告为基准，章首导入正文目标约800—1200字，即约占全文计划字数的1.6%—2.4%。其他总字数按该比例折算。该范围用于篇幅规划和生成控制，具体可结合章节复杂度小幅调整，但不得缩成几十字的形式性开场。

## 6. 技术章三个核心研究小点

每个技术章正文结构为：

```text
[无标题章首导入正文]
X.1 章内研究小点一
X.2 章内研究小点二
X.3 章内研究小点三
X.4 本章小结（默认）
```

默认由X.1、X.2、X.3形成核心技术二级标题。只有当前章预期目标、进度技术点或关键研究事项确实无法合理归并时，才允许最小扩展为4—5个核心技术二级标题，并逐项记录新增标题的来源依据。全部研究小点从当前章研究内容、预期目标、进度计划和内部技术要求中拆解，共同覆盖本章完整技术链。二级标题完整说明电力对象或约束、具体技术签名和作用，禁止纯计算机标题。三级技术标题与二级标题执行同等级的“双显化”要求：每个三级标题都必须独立写出可识别的电力对象/业务/运行约束，以及具体模型/算法变体、关键机制、约束或组合方式；不能只写Span抽取、双塔匹配、实体识别、置信校准、样本重加权、参数更新等任务动作，也不能依赖上位标题补足电力语义或技术签名。

先判定 `report_theme_type`。`non-evaluation` 主题不设置任何验证、评估、评价、测评、评测、验收、测试、试验、实验类二级或三级节；有限测试条件、量化结果和边界分析转写为精度、可靠性、时延、工况适应性、性能边界、集成能力等技术语义并嵌入X.1—X.N正文，本章小结位于最后一个核心研究点之后。只有 `evaluation-related` 主题且数据量大、分析体系独立，或用户明确要求时，才允许在最后一个核心研究点之后增加一个评估/验证类二级节，并记录例外原因，本章小结再顺延一位。

## 7. 核心二级标题与三级标题

技术章X.1—X.N章内核心研究小点标题按核心技术标题管理。标题应：

- 只服务当前技术章对应的研究内容范围；
- 全部核心标题共同覆盖预期目标、进度计划主要技术和考核要求；
- 每个标题体现电力对象或业务约束、具体人工智能/数据/知识/算法/系统技术和实际作用；
- 不得为了满足形式要求添加来源没有支持的术语；
- 不使用“关键技术、核心方法、技术实现、模型研究”等低信息标题；
- 技术研究课题标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点；`non-evaluation` 主题二、三级标题不得出现验证/评估/评价/测评/评测/验收/测试/试验/实验类章节词；
- 二级标题必须完整说明对象、具体 `technical_signature` 和作用；每个三级技术标题也必须独立显化自己的 `technical_signature`，不得只继承上位标题的具体性。
- 每个核心二级标题还必须显式包含具有区分度的细粒度计算机/人工智能技术；“人工智能、机器学习、深度学习、神经网络、大模型、优化算法”等上位概念不能承担创新技术角色，RAG、图神经网络、Transformer、强化学习等技术族名称也不能直接作为最终粒度；Span抽取、双塔匹配、置信校准、样本重加权、参数更新等操作名称同样不算技术签名，必须继续明确具体模型/算法变体、结构、机制、约束或组合方式；“基于具体技术签名的……”实行40%—60%双向硬门禁，但句式比例不能替代电力领域语义；每个技术研究章及全文二、三级技术标题的使用比例均必须处于40%—60%，且每条技术标题都必须独立保留电力对象/业务/运行约束，其余标题采用“电力对象/约束 + 直接复合技术签名 + 技术作用”表达；
- X.1—X.N必须围绕同一 `shared_chapter_question` 形成先后承接链；默认三节结构下，X.2利用X.1产出，X.3进一步利用前序产出完成后续推理、优化、决策、集成或验证。

本章小结属于功能性标题，不适用核心技术标题的对象—方法—作用完整关系要求。有限测试与结果分析优先作为X.1—X.N下的具体三级标题；仅在满足例外条件时，实验设置、实验结果、系统测试或应用验证可单设二级功能标题。

## 8. 三级标题和结构差异

核心二级标题数量默认3个，来源目标过多且无法合理归并时最小扩展到4—5个。章节差异通过三级标题、公式、图表和嵌入式证据安排体现：

- X.1—X.N必须分别展开默认2—4个三级标题；仅当窄技术点或预期目标确需标题级覆盖时，单个核心研究点最多扩到5个；
- 各核心二级节的三级标题数量可以不同，但编号必须从1开始连续；
- 不得机械复制三个核心标题的内容和三级结构，也不得以避免对称为由省略某一组；
- 三级技术标题用于独立算法、模型、具体方法、组件、接口或处理阶段，必须来自当前研究边界，并独立显化具体技术签名；只有 `evaluation-related` 主题的评估/验证类三级标题可按其实际评价对象保持相对简洁，`non-evaluation` 主题不得使用此类章节词。

## 9. 范围隔离与全量覆盖

每章只允许使用当前报告范围内与本章研究内容相关的内容，以及经用户明确确认的共用基础。任务材料中其他课题、专题或报告范围的研究内容、方法、指标、数据、案例和成果不得进入标题、正文、公式、图表、实验或结论。

本章范围内的预期目标、进度计划和内部技术要求必须具有明确落点。相关要求必须进入所属技术章X.1—X.N正文或其三级标题，并转写为报告自身的技术目标、设计约束、性能描述、适用条件、结果证据和能力边界。正式正文不得出现“任务书”“考核指标”“考核要求”“考核细则”“规定指标”或内部编号。不能把缺失的实现或结果写成已完成事实。

## 10. 本章小结

每个技术章必须以“本章小结”结束。`non-evaluation` 主题的小结编号位于最后一个核心研究点之后；仅 `evaluation-related` 主题按合法例外设置独立评估/验证二级节时再顺延一位。

本章小结的结构位置、篇幅、总—分—总组织、成果归纳、实验结果使用方式、生成时机与验收统一执行 `references/chapter-summary.md`。本文件不再维护另一套小结正文规则。

## 11. 全文核心标题逐项电力语义

所有技术章X.1—X.N逐项执行“电力对象/业务场景/运行约束 + 具体计算技术 + 技术作用”要求，不再以全局比例作为通过条件。每个标题都必须让读者仅从标题本身识别其电力研究对象或约束；已经出现明确领域对象时不机械重复“电力”二字。

## 12. 最后一章与参考文献

最后一章只能使用“总结”“总结与展望”或“结论”，按总体目标收束，不按章节编号逐章复述。最后一章只有一级标题，一级标题下直接组织连续自然段，不得再设置二级、三级或更低级标题。正文有效字数固定为700—800字，不随全文目标字数同比例放大。最后一章后必须设置参考文献。

## 13. 标题长度与实验类功能标题

目录标题原则上不超过25个可见字符。实验、评价指标、实验设置、数据集、测试环境和结果分析等功能性标题可以直接、简洁，不需要人为扩展成复杂技术句。简洁标题只适用于功能性二级/三级位置，不适用于X.1—X.N核心技术标题。技术研究章二、三级标题执行“电力领域语义显化 + 中文技术签名显化 > 40%—60%基于句式比例 > 25字符原则”，若压缩会损失技术签名或破坏比例，可保留超长标题并记录例外；当前映射单位的来源标题过长且无法安全缩短时，一级技术章标题也可记录例外理由。

## 14. 目录提交前检查

提交目录前至少检查：

1. 第一章是否准确命名为“项目概述”；
2. 第一章二级标题是否依次且仅为“项目背景与研究意义”“国内外研究现状”“主要研究内容及思路”；
3. 第一章三级标题是否准确为1.1.1“项目研究背景”、1.1.2“项目研究意义”、1.2.1“国外研究现状”、1.2.2“国内研究现状”、1.3.1“主要研究内容”、1.3.2“研究思路”；
4. 1.3.1是否与技术规划书/任务书研究内容逐项对应并作适度展开；
5. 技术章是否从第2章起按报告范围映射：总报告数量和顺序与课题一致，具体课题报告与研究内容小点一致；
6. 技术章标题是否仅由当前映射单位来源标题进行必要名词化整理，没有添加额外信息；
7. 技术章一级标题后是否直接规划无标题章首导入正文，且没有“概述”“技术路线/技术架构”二级标题；
8. 章首导入是否规划背景、研究主题、概括性技术路线和适合的图示；5万字报告是否按约800—1200字规划；
9. 是否默认设置三个核心研究小点，扩展到4—5个时是否有必要且可追溯的来源依据，并共同覆盖预期目标、进度计划主要技术和内部技术要求；
10. 技术研究章节标题是否避免把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，并避免机械改名；是否已判定 `report_theme_type`，且非评估主题二、三级标题无验证/评估/测试/实验类章节词；
11. 二级、三级技术标题是否都独立同时显化电力领域语义和具体中文语义 `technical_signature`；目录中的英文技术名/缩写是否已转换为能说明路线的中文技术表达；是否避免“Span抽取、双塔匹配、置信校准、参数更新”等任务动作充当技术点；每个技术研究章及全文二、三级技术标题中，“基于具体技术签名的……”句式占比是否均处于40%—60%的硬区间；
12. 是否排除了其他课题内容；
13. 是否默认未设置独立评估/验证二级节；若设置，是否同时满足 `evaluation-related` 主题及大量数据或用户明确要求的记录；
14. 是否设置本章小结，并已按 `references/chapter-summary.md` 完成统一规划与检查；
15. 最后一章是否只保留一级标题且正文控制在700—800字；
16. 是否设置最后一章和参考文献。

能够运行脚本时，使用 `scripts/validate_outline.py` 对结构化目录进行内部校验。校验失败时先修正，不向用户输出独立审查报告。
