# 中间技术章节生成规则

## 1. 章节闭环

每章在一次正文生成中自然完成：

`章节问题 → 技术原因 → 设计目标 → 方法/系统 → 实现 → 验证 → 结果解释 → 能力边界 → 本章结论`

不要把这些字段机械地全部写成标题，但逻辑不能缺失。

## 2. 技术章结构不得由闭环字段直接映射

“问题、原因、目标、路线、实现、证据、边界”是正文必须覆盖的论证闭环，不是标题名称。技术章一级标题之后先写无标题章首导入正文，合并原“概述”和“技术路线/技术架构”功能；随后默认进入X.1、X.2、X.3三个核心研究小点，确有来源覆盖必要时最小扩展为X.1—X.N。`non-evaluation` 主题有限测试、结果和边界分析只嵌入X.1—X.N正文，本章小结位于最后一个核心研究点之后，不得出现验证/评估/测试/实验类二三级标题；只有 `evaluation-related` 主题满足大量成体系数据或用户明确要求的例外条件时，才在最后一个核心研究点之后增加独立评估/验证节并将本章小结再顺延一位。不得使用“关键技术一、关键技术二”等占位标题。

章节目录必须先识别真实技术单元，再默认归并为三个互不重复且共同形成完整技术链的章内研究小点；仅在预期目标、进度技术点或关键研究事项确实无法合理归并时才最小扩展到4—5个。拆解依据包括当前来源研究内容、预期目标、进度计划和考核要求，并建立 `heading_source_term_plan`：预期目标、进度计划、考核要求中的关键且有实际含义的技术词按 `broad|narrow` 分级，概括性词分散进入二级标题，窄技术点进入对应三级标题，在不破坏技术链的前提下尽可能覆盖。技术研究课题标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点；`non-evaluation` 主题二三级标题不得出现验证、评估、评价、测评、评测、验收、测试、试验、实验类章节词。工程实现课题标题应落到系统、平台、架构、模块、接口、部署、集成或应用。X.1—X.N核心二级标题必须完整呈现电力对象、具体人工智能/数据/知识/算法/系统技术和技术作用；若标题含“的”，以“的”之后完整部分为主语，主语本身必须含强电力相关词；每个核心二级标题默认继续生成2—4个三级标题，窄技术点确需标题级覆盖时最多5个。技术研究章二三级技术标题约40%以“技术”收束、60%以“方法”收束。

## 3. 章首无标题导入正文

技术章一级标题之后直接进入正文，不输出“概述”“技术路线”“技术架构”或类似功能标题。章首导入应自然完成：

1. 简单背景介绍，说明本章研究对象、业务/工程场景、现实问题和研究意义；
2. 引入本章研究主题，明确核心挑战、研究目标、输入输出、适用范围和核心主张；
3. 概括性说明本章技术路线或技术架构，包括主要处理阶段、关键模型/算法/模块关系、输出和反馈；
4. 适合时插入技术路线图、总体架构图、数据流/知识流/控制流图，不只用文字罗列。

章首应聚焦本章，不能重复第一章背景，也不得引用其他章节编号、课题编号或材料来源。若需要统一定义研究对象、输入输出、状态、集合、目标或约束，可在章首给出1—3个真正必要的核心关系式并解释符号。

以5万字全文为基准，章首导入正文目标约800—1200字；其他全文字数按1.6%—2.4%同比例规划。

## 4. X.1至X.N：章内核心研究小点

X.1—X.N分别对应已确认的章内研究小点；默认N=3，必要扩展时N=4或5。每项自然包含：

- 本小点处理的电力对象、业务场景或运行约束；
- 局部问题和技术原因；
- 目标能力及对应预期目标、进度技术或内部性能要求；
- 具体人工智能、数据、知识、算法或系统技术；
- 核心原理、必要公式或流程；
- 具体实现、输入输出和接口；
- 本小点在完整技术链中的作用；
- 对应验证点和能力边界。

第二个及之后的核心小点开头应说明与前项的承接、并行、融合、补偿、反馈或工程化关系，但不得引用其他章节编号。目录或章节计划中已经确认的三级标题属于正文硬结构，必须依次输出并展开正文。

内部技术性考核事项必须在所属技术章X.1—X.N正文或其三级标题中隐性覆盖。正文不得出现“任务书”“考核指标”“考核要求”“考核细则”“规定指标”或内部编号。


## 5. 公式、伪代码和实现细节

本节必须执行 `formula-and-symbol-rules.md`。算法、模型、理论、机理、优化、决策、辨识、预测、评价和知识推理章节默认不得无公式。总体框架、技术概述和基础章节若承担共用变量、状态、集合、指标或约束定义，也应包含相应公式。 数据、语料与知识构建章默认标记为 `must`，应至少形式化对象或图结构、映射或对齐关系、质量指标、检索评分等真正承担技术论证作用的关系。

公式应围绕以下内容选择，而不是随意堆砌。既有公式需求分级和有效性规则保持不变，同时执行“描述性公式从简、技术公式从充分”：基本可用文字说明的简单计数、比例、集合归属和输入输出转写一般不单列公式；定理、电力物理关系、损失函数、目标函数、约束、更新、推断、评分和关键性能关系只要真实支撑技术主线就应充分写出。每个公式都要能够回答“删除后会缺失哪项技术论证或计算依据”；不能回答时应删除：

- 问题与输入输出的形式化定义；
- 核心模型或机理关系；
- 目标函数、损失函数和优化变量；
- 物理、业务、安全和资源约束；
- 状态更新、参数更新或推理规则；
- 评价指标、性能指标和可靠性关系。

每个核心公式的正文顺序必须是：先说明公式用于刻画什么问题，再给出公式，随后用“式中”或自然段定义所有首次出现的符号、上下标、单位和取值范围，并进一步解释其技术含义、假设和在算法或验证中的用途。符号对应明确电力对象时直接按真实设备或状态量定义，如节点电压、支路有功功率、变压器绕组温度或调度周期，不再追加泛化的“在电力应用中表示”。不得只给公式和符号表而缺少机理解释，也不得使用装饰性公式维持表面技术感。

过长推导放入附录，正文保留关键推导和结论；伪代码用于解释关键流程，不重复自然语言；实现细节包括影响可复现性或工程能力的参数、配置、软硬件环境和数据处理。

若技术章确实无自然可用的数学关系，必须在章节计划中将其标记为 `exempt`，说明为什么架构图、流程或接口定义足以表达技术内容，并经用户确认后方可无公式生成。

## 6. 证据与结果的嵌入式组织

默认不单设“实验和结果”“系统测试”或“应用验证”二级节。按照 `result-analysis-generation.md`，将必要的测试条件、量化结果、误差原因和能力边界放入X.1—X.N中与技术主张最直接相关的位置；需要展开时，使用能够说明电力对象和分析内容的具体三级标题。

`non-evaluation` 主题无论数据量大小、是否存在测试要求，都不得设置验证、评估、测试、实验类二三级标题；这些内容必须转写并嵌入技术正文。只有 `evaluation-related` 主题具有多组数据集、多类工况、多种对比基线、消融试验、参数敏感性分析或多张结果表，导致嵌入式组织明显破坏主线，或者用户明确要求时，才允许设置独立评估/验证二级节。章节计划必须记录例外原因。无论采用何种结构，均须覆盖全部核心研究小点的核心主张和全部内部技术要求，并把阈值、条件、结果和边界写成报告自身的技术陈述，不暴露外部规定来源。

如果用户尚未提供足够实验材料，不应仅因实验缺口停止章节计划。模型应为需要验证的当前章生成实验参考包，提出数据集方案、实验设置、评价指标、对比基线、消融/敏感性/鲁棒性设计以及模拟参考数据。参考包可以直接支撑报告草稿中的正常实验正文；若实际使用模拟数据，整章末尾统一说明一次，用户提供真实数据后再沿用相同实验结构替换。

## 7. 本章小结

本章小结的结构位置、篇幅、总—分—总组织、成果归纳、实验结果使用方式、生成时机与验收统一执行 `references/chapter-summary.md`。本文件不再维护另一套小结正文规则。

## 9. 技术正文的独立口吻

- 不写“任务书要求”“课题一提出”“按照课题分工”“最终材料中显示”“结题材料要求”等外部文件或行政任务表达；
- 不使用“课题一、课题2、子课题三”等带编号的课题称谓组织报告内容；
- 不写任何“第X章”“上一章”“下一章”“前一章”“后一章”等跨章互引；第一章1.3.2“研究思路”同样只描述研究内容之间的逻辑、依赖和推进关系，不使用章号复述全文结构；
- 引用既有成果时优先直接使用明确对象名称，如“电子规则库”“前述模型”“应用验证结果”；
- 需要概括衔接时使用“本文、前文、后文、前述、在此基础上、后续验证”等自然表达；
- 从材料中提取的考核要求直接改写为技术目标或验证标准；
- 上述改写不得改变指标数值和技术含义。

## 10. 每章生成必经检查

生成整章或任一分节前后，必须执行 `chapter-generation-preflight.md` 与 `three-subpoint-and-indicator-coverage.md`。生成前从已确认目录提取当前章完整标题锁定清单；生成后逐项核对一级、二级、三级标题的编号、名称、层级和顺序。正文展示前扫描具体章节编号和章序关系；任何正式正文中发现后都必须先改写。能够运行脚本时，先执行 `python scripts/validate_heading_coverage.py 当前章节.md --outline 已确认目录.json --chapter 当前章号`；分节草案使用`--section 当前二级节编号`，再执行 `python scripts/validate_report_language.py 当前章节.md --mode chapter`。任一已确认三级标题缺失时不得展示正文。

## 18. 核心技术主语的正文展开

每个技术章从已确认研究内容中读取 `primary_technical_subject`。X.1—X.N中被标记为 `primary_subject_section=true` 的二级节必须整体阐述该主体技术，不能把主体技术只作为标题中的定语或在多个子节中碎片化提及。

该节正文至少应覆盖：主体技术解决的问题与适用对象、总体技术思想、输入输出、核心组成及关系、主要处理/训练/推断/适配流程、关键约束与能力边界，以及它如何向下一研究小点提供输入或承接前序产物。三级标题用于拆解整体技术内部的关键组成，不得把“整体迁移适配技术”缩成若干孤立算法后就失去主体。

章节计划必须为该节分配足够篇幅，原则上不少于X.1—X.N正文计划字数的25%。正文完成后应检查该节实际有效字数是否达到其计划字数的80%，并确认读者在不阅读其他二级节时也能理解主体技术的整体方法框架。
