# 当前规则基线与一致性维护（v1.1.31）

本文件用于维护期冲突裁决。活动规则之间不得依赖“新规则覆盖旧规则”来共存；发现冲突时应直接修改旧规则，使所有活动源文件一致。`CHANGELOG.md` 与根目录各历史 manifest 只记录历史，不参与运行时规则。

- 技术类二级、三级目录标题必须使用中文语义技术签名：英文模型名、算法名和英文缩写可以保留在内部元数据或正文首次定义中，但不得直接裸露在目录标题；中文表达应简洁说明实际技术路线，不做生硬长全称翻译。

## 当前权威规则摘要

1. **目录架构、主题属性与章首过渡**：第一章固定为“项目概述”，包含1.1项目背景与研究意义、1.2国内外研究现状、1.3主要研究内容及思路及其固定三级结构；技术章从第2章起。目录阶段先自动登记 `report_theme_type=evaluation-related|non-evaluation`，只按报告核心研究主题判断，考核指标、验收要求、测试数据或实验安排本身不能触发评估类。凡章节存在二级标题，一级标题后不得立即出现首个二级标题：第一章及一般非技术章节先写50—100字无标题过渡正文；技术章继续执行既有长章首无标题导入（5万字报告约800—1200字）。技术章随后默认设置X.1—X.3核心技术二级标题；仅当预期目标/进度技术点无法合理归并时最小扩展到4—5个。`non-evaluation` 主题的二、三级标题不得出现验证、评估、评价、测评、验收、测试、试验、实验类章节词，本章小结紧随最后一个核心研究点；仅 `evaluation-related` 主题且满足大量成体系数据或用户明确要求时，才可在核心研究点后增加独立评估/验证节并将本章小结顺延。最后一章只保留“总结/总结与展望/结论”一级标题。
2. **标题命名与任务书技术词**：技术研究标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点。X.1—X.N及其技术类三级标题都必须独立显化电力对象/业务/运行约束、中文语义 `technical_signature` 和技术作用；技术族与任务动作仍需细化。“基于具体技术签名的……”在每个技术研究章及全文的使用比例保持40%—60%。技术章所有实质二级标题（仅“本章小结”除外）若出现“的”，以“的”之后完整部分为主语，该主语本身必须含强电力相关词；直接复合二级标题去除 `technical_signature` 后的任务主语同样必须具备强电力语义。同章三级技术标题任务主语继续保持唯一。预期目标、进度计划和考核要求中的关键且有实际含义的技术词必须建立 `heading_source_term_plan`：概括性 `broad` 词进入二级标题，窄 `narrow` 技术点进入三级标题，并在不破坏X.1—X.N技术链前提下分散覆盖；非评估主题不字面搬运验证/测试/验收动作词。技术研究章二、三级技术标题最终只以“技术”或“方法”收束，每章“技术”数量取最接近40%的整数，其余为“方法”，全文“技术”结尾比例35%—45%；该比例与“基于……”句式比例独立计算。标题长度优先级仍为“电力语义 + 中文技术签名 > 句式/结尾分布 > 25字符原则”。
3. **标题元数据、章内主线与技术粒度**：统一使用 `power_element`、`specific_computing_technology`、`technology_specificity_basis`、`technology_origin`、`shared_chapter_question`、`chain_order`、`chain_role`、`depends_on_previous`、`handoff_from_previous`、`output_to_next`、`chapter_mainline_map`、`parent_logic_link` 以及主体技术相关字段；`specific_computing_technology` 和 `technical_signature` 必须细化到技术变体/关键机制层级，不能只填RAG、图神经网络、Transformer、强化学习、大模型等技术族名称，也不能只填Span抽取、双塔匹配、置信校准、参数更新等任务动作。每个二级标题必须是当前一级标题核心对象、核心问题和核心输出主线下的直接子问题、关键步骤或核心输出，不采用“数据处理、模型优化、系统实现、性能分析”等词语黑名单判断；即使与整个项目技术上相关，只要其核心任务更属于相邻/后续章节，也不得放入当前章。历史版本中重复表达“人工智能元素/创新方法”的旧字段已废止，不再作为活动接口字段。
4. **目录可选技术**：目录生成时同步建立 `technology_option_sets`。对尚未由来源材料或用户唯一锁定技术路线的核心二级研究点，默认提供2—3个同 `problem_or_role`、同电力对象、同章节边界的候选，并只推荐1个；来源技术唯一锁定时设置 `source_locked=true` 并仅保留1个来源确认候选，不为凑数虚构替代技术。用户可见输出采用“正式目录正文 + 可选技术方案”两层结构；候选方案位于非编号说明区，不进入Word目录层级，也不计入二/三级标题数量。
5. **实验与数据**：REAL_PROJECT_EVIDENCE 严禁冒充或补造；REFERENCE_EXPERIMENT 允许并应按缺口生成实验设置、数据集方案、对比/消融/敏感性/鲁棒性/泛化实验、模拟参考数据、表格和结果分析。模拟值必须在结构化数据中保留来源状态，不得写成真实项目已验证成果；正式正文不逐项显式标注，使用模拟数据的章节在章末统一说明一次。用户有部分真实数据时仍可补齐其余参考实验缺口。单个实验可以展示多个指标，但结果分析正文最多重点分析2个；本章小结按每个核心二级研究点最多归纳1个代表性效果指标，无实验不强写。每章保留自己的技术指标，任务书硬指标集中由最后一个技术章节承接：能融合原实验则融合，确实不能融合时才最小增加总体性能分析位置；最后技术章小结写实际结果和技术效果，不复述阈值式验收句。
6. **插图与图表目录安全**：内容生成阶段不实际绘图。所有插图统一输出 `【此处插入图X-X】` + 图题，Word阶段转换为空白白框；模型可以生成模拟参考数据、结果表、预期趋势和绘图说明，但不能生成实际曲线、柱形图或带内容示意图。真正图题/表题必须独占一段并写成 `图X-X 图题` / `表X-X 表题`；普通说明段禁止以图号/表号起句，优先使用“该图应表达……”“该表给出……”“上述趋势/上述结果……”等表达。Word 排版只给确认过的真实题注写 F/T 隐藏 TC，清理普通说明段上的旧 F/T TC；`内容摘要` 与 `ABSTRACT` 必须保留 C 类隐藏 TC。最终保存时在 Microsoft Word 可用环境自动重新分页并更新主目录、图目录、表目录；视觉 QA 必须确认不出现“未找到目录项”且已有真实图题/表题时对应目录条目可见。
7. **摘要**：中文摘要固定三个连续自然段，总有效字数700—800；第一段200—250，第二段300—350，第三段补足总篇幅。正式中文摘要前先生成3—5个 `business_need_opening_candidates`，从不同业务需求/现实痛点/能力缺口角度形成可选首句，并选择1句作为第一段首句。第一段排序关键挑战，第二段按对应顺序写技术点；第三段以当前报告范围内 `task_book_assessment_results` 为指标性结果主集，任务书定量指标写实际结果，定性/混合指标也必须写形成的能力、功能、成果状态、适用性或工程效果。非任务书 `supplementary_result_metrics` 默认不写，确有补充价值时全篇最多1—2个；没有可用任务书考核事项时不得虚构。摘要与关键词同次生成英文版本，英文不得增加中文未确认的指标或结果。默认五个关键词，第1—2个为领域词，第3—5个分别对应主要研究点的具体计算/人工智能/算法技术词。
8. **篇幅**：普通章节/分节实际有效字数不得低于已确认计划字数的80%。技术章无标题章首导入仍按既有篇幅规则执行；技术章“本章小结”的完整篇幅、正文组织和成果归纳规则统一以 `references/chapter-summary.md` 为唯一来源；当前固定为500—600字的总—分—总结构，小结正文默认不使用引号包裹技术词、概念名或结论短语，只有必须保留的正式名称/直接引用例外。最后一章“总结/总结与展望/结论”属于固定例外：正文有效字数必须控制在700—800字，不适用普通章节80%下限规则，也不得通过二三级标题拆分篇幅。
9. **引用**：正式参考文献统一执行GB/T 7714—2015顺序编码制。
10. **审核与排版**：目录、章节、全文生成后必须调用 report-reviewer；最终Markdown确定性清洗后再进入Word排版。Word排版不重新定义内容规则。
