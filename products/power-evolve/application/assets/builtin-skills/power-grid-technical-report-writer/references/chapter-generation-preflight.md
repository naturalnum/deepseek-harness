# 每章生成必经规则

本文件是**每次生成技术章正文或分节正文前后都必须执行的短规则集**。开始生成当前章或当前节前必须重新读取；正文展示给用户前必须完成内部检查。其目的在于防止长报告后期遗忘研究范围、章节骨架、章内核心研究小点、电力标题比例、考核指标、公式、证据和语言要求。并必须同步执行 `three-subpoint-and-indicator-coverage.md`。

## 0. 课题角色与标题边界

生成前必须确认当前章的 `parent_task_id`、`parent_task_order` 和 `task_role`。前序课题为 `technical-research`，最后一个课题固定为 `engineering-implementation`，通常承担系统研发、平台实现、集成部署、示范应用或工程验证。

当前章只能使用所属课题和当前研究内容小点的技术、指标、数据、案例和成果。只匹配研究主题但属于其他课题的内容仍必须排除。

技术研究课题的一级、二级和三级标题不得把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，也不得机械改名；标题应直接描述实际采用的具体技术、方法、算法或模型。生成目录前必须判定 `report_theme_type`；`non-evaluation` 主题二、三级标题不得出现验证、评估、评价、测评、评测、验收、测试、试验、实验类章节词。工程实现课题标题应落到具体系统、平台、架构、模块、接口、部署、集成或应用。

每个技术章默认设置核心二级标题X.1—X.3；仅当预期目标/进度技术点无法合理归并时，才允许最小扩展至X.4或X.5，并登记扩展理由。各标题分别对应章内研究小点，必须从当前章研究内容、预期目标、进度计划和考核要求中拆解。每个标题必须逐项完整说明电力对象/约束、具有区分度的具体计算技术和技术作用，禁止纯计算机标题；技术类三级标题必须比上位标题更具体，并独立保留当前电力对象/业务/运行约束和具体技术签名；不得保留半句话、悬空修饰语或“数据处理、模型训练、参数设置、模块设计”等空泛标题。

## 1. 生成范围

- 只生成已确认计划中的当前章或当前节；
- 不提前生成下一节、下一章、摘要、总结或最终组装内容；
- 不擅自增加、删除或改名已确认标题；确需调整时先回到章节计划阶段；
- 从结构化目录加载当前生成范围的标题锁定清单。只要某个X.1—X.N下存在已确认三级标题，就必须逐项输出为`### 原编号 原标题`，不得用自然段、列表或加粗短语替代；
- 使用当前章节计划、覆盖矩阵、术语、公式清单、证据登记和占位策略，不依赖临时发挥。

## 2. 内容生成依据模式与材料边界

生成前必须读取`content-generation-mode.md`并确认：

- 默认模式是`source_grounded`还是`model_autonomous`；
- 当前章或当前节是否存在临时模式覆盖；
- 当前单元实际生效模式是什么；
- 模式选择是否已经由用户确认，不得自行猜测或每章重复询问。

### `source_grounded`模式

- 本章材料状态必须为`ready`，或者用户已经明确声明“本章交给模型生成”；
- 读取本章材料清单、材料—小节映射、材料缺口和已询问历史；
- 核心技术主张、方法、公式、参数、实现、试验设置和结果应能追溯到用户材料、范围内任务材料或已核验来源；
- 可以整理、重构、解释、补写逻辑衔接和电力物理意义，但不得把缺失项目事实自主补成既有成果；
- 已提供的内容不得重复询问，非阻塞缺口按章节计划使用占位或保守表述；
- 若用户仅对当前章或当前节临时切换，完成后恢复默认模式。

### `model_autonomous`模式

- 不要求逐章材料准备，不在每章开始时重复询问用户；
- 可以在已确认研究范围内自主设计技术路线、模型、算法、公式、架构和验证方案；
- 用户已提供材料仍应优先采用，不能被无理由覆盖；
- 自主设计不能把模型生成内容伪装成真实数据、真实试验结果、应用成效、第三方结论、论文或标准。允许按 `experiment-reference-generation.md` 生成带内部来源状态的实验设置、候选数据集、对比方法、消融/敏感性/鲁棒性方案和模拟数据。

无论采用哪种模式，其他课题隔离、证据真实性、公式有效性、独立报告口吻和逐章确认规则均保持不变。

## 3. 当前报告范围隔离

生成前必须读取`research_content_coverage.report_scope`及当前章的来源事项，并确认：

- 当前报告的目标研究范围是什么；
- 本章对应哪个范围内研究点；
- 本章允许使用哪些`in-scope`事项；
- 哪些内容已由用户确认可作为`shared-approved`共用基础；
- 哪些事项属于`excluded-other-task`，必须排除。

每章均禁止混入其他课题或其他报告范围的：

- 研究内容和技术路线；
- 模型、算法、系统模块和知识体系；
- 进度计划事项；
- 考核指标、测试条件和判定标准；
- 数据、实验结果、应用案例和成果结论；
- 章节名称、术语体系和技术主张。

同一材料中出现、主题相近或能够补足篇幅，都不能成为引用其他课题内容的理由。只有在覆盖矩阵中明确标记为`shared-approved`，且确属当前报告技术闭环所必需时才可使用；正文中仍不得出现其他课题名称或编号。

### 3.1 当前章与后续技术章职责隔离

生成前除课题范围外，还必须读取 `chapter_scope_boundary`。当前章二、三级标题和正文只展开当前一级标题为完成核心问题所必需的对象、输入输出、方法与实验，不得提前承担后续技术章的核心方法、独立实验、工程应用或结论。允许一句话说明当前章产物将作为后续输入，但不得因此展开后续章内容。

逐条检查核心二级标题与一级标题的父子研究逻辑：先抽取一级标题的核心对象、核心问题和核心输出，再判断每个X.i是否为完成该主线所必需的直接子问题、关键步骤或核心输出。不要按“数据处理、模型训练、参数优化、系统实现、性能分析、应用分析”等词做黑名单判断；即使标题电力语义和技术签名都完整，只要其核心任务转向本章主线之外、与相邻/后续章节更匹配，就必须调整。

## 4. 一级章名与研究内容小点映射

每个技术章一级标题必须直接对应当前报告范围内一个研究内容小点。生成前检查：

- 是否保存报告范围、所属课题、课题顺序、课题角色、当前映射单位来源标题、原始顺序和所属一级研究内容；总报告是否保存课题内全部小点；
- 章标题是否直接采用当前映射单位来源标题，或仅删除“研究、开展、构建、建立、提出、实现”等任务动作词；
- 原文不是名词性短语时，是否按课题角色补足允许中心词：技术研究使用“技术、方法、算法、模型”，工程实现使用“系统、平台、架构、模块、接口、部署、集成、应用”；
- 是否没有增加原文未提及的电力对象、人工智能算法、能力、指标或结论；
- 技术研究课题标题是否避免把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，并避免机械改名；非评估主题二、三级标题是否完全未出现验证/评估/测试/实验等章节词；
- 映射是否符合报告范围：总报告一个课题一个技术章，具体课题报告一个小点一个技术章，章序与对应单位原始顺序一致；
- 是否避免“研究内容一”“课题二”等来源编号；
- 是否没有混入其他课题或其他研究内容小点。

一级章名不是模型重新设计的完整解决方案名称。标题比当前映射单位来源标题信息更多时，必须删去新增信息并回到来源表达。

## 5. 技术章章首无标题导入和章内核心研究小点

每个核心技术章必须遵循：

```text
# X 技术章标题
[无标题章首导入正文：背景与意义 + 研究主题 + 总体技术路线/架构 + 关键输入输出与边界，适合时图文结合]
## X.1 章内研究小点一
## X.2 章内研究小点二
## X.3 章内研究小点三
## X.4 本章小结（默认）
```

`non-evaluation` 主题在最后一个核心研究点之后直接进入本章小结，不得设置验证/评估/测试/实验类二三级标题。只有 `evaluation-related` 主题且存在大量成体系数据或用户明确要求时，才允许在核心研究点后设置独立评估/验证节并将本章小结顺延1位。本章小结正文默认不使用引号包裹技术词、概念名或结论性短语，优先采用直接陈述；确需保留不可替代的原文名称或引用时才使用。章首导入正文不得显示“概述”“技术路线”“技术架构”或“技术路线与总体架构”等标题。技术研究与工程实现的路线差异通过章首正文内容和图示体现。章首导入继续执行本文件既有篇幅规则；本章小结统一执行 `references/chapter-summary.md`。

- `technical-research` 课题原则上使用“技术路线”；
- `engineering-implementation` 课题使用“技术架构”；
- 工程实现课题同时包含处理链和系统分层时使用“技术路线与总体架构”；
- X.1—X.3默认是核心技术二级标题；仅有明确来源目标且无法合理归并时才允许扩展到X.4—X.5；
- 全部核心小点必须依据当前章研究内容、预期目标、进度计划和考核要求拆解，不能从其他课题补足；
- 存在更多独立技术时优先归入默认三个小点，以三级标题展开；只有预期目标/进度技术点确实无法合理归并时才最小扩展到4—5个核心二级标题；
- 全部核心标题均需表达电力对象或约束、细粒度技术变体/关键机制和作用，禁止纯计算机标题；RAG、图神经网络、Transformer、强化学习等技术族名称本身不算具体技术；
- `non-evaluation` 主题不得设置独立实验、测试、应用验证、评估等二三级节，有限测试条件、量化结果和边界分析转写为实际技术约束或性能语义并嵌入X.1—X.N正文；
- 只有 `evaluation-related` 主题且大量成体系数据或用户明确要求时，才允许增加独立评估/验证二级节，并记录 `standalone_validation_mode` 与原因；
- 本章小结不计入核心研究小点；其正文遵循 `references/chapter-summary.md` 的少引号表达规则。

分节生成时，即使当前节不是默认X.1—X.3，也要核对全部X.1—X.N核心小点是否已完整锁定。

## 6. 章首无标题导入正文内容要求

章首导入不是二级小节，不显示任何编号或标题。它应直接位于技术章一级标题之后，并使用连贯自然段完成以下内容：

- 简要说明与本章研究主题直接相关的工程背景和现实问题，作用类似第一章“项目背景与研究意义”但必须聚焦本章对象，不重复第一章的一般背景；
- 引入本章研究主题，明确研究对象、适用边界、需要解决的核心问题以及对报告总体目标的支撑；
- 概括说明本章总体技术路线、技术架构或关键处理链，包括主要输入、处理阶段、关键模型/算法或系统模块、输出、反馈与边界；
- 说明全部核心研究小点之间的逻辑关系，为随后X.1—X.N的展开建立主线；
- 适合时配置技术路线图、总体架构图、数据流图或处理流程图，并在正文中解释图示，而不是只放图不解释。

技术研究课题侧重“技术路线”的输入—处理—输出—验证链；工程实现课题侧重“技术架构”的层次、模块、数据/知识/控制流、接口、部署、安全边界和容错关系。两者都在无标题章首正文中自然表达，不拆成“概述”“技术路线”“技术架构”或“技术路线与总体架构”等功能性小节。

以5万字全文为基准，章首无标题导入正文目标约800—1200字；其他全文目标字数按约1.6%—2.4%同比例规划。该范围用于章节计划和生成控制，不能通过重复背景、空洞过渡或与本章无关内容凑字数。

## 8. 研究内容、进度与考核指标覆盖

生成前读取当前章覆盖清单，确认：

- 本章需覆盖的来源研究内容子项；
- 章内核心研究小点分别覆盖哪些预期目标和主要进度技术；
- 本章范围内的指标、功能、性能、测试条件和能力要求；
- 每章自身技术要求登记 `assessment_item_id`、X.1—X.N正文融入位置、内容形式、表述方式、来源身份隐藏状态和证据状态；任务书硬指标另登记是否由最后技术章集中承接；
- 对 REAL_PROJECT_EVIDENCE，缺少真实结果的事项只能写成设计目标、验证方案或明确占位；对需要实验验证的内容，同时生成 REFERENCE_EXPERIMENT 的模拟参考结果和分析，不得把该句解释为“实验部分不能生成数值”。

各技术章自身技术性要求必须在所属技术章X.1—X.N正文或其三级标题中覆盖，至少说明所衡量的技术能力、对应电力对象或业务条件、计算或判定方法、单位、阈值、数据或工况条件、证据状态和能力边界。有真实结果时再给出结果和比较对象。不得只在第一章、总结章、附录或本章小结中一句带过，也不得把目标值写成已完成结果。

生成后逐项更新覆盖状态和 `confirmed_location`。正式正文不出现任务书、进度计划、考核指标、考核要求、考核细则、规定指标或来源编号，只写报告自身的技术目标、路线、实现、约束、性能、试验结果和边界。

### 8.1 实验指标重点与最后技术章硬指标

- 单个实验可以在表格或图中展示多个指标，但结果分析正文最多重点解释2个指标；优先1个主指标，必要时再选1个约束/代价/稳定性指标，其余指标不逐项展开；
- 本章小结按每个核心二级研究点最多选择1个代表性效果指标；该节没有实验或没有可靠量化结果时不强写指标；
- 每个技术章先维护本章自己的 `chapter_technical_indicators`；任务书中带明确阈值、数量、精度、时延、可靠性、规模等验收边界的硬指标统一由最后一个技术章节集中承接；
- 最后技术章先把硬指标融入与其研究对象、实验条件和技术主张一致的原实验位置；能融合时禁止新增标题；确实无法融合时，才最小新增一个总体性能分析三级标题，三级承载不下时才允许作为4—5个核心二级标题扩展的一部分；
- 最后技术章本章小结必须自然覆盖这些硬指标对应的实际结果与技术效果，不复述“超过××、不低于××、小于××”等任务书阈值句式，不写“达到/满足考核指标”。

## 9. 跨部分衔接与外部来源口吻

任何正式正文均禁止：

- `第2章中……`、`第六章的……`、`如第三章所述……`；
- `上一章……`、`下一章……`、`前一章……`、`后一章……`；
- `任务书中要求……`、`课题X提出……`、`最终材料中……`等来源表达。

优先直接使用“电子规则库、前述模型、应用验证结果”等明确对象；其次使用“本文、前文、后文、在此基础上、进一步、随后”。

## 10. 叙述聚焦与范围隔离联动

本节必须执行 `narrative-focus-and-power-grounding.md`。

- 当前小节和每个自然段先确定一个主要判断，不在同一段平铺多个研究主题；
- 减少“首先、其次、此外、同时、进一步、在此基础上、因此、综上”等过渡词和无信息过渡句；
- 尽量避免用多个“、”或“，”堆叠技术、动作和效果。确有离散并列时，各项必须属于同一上位概念并服务同一主旨；
- 并列项之间存在因果、先后、约束、包含或反馈关系时，改写为逻辑链；
- 并列内容较多时检查是否混入`excluded-other-task`事项。范围外内容直接删除，不能改名或泛化后继续保留；
- 删除范围外事项后重新确认段落中心，不得用新的无关并列项补足篇幅。

## 11. 电力对象与物理意义

- 技术介绍在确有联系的位置说明所处理的电网设备、状态量、运行约束和业务对象；
- 通用算法必须说明其如何作用于电压、潮流、负荷、温度、设备状态、拓扑、调度指令或安全边界等真实对象；
- 物理意义穿插在技术原理、公式解释和结果分析中，不单设空泛“电力应用意义”段落；
- 公式符号对应明确电力对象时直接按领域对象定义，例如`$T_i$表示第i台变压器的绕组温度`；
- 纯算法量或软件指标没有直接物理意义时如实说明，不强行附会。

## 12. 正文表达与标题锁定

- 正文以连贯自然段为主，离散步骤、模块、参数、约束和指标才分点；
- 已确认目录是正文标题的唯一真值源。生成整章时输出当前章全部锁定标题；生成二级节时输出该二级节及其全部锁定三级标题；生成单个三级节时输出该三级标题本身；
- 技术动机、机理解释、结果分析和本章小结不得写成汇报式清单；
- 沿用已确认目录，不把章节计划字段原样展开；
- X.1—X.N分别对应已确认章内研究小点，不统一使用“关键技术一、技术实现”等占位标题；
- 核心二级标题记录研究小点序号、来源依据、技术对象、技术方法、技术作用、电力元素和覆盖事项；三级标题记录相对上位标题的具体化依据；
- 所有核心二级标题均不得是纯计算机标题，每个标题都必须直接体现当前电力对象/约束；
- 标题不得以“的、与、及、和、基于、面向、针对、通过、利用”等悬空词结尾；
- 已确认三级标题不得被改名、调序、降级、合并或省略。正文内容不足以支撑某标题时应回退到章节计划阶段，不得在生成阶段静默删除。

## 13. 公式与符号

- 严格执行已确认的`formula_requirement`和公式清单；
- `must`章节或小节不得省略核心公式；
- 首次出现的符号、上下标、集合、向量、矩阵、单位、范围和假设必须解释；
- 公式必须说明技术含义及其在算法、系统或实验中的用途；
- 描述性公式从严删减：能够用一句话准确说明的简单计数、比例、单位换算、集合归属和输入输出转写一般不单列；
- 技术公式充分覆盖：本章存在真实定理、电力物理关系、损失、目标、约束、更新、推断、评分或关键性能关系时，不得用泛化文字替代；
- 不得用拆分等价式、重复变形或无后续用途符号凑公式数量；
- 不得用其他课题的公式、参数或指标定义填补本章内容。

## 14. 证据、数据与引用

- 不把实验参考包中的模拟数据、候选数据集、候选基线或预期性能冒充真实项目结果；当真实实验材料不足且本章需要验证时，应生成并展示实验方案、模拟数据、结果表和分析；来源状态保留在结构化数据中，正式正文仅在章末统一说明一次，供用户补充实验，不得仅以“无实测数据”为由省略；标准、论文和真实应用成效不得虚构；
- 只有当前报告范围内且可追溯的证据才能写成确定性结论；
- 不得借用其他课题的数据、测试报告、应用案例或成果结论；
- REAL_PROJECT_EVIDENCE 缺少数据时在已实现成果位置使用明确占位；实验部分可按 `experiment-evidence-layering.md` 生成带内部来源状态的 REFERENCE_EXPERIMENT 模拟数值；缺少文献且满足回退条件时只使用`【待补充来源】`；
- 结果段说明比较对象、条件、趋势、原因和能力边界；
- 生成“本章小结”时，统一执行 `references/chapter-summary.md` 的内容、证据和展示前检查；本预检文件不再重复维护小结正文规则。

## 15. 术语、数字和对象一致性

- 复用当前报告已确认的术语、缩写、符号、指标口径和对象名称；
- 同一对象不得随意更名，同一符号不得改变含义；
- 指标数值、单位和测试条件与证据登记一致；
- 不把其他课题的同名术语默认视为当前报告对象。

## 16. 字数验收

章节计划必须登记本章计划字数、80%最低验收字数，以及分节模式下每节计划字数和最低验收字数。正文展示前使用 `scripts/validate_word_count.py` 统计有效正文：汉字按字计数，连续拉丁字母/数字按一个词计数，Markdown标题、代码块、公式和链接地址不用于抬高字数。

- 当前节实际字数不得少于该节计划字数的80%；
- 整章完成时实际字数不得少于本章计划字数的80%；
- 不足时只补充本节或本章范围内的技术机理、实现细节、证据解释、实验分析、适用条件和能力边界；
- 禁止用重复背景、重复定义、空洞过渡、无效列表、装饰性公式或跨课题内容凑字数。

## 17. 展示前内部检查

当前章或当前节展示前必须检查：

1. 是否只生成当前允许范围；
2. 当前默认模式、临时覆盖和实际生效模式是否明确；`source_grounded`模式下本章材料是否就绪，是否严格按材料边界生成；
3. 一级章名是否仅为当前映射单位来源标题的必要名词化表达；
4. 技术章一级标题后是否直接进入无标题章首导入正文，且未显示“概述”“技术路线/技术架构/技术路线与总体架构”等功能性二级标题；
5. 章首导入是否完成本章背景与意义、研究主题引入、总体技术路线/架构、关键输入输出与边界说明，并在适合时安排图文结合；
6. 当前章全部来源事项是否属于`in-scope`或`shared-approved`；
7. 是否混入任何`excluded-other-task`内容、指标、数据、案例或结论；
8. 是否默认具有X.1、X.2、X.3三个核心研究小点；若扩展到4—5个，是否有无法合理归并的来源依据且均已实质展开；目录中已确认的三级标题是否全部按原编号、原名称、原层级和原顺序出现；
9. 本章范围内研究内容、预期目标、进度技术事项和内部技术要求是否全部进入X.1—X.N正文或其三级标题；
10. 每项技术要求是否包含能力含义、条件、单位、阈值、测试方法、证据状态和边界，并以报告自身技术表述呈现；
11. 三个核心标题是否逐项均为电力对象/约束—具体计算技术—作用表达；
12. 是否出现任务书、申报书、课题编号、最终材料、考核指标、考核要求、考核细则、规定指标等外部来源词汇；
13. 是否出现非法章节编号或章序互引；
14. 是否落实公式及符号解释，是否做到描述性公式从简、技术公式从充分；
15. 当前内容若为本章小结，是否已经按 `references/chapter-summary.md` 完成统一检查；
16. 当前内容若为第一章1.2研究现状，国内与国外是否统一使用“XXX等人”或“XXX团队”，未发生混用；
17. 是否存在无证据结论、虚构数据或非法文献占位；
18. 术语、符号、数字、单位和能力边界是否一致；
19. 当前生成单元和累计整章有效字数是否均达到计划字数的80%；
20. 标题覆盖脚本是否通过，尤其是三级标题保留数量是否为“已保留/计划 = 100%”。
21. 是否已提取 `primary_technical_subject`，并确认X.1—X.N至少一节为 `primary_subject_section=true` 的主体技术整体展开节；该节标题是否直接体现技术主语，计划篇幅是否原则上达到全部核心技术节正文的25%，正文是否实质说明整体方法而非仅列子模块。

能够运行脚本时，章节草案展示前执行：

```bash
python scripts/validate_heading_coverage.py 当前章节.md --outline 已确认目录.json --chapter 当前章号
# 分节草案改用：--section 当前二级节编号
python scripts/validate_report_language.py 当前章节.md --mode chapter
```

## 课题角色与核心技术标题必经核对

在生成每个技术章计划、目录调整或正文前，必须重新核对：

1. 当前章是否对应唯一且正确的映射单位：总报告对应课题并包含其全部小点，具体课题报告对应单一研究内容小点；章序是否与对应单位原始顺序一致；
2. 章标题是否只对当前映射单位来源标题进行必要名词化，没有增加任何额外技术信息；
3. 是否默认设置编号为X.1、X.2、X.3的三个核心二级标题；若扩展到X.4或X.5，是否有必要且可追溯的来源依据；全部核心标题是否按1—N连续登记 `research_subpoint_index`；
4. 全部核心小点是否从当前研究内容、预期目标、进度计划和考核要求中拆解，并且只使用当前所属课题的事项；
5. 每个核心标题是否完整具有电力对象、技术方法和技术作用，是否避免纯计算机表达；
6. 当前研究内容进度计划中的主要技术是否分配到核心二级标题，支撑技术是否进入相应三级标题；
7. 当前章的内部技术性要求是否全部进入X.1—X.N正文或其三级标题，并记录来源身份隐藏状态和证据状态；
8. 是否正确区分前序技术研究课题与最后工程实现课题；技术研究标题是否避免把“机制、建模、体系、定义”作为独立命题、中心名词或落脚点，并避免机械改名；是否已执行主题属性门禁，非评估主题二三级标题无验证/评估/测试/实验类章节词；工程实现标题是否落到具体系统、平台、模块、接口、部署、集成或应用对象；
9. 二级和技术类三级标题是否都能独立说明“处理什么电力对象/约束、采用什么具体技术签名、承担什么作用”；“基于……的……”句式是否仍保留电力领域语义；三级标题是否比上位标题进一步具体；
10. 全文每个X.1—X.N核心二级标题是否均直接体现电力对象/约束、具体计算技术和技术作用；
11. 是否因堆叠并列内容而混入其他课题的技术、指标、数据或案例。

发现核心技术标题仅为“知识抽取方法”“电网运行分析”“智能决策技术”“模型优化”等单边或泛化名称时，必须在生成正文前改名。功能性“实验、评价指标、实验设置、数据集、应用验证、本章小结”不适用对象—方法—作用完整关系要求，可保持简洁，但不得占用X.1—X.N核心标题位置；“概述、技术路线、技术架构、技术路线与总体架构”不得作为技术章二级标题出现。所有目录标题原则上不超过25个可见字符；但技术研究章二、三级标题优先保证具体 `technical_signature` 与40%—60%的“基于……的……”句式比例，必要时可超过25字符并记录长度例外。
