# Native turn continuation v2

English | [中文](native-turn-continuation-v2.zh.md)

`NativeTurnContinuationV2.transition()` settles an exact closed native turn under the current Session Writer and original operation attempt. Its required frame provider is `(client, request) => frames.verifyInTransaction(client, request)`. A prepared frame without a permanent owner claim cannot advance. An immutable claimed cohort remains consumed when prompt assembly fails before `step/start` or `user/message`.

For `kind: 'reconcile'`, the actual consumed-recovery provider reads the original claimed frame under a separately issued current storage attempt. `from.frame` retains the original consumption epoch and Writer; `from.operationToken` authenticates current storage, and `storageOperationEpoch` must equal that later current epoch. Original worker, Writer epoch and stored operation digest prove the historical command receipts. The current storage epoch protects the publisher seal, attempt closure, lease transfer and final clocks. This path creates no current claimed execution frame and cannot authorize another model or business tool call.

The transaction checks every cohort in the turn against the official pre-removal inbox projection, immutable origin/revision/claim records, original command receipt, exact step binding when a step exists, original accepted operation metadata, the frozen execution snapshot, and the actual publisher ordinal/revision/event watermark. It settles A and all origin operations genuinely consumed in that turn without issuing attempts for those origins. An older attempted non-owner input must separately prove bounded prepared-only history and exclusive consumption in this complete cohort. Native pending origins remain unchanged until the selected successor is issued.

The successor is the real `next-turn` head, or the first `next-step` input when no turn head exists. Its Grant retains its own original model settings, selected skill versions, tool selections, source references, native content and ordered attachments. The live TaskStore restoration supplies deployment/runtime fields; its broader Session attachment list does not replace the original origin audit. A historical prepared successor retains its complete original frozen snapshot, including bounded non-user text, with only epoch and bearer replaced. Its older attempts and frames remain recorded. The successor starts with a prepared v2 frame and receives execution permission only through the installed native execution authority after a complete claim and real step binding. Empty input or exhausted capacity parks the Session without minting a bearer or renewing Writer occupancy.

Host retains the entire strict v2 intent, transition identity and candidate token through an uncertain response. The unique durable receipt stores hashes and tokenless metadata. Exact retries return that original receipt and the same candidate bearer only while the original successor remains live; they do not extend expiry, remint or execute another origin. The sealed A publisher and old operation bearer lose authorization during transfer. Settlement, publisher seal, successor attempt/frame and receipt share one PG transaction, with original operation, presentation and Writer clocks checked before commit.

The service requires `pe_native_turn_transitions_v2` beside the actual v2 frame and input-ledger tables. Its row Writer epoch always references the original source frame's Writer in the existing four-column foreign key; receipt JSON records the current Writer, and the entire intent digest binds current storage authority. Exact retry checks both identities. Product initialization and transport installation own schema migration and endpoint registration. Private diagnostic SQL and source tests are not formal schema5, Host/browser acceptance or coverage evidence.
