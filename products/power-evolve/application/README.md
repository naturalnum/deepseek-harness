# PowerEvolve application plugins

English | [中文](README.zh.md)

This private package supplies three separately launched applications. The host bundle loads `scope`, `persistence`, `model`, and `host`; the platform bundle loads `platform`; the local device bundle loads `device`. Sharing a package does not share a process, database connection, or provider credential.

## Host

`scope` calls one configured platform endpoint and holds grants by native Session identity. `persistence` implements the native Session storage service for leased root Sessions; authenticated session creation belongs to the platform API. Unleased access, forks, and arbitrary native creation are refused. Inactive histories stay in PostgreSQL. Each operation restores an Agent and disposes it after durable completion.

`model` uses the native DeepSeek Messages codec. It flushes the consumed input and request records before inference, then presents the operation grant to the platform. `host` exports only the product Typert namespace through authenticated JSON RPC and bounded NDJSON subscriptions. Agent-scoped native tools expose the controlled note query, approval proposal, and a command receipt for the selected cloud or desktop target. Native operator-wide configuration, arbitrary filesystem access, process tools, plugin installation, and execution routes are absent from this composition.

Every resumed Agent installs an awaited `tools/execute` checkpoint before its tools are used. This includes nested transport calls: each dispatch persists its already-recorded event prefix, checks cancellation again, and only then enters the tool body. A missing writer or failed flush refuses dispatch. Later concurrent events and the tool result are not covered by that prefix checkpoint. The scheduler still attempts fenced failure settlement when persistence or handle disposal fails, preserving a known Platform error code such as `history_limit`; failed settlement is left for lease reconciliation. A full history is not truncated or silently replayed.

The Host sends every server-side Platform request, including token exchange, native Session and event calls, model traffic, and authenticated artifact download, through the configured internal `scope.platformUrl`. It does not follow artifact redirects. Browser navigation, upload tickets, CSP, Origin checks, and approval links use the separate public `host.platformOrigin`; browser input cannot select the internal endpoint.

For the native Web adapter, the platform login page can POST a newly issued Agent token from memory to the Host `/auth/exchange` endpoint. The platform consumes that token atomically and returns a replacement with the original expiry for HttpOnly, SameSite=Strict cookies scoped to `/native/api` and `/api/powerEvolve`; no credential belongs in a URL or browser storage. The adapter uses `powerEvolveBrowserAuth.authenticate(request)` on every product RPC or stream request, including WebSocket upgrades. Cookie requests require the configured Host Origin, while exchange requires the configured platform Origin; the platform remains the authority for expiration and logout. HTTPS is required outside loopback. The native carrier exposes bounded Session list, create, text prompt, cancel, page, projection, follow, and control calls plus the authorized Workspace follow baseline under `/native/api`. It also serves the upstream Workspace Files read, stat, list, byte preview, and change stream for tenant-owned Sessions. Paths visible to the browser are rooted at `/workspace`; the platform resolves them to each authenticated Session's bound POSIX Workspace and rechecks ownership for every call. Its WebSocket uses the upstream Gateway stream mux, while platform calls retain tenant authorization. Other native endpoints return a failure; the Host does not expose upstream operator endpoints.

Native assets resolve through the declared `cloud-web` package, and approval browser code through `contracts`; their physical directories need not be adjacent to this package. `PE_NATIVE_WEB_DIST` may select another built native directory; its asset allowlist still applies. The native CSP permits same-origin and blob workers for PDF and spreadsheet previews; login, approval and local Device assets retain their separate policies.

Native Word/PowerPoint previews use durable Platform prepare/status/content/cancel requests. The Host bounds polling and validates the source version, converter generation and complete PDF bytes before native multipart delivery. Browser disconnection requests cancellation without establishing parser termination. `officePreviewEnabled` enables this adapter; `officePreviewPollMs`, `officePreviewRenderDeadlineMs`, `officePreviewCancelTimeoutMs` and `officePreviewMaxActiveRenders` configure its per-Host limits.

Native WebSocket admission preserves actual 401 and 403 refusals. Platform connection failures, timeouts, unavailable verification, and invalid verification responses reject the upgrade with 503 without clearing the browser credential.

The loopback [trial Host proxy](../scripts/trial-lb.mjs) preserves non-101 upgrade responses, including 401, 403 and 503, with end-to-end headers. It removes hop headers, forwards at most the first 8 KiB of the rejection body within a 3-second response deadline, recalculates Content-Length and closes both connections. Connection failures remain 502; the proxy never retries an upgrade.

The native Session follow stream retains its last delivered event cursor across temporary Platform connection failures, read timeouts, and 502/503/504 responses. Snapshot and history reads retry at `host.pollMs`, under `scope.timeoutMs` and `scope.maxResponseBytes`. Recovery delivers the committed suffix without resubmitting input or replacing an already delivered snapshot. Cancellation stops waiting, retries, and delivery; any in-flight read retains its request bounds. Authorization denial, invalid responses, response-limit errors, and history gaps terminate the stream.

## Trusted platform

Office preview records use the [adjacent task migration](src/platform/office-preview-schema.ts). A cancellation received before admission remains a permanent cancelled receipt; it cannot become a runnable task. Parser reservations retain their slot across lease expiry and unconfirmed termination. Account disablement requests cancellation without releasing those slots; account deletion and backup admission refuse unsettled parser work. These records do not change native Session logs or prior execution facts.

Deployment backups exclude derived Office PDFs; terminal receipts remain history and do not guarantee PDF delivery, and reconversion requires a new request ID without replaying the old request. If restored receipts exhaust `maxRetainedJobsPerUser`, an operator must explicitly increase and validate that retention setting before admitting new conversions.

`officePreviewConfigFile` and `officePreviewKubeconfigFile` enable the isolated parser together; omission disables conversion. The latter accepts an absolute credential filename or `in-cluster`. The [complete JSON example](../platform/office-preview.example.json) supplies every placement, retention and resource budget. The private preview root must correspond to the configured PVC subpath and must not overlap Workspace, artifact, Home or Skill roots. Platform prepares physical input/output directories for UID 1000; parser Pods mount only those task directories and bounded temporary storage. Deployment must deny parser ingress and egress. The fixed image supplies fonts and its entrypoint; browser requests cannot supply commands, image tags or mount paths. The retained-job quota includes cancelled receipts; automatic history pruning is absent.

`accountManagementFile` enables the trusted account routes and defines the model catalog, initial settings, and account limit. The bundled Platform requires this private configuration; custom profiles that omit it return `account_unavailable` for account management. `accountBootstrapFile` is optional and explicitly selects or creates the first administrator under a database lock; existing identities never become administrators implicitly. Account login shares the Platform login limits, and every account POST requires the exact Platform Origin. The [account client](../client-account/README.md) owns the management UI and its browser-safe build checks.

Account deletion rejects unfinished directory or binding operations and retained business receipts. It inspects every owned storage root through descriptor-relative access, allowing only empty directories belonging to the persisted default binding and its ancestors. Opening the storage selector alone does not prevent deletion; links, special entries and files in unbound personal storage do.

The Platform serves the account package's trusted assets at `/account` and `/account/`, with files below `/account/` restricted to its built `asset-list.json`. Unknown paths do not fall back to HTML; source maps, traversal paths and unsupported asset types are refused. Responses disable caching and MIME sniffing, permit scripts and connections only to the Platform origin, and prohibit framing. Inline styles remain permitted for the migrated React components. The account package must supply its trusted build before this page can be served; the Host does not serve these assets.

Identity verifies persisted accounts and issues separate expiring Agent, approval, and account credentials. Seed configuration only inserts missing identities; it does not overwrite account changes. Session APIs derive ownership from the authenticated identity. Task admission, request deduplication, per-user capacity, claims, and lease epochs commit in PostgreSQL transactions. Event appends require the current grant; repeated records must match exactly. Model egress validates the grant, model and output allowance and injects the real provider key. Each user has one default POSIX Workspace and may create additional titled Workspaces through `/workspaces/create`; `/workspaces/list` returns only that user's metadata. Session creation binds one owned Workspace permanently, defaulting to the original Workspace when no ID is supplied. The original platform `/files` API remains scoped to that default; native reads and product `/files/session` operations use the Workspace bound to their authenticated Session. File writes use expected revisions and request IDs and refuse a user whose writable cloud mount is reserved or active. The platform also owns each user's personal skill library; selections are frozen when a task is accepted. The native skill registry exposes only the accepted catalog; the `skill` tool reads selected instruction bytes on demand. The `skill_resource` tool lists verified manifest entries or reads bounded UTF-8 text through the platform. Both reads recheck the grant after filesystem access and create no Sandbox.

Login and approval-login share two PostgreSQL limits across all Platform replicas: a small window keyed by the SHA-256 digest of the exact submitted account name, and a separate high-capacity global overload window. Every request counts toward the global window before its body is parsed; valid account names also count toward their own window before password verification. The trial Platform load balancer connects from loopback and forwards caller-supplied `X-Forwarded-For`, so neither the socket peer nor that header identifies a user for admission. The default 60-second window permits 20 attempts per account, tracks up to 100,000 account names, and permits up to 100,000 requests globally; size the global threshold for expected login traffic and authentication capacity. Reaching the global threshold rejects all login attempts until its window expires. Schema 19 stores the admission configuration in one PG row. A replica with different login limits or `sandboxConcurrency` refuses to start. To change those limits, stop all Platform replicas, update `pe_platform_admission_policy` to match the new configuration, then start them with the same values.

Artifact publication copies one authorized Session file of at most 2 MiB into a private directory outside Sandbox mounts and commits immutable, owner-scoped metadata in PG. A stable request ID deduplicates publication. Listing, bounded preview, and verified byte download recheck ownership; subsequent Workspace edits or Sandbox recycling do not change a published artifact. The Host allows a same-origin safe GET with its scoped cookie for a download link, verifies the credential through the platform, and forwards the bounded response without retaining a platform secret.

Workspace batch downloads use `filesDownloadPrepare` followed by a same-origin content GET. The Platform rechecks Session ownership and prepared file digests, then streams one file or a ZIP while the Host forwards bounded chunks. Changed sources reject preparation or terminate an incomplete response. Cancellation propagates to the file helper; each transfer retains its permit until its actual reads finish. Credentials are rechecked before further output, and a stalled socket is bounded by the transfer deadline; bytes already sent cannot be withdrawn. No Sandbox is created and no file bytes are stored in the Host. The [file completion slice](../S2-COMPLETION.md) owns the client protocol and acceptance scope.

`fileDownloadMaxFiles`, `fileDownloadMaxTotalBytes`, `fileDownloadMaxConcurrentTransfers`, `fileDownloadMaxUserConcurrentTransfers` and `fileDownloadTransferTimeoutMs` configure selection count, source bytes, per-Platform transfer capacity, per-user capacity on that replica, and total lifetime. Preparation uses the same capacity pool and the Host's ordinary RPC timeout. Host content transfers use their separate `fileDownloadTimeoutMs`; both transfer defaults are 60 seconds. These are replica limits, not cluster-wide quotas. The existing 2 MiB single-file limit still applies.

The connector queries a controlled HTTP note API without an execution sandbox. A write tool persists one exact proposal in PG, then returns an approval receipt; it cannot directly perform the write. A separate platform-origin page shows the content and fingerprint. The platform checks the action owner and reviewed fingerprint before deciding, checks the current permission before dispatch, and uses a stable remote idempotency key. Unknown results are queried before any retry. A terminal result queues one platform-origin follow-up in the original Session. The API credential stays in the platform process.

Remote MCP uses immutable per-operation tool declarations, a separately scoped management service, and [controlled transport](tests/s6-mcp-controlled-transport.md). Schema 23 stores exact action arguments, human decisions, revocable session or persistent tool permissions, and one-use dispatch intent. Only a committed new permit authorizes the first remote invocation; an expired intent becomes uncertain and stops its automatic request chain. Successful results preserve the original tool selection and root call/time budget through MCP, API, cloud, desktop, STDIO, and SSH continuations. Raw MCP arguments and results use JSON columns to preserve escaped NUL. The Platform runs separate discovery and action workers, accepts credentials only through its direct upload endpoint, and authenticates human decisions with the approval audience. The Host registers the admitted native MCP definitions and returns durable receipts; remote output resumes the same Session. Unknown dispatch or completion acknowledgements never authorize another remote POST. Shutdown waits for these workers and their final PG writes before closing the database pool. The trusted approval page supports exact once, session, persistent and reject choices; native browser and real-model acceptance remain release gates.

MCP preserves the advertised JSON Schema in native model requests and validates arguments and structured results independently. The product validator supports draft 2020-12 (the default), 2019-09 and draft-07, including numeric bounds, string lengths, array bounds, composition and bounded acyclic document references. It refuses regex/format constraints, `uniqueItems: true`, dynamic or recursive references, external references, nested dialect or ID changes, asynchronous validation and custom vocabularies. Fixed depth, schema-size, reference-expansion and estimated-work limits bound synchronous validation in shared services; see [the validator](src/mcp-json-schema.ts) for exact limits. Unsupported constraints fail discovery explicitly; they are never removed or ignored.

Set `PE_REMOTE_MCP_CONFIG_FILE` to an absolute Platform-only JSON filename based on [the complete example](../platform/remote-mcp.example.json). Its `credentialKeyFile` contains a private 32-byte base64url key. Management, admission, action and transport limits are required; `renewMs` must be shorter than both worker leases. `cleanupMs` and `cleanupBatchSize` bound periodic owner cleanup. Expired drafts free capacity while their creation records remain for the one-hour frequency limit. Outbound destinations default to public HTTPS; an operator exception names an exact origin, approved IP addresses, optional `allowHttp`, and an absolute `caFile` for a CA bundle. Set `requireOriginException: true` to reject unlisted origins before DNS; an empty exception list then denies all remote MCP destinations. Personal connection requests cannot set these exceptions. Startup refuses malformed configuration; do not mount this file or key into the Host.

The platform issues owner-scoped, short-lived SSH credential upload tickets. The browser sends metadata and serialized byte length through the Host, then uploads the versioned envelope directly to the platform origin. Passwords, private keys and optional key passphrases are bounded to 4096, 7168 and 1024 UTF-8 bytes respectively. Historical raw-password uploads use an explicit separate format. A completed retry must upload the same secret bytes before receiving its original result; a changed secret is rejected. Profile settings bound connections, pending tickets, ticket lifetime and completed-request mismatches. Credentials are bound to owner, connection and version identities. PG stores only ciphertext; the Host never receives credential values.

Personal SSH management uses stable request IDs and compare-and-swap configuration revisions. Editing explicitly retains or replaces credentials; clearing a private-key passphrase is a distinct choice. A lost mutation response can be recovered through an owner-scoped receipt. Deletion leaves a disabled tombstone, while immutable configuration and credential versions retain historical approval targets. Disabling or deleting a connection remains possible when Runner configuration or credential access is unavailable. New installs require an isolated Connector Runner and destination policy; this intake grants no SSH execution in the shared Host or writable programming Sandbox.

The fixed process MCP preset gives each user a revisioned, owner-scoped connection on the native Plugins page. Task admission pins the enabled connection revision; a native Agent tool submits its stable tool-call ID through the shared Host to the trusted platform. The platform durably accepts the call, creates a short-lived Connector Runner Pod with no network egress or user file mounts, and starts only the image-owned read-only STDIO MCP server. A terminal or uncertain result is persisted and queued once into the originating Session. Reclaimed dispatch intent queries the exact Pod UID, Runner instance, and call digest; missing status is uncertain and never triggers another POST. The Host receives only connection metadata, a receipt, and bounded result text. This preset does not accept user commands, packages, or credentials.

Resource recovery accepts recognized Kubernetes NetworkPolicy, Service, and Pod defaults while rejecting changed selectors, ports, execution settings, and Pod identity. Terminal resources receive cleanup attempts even while new calls remain queued.

An optional `sshRunnerImagePullSecretName` selects one registry Secret in the Connector namespace for both SSH and process MCP Pods. Its name must be a DNS label and requires an enabled Runner; an empty value leaves the reference absent. The operator provisions the Secret separately. Only its name enters the Pod's `imagePullSecrets`; its bytes never enter the Host or Runner filesystem. The expected reference is part of process MCP resource recovery, so a changed or additional pull reference is rejected rather than treated as an API default.

After persisting a confirmed `running` SSH authentication or command, the worker releases its lease for observation after `sshRunnerPollMs` (default 500 ms, minimum 100 ms). The next worker queries the original Runner instead of waiting for the full recovery lease or sending another command. Owner and epoch checks reject stale lease renewal and release attempts. Uncertain calls retain their existing reconciliation schedule.

For an enabled SSH connection, task admission pins its connection and credential revisions. The native Agent tool may submit one exact command per operation using its stable tool-call ID. Its system instructions list the selected connection metadata in a fenced `jsonl` block, with each connection UUID separate from username, host and port; the `connectionId` argument accepts only the exact selected UUID. The trusted platform freezes any configured working directory into the command before computing its fingerprint and encrypting it in `pe_ssh_execute_actions`. Absolute paths are literal; relative paths and `~` use the remote HOME. Directory bytes, including spaces, are preserved; a failed directory change exits before the submitted command can run. The complete rendered command remains within 16,384 UTF-8 bytes. A separate approval identity reviews that command, the historical target, host-key fingerprint and revisions on the platform page. Later edits never alter an existing approval.

Only approval creates an `ssh.execute` call. The worker verifies the Pod's destination and egress policy, then atomically checks the call lease, matching approval, cancellation and current connection revisions while committing one dispatch permit. Runner I/O begins after that transaction commits; revocation and cancellation can complete while the network request is pending. The call row holds neither command nor credential plaintext, and the result is encrypted with the action. Revocation blocks new permits but cannot retract an already committed permit, whose POST may arrive afterward. Recovery queries the original Pod UID, Runner instance and digest; it never reuses the permit to send another POST. Bounded output or terminal status continues the original native Session once.

An SSH Runner failure is definitive only when `effectMayHaveOccurred` is explicitly false. A true or absent flag leaves the action uncertain, as does channel closure without an observed exit code or signal. The Platform persists that outcome, queues one continuation forbidding automatic retry, and permits cleanup without redispatch after restart. An observed nonzero exit code or exit signal remains an execution result; callers must inspect it before claiming command success.

The execution service accepts a command only under the current Session grant and records its call ID before returning. It creates one Agent Sandbox on demand for the root Session, mounts only that Session's owned POSIX Workspace and the user's Home, and queries the runner before any retry. Each user has one physical Kubernetes resource slot while Home remains shared; a different Session can use it only after the previous Pod UID has native stop evidence in PG. The owned Workspace mount source is prepared before slot acquisition; Home and Skill package mount sources are prepared and checked under the per-user transaction lock before a reservation is committed. A local preparation failure leaves no reservation or Kubernetes mutation. The new Session receives a distinct Pod UID, runner identity, and token. An interrupted Kubernetes creation or missing stop proof blocks replacement, including after a lease expires. Completed results queue a platform-origin follow-up in the same Session. Idle recycling retains Git files and history. Kubernetes credentials stay in the platform process.

A retry of interrupted creation observes only the same Session's reservation, owner, generation, storage binding and existing Secret, Service and Sandbox. It captures the Pending Pod UID in the creating instance; the reserved slot retains null Pod and Runner identities until both records become ready together. A disconnected finalizer write can continue for that captured UID. Missing resources or a changed captured Pod do not permit creation, slot release or replacement.

Cancelling an uncertain creation with a captured Pending Pod UID keeps the original execution claimable until cleanup finishes. The worker leaves the mount slot reserved and marks the instance deleting, which fences late readiness observations. It deletes the owned Sandbox by UID with background propagation and retains the original Pod finalizer until native deletion evidence is committed in both PG records. An unscheduled, deleting Pod uses `UNSCHEDULED_DELETING`; an assigned Pod requires strict `KUBELET_STOPPED` evidence. These creation proofs carry a null Runner identity and do not relax ready-writer or Workspace recovery proofs. Only confirmed removal of the Pod, Sandbox, Service and Secret releases the slot; cancellation then becomes terminal. Account revocation permits this cleanup, suppresses continuation and never dispatches the cancelled command. Missing original identity, replacement resources, unknown parent finalizers, unavailable stop evidence or lost lease leave the reservation blocked for the same execution's next claim.

Before upgrading, check for cancelled terminal executions that still own reserved creation records. This cleanup requires a nonterminal, cancelling execution lease and does not automatically claim reservations already stranded by older versions. Preserve those identities for operator reconciliation; clearing the slot or treating resource absence as stop evidence is unsafe.

Before its first Runner POST, the execution worker must durably capture the ready Pod and Runner identities under its current lease. A creation outcome without that capture may recover to `starting` only when the original authorized Sandbox becomes ready; status is queried before its first dispatch. Once an identity has been captured, an uncertain command with missing Runner status remains uncertain and is not dispatched again. Cancellation, account authority and mount authorization still gate dispatch.

`sandboxConcurrency` caps active execution workers across all Platform replicas. Each worker claim counts live PG leases under a shared transaction lock; a crashed worker releases capacity when its lease expires and a replacement reconciles the execution. A `running` command that has been deferred for later observation releases its worker lease, so this limit is distinct from the number of live Pods. Per-user mount slots govern Pod replacement.

New Sandbox Pods receive file scan budgets from the Platform Profile: `sandboxScanMaxEntries` (default 4,096; maximum 65,536), `sandboxScanMaxHashBytes` (32 MiB; 200 MiB), `sandboxScanTimeoutMs` (5,000; 30,000), `sandboxScanMaxSnapshotBytes` (1 MiB; 4 MiB), and `sandboxScanMaxFiles` (100; 100). All are positive integers; snapshot bytes have a 1 KiB minimum. Each scan before or after a command has its own budget. Changes apply to newly created Pods. Platform byte verification has a separate `sandboxFileVerifyTimeoutMs` (default 15,000; range 100–60,000). Limited or failed scans do not establish an empty complete result, and metadata verification failure does not discard an authenticated terminal command result.

The platform also stores device identity, directory grants and desktop command state. A separate local device profile pairs with a short-lived code, keeps absolute paths and its token on the device, and runs commands in disposable Docker containers mounted to one authorized directory. It journals command identity before creation and checks container state after restart. Files move between desktop and cloud only through an explicit, bounded device action.

An owned Electron launch explicitly sets `PE_DEVICE_LAUNCH_ID` and an IPC channel. The Device installs private lifecycle listeners before initialization and publishes readiness only after official Profile `appReady`. Quiesce closes command and local API admission, waits for owned actions and picker termination, then reads and syncs original journal and cleanup records while retaining the process lock. Read or sync failure refuses a drain report; process quiescence does not establish container termination. Terminate requires that launch's exact instance and completed drain. Parent disconnection performs the same drain before requesting application exit. Standalone Device launch retains its existing ready file and shutdown behavior; see the [desktop adapter](../desktop/README.md).

Configuration is explicit in the three bundle patches. Required secret values are read from private files at startup. The private artifact root must be outside the writable Workspace root. Workspace file access requires Python 3.9+ and the packaged [descriptor-relative helper](../S2-SAFE-POSIX.md); startup fails closed if it is unavailable. Database pool, timeouts, request/history/output limits, per-user admission and Workspace count, host concurrency, polling, lease renewal, and subscription bounds are configuration inputs. Readiness files identify the owning process instance for the trial lifecycle script.

The Platform logs a PostgreSQL connection-loss transition from either its request pool or bounded health pool. `/health` reads the current schema version from PG; it returns HTTP 503 with `ready: false` and `schema: null` while PG is unavailable and returns 200 with the observed version after a successful reconnect, so the Platform load balancer stops routing to an unavailable replica. An interrupted login fails without issuing a credential; the client must explicitly retry after recovery. The health probe does not dispatch or replay work. Durable task and execution workers retain their existing lease and reconciliation rules. Leased transactions also handle connection errors between queries: a lost connection cannot commit the callback result and is discarded, while a callback failure retains its original error. This does not cancel external work already started or resolve a lost COMMIT response.

The bundled catalog contains nine pinned packages from the reference product. Installation is owner-scoped and request-deduplicated; configured preinstallation applies before a new or existing Session accepts input and before listing personal skills. Disabled and revoked installations remain disabled or revoked. An explicit catalog upgrade may replace only the current version of that same built-in package, preserving its identity and disabled state; it cannot replace a same-name private upload. Accepted Operations retain their original package bytes. Complete selections of the four report packages receive a verified, immutable directory tree from their persisted installation receipts, so sibling references resolve across later catalog changes. Package revocation rejects new reads; it cannot erase bytes already read or mounted by a running execution. The `office` tool submits a bounded, quoted OfficeCLI command to the same durable cloud execution service as `cloud_exec`; only the Sandbox image runs OfficeCLI and document libraries. `load_skill` output starts with the product runtime instructions: resident mode is disabled, every command names its file, and direct mutations persist before returning. The upstream guide follows unchanged.

Schema 20 adds owner-bound catalog installation receipts, including retry IDs that reuse an existing package version. Accepted skill metadata allows up to 256 entries; claiming work does not require instruction files. Current grants can read only their persisted selection, and an expired grant is rejected.

The local `scripts/trial.mjs` launcher accepts `PE_TRIAL_DATABASE=external` to reuse an existing PostgreSQL server. Provision a separate trial database and its private `database-url` before starting; this mode performs readiness checks without creating a database container. The default remains `compose`. For synthetic MCP acceptance, `PE_REMOTE_MCP_FIXTURE=1` adds an owned loopback target at `PE_REMOTE_MCP_PORT`; its private `remote-mcp-fixture-users.json` supplies at least two `{username, token, unitPrice}` records (tokens at least 24 characters). The target provides private item lookup and quote calculation, logs only synthetic calls locally, and performs no purchases. Its `/mcp/public` route supplies fixed public test data without authentication, `/mcp/empty` returns an empty tool catalog, and `/mcp/slow` delays requests for cancellation and timeout checks; disconnect and shutdown release pending requests. `stop` also closes it when the same fixture flag is present. The launcher passes `PE_REMOTE_MCP_CONFIG_FILE` only to profile preparation, which writes it into the Platform configuration; the Host process does not receive that environment variable.

## Recovery and limits

Cloud execution resolution accepts one independently approved stop-and-reconcile intent for an owned `uncertain` execution with a complete frozen writer identity. The intent revokes the ordinary execution lease and exclusively owns cleanup against writer admission, idle recycling and binding recovery. Identical request retries retain the original identity and receipt; identity changes permanently block the intent. A verified Runner terminal result is preserved; otherwise exact kubelet stop evidence permits `closed_unknown`, which reports an unknown command outcome and forbids replay. Terminal state, the original unique continuation and mount release commit together. Disabled accounts retain cleanup without model continuation.

Resolution list, inspect and status use Agent-authenticated Host RPCs. Confirmation is available only under `/approvals/executions/resolve`, with an independent approval bearer and the exact configured Platform Origin; missing Origin is refused. The existing trusted approval page consumes the standalone shared browser validation build, retains a stable request after a lost response and queries status before an explicit retry. Host and Agent invocations cannot confirm resolution or submit stopped-writer evidence.

Schema 28 preserves the complete Runner dispatch request before its first HTTP dispatch and stores resolution identities, owner/epoch leases, observations, stop evidence and receipts. Historical executions without a dispatch snapshot can verify a reconstructed request only when its admission digest matches the original; changed timeout configuration cannot authorize a guessed request. Missing identities in creating reservations remain on the conservative creation-cancellation path. Temporary infrastructure failure retains the intent for the same identity; Pod absence and deletion acknowledgements never establish a stopped writer.

Schema 27 retains existing Workspace and Session identities while moving physical storage selection into owner-scoped spaces and generation-checked bindings. The native Workspace creation carrier accepts a stable request ID and an optional private directory selection; product storage RPCs accept no physical roots or writer-stop claims. Directory creation and binding recovery recheck the browser bearer under the account lock before accepting or retrying an intent. Revocation rejects new browser requests; already committed intents may continue while the account remains enabled. `workspaceRecoveryPollMs` and `workspaceRecoveryLeaseMs` configure the PG recovery worker; shutdown waits for its final database writes. Downloads retain the prepared binding generation, and publication reuses its authorization transaction. Backup refuses pending directory or binding changes; restore uses recorded storage root keys for schema 27 and legacy Workspace IDs for older backups, preserving absent roots as absent. See the [file completion slice](../S2-COMPLETION.md) for recovery admission and pending acceptance.

Recovering bindings retain ownership of writer cleanup. Shutdown releases the recovery lease while retaining its captured writer and committed stop proof for another worker. If recovery becomes blocked and the account is disabled or deleted, the idle recycler may stop that account's exact current writer. Cleanup retains the binding fence and generation; it requires persisted kubelet stop evidence before freeing the mount slot. After finalizer removal, cleanup tolerates a briefly visible Pod only while its exact identity, terminating state and durable proof still agree. Re-enabling the account requires an explicit recovery retry before rebinding.

Schema 26 stores an optional expected source digest with each immutable artifact publication request. Existing publications retain a null value. The same request ID must retain its Session, path and expected digest; conditional publication rejects changed source bytes. Execution file observations use the existing execution result column, without changing native Session event types. See the [file completion slice](../S2-COMPLETION.md) for verification and rollout requirements.

Schema 24 separates immutable SSH configuration and credential versions from current connection pointers and owner-scoped mutation receipts. Migration preserves existing ciphertext and its original encryption context, including historical calls and approvals. Missing historical credentials, inconsistent historical targets or conflicting request IDs abort the entire migration. Stop Platform writers and retain a verified database and key backup before upgrading; an older build requires restoring that backup rather than downgrading these records.

The local backup CLI supports an existing PostgreSQL server and preserves MCP configuration, encryption keys and referenced CA files. Restoring requires an independent empty database and private storage paths. `PE_BACKUP_KEEP_STOPPED=1` preserves the stopped application state; it does not stop PostgreSQL. See [backup prerequisites and failure boundaries](../TRIAL-S7C-BACKUP.md) before using either database mode.

Schema 22 stores immutable remote MCP configuration, credential and catalog versions separately from the fixed connector preset. When `TaskStore` receives a remote MCP admission policy, input acceptance saves the owner's complete enabled tool selection, its original schemas, and the exact native model declarations in the same transaction as the Operation. Each new selection includes the current connection display name, its stable ID and the original tool name as quoted metadata in the persisted model description. Labels grant no authority. Duplicate admission and task recovery retain their original declarations after catalog or display-name changes. Unsupported schemas, required MCP tasks, name collisions and whole-selection budget excess reject admission; no tools are silently dropped. The model proxy loads the accepted definitions from PG and refuses changed names, descriptions or argument schemas from the Host. It validates native mid-conversation tool additions against those declarations and derives the fixed provider beta header from valid system-role references. The default Flash route accepts deferred additions; Pro receives complete immediate declarations. Historical calls and results remain unchanged and grant no permission for new actions; Host-supplied beta headers are not forwarded. This admission path does not create an execution Sandbox or grant permission to call a tool. Generic MCP is disabled unless the Platform Profile receives an explicit private configuration file.

Schema 21 stores native events and cloud, desktop, and connector result payloads as PostgreSQL `json`. These opaque values preserve escaped NUL and other JSON string contents that `jsonb` cannot represent. Read whole values through the driver; do not cast them to `jsonb` or extract arbitrary text in SQL. Ownership, ordering, state and indexes use separate typed columns. Apply the migration with Platform writers stopped and a verified backup; older Platform builds refuse this schema, so returning to an older build requires restoring its pre-upgrade database and files.

Platform-origin continuation input retains up to 256 KiB of JSON-encoded text, further bounded to half `maxEventBytes`. Larger results become explicitly labeled head/tail excerpts; the original Operation input and execution result remain unchanged in PG. Claims apply the same bound to already queued results after restart. User prompts remain limited to 16,384 characters.

Kubernetes resource responses are bounded to 256 KiB. Cloud Sandbox and SSH Runner adapters explicitly use a separate 1 MiB response budget, covering the sixfold JSON escaping of their bounded output streams. A Runner token alone does not increase the resource budget. Truncated responses reject immediately; oversized responses and socket inactivity timeouts reject and close the request. These transport failures retain the execution's reconciliation rules and do not authorize command replay.

A client receives `accepted` only after the operation commits. An unconsumed input can be delivered after restart. Consumed input with no completed turn is closed as interrupted by native DSH restoration and reported as failed. It is not automatically sent to the model again. A lost completion response is reconciled from the recorded turn when the lease is reclaimed.

Session cancellation checks the authenticated owner in PG. An unclaimed input settles as failed without starting a model call; a running input stores a cancellation request that the leased Host sees on renewal. A live Host cancels its Agent and flushes the native log before releasing its grant. A replacement Host does not replay a cancelled input, and a later prompt can use the same Session. Repeating cancel with no active operation succeeds without changing history. If a turn finishes before the Host observes the request, its recorded completion or failure wins over the late cancellation.

Execution grant checks recheck expiration against the current PostgreSQL clock after acquiring the Session lock. A renewal or event append that waits beyond the deadline fails with `lease_lost`; renewal also checks the deadline in its final update. Claims and successful renewals calculate expiration from the current database time when writing the lease, so lock waits do not consume the new lease duration.

Account disablement commits with revocation of existing Session grants, terminal failure of queued or running inputs, and cancellation of unfinished approvals and executions. New browser acceptance and approval recheck the original bearer under the account lock; new execution dispatch checks the current account. Workers retain execution identities for cancellation, observation and exact cleanup. Actual results remain stored with `account_disabled` and cannot queue an Agent continuation, including after re-enable. Re-enable admits only new work; password rotation revokes browser credentials while accepted execution grants remain valid for active accounts, including during a required password change.

This slice supports root text conversations, bounded file transfer and text editing, personal skill instructions, two controlled remote API tools, cloud commands, and desktop commands in selected local projects. Completed output arrives through durable event subscriptions; partial model tokens are not broadcast to browsers. The private profile does not promise compatibility with every native controller or Session persistence consumer. It refuses unknown Session generations rather than migrating the older PowerEvolve database. An unresolved remote write or command remains in PG for reconciliation; the host never replays it blindly.

The local trial runs separate host and platform processes under the current OS user, so it does not enforce process identity separation. Cloud commands run under gVisor in namespace-scoped Agent Sandboxes; local commands use Docker on a paired device. Descriptor-relative Workspace file access resists concurrent symlink replacement. Production deployment still needs separate service identities, network egress rules, device attestation, and multi-node POSIX mount validation before accepting untrusted tenants. The connector is a loopback trial target, not a general third-party connector catalog. Production ingress is a later slice.
