# Native input owner routing integration draft

This reference describes the independent Platform router. Root owns installation in the named Platform profile and the receiving Host's real `NativeInputCoordinator`; the module alone does not launch either application.

`loadNativeInputOwnerRoutingConfig` reads an absolute private JSON file containing required `workerOrigins`, `timeoutMs` and `maxResponseBytes`. `workerOrigins` maps canonical lowercase UUID worker IDs to fixed HTTP or HTTPS origins without credentials, paths, queries or fragments. The receiving Host worker ID must match its configured destination. Deployment changes replace the configuration through ordinary profile setup; there is no dynamic registration or new lease.

Install `NativeInputOwnerRouting(pool, config, replay)` with the real Platform PG pool. The required replay callback calls `NativeInputLedger.lookupQueueReceiptInTransaction` inside a real `transaction`; it returns only an existing immutable receipt or null. A historical receipt is checked before owner discovery, so a completed command can replay after its original occupancy expires. Reusing the nonce with another command fails through the ledger.

`queue(credential, command)` authenticates the actual browser account and Session owner before replay. For a new command it reads and locks the actual Session, Native Writer, running operation and open attempt at the Session's current operation epoch, requiring the attempt's worker to equal the Writer's worker. Both operation and Writer expiries use PostgreSQL `clock_timestamp()` and are checked again after lock waits. A missing, expired or inconsistent owner fails, and an unmapped owner fails without trying another Host.

After the routing transaction finishes, the router posts once to the selected origin's fixed `/native/input/queue` endpoint. It sends the original browser bearer and original queue command, preserving its nonce and complete payload. Browser input cannot supply destinations or forwarding budgets. Operation grants, Writer tokens and execution phase data are absent from the wire request and no browser credential is persisted by the router. Redirects fail. The receiving Host must execute only through its own real Coordinator, and the Platform queue commit must independently repeat full current browser, Writer, operation, frame and attempt authorization. Owner discovery does not grant mutation authority.

The HTTP timeout includes response streaming. Both announced and observed response bytes are bounded by `maxResponseBytes`; malformed JSON, invalid response fields and mismatched Session, actor user, nonce, payload digest or command kind fail. Successful responses must be strict tokenless `InputCommandReceipt` records. Strict remote error responses retain their HTTP status and Platform error code. The router neither fabricates success nor retries uncertain external effects; retrying the same original nonce uses the actual ledger lookup.

The independent PG spec creates and removes its own database, storage and HTTP listeners. Its browser ingress B routes to actual PG Writer/attempt A and the HTTP test adapter obtains its positive response from actual ledger planning and commit. Replay also reads that actual ledger. These endpoints verify wire behavior and durable queue changes, not a launched Host profile or complete Coordinator E2E. Profile composition, public endpoint installation and end-to-end deployment acceptance remain Root integration work.
