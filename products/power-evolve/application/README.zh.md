# PowerEvolve 应用插件

[English](README.md) | 中文

这个私有包提供三个独立启动的应用。宿主 Bundle 加载 `scope`、`persistence`、`model` 和 `host`，平台 Bundle 加载 `platform`，本机设备 Bundle 加载 `device`。共用包不代表共用进程、数据库连接或模型凭据。

<a id="host"></a>
## 宿主

`scope` 调用指定的平台端点，按原生 Session 身份保存执行授权。`persistence` 为获得租约的根会话实现原生 Session 存储服务；经过身份验证的会话创建由平台 API 负责。未获租约的访问、分叉和任意原生创建会被拒绝。非活跃历史保存在 PostgreSQL。每个操作恢复一个 Agent，持久完成后将其释放。

`model` 使用原生 DeepSeek Messages 编解码器。它在推理前持久保存已消费输入和请求记录，然后向平台提交操作授权。`host` 通过经过身份验证的 JSON RPC 和有限额的 NDJSON 订阅，仅暴露产品 Typert 命名空间。按 Agent 装载的原生工具提供受控便签查询、审批申请，以及按本次选择的云端或桌面目标提交命令的回执。此组合没有原生操作者级全局配置、任意文件系统访问、进程工具、插件安装和执行路由。

宿主的所有服务端 Platform 请求，包括凭据交换、原生会话与事件、模型调用和鉴权产物下载，都通过配置的内网 `scope.platformUrl`；产物下载不跟随重定向。浏览器跳转、上传票据、CSP、Origin 校验和审批链接使用独立的公开 `host.platformOrigin`；浏览器输入不能选择内网目标。

原生 Web 的登录页可把仅保存在内存中的 Agent 凭据 POST 到宿主 `/auth/exchange`。平台原子地注销这枚凭据，并签发保留原过期时间的新凭据；宿主将新凭据写入只发往 `/native/api` 和 `/api/powerEvolve` 的 HttpOnly、SameSite=Strict Cookie。URL 和浏览器存储不包含凭据。适配器对每次产品 RPC、事件流和 WebSocket 升级调用 `powerEvolveBrowserAuth.authenticate(request)`；Cookie 请求必须来自配置的宿主 Origin，交换请求必须来自配置的平台 Origin。平台仍负责校验到期和注销。除本机回环地址外必须使用 HTTPS。原生传输层在 `/native/api` 提供受限的会话列表、创建、文本输入、取消、历史分页、投影、订阅、控制和获授权的工作区订阅基线，也提供归属会话的文件列表、状态、文本、字节预览和变更订阅。浏览器看到的路径以 `/workspace` 为根；平台按每个已鉴权会话绑定的 POSIX 工作区解析路径，并逐次核验归属。WebSocket 复用上游 Gateway 的流复用器，平台调用仍按用户授权。其余原生端点返回错误，宿主不开放上游操作员接口。

原生 Session follow 流在 Platform 临时断连、读取超时或返回 502/503/504 时，保留最后已投递事件的游标。快照和历史读取按 `host.pollMs` 重试，并沿用 `scope.timeoutMs` 与 `scope.maxResponseBytes`。恢复后投递已提交的后续事件，不重新提交输入，也不替换已投递的快照。取消停止等待、重试和投递；已发起的读取仍受原请求上限约束。授权拒绝、响应无效、响应超限和历史缺口会终止订阅。

<a id="trusted-platform"></a>
## 可信平台

账号删除拒绝尚未完成的目录或绑定操作，以及保留的业务回执。平台通过描述符相对访问检查所有自有存储根，仅允许持久默认绑定对应的空目录及其祖先。仅打开存储选择器不妨碍删除；链接、特殊文件以及未绑定个人存储中的文件均会阻止删除。

`accountManagementFile` 启用可信账号接口，并定义模型目录、初始设置和账号数量上限。产品 Platform Bundle 要求此私有配置；自定义 Profile 未配置时，账号管理返回 `account_unavailable`。可选的 `accountBootstrapFile` 在数据库锁内显式选择或创建首个管理员；不会隐式将现有身份提升为管理员。账号登录共用 Platform 登录限流，每个账号 POST 都要求准确的 Platform Origin。[账号客户端](../client-account/README.zh.md)拥有管理界面及其浏览器构建检查。

Platform 在 `/account` 和 `/account/` 提供账号包的可信页面，`/account/` 下的文件仅限构建产物 `asset-list.json` 中的条目。未知路径不回退到 HTML；source map、路径越界和不支持的资源类型均被拒绝。响应禁用缓存和 MIME 嗅探，脚本与连接仅允许 Platform origin，并禁止页面嵌入框架。迁移的 React 组件仍可使用内联样式。账号包必须先生成可信构建产物，该页面才能提供服务；Host 不提供这些资源。

身份模块验证持久账号，分别签发有期限的 Agent、审批和账号凭据。种子配置只插入缺少的身份，不覆盖已有账号变更。会话 API 从经过验证的身份确定资源归属。任务准入、请求去重、用户容量、领取和租约代次在 PostgreSQL 事务中提交。事件追加需要当前授权，重复记录必须完全一致。模型出口验证授权、模型及输出额度，并注入真实模型密钥。每个用户有一个默认 POSIX 工作区，可通过 `/workspaces/create` 创建更多带标题的工作区；`/workspaces/list` 只返回本人的元数据。创建会话时永久绑定一个本人工作区，未指定 ID 则绑定原默认工作区。原平台 `/files` API 仍只访问默认工作区；原生读取和产品 `/files/session` 操作使用已鉴权会话绑定的工作区。文件写入要求匹配原版本和请求 ID；用户的可写云端挂载处于预留或活跃状态时拒绝平台直写。平台还拥有每个用户的个人技能库；任务受理时固定选用的技能版本。原生技能注册表只暴露已受理目录，`skill` 工具按需读取选中说明；`skill_resource` 通过平台列举已校验的清单或读取有大小上限的 UTF-8 文本。两种读取都在文件访问后重新核验授权，不创建沙盒。

登录和审批登录在所有 Platform 副本间共用两级 PostgreSQL 限额：按准确提交的账号名 SHA-256 摘要划分的小窗口，以及独立的高容量全局过载窗口。每个请求在解析正文前计入全局窗口；合法账号名还会在验证口令前计入该账号窗口。试用 Platform 负载均衡器从回环地址连接后端，并透传调用方自带的 `X-Forwarded-For`，因此限流不把 socket 对端或这个请求头当作用户身份。默认 60 秒窗口每账号允许 20 次，最多跟踪 100,000 个账号名，全局允许 100,000 次请求；应按预期登录流量和认证处理能力设置全局阈值。达到全局阈值后，该窗口过期前的全部登录请求都会被拒绝。Schema 19 在 PG 单行保存准入配置；登录限额或 `sandboxConcurrency` 不一致的副本拒绝启动。变更限额时，先停止全部 Platform 副本，更新 `pe_platform_admission_policy` 中的值以匹配新配置，再以相同配置启动。

发布产物时，平台把当前用户会话中不超过 2 MiB 的授权文件复制到沙盒不可见的私有目录，并在 PG 提交不可变元数据。稳定请求 ID 用于去重。列表、有界预览和校验后的字节下载逐次核验归属；之后修改工作区文件或回收沙盒不改变已发布产物。宿主允许同源安全 GET 使用限定路径的 Cookie 下载，向平台验证凭据并转发有界响应，不保存平台密钥。

工作区批量下载先调用 `filesDownloadPrepare`，再从同源内容入口 GET。平台重新核验会话归属及准备时的文件摘要，然后流式输出单个文件或 ZIP，宿主只转发有界数据块。源文件变化会拒绝准备或中断尚未完成的响应。取消传递到文件助手，实际读取结束后才归还传输槽。进一步输出前重新核验凭据，阻塞的 socket 受总时限约束；已经发出的字节不能撤回。此流程不创建沙盒，宿主不保存文件字节。[文件补齐切片](../S2-COMPLETION.md) 定义客户端协议及验收范围。

`fileDownloadMaxFiles`、`fileDownloadMaxTotalBytes`、`fileDownloadMaxConcurrentTransfers`、`fileDownloadMaxUserConcurrentTransfers`、`fileDownloadTransferTimeoutMs` 分别配置选择数量、源字节总量、单平台传输容量、该副本上的单用户容量和总时限。准备阶段共用传输槽，并受宿主普通 RPC 超时约束。宿主内容传输使用独立的 `fileDownloadTimeoutMs`，两端传输时限默认均为 60 秒。这些是副本限额，不是集群全局配额；现有单文件 2 MiB 上限仍适用。

连接器不启动执行沙盒即可查询受控 HTTP 便签 API。写入工具先在 PG 中持久保存准确的申请内容，并返回待审批回执，不能直接写入。平台域名下的独立页面展示原文和指纹。平台按当前身份核对归属和审批指纹，在派发前再次检查权限，并使用稳定的远端幂等键。结果不明时先查询，再决定是否重试。终态结果在原会话中排入一次平台消息；API 凭据只留在平台进程。

远程 MCP 使用按操作固定的工具定义、独立授权的管理服务和[受控传输](tests/s6-mcp-controlled-transport.md)。Schema 23 保存准确参数、人工决定、可撤销的会话或持久工具权限，以及仅可使用一次的派发意图。只有新许可提交后才能首次调用远端；已提交意图过期则进入结果不明状态，并停止该原请求的自动调用链。成功结果经过 MCP、API、云端、桌面、STDIO 或 SSH 续接时，保留原工具选择和总次数／时间预算。原始 MCP 参数与结果使用 JSON 列保留转义 NUL。Platform 分别运行发现和调用 worker，仅通过直传端点接收凭据，并以独立审批身份确认人工决定。Host 注册已受理的原生 MCP 工具定义并返回持久回执；远端输出在原会话续接。派发或完成回执不明时，不会再次向远端 POST。停服时先等待这些 worker 及其最后的 PG 写入，再关闭数据库连接池。可信审批页提供准确的单次、会话、持久授权及拒绝选项；原生浏览器和真实模型验收仍属于发布门禁。

MCP 在原生模型请求中保留已声明的 JSON Schema，并独立校验参数与结构化结果。产品验证器支持 draft 2020-12（默认）、2019-09 和 draft-07，包括数值界限、字符串长度、数组界限、组合及有界的非循环文档内引用。正则或格式约束、`uniqueItems: true`、动态或递归引用、外部引用、嵌套方言或 ID 变化、异步验证及自定义词汇表会被拒绝。固定的深度、schema 大小、引用展开和估算工作量上限限制共享服务内的同步验证，准确数值见[验证器](src/mcp-json-schema.ts)。不支持的约束会使发现明确失败，绝不删除或忽略。

设置 `PE_REMOTE_MCP_CONFIG_FILE`，指向仅 Platform 可读的绝对 JSON 路径，内容参考[完整示例](../platform/remote-mcp.example.json)。其中 `credentialKeyFile` 保存私有的 32 字节 base64url 密钥。管理、受理、动作和传输限额均须提供；`renewMs` 必须小于两类 worker 的租约时长。`cleanupMs` 和 `cleanupBatchSize` 限定按用户定期清理的周期与批量。过期草稿释放容量，创建记录仍保留以执行一小时频率限额。默认仅允许 HTTPS 公网出口；运营例外指定准确 origin、获准 IP 地址、可选 `allowHttp`，以及 CA 证书包的绝对 `caFile`。设置 `requireOriginException: true` 后，未列明的 origin 会在 DNS 解析前被拒绝；此时空例外列表拒绝所有远程 MCP 目标。个人连接请求不能设置这些例外。配置无效时拒绝启动；不得把该文件或密钥挂载给 Host。

平台签发绑定用户、短时有效的 SSH 凭据上传票据。浏览器只经宿主发送元数据和序列化后的字节长度，再把带版本的封装直接上传到平台域名。口令、私钥和可选的私钥口令分别限制为 4096、7168 和 1024 个 UTF-8 字节。历史原始口令上传使用明确区分的格式。已完成请求的重试仍须上传相同秘密字节，才能取得原结果；不同秘密会被拒绝。Profile 配置限制连接数、待上传票据数、票据有效期和已完成请求的不匹配次数。凭据按用户、连接和版本加密；PG 不保存明文，宿主不接收明文。

个人 SSH 管理使用稳定请求 ID，并以配置版本执行比较后更新。编辑时明确保留或替换凭据，清除私钥口令是独立选项。变更响应丢失后，可以通过本人回执恢复结果。删除留下已禁用的墓碑记录；不可变的配置与凭据版本保留历史审批目标。Runner 配置或凭据访问不可用时，仍可禁用或删除连接。新安装要求已配置独立 Connector Runner 和目的地策略；这条接收链路不会授权共享宿主或带可写工作区的编程沙盒运行 SSH 命令。

固定进程型 MCP 预设在原生插件页为每位用户提供带状态修订、仅本人可见的连接。任务受理时固定已启用的连接修订；原生 Agent 工具经共享宿主向可信平台提交稳定的工具调用 ID。平台先持久受理，再创建禁止网络出口且不挂载用户文件的短时 Connector Runner Pod，只启动镜像内置的只读 STDIO MCP 服务。终态或结果不明的调用在 PG 中保存，并向原会话排入一次消息。重新领取已提交的派发意图时，平台查询准确的 Pod UID、Runner 实例和调用摘要；状态缺失则标记不确定，不再 POST。宿主只接收连接元数据、回执和有界结果文本。此预设不接收用户命令、安装包或凭据。

资源恢复接受已识别的 Kubernetes NetworkPolicy、Service 和 Pod 默认字段，同时拒绝 selector、端口、执行配置及 Pod 身份变化。即使仍有新调用排队，终态资源也会获得清理机会。

SSH 认证或命令已确认处于 `running` 并持久化后，worker 释放租约，在 `sshRunnerPollMs` 后允许再次观察（默认 500 毫秒，最小 100 毫秒）。下一个 worker 查询原 Runner，无须等完整恢复租约过期，也不会再次发送命令。owner 和 epoch 检查拒绝旧执行者续租或释放租约；结果不明的调用沿用原有对账节奏。

启用 SSH 连接后，任务受理固定连接和凭据版本。原生 Agent 工具使用稳定的工具调用 ID，为每次操作提交一条确切命令。系统说明将连接 UUID 与用户名、主机和端口分别列出；`connectionId` 参数只接受选中连接的原始 UUID。可信平台先把配置的工作目录固定到命令中，再计算指纹并加密保存在 `pe_ssh_execute_actions`。绝对路径按字面使用，相对路径和 `~` 使用远端 HOME。目录字节（包括空格）保持不变；切换目录失败时退出，不运行所提交的命令。完整命令限制为 16,384 个 UTF-8 字节。独立审批身份在平台页面核对该命令、历史目标、主机密钥指纹和版本。后续编辑不会改变已有审批。

只有批准才创建 `ssh.execute` 调用。工作者验证 Pod 的目的地和出口策略，再在同一事务内核验调用租约、匹配的审批、取消标记和当前连接版本，提交一次派发许可。事务提交后才向 Runner 发送请求；网络等待期间，撤销和取消仍可完成。调用表不保存命令或凭据明文，结果随审批动作加密保存。撤销阻止签发新许可，但无法收回已经提交的许可，其 POST 可能随后才到达。恢复时只查询原 Pod UID、Runner 实例和摘要，不会复用许可再次 POST。有界输出或终态状态只向原生会话续接一次。

SSH Runner 只有明确报告 `effectMayHaveOccurred` 为 false 时，失败才能确定为未执行。该标记为 true 或缺失，以及通道关闭时未观察到退出码或信号，都会使动作进入结果不明状态。Platform 持久保存此结果，只续接一次并禁止自动重试；重启后可以清理 Runner，但不会重新派发。已观察到的非零退出码或退出信号仍作为执行结果返回，调用者须检查后才能认定命令成功。

执行服务仅在当前会话授权下受理命令，返回前先保存调用 ID。首次需要执行时，它为根会话创建一个 Agent Sandbox，只挂载该会话绑定的本人 POSIX 工作区和用户 Home；重试前先查询执行器状态。Home 仍为用户共享，因此每个用户只有一个 Kubernetes 物理资源槽位；前一个 Pod UID 的 kubelet 原生停止证据写入 PG 后，另一会话才可使用。本人工作区的挂载源在获取槽位前准备；Home 和 Skill 包挂载源在用户事务锁内完成准备与校验，之后才提交预留。本地准备失败不会留下预留或触发 Kubernetes 变更。新会话获得不同的 Pod UID、runner 身份和令牌。Kubernetes 创建中断或缺少停止证据时，即使租约过期也不能放行替代实例。终态结果在同一会话中排入平台消息，空闲回收保留 Git 文件和历史。Kubernetes 凭据只留在平台进程。

`sandboxConcurrency` 限制所有 Platform 副本合计的活跃执行 worker。认领 worker 时，在共享事务锁下统计 PG 有效租约；崩溃 worker 的租约过期后释放容量，由接替者核对执行状态。已进入 `running` 并延期观察的命令会释放 worker 租约，因此此限额不同于存活 Pod 数量；用户挂载槽位另行约束 Pod 替换。

新建 Sandbox Pod 从 Platform Profile 接收文件扫描预算：`sandboxScanMaxEntries`（默认 4,096，上限 65,536）、`sandboxScanMaxHashBytes`（32 MiB，200 MiB）、`sandboxScanTimeoutMs`（5,000，30,000）、`sandboxScanMaxSnapshotBytes`（1 MiB，4 MiB）和 `sandboxScanMaxFiles`（100，100）。这些值均为正整数，快照字节数下限为 1 KiB。命令执行前、执行后的扫描分别使用独立预算，配置变更适用于新建 Pod。Platform 字节核验另用 `sandboxFileVerifyTimeoutMs`（默认 15,000，范围 100–60,000）。扫描受限或失败不能视为完整且为空的结果；元数据核验失败也不会丢弃已认证的命令终态。

平台还保存设备身份、目录授权和本地命令状态。独立的本机设备 Profile 使用短期配对码接入，绝对路径和设备令牌只留在本机；命令在仅挂载一个获授权目录的临时 Docker 容器中执行。设备先记下命令身份，再创建容器，重启后核对容器状态。桌面与云端文件只通过明确的受限设备操作传输。

配置在三个 Bundle 补丁中显式声明。必需的秘密值在启动时从私密文件读取。私有产物根目录必须位于可写工作区根目录之外。工作区文件访问需要 Python 3.9+ 和随包部署的[目录描述符助手](../S2-SAFE-POSIX.md)；缺少时启动会拒绝就绪。数据库连接池、超时、请求/历史/输出限制、用户准入及工作区数量、宿主并发、轮询、租约续期和订阅上限均可配置。就绪文件记录所属进程实例，供试用生命周期脚本核验。

Platform 的请求连接池或有界健康检查连接池失去 PostgreSQL 连接时会记录状态变化。`/health` 从 PG 只读查询当前 schema 版本；PG 不可用时返回 HTTP 503、`ready: false` 和 `schema: null`，连接恢复后返回 200 和实际版本，Platform 负载均衡器据此停止向不可用副本转发。中断的登录不会签发凭据，恢复后需要客户端明确重试。健康检查不会派发或重放任务；持久任务与执行 worker 继续遵守已有租约和对账规则。已租用的事务连接也处理查询之间的断连：断连后不提交回调结果并丢弃连接，回调失败仍保留原异常。这不会取消已开始的外部操作，也不解决 COMMIT 响应丢失的不确定结果。

内置目录包含参考产品的九个固定版本包。安装按用户隔离并按请求去重；配置的预置在新旧会话受理输入及列举个人技能前执行，保留已有禁用和撤销状态。显式目录升级只替换同一内置包的当前版本，保留技能身份及禁用状态，不覆盖同名私有上传包；已受理操作继续使用原始包字节。完整选中四个报告包时，平台根据持久安装回执提供经过校验的不可变实体目录，后续目录版本变化不影响相邻包引用。撤销拒绝后续读取，但无法抹除运行中执行已读取或已挂载的字节。`office` 工具把有长度上限、经过参数引用的 OfficeCLI 命令提交给与 `cloud_exec` 相同的持久执行服务；OfficeCLI 和文档依赖只在沙盒镜像中运行。`load_skill` 输出以产品运行规则开头：禁用常驻模式，每条命令指定文件，直接修改在返回前落盘；后面保留原始上游指南。

Schema 20 增加归属用户的目录安装回执，包括复用既有包版本的重试 ID。已受理的技能元数据最多包含 256 项；领取任务不依赖说明文件。当前授权只能读取其持久选用记录，过期授权会被拒绝。

本机 `scripts/trial.mjs` 启动器支持通过 `PE_TRIAL_DATABASE=external` 复用现有 PostgreSQL 服务。启动前先创建独立的试用数据库及私有 `database-url`；该模式检查数据库就绪状态，不创建数据库容器。默认仍为 `compose`。合成 MCP 验收可用 `PE_REMOTE_MCP_FIXTURE=1` 在 `PE_REMOTE_MCP_PORT` 启动归启动器管理的回环目标；私有 `remote-mcp-fixture-users.json` 提供至少两个 `{username, token, unitPrice}` 记录（令牌至少 24 个字符）。目标只查询私有测试商品和计算报价，在本机记录合成调用，不执行购买。`/mcp/public` 无需认证并提供固定公共测试数据，`/mcp/empty` 返回空工具目录，`/mcp/slow` 延迟请求以验证取消和超时；断开及停服会释放等待中的请求。使用相同开关执行 `stop` 时会一并关闭。启动器仅向 Profile 准备步骤传入 `PE_REMOTE_MCP_CONFIG_FILE`，由其写入 Platform 配置；Host 进程不接收该环境变量。

## 恢复与限制

Schema 27 保留既有工作区及会话身份，通过按用户授权的存储空间与绑定代次确定物理目录。原生工作区创建入口接收稳定请求 ID 和可选私有目录；产品存储 RPC 不接收物理根路径或客户端提供的写者停止证明。`workspaceRecoveryPollMs` 和 `workspaceRecoveryLeaseMs` 配置 PG 恢复执行者；服务关闭前等待其最终数据库写入。下载保持准备时的绑定代次，发布复用已有授权事务。备份拒绝尚未完成的目录或绑定变更；恢复对 Schema 27 使用持久存储根标识，对更早备份使用旧工作区 ID，缺失目录仍保持缺失。恢复准入及待完成验收见[文件补齐切片](../S2-COMPLETION.md)。

正在恢复的绑定独占写者清理。服务关闭时释放恢复租约，保留捕获的写者身份和已提交的停止证明，供其他执行者接管。如果恢复转为阻塞，且账号已停用或删除，空闲回收器可以停止该账号当前的确切写者。清理保留绑定围栏与代次，取得并持久化 kubelet 停止证明后才释放挂载槽。移除 finalizer 后仍短暂可见的 Pod，只有确切身份、终止状态及持久证明一致时才允许继续等待消失。账号重新启用后，须明确重试恢复才能重新绑定。

Schema 26 为不可变产物发布请求保存可空的预期源摘要，已有发布保留空值。同一请求 ID 须保留原 Session、路径和预期摘要；条件发布拒绝已变化的源字节。执行文件观察沿用执行结果列，不改变原生 Session 事件类型。核验和部署要求见[文件补齐切片](../S2-COMPLETION.md)。

Schema 24 将不可变的 SSH 配置与凭据版本、当前连接指针和用户变更回执分开保存。迁移保留已有密文及原始加密上下文，包括历史调用和审批。历史凭据缺失、历史目标不一致或请求 ID 冲突时，整个迁移回滚。升级前停止 Platform 写入，并保留经过验证的数据库和密钥备份；恢复旧版本必须还原该备份，不能降级这些记录。

本地备份 CLI 支持既有 PostgreSQL 服务，并保留 MCP 配置、加密密钥和引用的 CA 文件。恢复需要独立的空数据库及私有存储路径。`PE_BACKUP_KEEP_STOPPED=1` 保持应用停止，不会停止 PostgreSQL。使用任一数据库模式前，请阅读[备份前置条件与失败边界](../TRIAL-S7C-BACKUP.md)。

Schema 22 独立保存远程 MCP 的不可变配置、凭据和目录版本，不替换固定连接器预设。为 `TaskStore` 提供远程 MCP 受理策略时，输入受理在同一事务中保存该用户完整的已启用工具选择、原始模式及精确的原生模型声明。每次新选择会将当前连接显示名、稳定 ID 和原工具名作为引用的元数据写入持久模型描述；标签不授予权限。目录或显示名变化后，重复受理和任务恢复仍保留原声明。不支持的模式、必需的 MCP Task 扩展、名称碰撞和整体选择超限会拒绝受理，不会静默丢弃工具。模型代理从 PG 读取已受理定义，拒绝宿主篡改名称、描述或参数模式。它根据这些声明核验原生会话中途新增的工具，并从合法的 system 角色引用派生固定的模型服务 beta 请求头。默认 Flash 路由支持延迟新增；Pro 接收完整且立即可用的工具声明。历史调用与结果保持不变，不授予新动作权限；宿主提供的 beta 请求头不会转发。该路径不创建执行沙盒，也不授予工具调用权限。只有为 Platform Profile 指定私有配置文件，才会启用通用 MCP。

Schema 21 用 PostgreSQL `json` 保存原生事件及云端、桌面、连接器的结果载荷。这些不透明值完整保留转义的 NUL 及 `jsonb` 无法表示的其他 JSON 字符串内容。通过驱动整值读取，不转换为 `jsonb`，也不在 SQL 中提取任意文本；归属、排序、状态和索引使用独立的类型化列。迁移前停止 Platform 写入者并验证备份；旧版 Platform 拒绝此 schema，回退旧程序须恢复升级前的数据库和文件。

平台续接输入最多保留 256 KiB 的 JSON 编码文本，同时不超过 `maxEventBytes` 的一半。超限结果以明确标记的首尾摘录传给模型；PG 中原始 Operation 输入和执行结果保持完整。重启后领取已排队结果时应用同一限制。用户输入仍限制为 16,384 个字符。

Kubernetes 资源响应限制为 256 KiB。云沙盒与 SSH Runner 适配器显式使用独立的 1 MiB 响应预算，容纳其有界输出流经 JSON 转义后最多六倍的膨胀；仅携带 Runner 令牌不会提高普通资源预算。响应中途断开会立即拒绝；超限响应和 socket 空闲超时会拒绝并关闭请求。这些传输失败仍遵守执行对账规则，不授权重放命令。

操作提交后，客户端才收到 `accepted`。未消费的输入可以在重启后投递。已消费但没有完成轮次的输入由原生 DSH 恢复逻辑补齐中断记录，并报告失败，不会自动再次发送给模型。完成响应丢失时，重新领取租约后根据已保存的轮次核对结果。

取消会话时，平台在 PG 中核对当前用户的归属。尚未领取的输入直接以失败终结，不启动模型调用；运行中的输入保存取消意图，由持有租约的宿主在续租时读取。仍在运行的宿主取消 Agent，并在释放授权前保存原生日志。接替宿主不会重放已取消输入，后续仍可在同一会话提问。没有活跃操作时重复取消只返回成功，不改动历史。若轮次在宿主收到取消请求前已经结束，则以已记录的完成或失败结果为准。

执行授权在取得会话锁后，按 PostgreSQL 当前时钟重新校验期限。续租或事件追加若在等待期间超过期限，则返回 `lease_lost`；续租最终更新也再次检查期限。领取任务及成功续租均从写入租约时的数据库当前时间计算到期，等待锁不会消耗新租约的有效时长。

账号停用与旧会话授权撤销、排队和运行中输入终结、未完成审批及执行取消在同一事务提交。浏览器受理和审批在账号锁内重查原始凭据，新执行派发检查当前账号状态。工作进程保留执行身份用于取消、观察和精确清理；实际结果仍保存，并保留 `account_disabled` 标记，即使账号再启用也不生成 Agent 续接。再启用仅允许新工作；密码轮换撤销浏览器凭据，已受理的执行授权在账号有效时继续有效，要求改密期间也适用。

本切片支持根会话文本对话、有限大小的文件传输和文本编辑、个人技能说明、两个受控远程 API 工具、云端命令及选定本地项目中的桌面命令。完成的输出通过持久事件订阅传送，部分模型 token 不广播到浏览器。私有 Profile 不承诺兼容所有原生 Controller 或 Session 存储消费者。它拒绝未知 Session 版本，不迁移旧 PowerEvolve 数据库。结果不明的远端写入或命令留在 PG 中等待对账；宿主不会盲目重放。

本机试用的宿主与平台进程仍使用当前 OS 用户，尚未按进程身份隔离。云端命令在按命名空间授权的 gVisor Agent Sandbox 中执行，本地命令使用配对设备上的 Docker。工作区文件已通过目录描述符相对访问抵御并发替换符号链接。生产部署接入不可信租户之前，还需要独立服务身份、网络出口规则、设备可信证明，以及多节点 POSIX 挂载验证。当前连接器是本机受控试用目标，并非通用第三方连接器目录。生产入口属于后续切片。

## 验证

产品 JSDoc 定向检查需向 `node --import tsx/esm scripts/verify-export-jsdoc.ts` 显式传入源文件路径；不传文件时，上游检查仅扫描 `packages`。产品回归包含一个缺失导出说明时必须失败的反例。

`pnpm run test:power-evolve` 使用构建后的 `dsh` Profile、真实且唯一命名的测试数据库，以及确定性模型、远端 API 和沙盒执行器。测试覆盖身份和配置区分、授权拒绝、订阅、重复受理、中断/重启、旧授权、退出、原生历史回放、Agent/Session 回收、文件字节、个人技能、审批、远端对账、云端和设备执行、取消、实例变化及原会话续接。测试监听端口由 OS 分配，清理时等待子进程退出和数据库连接关闭。本机浏览器试用另行验证真实 DeepSeek、k3s 和已配对的本机设备。
