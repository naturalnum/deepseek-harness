# PowerEvolve 应用插件

[English](README.md) | 中文

这个私有包提供三个独立启动的应用。宿主 Bundle 加载 `scope`、`persistence`、`model` 和 `host`，平台 Bundle 加载 `platform`，本机设备 Bundle 加载 `device`。共用包不代表共用进程、数据库连接或模型凭据。

<a id="host"></a>
## 宿主

`scope` 调用指定的平台端点，按原生 Session 身份保存执行授权。`persistence` 为获得租约的根会话实现原生 Session 存储服务；经过身份验证的会话创建由平台 API 负责。未获租约的访问、分叉和任意原生创建会被拒绝。非活跃历史保存在 PostgreSQL。每个操作恢复一个 Agent，持久完成后将其释放。

`model` 使用原生 DeepSeek Messages 编解码器。它在推理前持久保存已消费输入和请求记录，然后向平台提交操作授权。`host` 通过经过身份验证的 JSON RPC 和有限额的 NDJSON 订阅，仅暴露产品 Typert 命名空间。按 Agent 装载的原生工具提供受控便签查询、审批申请，以及按本次选择的云端或桌面目标提交命令的回执。此组合没有原生操作者级全局配置、任意文件系统访问、进程工具、插件安装和执行路由。

宿主的所有服务端 Platform 请求，包括凭据交换、原生会话与事件、模型调用和鉴权产物下载，都通过配置的内网 `scope.platformUrl`；产物下载不跟随重定向。浏览器跳转、上传票据、CSP、Origin 校验和审批链接使用独立的公开 `host.platformOrigin`；浏览器输入不能选择内网目标。

原生 Web 的登录页可把仅保存在内存中的 Agent 凭据 POST 到宿主 `/auth/exchange`。平台原子地注销这枚凭据，并签发保留原过期时间的新凭据；宿主将新凭据写入只发往 `/native/api` 和 `/api/powerEvolve` 的 HttpOnly、SameSite=Strict Cookie。URL 和浏览器存储不包含凭据。适配器对每次产品 RPC、事件流和 WebSocket 升级调用 `powerEvolveBrowserAuth.authenticate(request)`；Cookie 请求必须来自配置的宿主 Origin，交换请求必须来自配置的平台 Origin。平台仍负责校验到期和注销。除本机回环地址外必须使用 HTTPS。原生传输层在 `/native/api` 提供受限的会话列表、创建、文本输入、取消、历史分页、投影、订阅、控制和获授权的工作区订阅基线，也提供归属会话的文件列表、状态、文本、字节预览和变更订阅。浏览器看到的路径以 `/workspace` 为根；平台按每个已鉴权会话绑定的 POSIX 工作区解析路径，并逐次核验归属。WebSocket 复用上游 Gateway 的流复用器，平台调用仍按用户授权。其余原生端点返回错误，宿主不开放上游操作员接口。

<a id="trusted-platform"></a>
## 可信平台

身份模块验证预置测试账号，分别签发有期限的 Agent 和审批凭据，并在退出时撤销。会话 API 从经过验证的身份确定资源归属。任务准入、请求去重、用户容量、领取和租约代次在 PostgreSQL 事务中提交。事件追加需要当前授权，重复记录必须完全一致。模型出口验证授权、模型及输出额度，并注入真实模型密钥。每个用户有一个默认 POSIX 工作区，可通过 `/workspaces/create` 创建更多带标题的工作区；`/workspaces/list` 只返回本人的元数据。创建会话时永久绑定一个本人工作区，未指定 ID 则绑定原默认工作区。原平台 `/files` API 仍只访问默认工作区；原生读取和产品 `/files/session` 操作使用已鉴权会话绑定的工作区。文件写入要求匹配原版本和请求 ID；用户的可写云端挂载处于预留或活跃状态时拒绝平台直写。平台还拥有每个用户的个人技能库；任务受理时固定选用的技能版本。原生技能注册表只暴露已受理目录，`skill` 工具按需读取选中说明；`skill_resource` 通过平台列举已校验的清单或读取有大小上限的 UTF-8 文本。两种读取都在文件访问后重新核验授权，不创建沙盒。

登录和审批登录在所有 Platform 副本间共用两级 PostgreSQL 限额：按准确提交的账号名 SHA-256 摘要划分的小窗口，以及独立的高容量全局过载窗口。每个请求在解析正文前计入全局窗口；合法账号名还会在验证口令前计入该账号窗口。试用 Platform 负载均衡器从回环地址连接后端，并透传调用方自带的 `X-Forwarded-For`，因此限流不把 socket 对端或这个请求头当作用户身份。默认 60 秒窗口每账号允许 20 次，最多跟踪 100,000 个账号名，全局允许 100,000 次请求；应按预期登录流量和认证处理能力设置全局阈值。达到全局阈值后，该窗口过期前的全部登录请求都会被拒绝。Schema 19 在 PG 单行保存准入配置；登录限额或 `sandboxConcurrency` 不一致的副本拒绝启动。变更限额时，先停止全部 Platform 副本，更新 `pe_platform_admission_policy` 中的值以匹配新配置，再以相同配置启动。

发布产物时，平台把当前用户会话中不超过 2 MiB 的授权文件复制到沙盒不可见的私有目录，并在 PG 提交不可变元数据。稳定请求 ID 用于去重。列表、有界预览和校验后的字节下载逐次核验归属；之后修改工作区文件或回收沙盒不改变已发布产物。宿主允许同源安全 GET 使用限定路径的 Cookie 下载，向平台验证凭据并转发有界响应，不保存平台密钥。

连接器不启动执行沙盒即可查询受控 HTTP 便签 API。写入工具先在 PG 中持久保存准确的申请内容，并返回待审批回执，不能直接写入。平台域名下的独立页面展示原文和指纹。平台按当前身份核对归属和审批指纹，在派发前再次检查权限，并使用稳定的远端幂等键。结果不明时先查询，再决定是否重试。终态结果在原会话中排入一次平台消息；API 凭据只留在平台进程。

平台签发绑定用户、短时有效的 SSH 凭据上传票据。浏览器只经宿主发送元数据和口令字节长度，再把最多 4096 字节的 UTF-8 口令直接上传到平台域名。同一安装请求 ID 重试时，平台重新签发票据，收到口令后核对带密钥摘要；相同口令返回原结果，不同口令拒绝；三次不匹配后阻止该请求 ID 继续重试。平台按用户、连接和版本加密凭据；PG 不保存明文。独立 Connector Runner 和目的地策略尚未配置时，原生插件页不能开放安装。这条接收链路不会授权共享宿主或带可写工作区的编程沙盒运行 SSH 命令。

固定进程型 MCP 预设在原生插件页为每位用户提供带状态修订、仅本人可见的连接。任务受理时固定已启用的连接修订；原生 Agent 工具经共享宿主向可信平台提交稳定的工具调用 ID。平台先持久受理，再创建禁止网络出口且不挂载用户文件的短时 Connector Runner Pod，只启动镜像内置的只读 STDIO MCP 服务。终态或结果不明的调用在 PG 中保存，并向原会话排入一次消息。重新领取已提交的派发意图时，平台查询准确的 Pod UID、Runner 实例和调用摘要；状态缺失则标记不确定，不再 POST。宿主只接收连接元数据、回执和有界结果文本。此预设不接收用户命令、安装包或凭据。

资源恢复接受已识别的 Kubernetes NetworkPolicy、Service 和 Pod 默认字段，同时拒绝 selector、端口、执行配置及 Pod 身份变化。即使仍有新调用排队，终态资源也会获得清理机会。

启用 SSH 连接后，任务受理固定连接和凭据版本。原生 Agent 工具使用稳定的工具调用 ID，为每次操作提交一条确切命令。可信平台将命令加密保存在 `pe_ssh_execute_actions`，只返回待审批回执；独立审批身份在平台页面核对解密后的命令、目标和指纹，再批准或拒绝。只有批准才创建 `ssh.execute` 调用。工作者首次向 Runner POST 口令和命令前，在数据库锁下复核连接仍启用，并验证 Pod 的目的地和出口策略。调用表不保存命令或口令明文，结果随审批动作加密保存。取消会阻止尚未派发的调用；已派发调用按 Pod UID、Runner 实例和摘要对账，结果不明时不会重放。有界输出或终态状态只向原生会话续接一次。

执行服务仅在当前会话授权下受理命令，返回前先保存调用 ID。首次需要执行时，它为根会话创建一个 Agent Sandbox，只挂载该会话绑定的本人 POSIX 工作区和用户 Home；重试前先查询执行器状态。Home 仍为用户共享，因此每个用户只有一个 Kubernetes 物理资源槽位；前一个 Pod UID 的 kubelet 原生停止证据写入 PG 后，另一会话才可使用。本人工作区的挂载源在获取槽位前准备；Home 和 Skill 包挂载源在用户事务锁内完成准备与校验，之后才提交预留。本地准备失败不会留下预留或触发 Kubernetes 变更。新会话获得不同的 Pod UID、runner 身份和令牌。Kubernetes 创建中断或缺少停止证据时，即使租约过期也不能放行替代实例。终态结果在同一会话中排入平台消息，空闲回收保留 Git 文件和历史。Kubernetes 凭据只留在平台进程。

`sandboxConcurrency` 限制所有 Platform 副本合计的活跃执行 worker。认领 worker 时，在共享事务锁下统计 PG 有效租约；崩溃 worker 的租约过期后释放容量，由接替者核对执行状态。已进入 `running` 并延期观察的命令会释放 worker 租约，因此此限额不同于存活 Pod 数量；用户挂载槽位另行约束 Pod 替换。

平台还保存设备身份、目录授权和本地命令状态。独立的本机设备 Profile 使用短期配对码接入，绝对路径和设备令牌只留在本机；命令在仅挂载一个获授权目录的临时 Docker 容器中执行。设备先记下命令身份，再创建容器，重启后核对容器状态。桌面与云端文件只通过明确的受限设备操作传输。

配置在三个 Bundle 补丁中显式声明。必需的秘密值在启动时从私密文件读取。私有产物根目录必须位于可写工作区根目录之外。工作区文件访问需要 Python 3.9+ 和随包部署的[目录描述符助手](../S2-SAFE-POSIX.md)；缺少时启动会拒绝就绪。数据库连接池、超时、请求/历史/输出限制、用户准入及工作区数量、宿主并发、轮询、租约续期和订阅上限均可配置。就绪文件记录所属进程实例，供试用生命周期脚本核验。

Platform 的请求连接池或有界健康检查连接池失去 PostgreSQL 连接时会记录状态变化。`/health` 从 PG 只读查询当前 schema 版本；PG 不可用时返回 HTTP 503、`ready: false` 和 `schema: null`，连接恢复后返回 200 和实际版本，Platform 负载均衡器据此停止向不可用副本转发。中断的登录不会签发凭据，恢复后需要客户端明确重试。健康检查不会派发或重放任务；持久任务与执行 worker 继续遵守已有租约和对账规则。已租用的事务连接也处理查询之间的断连：断连后不提交回调结果并丢弃连接，回调失败仍保留原异常。这不会取消已开始的外部操作，也不解决 COMMIT 响应丢失的不确定结果。

内置目录包含参考产品的九个固定版本包。安装按用户隔离并按请求去重；配置的预置在新旧会话受理输入及列举个人技能前执行，保留已有禁用和撤销状态。显式目录升级只替换同一内置包的当前版本，保留技能身份及禁用状态，不覆盖同名私有上传包；已受理操作继续使用原始包字节。完整选中四个报告包时，平台根据持久安装回执提供经过校验的不可变实体目录，后续目录版本变化不影响相邻包引用。撤销拒绝后续读取，但无法抹除运行中执行已读取或已挂载的字节。`office` 工具把有长度上限、经过参数引用的 OfficeCLI 命令提交给与 `cloud_exec` 相同的持久执行服务；OfficeCLI 和文档依赖只在沙盒镜像中运行。`load_skill` 输出以产品运行规则开头：禁用常驻模式，每条命令指定文件，直接修改在返回前落盘；后面保留原始上游指南。

Schema 20 增加归属用户的目录安装回执，包括复用既有包版本的重试 ID。已受理的技能元数据最多包含 256 项；领取任务不依赖说明文件。当前授权只能读取其持久选用记录，过期授权会被拒绝。

## 恢复与限制

Schema 22 独立保存远程 MCP 的不可变配置、凭据和目录版本，不替换固定连接器预设。为 `TaskStore` 提供远程 MCP 受理策略时，输入受理在同一事务中保存该用户完整的已启用工具选择、原始模式及精确的原生模型声明。目录变化后，重复受理和任务恢复仍保留原声明。不支持的模式、必需的 MCP Task 扩展、名称碰撞和整体选择超限会拒绝受理，不会静默丢弃工具。模型代理从 PG 读取已受理定义，拒绝宿主篡改名称、描述或参数模式。该路径不创建执行沙盒，也不授予工具调用权限；标准 Profile 仍只开放已有固定连接器。

Schema 21 用 PostgreSQL `json` 保存原生事件及云端、桌面、连接器的结果载荷。这些不透明值完整保留转义的 NUL 及 `jsonb` 无法表示的其他 JSON 字符串内容。通过驱动整值读取，不转换为 `jsonb`，也不在 SQL 中提取任意文本；归属、排序、状态和索引使用独立的类型化列。迁移前停止 Platform 写入者并验证备份；旧版 Platform 拒绝此 schema，回退旧程序须恢复升级前的数据库和文件。

平台续接输入最多保留 256 KiB 的 JSON 编码文本，同时不超过 `maxEventBytes` 的一半。超限结果以明确标记的首尾摘录传给模型；PG 中原始 Operation 输入和执行结果保持完整。重启后领取已排队结果时应用同一限制。用户输入仍限制为 16,384 个字符。

Kubernetes 资源响应限制为 256 KiB。云沙盒与 SSH Runner 适配器显式使用独立的 1 MiB 响应预算，容纳其有界输出流经 JSON 转义后最多六倍的膨胀；仅携带 Runner 令牌不会提高普通资源预算。响应中途断开会立即拒绝；超限响应和 socket 空闲超时会拒绝并关闭请求。这些传输失败仍遵守执行对账规则，不授权重放命令。

操作提交后，客户端才收到 `accepted`。未消费的输入可以在重启后投递。已消费但没有完成轮次的输入由原生 DSH 恢复逻辑补齐中断记录，并报告失败，不会自动再次发送给模型。完成响应丢失时，重新领取租约后根据已保存的轮次核对结果。

取消会话时，平台在 PG 中核对当前用户的归属。尚未领取的输入直接以失败终结，不启动模型调用；运行中的输入保存取消意图，由持有租约的宿主在续租时读取。仍在运行的宿主取消 Agent，并在释放授权前保存原生日志。接替宿主不会重放已取消输入，后续仍可在同一会话提问。没有活跃操作时重复取消只返回成功，不改动历史。若轮次在宿主收到取消请求前已经结束，则以已记录的完成或失败结果为准。

本切片支持根会话文本对话、有限大小的文件传输和文本编辑、个人技能说明、两个受控远程 API 工具、云端命令及选定本地项目中的桌面命令。完成的输出通过持久事件订阅传送，部分模型 token 不广播到浏览器。私有 Profile 不承诺兼容所有原生 Controller 或 Session 存储消费者。它拒绝未知 Session 版本，不迁移旧 PowerEvolve 数据库。结果不明的远端写入或命令留在 PG 中等待对账；宿主不会盲目重放。

本机试用的宿主与平台进程仍使用当前 OS 用户，尚未按进程身份隔离。云端命令在按命名空间授权的 gVisor Agent Sandbox 中执行，本地命令使用配对设备上的 Docker。工作区文件已通过目录描述符相对访问抵御并发替换符号链接。生产部署接入不可信租户之前，还需要独立服务身份、网络出口规则、设备可信证明，以及多节点 POSIX 挂载验证。当前连接器是本机受控试用目标，并非通用第三方连接器目录。生产入口属于后续切片。

## 验证

`pnpm run test:power-evolve` 使用构建后的 `dsh` Profile、真实且唯一命名的测试数据库，以及确定性模型、远端 API 和沙盒执行器。测试覆盖身份和配置区分、授权拒绝、订阅、重复受理、中断/重启、旧授权、退出、原生历史回放、Agent/Session 回收、文件字节、个人技能、审批、远端对账、云端和设备执行、取消、实例变化及原会话续接。测试监听端口由 OS 分配，清理时等待子进程退出和数据库连接关闭。本机浏览器试用另行验证真实 DeepSeek、k3s 和已配对的本机设备。
