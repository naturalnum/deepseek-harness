# S6 连接器补齐实施约定

本文固定[交付计划](DELIVERY-PLAN.md)中“连接器完整功能”这一行的范围、接口职责和并行文件所有权。它是实施计划，不是已交付记录。开始条件是内置技能切片完成端到端验收并保留独立试用；MCP 和 SSH 各自形成可试用的纵切面，不能以配置表单或固定探针代替真实工具执行。

## 完成出口

| 子切面 | 原生客户端操作 | 必须贯穿的后端能力 |
| --- | --- | --- |
| 远程 MCP | 复用旧版个人 MCP 页的多连接列表、搜索、创建、编辑、删除、启停、保存配置检查与草稿检查；支持无认证、Bearer 和自定义认证头 | Streamable HTTP 发现多个带参数工具，保存目录版本，按会话授权并调用，展示真实结果及可信审批；普通 HTTP 调用不创建执行沙盒 |
| SSH | 复用旧版个人 SSH 页，补私钥及口令、编辑、删除，保留密码与主机密钥指纹 | 真实 SSH 服务上的认证和普通命令、独立具体命令审批、取消、撤销与结果不明处理；SSH 进程仍在执行 Runner |

旧产品的个人 MCP 执行配置只声明 `streamable-http`。本片恢复该范围；OAuth、独立旧式 HTTP+SSE 和任意用户 STDIO 配置不以固定 `whoami` 代替，也不宣称已经支持。现有隔离 STDIO 路径保留，其用户进程禁止迁入共享 Host。涉及新的进程型工具配置时，仍须单独通过 Runner 和真实执行验收。

## 接口与数据归属

1. **客户端 → Host：** 登录后的连接元数据、列表、查询、启停、删除和一次性凭据上传票据。沿用原生 Typert 入口；只返回认证种类、是否配置、请求头名称等脱敏状态。旧客户端 Port 接口通过适配器迁移，不再创建一套页面。
2. **客户端 → Platform：** 凭据上传和可信审批。票据固定用户、用途、请求 ID、连接版本、大小及有效期；重复请求的元数据或凭据不同必须冲突。密钥只在可信后台加密持久化，不进入 Host RPC、日志或模型上下文。
3. **Host → Platform：** 当前执行授权下的工具目录和调用提交。提交固定 `callKey`、连接版本、目录版本、工具标识及原始参数；重复提交返回同一持久记录。工具返回排队／审批收据，最终结果通过一次持久续接回到原会话。
4. **Platform 内部：** 配置与凭据版本、目录发现、权限与审批、调用派发分别由明确的所有者实现。网络 I/O 不占用数据库事务。Platform 保留实际 endpoint、凭据和网络客户端，Host 只登记经授权的 DSH 工具定义。

配置写入使用 `requestId` 和 `baseRevision`，删除保留审计及历史版本；禁用、删除或更新后，旧版本不得继续获得新的派发许可。密码和私钥采用显式的凭据格式版本，历史密码载荷不能尝试按新 JSON 格式解析。

草稿检查有独立的 `draftId`、`checkId`、`requestId`、用户、Session 和不可变草稿版本，可选引用本人已保存连接及 `baseRevision`。编辑草稿支持保留、替换和清除原认证值，不回显旧秘密。凭据票据区分创建、更新及草稿检查用途；草稿无需先保存或启用正式连接。检查提供持久状态与取消，只握手和列举工具，有容量、过期和清理限制；草稿目录不能进入普通 Operation 或继承执行授权。

PG 在原有连接身份上增加不可变配置／凭据版本、目录版本、变更请求、工具权限及调用记录。MCP 调用记录包含用户、Session、源 Operation、callKey、所用版本、参数摘要、审批状态、派发意图、结果及唯一续接请求。原始 MCP 目录、参数和返回载荷使用可保留 NUL 的 JSON 整值存储；可查询的身份、状态、摘要和索引单独列存储。

输入持久受理时固定启用的连接、凭据版本和已发现目录。认领或恢复不能用最新配置替换旧选择，也不能通过重查远端目录改变已经受理的模型工具集合。尚未发现成功的连接显示明确状态；零工具是合法发现结果。已有固定 `whoami` 记录按历史格式识别，不能悄悄转换成当前任意远端调用。

## 工具与权限

Host 使用上游公开 `createMcpToolDefinition` 适配器，保留结构化参数和 MCP 结果类型。公共工具名稳定、长度受控并避免不同连接或截断名称碰撞；路由使用保存的工具标识，不从名称反向猜测连接。工具描述、参数模式和模型可见内容均能从原生日志恢复。

模型代理按当前授权内的具体工具名和参数模式校验。不能把现有固定名称枚举改成允许任意 `mcp__` 前缀。工具数、单项模式、整个目录、调用输入和输出均有经过配置校验的预算；超限返回明确错误，不能静默取前若干工具。

这里的模型工具集合由 Platform 在 Operation 受理时固定，包含允许提请审批的工具，与用户已经批准调用是两种状态。工具定义版本记录公共名到连接／配置／凭据／目录／原始工具标识的映射，保存原始输入模式及 DSH 规范化后的模型模式和描述摘要。不支持的模式明确拒绝。代理独立读取可信快照核对声明，不能接受 Host 自报的摘要；Platform 还须按固定原始模式校验实际参数。发现目录变化产生新版本并停止给旧版本签发新调用许可，保留历史集合；本地目录摘要不保证远端实现永远不变。

未获授权的工具默认等待可信审批。MCP 的只读、破坏性或幂等注解不授予权限。审批显示实际目标、连接与目录版本、具体工具和冻结参数；指纹绑定用户、Session、Operation、调用 ID、所有版本及参数摘要。Host 只能给出审批链接。

可信入口可批准一次，也可明确授权当前会话的指定版本工具；持久授权必须由用户另行选择且可撤销。新工具或版本变化不自动继承旧授权。审批决定和派发前都检查当前权限；拒绝、过期、成功、失败及结果不明均需持久记录并使原会话收到明确状态。

派发意图落盘后，发生超时、断线或执行者故障，通用 MCP 默认进入结果不明状态。不得因远端声明 `idempotent` 而自动重放，也不得沿用便签测试服务特有的结果查询协议。只有真实服务提供并已验证稳定幂等键和查询能力时，才可使用对应受控对账实现。

调用唯一键为 `(operationId, callKey)`。同键、同冻结指纹返回原收据；任一连接、目录、工具或参数不同返回冲突。重复的待审批、拒绝、过期、终态或不确定请求均不创建新派发。派发许可的线性化点是持有连接和动作记录锁时，检查当前权限及 worker 租约／epoch，并提交 `dispatch-intent` 的事务：撤销阻止此后签发许可，已经签发的一次许可可能在撤销返回后到达远端。网络发送不占用该事务；仅获得许可的当前 worker 能使用一次，SDK 不得自行重发工具调用，恢复实例不能接续使用旧许可。界面和文档不能声称撤销可撤回已经签发的远端动作。

成功续接可以在原有固定目录和当前授权下进行后续步骤，每个新调用仍有独立持久标识、权限检查和次数／时间预算。不能把通用工具续接永久限制为只读出结果，导致多步骤任务必须由用户逐条推动。结果不明不触发原动作重试；验收至少包括两个不同工具先后完成同一个用户任务。

## 网络与生命周期

远程 MCP 默认只允许 HTTPS 公网地址，内网或本机试用目标需运营配置明确授权。检查所有 DNS 结果及 IPv4 映射地址，将已批准地址绑定到实际连接，同时保留原主机名的 SNI 与证书验证。禁止重定向、环境代理绕过和不受控的资源／模式外链抓取。

认证头与传输头分开处理；拒绝 Host、代理、Cookie、MCP 会话以及连接控制类头的用户覆盖，拒绝控制字符和大小写冲突。连接缓存至少按用户、连接、配置／凭据版本和授权作用域隔离，具有明确关闭和过期行为；不共享“当前用户”的客户端。

SSH 继续复用固定主机密钥、受控地址和隔离 Runner。编辑连接或替换凭据使旧审批失效；已派发且状态不明的命令先对账，不能在新凭据下重执行。

## 并行文件所有权

| 所有者 | 文件与工作 |
| --- | --- |
| 集成者 | `contracts.ts` 及新连接器 DTO、`schema.ts`、数据库初始化、TaskStore、模型代理、Platform／Host 路由、Profile、依赖与锁文件、续接字段；分配下一迁移版本，最终联调与试用冻结 |
| 配置实现者 | 新 `platform/mcp-connections.ts` 及凭据／目录仓储辅助文件、对应独立测试；SSH 阶段再分配管理代码 |
| 调用实现者 | 新 `platform/mcp-transport.ts`、`platform/mcp-actions.ts`，发现、受控网络、审批状态及派发实现、独立 TLS／协议和恢复测试 |
| 客户端实现者 | 旧个人 MCP 页面与 Port 适配、`host/mcp.ts` 的动态工具登记、相应客户端与 Host 测试；按约定扩展现有可信审批页，不创建替代产品页面 |

共同字段和服务方法先在集成者维护的 DTO 中落定，再并行实现。可信审批页的具体文件一次只交给一个所有者。任何需要修改他人文件的情况先回报集成者，由所有者修改或重新划分；隔离分支提交后串行合并。

## 验收次序

1. 两个真实浏览器身份分别创建至少两个连接，发现不同带参数工具并调用；验证名称碰撞、空目录、Bearer／自定义头、设置隔离及不创建沙盒。凭据上传必须直达 Platform。
2. 使用同一请求 ID 重发、版本竞争更新、禁用／删除与旧接受记录并存；篡改用户、连接、目录或工具标识被拒绝。断开及重启后不能更换已固定版本或串用连接。
3. 在独立可信入口批准和拒绝具体调用，验证一次授权、会话授权及撤销；用受控真实服务记录外部调用次数，响应丢失后不自动重发。替身模型与真实模型证据分别记录。
4. 真实 TLS／DNS 拒绝、资源预算和截断响应测试通过后，完成原生客户端双用户试用与记录，固定 MCP 版本。随后按同样方式完成 SSH 密码／私钥、普通命令和故障路径，保留两个阶段的可回退试用。
5. 执行受影响的构建、类型检查、原生会话快照和发布产物检查；记录迁移前备份及适用的恢复证据。连接器行完成后再合入账号生命周期的新页面。
