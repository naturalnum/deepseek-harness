# Report and Paper Visual Narrative

This reference adapts the OpenAI4S `paper-narrative` idea for reports and papers.

Inventory the current title, abstract or result summary, section takeaways,
captions, and visual artifacts. Write a one-line role for each visual:

- orientation or scope;
- decisive result;
- mechanism or explanation;
- robustness or alternative;
- application or implication;
- limitation or boundary.

Then check:

1. Does the first visual help a cold reader understand the result or scope?
2. Is the strongest evidence visually prominent rather than buried after
   process material?
3. Does each later visual add a distinct role?
4. Is any panel repeated in another figure, viewer, card, or table?
5. Is a missing visual actually a missing analysis rather than a design task?

Recommend moving, combining, simplifying, or deleting visuals before proposing
new ones. For ordinary reports, keep the reading path linear: answer, decisive
evidence, interpretation, limitations, and reproducibility. For papers, hand a
single claim to the multi-panel workflow only after the whole figure arc is
coherent.
