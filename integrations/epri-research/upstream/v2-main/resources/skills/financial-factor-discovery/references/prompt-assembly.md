# XAlpha Prompt Assembly

The upstream snapshot is a prompt library, not an executable runtime. DeepScientist assembles only the blocks required by the current assignment. A submission bundle and Git history are the durable handoff; no hidden search engine or promotion state is required.

## Phase router

| Phase                       | Read these upstream prompt families                                                                                                                                                                                                                                                                            | Required delivery                                                                                                                                                                                      |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Report-to-Memory Absorption | `shared/utility_constitution.md`, `report_to_memory/research_md_clean_instruction.md`, `report_to_memory/chunk_filter_system_template.md`, `report_to_memory/report_b_layer_mining_template.md`, `report_to_memory/route_cluster_to_c_layer_template.md`                                                       | `source_map`, eligible mechanism families, concrete archetypes, applicability limits, and rejected material with reasons                                                                               |
| Macro routing               | `shared/xalpha_constitution.md`, `shared/macro_brain_constitution.md`, `macro_brain/global_agent_routing_prompt.md`, `macro_brain/active_agent_intro_prompt.md`, `macro_brain/active_agent_guidance_prompt.md`, `macro_brain/hypothesis_subset_planner_prompt.md`                                              | routing mode, one primary mechanism, three or four supporting mechanisms when available, active archetypes, falsifiable hypotheses, and cheapest decisive tests                                        |
| Micro seed and evolution    | `shared/micro_brain_constitution.md`, `shared/normal_factor_agent.md` or `shared/novelty_factor_agent.md`, plus exactly one of `micro_brain/mutation_prompt.md`, `crossover_prompt.md`, `refinement_prompt.md`, or `runtime_repair_prompt.md`; add alignment review or revision only when that gate is reached | one candidate with Hypothesis Card Lite, formula or code, explanation, point-in-time fields, expected sign and horizon, parent ids, operation, generation, alignment verdict, and deterministic checks |
| Deterministic validation    | [evaluation-gates.md](evaluation-gates.md); register/freeze the contract with `factor_lab`, then use upstream alignment and repair prompts only to explain or repair a concrete failed gate                                                                                                                    | one `evaluationId`, signed evaluator receipt, split and cost contract, failed and passed gates, counterexample, and `keep`, `mutate`, or `discard` recommendation                                      |
| Cross-family consolidation  | `shared/cross_brain_constitution.md`, `cross_brain/factor_to_b_layer_prompt.md`, `cross_brain/factor_to_c_layer_prompt.md`, `cross_brain/good_feedback_summary_prompt.md`, `cross_brain/bad_feedback_summary_prompt.md`, and `cross_brain/factor_record_format.md`                                             | final mechanism re-attribution, deduplicated GOOD/BAD lessons, reusable principle, failure boundary, repair condition, and Memory promotion recommendation                                             |

Do not load every file in a family. Start with the constitution and task template named above, then read an optional helper only when its corresponding input exists. Preserve upstream instruction hierarchy: constitution and safety constraints outrank a phase task template, and project/user constraints outrank stylistic examples.

## Handoff envelope

Every Team delivery uses `team_submit` against the assigned Core WorkItem and includes useful outputs, evidence, limitations, and the next recommendation in its `evidence` field. The submission and reviewer notification are committed together. When files changed, Git submit additionally carries only the next unused content revision and immutable head; Core derives repository, branch, and base from the WorkItem assignment. Use `team_send_message` only for optional attachments or follow-up context. Evidence and falsification are required only when the acceptance criteria need them.

## DeepScientist integration rules

- `factor-research/submissions.json` is the new user-facing submission stream. `factor-research/portfolio.json` remains a read-only projection for historical projects.
- Git records implementation, evaluator changes, worktree branches, charts, and concise campaign notes. A submission references these files rather than duplicating their contents.
- Search scores and in-sample metrics may guide exploration but cannot be presented as out-of-sample evidence. Unknown values stay pending.
- One Lead owns the visible handoff and canonical `factor_lab` evaluation. Workers increase breadth, not the number of competing truths; the Lead may skip a phase when it is irrelevant and state why in `limitations`.

## Minimal example

For a report-grounded campaign, the Lead may ask the Memory Curator for mechanisms, the Macro Brain for routing, two Micro workers for independent candidates, and a generic Data Auditor for field availability. After reading the handoffs, the Lead freezes one protocol, evaluates the accepted candidate with `factor_lab`, and submits its single `evaluationId` with `factor_submit`. No repeated metric ids, empty Portfolio, or hidden search job is needed.
