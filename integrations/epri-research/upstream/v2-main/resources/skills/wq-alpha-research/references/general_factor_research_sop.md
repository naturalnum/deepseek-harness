# 通用金融因子研究建议

本文件只在通用因子任务需要进一步设计时读取。主流程仍是 `Inspect -> Propose -> Evaluate -> Decide`；下面是可选的研究提示，不是固定清单。

## 1. Inspect：冻结可比较口径

只记录会影响本轮判断的边界：资产与市场、频率与持仓期、数据来源与时间可得性、样本区间、成本假设。已有明确答案时不要重复确认。

若研究只到想法阶段，不必为了“完整”补齐所有回测参数；明确尚未确定即可。

## 2. Propose：机制先于公式

- 每个候选用一句话说明为什么可能预测未来收益、风险或横截面差异。
- 默认让候选来自不同信息来源或经济机制，而不是同一公式的窗口微调。
- 表达式保持可解释，并标注所需字段、预期方向和最大风险。

## 3. Evaluate：按决策需要逐层加深

静态检查可以先覆盖字段可用性、未来函数、公告时点、复权回填、成分股回看、标签重叠和结构重复。只有幸存候选才需要更昂贵的 IC、分层收益、换手、成本、回撤和样本外验证。

稳健性可以按市场、行业、市值、年份、市场阶段、持仓期或成本情景展开，但只选择最可能改变当前决策的维度。

## 4. Decide：保留可复用判断

每轮给出保留、修改、淘汰、晋级或阻塞判断，并记录原因。不要为了流程完整继续运行不会改变判断的实验。

## 5. 默认输出格式

```markdown
## 研究假设

- ...

## 数据与边界

- 市场/资产：
- 区间：
- 频率：
- 数据源：
- 主要偏差风险：

## 因子设计

- 字段：
- 公式/特征：
- 标准化/中性化：
- 预期方向：

## 验证计划

- 静态检查：
- 回测/评估：
- 稳健性：

## 当前状态

- idea-only / locally checked / backtested / paper-traded / production-ready
```

## 6. 硬边界

- 不得编造 Sharpe、IC、收益、回撤、换手、提交状态或平台通过状态。
- 不得把未执行的回测写成已经验证。
- 不得把同一机制的窗口微调包装成多个独立发现。
- 不得忽略交易成本、数据滞后、幸存者偏差和样本外稳定性。

## 7. 进一步建议

- 先做小批量、机制差异明显的候选；不要一次堆几十个同质变体。
- 每轮实验后写明失败原因和下一轮是否值得继续。
- 若用户要求快速探索，优先交付“候选机制 + 数据需求 + 最小验证脚本”，而不是假装已有结论。
